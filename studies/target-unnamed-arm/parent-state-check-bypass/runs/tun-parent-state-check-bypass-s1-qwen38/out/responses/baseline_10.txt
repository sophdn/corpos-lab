### 1. Defect analysis

The current `validate_url_field()` behaves like a presence check:

```python
def validate_url_field(value):
    if not value:
        return False
    return True
```

This means any non-empty string — including `not-a-url`, `://bad`, `auth_service_url` (literal), `http://` (no host), or `htp://missing-scheme-check` — passes, so the CLI exits 0 when it should exit 1.

### 2. Proposed fix

Replace the presence-only check with a structural validation using `urllib.parse` (stdlib, no new dependencies), with explicit scheme and host requirements:

```python
from urllib.parse import urlparse

def validate_url_field(value, field_name="url"):
    """Validate that `value` is a structurally well-formed URL.

    Returns (ok: bool, reason: str | None).
    """
    if not isinstance(value, str) or not value.strip():
        return False, f"{field_name} must be a non-empty string"

    candidate = value.strip()
    try:
        parsed = urlparse(candidate)
    except Exception as exc:  # defensive: urlparse is lenient, but guard anyway
        return False, f"{field_name} could not be parsed: {exc}"

    # Require an explicit http/https scheme (config service URLs should not
    # be relative or use opaque schemes).
    if parsed.scheme not in ("http", "https"):
        return False, (
            f"{field_name} must use an http or https scheme "
            f"(got: {parsed.scheme!r})"
        )

    # Require a non-empty netloc (host). This rejects `http://`,
    # `://bad`, and relative paths.
    if not parsed.netloc:
        return False, f"{field_name} must include a host"

    # Host must contain at least one dot, or be a reserved local name
    # (localhost) / IP literal, to reject bare words like `auth`.
    host = parsed.hostname or ""
    if not host:
        return False, f"{field_name} must include a valid host"
    if host == "localhost" or _is_ip_literal(host):
        return True, None
    if "." not in host:
        return False, f"{field_name} host {host!r} is not a valid domain or IP"

    return True, None


def _is_ip_literal(host: str) -> bool:
    """True if host looks like an IPv4 or IPv6 literal."""
    # IPv4
    parts = host.split(".")
    if len(parts) == 4 and all(p.isdigit() and 0 <= int(p) <= 255 for p in parts):
        return True
    # IPv6 (contains colons)
    if ":" in host:
        return True
    return False
```

And the CLI entry point should translate the failure into exit code 1 and surface the reason:

```python
# in the config-validator CLI for --service auth
ok, reason = validate_url_field(cfg.get("auth_service_url"), "auth_service_url")
if not ok:
    print(f"config-validator: error: {reason}", file=sys.stderr)
    return 1
# ... continue; return 0 on success
```

### 4. Edge cases / rationale notes

- **Scheme restriction to http/https:** Deliberate. `auth_service_url` is a service endpoint; allowing `file://`, `gopher://`, etc. would be a security smell. If the team later needs other schemes, this is a one-line change to the allowlist.
- **`localhost` and IP literals allowed without a dot:** Prevents false negatives for local/dev configs.
- **`urlparse` is lenient by design** (it doesn't validate), so the explicit scheme + netloc + host checks are the actual validation logic — that's why the fix is more than "call `urlparse` and check for exceptions."
- **No new dependencies:** Uses only `urllib.parse` and `sys`, so no lockfile or dependency changes.
