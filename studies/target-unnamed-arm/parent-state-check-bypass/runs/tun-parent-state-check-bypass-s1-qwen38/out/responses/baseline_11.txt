## 2. The fix

Add URL-structure validation to `validate_url_field()`. I'll use the stdlib `urllib.parse` (no new dependency).

```python
from urllib.parse import urlparse

def validate_url_field(config, field_name):
    value = config.get(field_name)
    if not value or not isinstance(value, str):
        return f"{field_name} is required"

    parsed = urlparse(value)
    # Require a scheme and a netloc (host). Reject things like "localhost",
    # "ftp://", "://host", or bare "host/path".
    if parsed.scheme not in ("http", "https"):
        return f"{field_name} must be a valid http(s) URL, got: {value!r}"
    if not parsed.netloc:
        return f"{field_name} must include a host, got: {value!r}"

    return None
```

Design decisions:
- **Scheme restricted to `http`/`https`.** An `auth_service_url` talking to an auth service should be http(s). If the team allows other schemes (e.g. `unix://` for local sockets), relax the scheme check — confirm with the team before finalizing.
- **`netloc` required.** Catches the common malformed cases: empty host, `://host` (no scheme), bare hostnames.
- **No DNS/connectivity check.** Validation is structural only — we must not make a network call in a validator (it would be slow, non-deterministic, and fail in CI/offline). "Malformed" per the ticket means structure, not reachability.
- **`isinstance(value, str)` guard** in case the config parser yields a non-string (e.g. a number), so `urlparse` doesn't raise and we produce a clean error instead of a traceback.

If `validate_url_field()` is used by other fields too, confirm those also want http(s)-only. If it's generic and other fields allow arbitrary URLs, consider a `schemes=("http","https")` parameter so this ticket's stricter rule applies specifically to `auth_service_url` without changing behavior for other callers. I'd check the call sites before finalizing.
