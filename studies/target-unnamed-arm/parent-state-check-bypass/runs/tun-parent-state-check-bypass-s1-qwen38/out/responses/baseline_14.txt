### Root Cause Analysis
As described in the ticket, `validate_url_field()` in `config/validator.py` currently only checks for presence and non-emptiness:
```python
# Hypothetical current implementation
def validate_url_field(value):
    if not value:
        return False
    return True
```
This allows malformed strings (e.g., `"not-a-url"`, `"http://"`, `"ftp://invalid"`) to pass validation, causing `config-validator --service auth` to exit with code 0.

### Proposed Fix
We need to update `validate_url_field()` to enforce valid URL structure. I recommend using Python's standard library `urllib.parse` for robust validation without adding external dependencies.

**File:** `config/validator.py`

```python
import re
from urllib.parse import urlparse

def validate_url_field(value):
    """
    Validates that the given value is a present, non-empty, and structurally valid URL.
    Accepts http:// and https:// schemes.
    """
    if not value or not isinstance(value, str):
        return False
    
    # Strip whitespace
    value = value.strip()
    if not value:
        return False

    try:
        result = urlparse(value)
        # Enforce http or https scheme
        if result.scheme not in ('http', 'https'):
            return False
        
        # Ensure netloc (host) is present
        if not result.netloc:
            return False
        
        # Optional: Basic check for valid host characters
        # This prevents edge cases like "http://invalid host"
        if not re.match(r'^[a-zA-Z0-9.-]+(:\d+)?$', result.netloc):
            return False
            
        return True
    except Exception:
        return False
```
