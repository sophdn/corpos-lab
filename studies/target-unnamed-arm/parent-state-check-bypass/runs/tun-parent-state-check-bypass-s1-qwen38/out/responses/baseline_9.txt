## Root-Cause Analysis

The described root cause is a classic *presence-only* check. The current `validate_url_field()` (as summarized in the ticket) does roughly this:

```python
def validate_url_field(value: str) -> bool:
    return bool(value)          # present and non-empty, nothing more
```

So `"not a url"`, `"http://"`, `"ftp://"` (if the schema expects http/https), a bare hostname, or a URL with an unbalanced scheme all pass, because the string is non-empty. The validator then reports success and the process exits 0 — masking a config that will fail at runtime in the auth service.

## Fix Plan

1. Add real URL-structure validation inside `validate_url_field()`.
2. Preserve the contract: return a boolean (or raise a typed error that the caller converts to exit code 1).
3. Keep valid URLs passing (http/https with host; permissive about port/path/query).
4. Update the CLI path so a `False` from the validator (or a raised `ValidationError`) maps to `sys.exit(1)` with a clear message on stderr.
5. Add regression tests covering the malformed cases and the valid cases.

## Concrete Patch (for `config/validator.py`)

```python
# config/validator.py
from __future__ import annotations

from urllib.parse import urlparse
from urllib.error import ParseError


class ValidationError(Exception):
    """Raised when a config field fails validation."""


def validate_url_field(value: str, *, field: str = "auth_service_url") -> bool:
    """
    Validate that `value` is a structurally valid URL.

    Acceptance criteria (per DEF-2026-04-1047):
      - Rejects empty / whitespace-only values.
      - Rejects values with no scheme (e.g. "localhost:8080").
      - Rejects values whose scheme is not http/https.
      - Rejects values with no netloc (e.g. "http://").
      - Rejects values that fail to parse.
      - Accepts http/https URLs with a host, optional port, path, query.

    Returns True if valid, False otherwise.
    """
    if not isinstance(value, str):
        return False
    candidate = value.strip()
    if not candidate:
        return False

    try:
        parsed = urlparse(candidate)
    except (ParseError, ValueError):
        return False

    # Scheme must be http or https.
    if parsed.scheme not in ("http", "https"):
        return False

    # A netloc (host) is required for a service URL.
    if not parsed.netloc:
        return False

    # Host must be present in the netloc.
    host = parsed.hostname
    if not host:
        return False

    # If a port is present, it must be a valid integer in range.
    if parsed.port is not None:
        if not (0 < parsed.port <= 65535):
            return False

    return True
```

> Note: `urlparse` is intentionally lenient — it does not raise on most malformed inputs; it just produces a result. That's why we must explicitly check `scheme`, `netloc`, and `hostname` rather than relying on an exception.

# config/validator_cli.py (or wherever --service auth is handled)
import sys

def run(service: str, config: dict) -> int:
    if service == "auth":
        url = config.get("auth_service_url")
        if not validate_url_field(url, field="auth_service_url"):
            print(
                f"error: 'auth_service_url' is not a valid http(s) URL: {url!r}",
                file=sys.stderr,
            )
            return 1
    # ... other services ...
    print("OK")
    return 0

if __name__ == "__main__":
    sys.exit(run(*parse_args()))
```

# tests/test_config_validator.py
import pytest
from config.validator import validate_url_field


VALID = [
    "http://localhost:8080",

    "https://auth.example.com:8443/api/v2?x=1",

INVALID = [
    "",
    "   ",
    "not a url",
    "localhost:8080",          # no scheme
    "http://",                 # no host
    "http:///path",            # no host
    "ftp://auth.example.com",  # wrong scheme
    "gopher://auth.example.com",
    "http://",
    "://no-scheme",
    "http://host:99999999",    # port out of range (urlparse may reject or coerce; assert behavior)
]


@pytest.mark.parametrize("value", VALID)
def test_valid_urls_pass(value):
    assert validate_url_field(value) is True


@pytest.mark.parametrize("value", INVALID)
def test_malformed_urls_fail(value):
    assert validate_url_field(value) is False
```

> The `http://host:99999999` case is edge-casey: `urlparse` in some Python versions stores out-of-range ports as `None` rather than raising, so the explicit port-range check in `validate_url_field()` is what makes the rejection deterministic. If your environment's `urlparse` raises on it, the `try/except` handles it.
