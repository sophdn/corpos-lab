Based on the defect description for **DEF-2026-04-1047**, here is the implementation plan and the proposed code fix to resolve the issue in `config/validator.py`.

### 1. Root Cause Analysis
The current implementation of `validate_url_field()` in `config/validator.py` performs a shallow check:
```python
# Hypothetical current buggy code
def validate_url_field(field_name, value):
    if not value:
        return False
    return True # Bug: Returns True for any non-empty string, e.g., "not-a-url"
```
This allows malformed strings (e.g., `auth://missing-host`, `http://`, `javascript:void(0)`) to pass validation, causing `config-validator --service auth` to exit with code `0` (success) instead of `1` (failure).

### 2. Proposed Fix
We need to replace the presence check with a structural URL validation. Python's standard library `urllib.parse` is the appropriate tool for this, as it requires no external dependencies.

**Key Validation Criteria:**
1.  The URL must have a valid scheme (`http` or `https` for service URLs).
2.  The URL must have a valid netloc (host).
3.  The URL must be parseable without raising a `ValueError`.

**Code Change in `config/validator.py`:**

```python
import urllib.parse

def validate_url_field(field_name, value):
    """
    Validates that the given value is a structurally valid URL.
    Returns True if valid, False otherwise.
    """
    if not value or not isinstance(value, str):
        return False
    
    try:
        parsed = urllib.parse.urlparse(value)
        
        # 1. Scheme must be present and valid (http/https expected for services)
        if parsed.scheme not in ('http', 'https'):
            return False
        
        # 2. Netloc (host) must be present and non-empty
        if not parsed.netloc:
            return False
        
        # 3. Optional: Check for invalid characters in the netloc
        # urlparse generally handles this, but explicit check ensures robustness
        if not all(c.isalnum() or c in '-._~' for c in parsed.hostname):
            return False
            
        return True
    except (ValueError, AttributeError):
        return False
```
