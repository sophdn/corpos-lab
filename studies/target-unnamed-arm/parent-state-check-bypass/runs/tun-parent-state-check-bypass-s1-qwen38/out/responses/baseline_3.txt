## Step 2 — Root cause analysis

The ticket description already names the defect precisely, so I'll restate it to confirm the fix target:

`validate_url_field()` currently performs only a **presence** check — it verifies that `auth_service_url` is present and non-empty. It performs **no structural validation** of the URL. Consequence:

- Input: `auth_service_url = "not a url"` (or `"http://"`, `"htp:/x"`, etc.)
- Current behavior: field is present and non-empty → treated as valid → process exits **0**.
- Expected behavior: field is structurally malformed → treated as invalid → process exits **1**.

The exit code is presumably propagated from the validator's return value (e.g., `sys.exit(0 if all_valid else 1)`), so the fix is confined to making `validate_url_field()` return a failure for malformed URLs. No caller changes are required.

## Step 3 — Fix design

I will add a URL **structure** check to `validate_url_field()`. Design choices:

1. **Use the standard library** (`urllib.parse`) rather than a new dependency. `urllib.parse.urlparse` is available, dependency-free, and sufficient for structural validation.
2. **Require a recognized scheme and a network location.** For an *auth service URL*, a host is mandatory. I'll accept the schemes an auth endpoint realistically uses (`http`, `https`) and require a non-empty `hostname`. This rejects `"not a url"` (no scheme), `"http://"` (no host), and `"ftp://..."` (wrong scheme) while accepting `"https://auth.example.com"` and `"http://auth.internal:8443/v1"`.
3. **Preserve the existing presence check** — a missing/empty field must still fail, and the new structural check layers on top of it.
4. **Keep the function's contract** (return a boolean / validation result) so the existing exit-code propagation is untouched.

### Proposed change to `config/validator.py`

```python
from urllib.parse import urlparse

_ALLOWED_SCHEMES = {"http", "https"}

def validate_url_field(value, field_name="auth_service_url"):
    """Validate that a URL field is present, non-empty, and structurally valid.

    Returns True if the field is a well-formed http(s) URL with a host,
    False otherwise.
    """
    # Existing behavior: presence + non-empty.
    if not value or not str(value).strip():
        return False

    url = str(value).strip()
    try:
        parsed = urlparse(url)
    except (ValueError, TypeError):
        return False

    # Structural validation (the missing piece that caused DEF-2026-04-1047).
    if parsed.scheme not in _ALLOWED_SCHEMES:
        return False
    if not parsed.hostname:
        return False
    return True
```

**Why this satisfies both acceptance criteria:**

- *Criterion 1 (exit 1 for malformed):* `"not a url"` → `urlparse` yields `scheme=''`, so `parsed.scheme not in {"http","https"}` → `False` → validation fails → exit 1. `"http://"` → `hostname is None` → `False` → exit 1. `"ftp://x"` → wrong scheme → `False` → exit 1. ✅
- *Criterion 2 (valid URLs still pass):* `"https://auth.example.com"` → scheme `https`, hostname `auth.example.com` → `True` → exit 0. `"http://auth.internal:8443/v1"` → scheme `http`, hostname `auth.internal` → `True` → exit 0. ✅
