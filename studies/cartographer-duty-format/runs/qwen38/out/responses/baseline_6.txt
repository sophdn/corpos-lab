# Duty: `repair-duty`

**Scope**: This duty governs the repair of a confirmed software defect with a known locus.
**Executor**: Any office of the Agentic Order.
**Prerequisite**: The defect is confirmed, and the locus (file, line, and nature of failure) is known.

---

## Gate 1: Context Acquisition & Reproduction

**Verification**:
The executor has accurately reproduced the defect in a controlled environment and has fully mapped the immediate context of the locus.

**Requirements for Completion**:
1.  **Reproduce**: Execute the specific input that triggers the defect (e.g., calling `calculate_average([])`) and confirm the exact error type and message (e.g., `ZeroDivisionError`).
2.  **Isolate**: Identify the specific line of code where the failure occurs (e.g., `calculator.py:2`).
3.  **Context Map**: Retrieve the full function definition containing the locus, its docstring (if any), and its type hints. Identify all callers of the function within the codebase if feasible, to understand expected usage patterns.
4.  **Record**: Log the reproduction steps, the exact error trace, and the current source code of the affected function.

---

## Gate 2: Root Cause Analysis & Design

**Verification**:
The executor has identified the precise logical flaw and designed a repair strategy that addresses the root cause without introducing new side effects.

**Requirements for Completion**:
1.  **Diagnose**: Explicitly state why the defect occurs. For the anchor case: The function performs division by `len(values)` without checking if the list is empty, leading to a division by zero.
2.  **Select Strategy**: Choose one of the following repair strategies, justified by the function’s contract and usage:
    *   **Strategy A (Raise Explicit Error)**: Replace the implicit `ZeroDivisionError` with a more descriptive custom exception or `ValueError` to signal invalid input.
    *   **Strategy B (Return Default/Neutral Value)**: Return a neutral value (e.g., `0.0` or `None`) if the list is empty, provided this aligns with the function’s intended semantics.
    *   **Strategy C (Guard Clause)**: Add an explicit check at the start of the function to handle the empty case before performing the calculation.
3.  **Define New Behavior**: Specify the exact new behavior for the edge case (empty list) and confirm that normal cases (non-empty lists) remain unchanged.
4.  **Update Contract**: If the behavior changes (e.g., returning `None` instead of raising), update the docstring and type hints to reflect the new contract.

---

## Gate 3: Implementation

**Verification**:
The repair is implemented in the source code at the known locus, adhering to code style and the design chosen in Gate 2.

**Requirements for Completion**:
1.  **Modify Code**: Edit the file at the known locus (e.g., `calculator.py`).
2.  **Apply Fix**: Implement the chosen strategy.
    *   *Example for Strategy A*:
        ```python
        def calculate_average(values: list) -> float:
            if not values:
                raise ValueError("Cannot calculate average of an empty list")
            return sum(values) / len(values)
        ```
    *   *Example for Strategy B*:
        ```python
        def calculate_average(values: list) -> float:
            if not values:
                return 0.0
            return sum(values) / len(values)
        ```
3.  **Style Compliance**: Ensure the code follows the project’s linting and formatting standards.
4.  **Atomicity**: The change should be minimal and focused solely on the defect repair.

---

## Gate 4: Verification & Regression Testing

**Verification**:
The repair resolves the confirmed defect and does not break existing functionality.

**Requirements for Completion**:
1.  **Defect Resolution**: Re-execute the reproduction steps from Gate 1. The original error (`ZeroDivisionError`) must no longer occur. The new behavior (e.g., `ValueError` or `0.0`) must be observed as designed.
2.  **Regression Check**: Execute existing test cases for the function (if available) to ensure normal behavior is preserved.
    *   *Example*: `calculate_average([1, 2, 3])` must still return `2.0`.
3.  **Edge Case Check**: Test other edge cases relevant to the function (e.g., lists with `None`, non-numeric types) to ensure no unintended side effects from the added guard clause.
4.  **Static Analysis**: Run available linters or type checkers on the modified file to ensure no syntax or type errors were introduced.

---

## Gate 5: Documentation & Handoff

**Verification**:
The repair is documented, and the change is ready for review or deployment.

**Requirements for Completion**:
1.  **Update Documentation**: Ensure the docstring reflects any changes in behavior (e.g., "Raises ValueError if the list is empty" or "Returns 0.0 for an empty list").
2.  **Commit Message**: Draft a clear commit message that includes:
    *   The defect ID or description.
    *   The file and line of the locus.
    *   A brief summary of the fix (e.g., "Fixed ZeroDivisionError in calculate_average for empty lists by raising ValueError").
3.  **Handoff Report**: Produce a final summary stating:
    *   The original defect and locus.
    *   The chosen repair strategy and rationale.
    *   Evidence of successful reproduction and verification.
    *   Any known limitations or follow-up tasks (e.g., "Callers may need to handle the new ValueError").

---

**End of Duty**
