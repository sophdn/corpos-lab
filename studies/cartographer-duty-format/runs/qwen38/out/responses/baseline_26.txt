# Repair-Duty

**ID:** `repair-duty`
**Scope:** Any office of the Agentic Order executing a repair.
**Preconditions:**
1. A software defect has been confirmed.
2. The locus (file path and line number) is known and verified.
3. The executor has write access to the repository.

**Objective:**
Transform the defective code at the confirmed locus into a state that resolves the specific failure mode without introducing new defects or breaking existing functionality.

---

## Gate 1: Contextual Verification
**Verification:**
- The executor confirms that the file path and line number provided in the defect report match the current state of the repository.
- The executor reads the function or code block containing the locus to understand its intended behavior, inputs, and outputs.
- The executor confirms that the failure mode described in the defect report (e.g., `ZeroDivisionError`) is reproducible or logically derivable from the code at the locus.

**Completion Requirement:**
- The executor has identified the specific code segment responsible for the defect.
- The executor has documented the intended behavior of the code versus the observed behavior.
- The executor has confirmed that the locus is the root cause, not merely a symptom.

---

## Gate 2: Remediation Strategy Selection
**Verification:**
- The executor evaluates potential repair strategies based on the context:
  - **Edge Case Handling:** Is the defect caused by an unhandled edge case (e.g., empty input, null values, boundary conditions)?
  - **Logic Error:** Is the defect caused by incorrect logic (e.g., wrong operator, incorrect formula)?
  - **State Management:** Is the defect caused by improper state handling or resource management?
- The executor selects the minimal viable repair strategy that addresses the root cause.
- The executor ensures that the repair strategy does not violate established design patterns or coding standards.

**Completion Requirement:**
- The executor has chosen a specific repair strategy.
- The executor has justified the choice of strategy in the context of the defect.
- The executor has identified any side effects or trade-offs associated with the chosen strategy.

---

## Gate 3: Implementation of Repair
**Verification:**
- The executor modifies the code at the confirmed locus according to the selected strategy.
- The executor ensures that the repair is minimal and focused on the root cause.
- The executor adds or updates inline comments to clarify the intent of the repair, if necessary.
- The executor ensures that the code remains syntactically correct and adheres to language-specific best practices.

**Completion Requirement:**
- The code at the locus has been modified.
- The repair is syntactically valid.
- The repair addresses the specific failure mode identified in Gate 1.
- No unrelated code has been modified.

---

## Gate 4: Verification of Repair
**Verification:**
- The executor runs the specific test case that originally exposed the defect to confirm that the failure mode no longer occurs.
- The executor runs a broader suite of tests (if available) to ensure that the repair has not introduced new defects or broken existing functionality.
- The executor performs manual or static analysis to verify that the repair handles all edge cases related to the defect.

**Completion Requirement:**
- The original defect is resolved.
- No new defects have been introduced.
- The repair passes all relevant tests.
- The executor has documented the verification results.

---

## Gate 5: Documentation and Handoff
**Verification:**
- The executor updates the defect report to mark the defect as resolved.
- The executor provides a concise summary of the repair, including:
  - The root cause of the defect.
  - The repair strategy used.
  - The specific code changes made.
  - The verification results.
- The executor ensures that the documentation is clear and accessible to other members of the Agentic Order.

**Completion Requirement:**
- The defect report is updated.
- The repair summary is provided.
- The documentation is complete and accurate.
- The repair is ready for review or deployment, as per the policies of the Agentic Order.

---

**End of Duty**
