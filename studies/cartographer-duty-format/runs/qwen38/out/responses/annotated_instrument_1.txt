# Duty: repair-duty

**Jurisdiction:** Any office of the Agentic Order executing a repair on a confirmed software defect with a known locus.
**Canon Dependency:** The Taboo Registry (see below).

## Taboos

| Taboo | Why it applies |
|-------|----------------|
| `triggers-routing` | The office must verify that the prompt is correctly classified as a repair (defect exists, locus known) before execution, preventing the execution of a repair when an investigation was required. |
| `explicit-prerequisite-gate` | The office cannot begin code modification without a formally confirmed locus record containing the file path, line number, and failure mode. |
| `investigation-fix-criterion-predeclaration` | The office must declare a passing criterion before attempting the fix to prevent post-hoc fitting of the criterion to the change. |
| `investigation-fix-scope-boundary` | The office must restrict edits to the lines named in the confirmed locus to prevent opportunistic adjacent edits that break the anchor to the root cause. |
| `fix-locus-identification` | The office must verify that the fix is applied to the canonical source location, not a call site or consumer, to ensure the root cause is addressed. |
| `fix-attempt-root-cause-reassessment` | If a fix attempt fails, the office must revise the root-cause citation before attempting a second fix to prevent blind iteration. |
| `investigation-advisory-fix-durability` | If the proposed fix is advisory (comment, docstring, warning), the office must perform a durability check to confirm a caller cannot bypass it. |
| `completion-evidence-required` | The office cannot declare the repair complete without a co-located verification artifact. |
| `document-claim-verification` | Verification must be by observed test result or output, not by written claim. |
| `known-constraint-documentation` | Any environmental constraint discovered during the repair must be recorded before the session closes. |

## Gates

### Gate 1: Routing Confirmation
*Taboo: `triggers-routing`*

**When this gate fires:**
Immediately upon receipt of the repair request, before any code analysis or modification begins.

**When this gate does not fire:**
It does not fire if the prompt is already verified as a routing decision by a prior gate in a different duty, but in the context of this duty, it always fires as the first check.

**Rejection clause:**
The office rejects the repair execution if the prompt does not explicitly confirm that a defect exists and that the locus is known. If the defect is not confirmed or the locus is not known, the office must route to an investigation duty instead. This blocks the failure mode of misrouting a prompt that requires investigation into a repair execution.

### Gate 2: Locus Record Verification
*Taboo: `explicit-prerequisite-gate`*

**When this gate fires:**
After routing confirmation, before any fix attempt is formulated.

**When this gate does not fire:**
It does not fire if the locus record is already present and verified in the session context, but it must be explicitly checked.

**Rejection clause:**
The office rejects the repair if a confirmed locus record is not present. The locus record must name the file, line, and failure mode. If any of these fields is missing, the repair cannot begin. This blocks the failure mode of beginning a repair without a confirmed locus.

### Gate 3: Pre-declaration of Passing Criterion
*Taboo: `investigation-fix-criterion-predeclaration`*

**When this gate fires:**
After the locus record is verified, before any code change is made.

**When this gate does not fire:**
It does not fire if the passing criterion is already declared in the session context, but it must be explicitly checked.

**Rejection clause:**
The office rejects the fix attempt if a passing criterion is not declared before the change is made. The passing criterion must be a testable condition that defines what "fixed" means. This blocks the failure mode of fitting the criterion to whatever change was made.

### Gate 4: Scope Boundary Check
*Taboo: `investigation-fix-scope-boundary`*

**When this gate fires:**
Before any code change is applied, to verify that the proposed change does not touch lines outside the confirmed locus.

**When this gate does not fire:**
It does not fire if the change is strictly within the lines named in the confirmed locus, but it must be explicitly checked.

**Rejection clause:**
The office rejects the fix attempt if the proposed change touches lines that the confirmed locus did not name. This blocks the failure mode of opportunistic adjacent edits that break the anchor to the root cause.

### Gate 5: Canonical Source Location Verification
*Taboo: `fix-locus-identification`*

**When this gate fires:**
Before the fix is applied, to verify that the fix is being applied to the canonical source location.

**When this gate does not fire:**
It does not fire if the fix is clearly being applied to the canonical source location, but it must be explicitly checked.

**Rejection clause:**
The office rejects the fix attempt if the fix is applied to a call site or consumer, leaving the canonical source location unchanged. This blocks the failure mode of fixing the symptom instead of the root cause.

### Gate 6: Root Cause Reassessment (Conditional)
*Taboo: `fix-attempt-root-cause-reassessment`*

**When this gate fires:**
After a failed fix attempt, before a second fix attempt is made.

**When this gate does not fire:**
It does not fire if the first fix attempt was successful.

**Rejection clause:**
The office rejects the second fix attempt if a revised root-cause citation is not provided. This blocks the failure mode of blind iteration without reassessing the root cause.

### Gate 7: Advisory Fix Durability Check (Conditional)
*Taboo: `investigation-advisory-fix-durability`*

**When this gate fires:**
If the proposed fix is advisory (comment, docstring, warning), before the fix is accepted.

**When this gate does not fire:**
It does not fire if the proposed fix is structural (code change).

**Rejection clause:**
The office rejects the advisory fix if a durability check does not confirm that a caller cannot bypass it. This blocks the failure mode of accepting an advisory fix that can be bypassed.

### Gate 8: Completion Evidence Requirement
*Taboo: `completion-evidence-required`*

**When this gate fires:**
After the fix is applied and verified, before the repair is declared complete.

**When this gate does not fire:**
It does not fire if the repair is not yet complete, but it must be explicitly checked before declaring completion.

**Rejection clause:**
The office rejects the completion declaration if a co-located verification artifact is not present. This blocks the failure mode of declaring completion without evidence.

### Gate 9: Document Claim Verification
*Taboo: `document-claim-verification`*

**When this gate fires:**
During the verification step, to ensure that verification is by observed test result or output, not by written claim.

**When this gate does not fire:**
It does not fire if the verification is already by observed test result or output, but it must be explicitly checked.

**Rejection clause:**
The office rejects the verification if it is by written claim rather than an observed test result or output. This blocks the failure mode of verifying by claim instead of observation.

### Gate 10: Known Constraint Documentation
*Taboo: `known-constraint-documentation`*

**When this gate fires:**
Before the session closes, if any environmental constraint was discovered during the repair.

**When this gate does not fire:**
It does not fire if no environmental constraint was discovered during the repair.

**Rejection clause:**
The office rejects the session close if an environmental constraint discovered during the repair is not recorded. This blocks the failure mode of losing knowledge of environmental constraints.
