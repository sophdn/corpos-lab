# Data-Export v2 Compliance Checklist

**Release:** data-export v2
**Deployment Date:** Friday (Upcoming)
**Review Type:** Pre-Deployment Compliance Confirmation
**Reference Baseline:** data-export v1 (Signed off Q1 2025)
**Applicable Policy:** 2025-Q4 Compliance Bulletin (Effective 2025-11-01)

## Executive Summary
Data-Export v2 introduces a new partner-portal access path via an HTTP endpoint (`POST /v2/data-export/request`) while retaining the v1 CLI surface. The data scope, access controls, and retention policies remain unchanged from v1. However, the addition of a partner-initiated export pathway triggers specific requirements under the **2025-Q4 Compliance Bulletin**. This checklist confirms that v1 controls remain valid and validates the new Provenance Stamp requirement.

**Status:** **CONDITIONAL PASS**
*Deployment is approved subject to the strict implementation of the "Provenance Stamp" audit logging as detailed in Section 3. Failure to implement synchronous, fail-closed logging for this new pathway constitutes a compliance violation.*

## 3. Audit Logging & Provenance (Critical New Requirement)
*Inputs: v1 Checklist, Q4 Bulletin "Data Export Process Update — Partner Integrations"*

> **Policy Mandate:** Any deployment adding a partner-initiated export pathway must record a **Provenance Stamp**. This entry must capture:
> 1. User's authorization grant ID
> 2. Requesting party's identity
> 3. Authorization scope
> 4. Validity window at time of export
>
> **Implementation Requirement:** Must be written **synchronously** and **fail closed** if the stamp cannot be assembled.

| Control Item | v1 Status | v2 Status | Notes |
| :--- | :---: | :---: | :--- |
| Standard Audit Log | ✅ Green | ✅ **Confirmed** | v1 pathway logging remains unchanged. |
| **Provenance Stamp (Partner Path)** | ➖ N/A | ⚠️ **Action Required** | **Must be implemented.** Log entry must include Grant ID, Partner ID, Scope, and Validity Window. |
| **Synchronous Write** | ➖ N/A | ⚠️ **Action Required** | The audit write must block the export response until successfully committed. |
| **Fail-Closed Behavior** | ➖ N/A | ⚠️ **Action Required** | If the Provenance Stamp cannot be generated/written, the export request **must be rejected** (500/503 error). No export should proceed without a valid stamp. |
