# Data-Export v2 Compliance Checklist

## Access Controls

- **Review**: The access controls defined in the v1 release remain applicable to v2. The v2 release retains the v1 CLI surface and adds an HTTP endpoint for partner-portal integration.
- **Compliance**: Partners authenticate via OAuth scope, ensuring that only authorized users can request data exports.
- **Audit**: Access control mechanisms are pathway-agnostic, as previously confirmed, and continue to apply without change.

## Retention Policies

- **Review**: The data retention policies established in the v1 release are unchanged in the v2 release.
- **Compliance**: No modifications to data retention protocols or timelines have been introduced in v2.

## Data Scope

- **Review**: The data scope remains consistent with the v1 release, with no changes in the types or quantities of data exported.
- **Compliance**: The unchanged data scope ensures ongoing compliance with established data policies.

## Audit Logging

- **Review**: The audit logging requirements from v1 continue to apply, with no changes in logging practices or requirements.
- **Compliance**: The audit logs should continue to capture all relevant data access and export activities.

## Partner-Portal Access Path

- **Review**: The v2 release introduces a new HTTP endpoint (`POST /v2/data-export/request`) for partner-portal integration.
- **Compliance**: Partners authenticate using OAuth scope and request exports for users with active authorizations.

## Provenance Stamp

- **Review**: In accordance with the Compliance Office Q4 2025 bulletin, the addition of a partner-initiated export pathway necessitates recording a Provenance Stamp.
- **Compliance**: Each data export request must capture:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
- **Audit**: The Provenance Stamp must be written synchronously and fail closed if it cannot be assembled.

## Overall Compliance Status

- **Status**: The v2 release maintains compliance with all relevant policies and requirements, incorporating necessary updates for the new partner-portal access path.
- **Approval**: All changes and requirements have been reviewed and confirmed to align with existing compliance standards.

---

This checklist confirms that the v2 release adheres to all necessary compliance standards, with specific attention to the new requirements introduced by the partner-portal access path.
