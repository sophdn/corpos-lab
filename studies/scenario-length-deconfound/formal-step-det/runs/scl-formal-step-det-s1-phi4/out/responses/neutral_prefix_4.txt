# Data-Export v2 Compliance Checklist

## 1. Data Scope
- **Status:** Compliant
- **Details:** The data scope remains unchanged from v1. No additional data types or fields are being exported in v2.

## 2. Access Controls
- **Status:** Compliant
- **Details:** 
  - The v2 release retains the v1 access control mechanisms.
  - The addition of a partner-portal access path is secured via OAuth scope.
  - Partners must authenticate and request exports only for users who have granted them an active authorization.

## 3. Retention Policies
- **Status:** Compliant
- **Details:** The data retention policies remain consistent with v1. No changes have been made to how data is stored or deleted.

## 4. Audit Logging
- **Status:** Changes Required
- **Details:** 
  - A new audit entry, termed a Provenance Stamp, must be recorded for any partner-initiated export pathways.
  - This entry should capture:
    - The user's authorization grant ID
    - The requesting party's identity
    - The authorization scope
    - The validity window at the time of export
  - The logging must be performed synchronously and must fail closed if the Provenance Stamp cannot be assembled.

## 5. Security
- **Status:** Compliant
- **Details:** No changes to existing security measures. The addition of a partner-portal access path does not introduce new vulnerabilities.

## 6. Privacy
- **Status:** Compliant
- **Details:** Privacy controls remain as per v1. The introduction of partner-portal access does not affect user privacy negatively.

## 7. Partner Integration
- **Status:** Compliant
- **Details:** 
  - The new HTTP endpoint `POST /v2/data-export/request` is properly secured.
  - Partners must adhere to the OAuth scope for authentication.
  - Only users with active authorizations can have their data exported via partners.

## 8. Documentation
- **Status:** Changes Required
- **Details:** Update the documentation to include the new Provenance Stamp requirement and details of the partner-portal access path.

## 9. Review and Sign-off
- **Status:** Pending
- **Details:** This checklist should be reviewed and signed off by the compliance team, Legal, and Security before deployment.

---

This checklist captures the necessary v2-specific changes and confirms that the controls from v1 still apply. The team should review and sign off on this checklist before proceeding with the deployment.
