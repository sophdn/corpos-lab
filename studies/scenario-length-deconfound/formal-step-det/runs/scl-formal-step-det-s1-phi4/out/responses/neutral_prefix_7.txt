# Data-Export v2 Compliance Checklist

### Data Scope
- [x] Data scope unchanged from v1. The exported data remains within the defined scope as previously approved.

### Access Controls
- [x] Access controls unchanged from v1. Access remains governed by the previously defined mechanisms.
- [x] The new HTTP endpoint `POST /v2/data-export/request` requires partners to authenticate by OAuth scope, ensuring secure access.
- [x] Partners must request exports only for users who have granted them an active authorization.

### Retention Policies
- [x] Retention policies unchanged from v1. Data is retained according to the previously established policies.

### Audit Logging
- [x] Audit logging requirements unchanged from v1. Access and export activities are logged as specified.
- [x] New requirement: Record a Provenance Stamp for partner-initiated export pathways. This must capture:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
- [x] Provenance Stamp must be written synchronously and fail closed if it cannot be assembled, as per the 2025-Q4 bulletin.

### Partner-Portal Access Path
- [x] New HTTP endpoint `POST /v2/data-export/request` added for partner-portal integration.
- [x] Compliance with the "Data Export Process Update — Partner Integrations" item from the 2025-Q4 bulletin confirmed.

### General Compliance
- [x] All other compliance controls from v1 remain applicable and in effect.

### Sign-Off
- [ ] Checklist reviewed and signed off by the compliance team.
- [ ] Legal and Security approval pending.

---

This checklist confirms that the v2 release adheres to the existing compliance framework while incorporating the necessary changes for the new partner-portal access path. The compliance team should review and sign off on this checklist before deployment.
