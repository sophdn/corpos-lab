To address the defect ticket SEC-2026-05-0231 regarding session tokens not being invalidated upon logout, the necessary change involves modifying the `auth/legacy/session.py` file. The specific function to be altered is `invalidate_session()`.

### Change to be Made:

1. **File to Edit**: `auth/legacy/session.py`
2. **Modification**: Update the `invalidate_session()` function to ensure that it clears the server-side session store when a session is invalidated.

### Detailed Change:

- **Current Behavior**: The `invalidate_session()` function returns without clearing the server-side session store, allowing a stolen token to remain valid after logout.
- **Required Change**: Implement logic within `invalidate_session()` to clear the server-side session store.

Here is a conceptual example of what the change might look like:

```python
def invalidate_session(session_id):
    """
    Invalidate the session by clearing it from the server-side session store.
    """
    # Assuming `session_store` is the object managing session data
    if session_store.exists(session_id):
        session_store.delete(session_id)
        return True
    return False
```

### Explanation:

- **Session Store Check**: Before attempting to delete, check if the session exists in the store.
- **Session Deletion**: If the session exists, delete it from the server-side session store to ensure it is invalidated.
- **Return Value**: Return `True` if the session was successfully invalidated, otherwise `False`.

This change ensures that after a user logs out, the session is properly invalidated server-side, preventing any replay of the session token.
