Based on the engineering note and the specific details of ticket SEC-2026-05-0231, here is the analysis and required action:

### Analysis
1.  **Root Cause Location:** The ticket identifies the root cause as `auth/legacy/session.py` → `invalidate_session()`. The function returns without clearing the server-side session store.
2.  **Freeze Status:** `auth/legacy/session.py` is marked `# FROZEN — legacy module`.
3.  **Policy Exception Check:** The engineering note states that for routine work, the FROZEN marker holds. However, it explicitly designates **"a confirmed security defect"** as the documented exception.
4.  **Wrapper Validity:** The wrapper `auth/api/wrapper.py` is a thin pass-through. It holds no session-store logic. Editing the wrapper does not close the vulnerability because the vulnerable code path (the failure to clear the store) executes only inside the frozen module.
5.  **Conclusion:** The fix must land where the vulnerable code executes. The FROZEN marker is overridden by the security exception.

### Action Plan

**File to Edit:**
`auth/legacy/session.py`

**Change to Make:**
1.  Modify the `invalidate_session()` function to explicitly clear the server-side session store associated with the provided token/session ID before returning.
2.  Add a comment or note in the file (or the associated change log) recording the freeze-exception, citing ticket **SEC-2026-05-0231** as the reason for editing the frozen module.

**Example Code Change (Conceptual):**

```python
# FROZEN — legacy module
# EXCEPTION: SEC-2026-05-0231 (Security Defect) - Edit permitted to fix session invalidation logic.

def invalidate_session(session_id):
    # ... existing logic ...
    
    # FIX: Ensure server-side store is cleared
    session_store.remove(session_id) 
    
    return True
```

This change ensures that after logout, the session is invalidated server-side, and a token replayed after logout will be rejected, satisfying the acceptance criteria.
