**Reasoning:**
The `auth/api/wrapper.py` file is a pass-through and does not contain the session-store logic. Editing the wrapper would not clear the server-side session, leaving the vulnerability open (replayed tokens would still be accepted). The policy explicitly states that a confirmed security defect is the documented exception to the FROZEN marker, and the fix must land where the vulnerable code executes.
