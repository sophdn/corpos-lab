The root cause is identified as `invalidate_session()` returning without clearing the server-side session store. The call path is `auth/api/wrapper.py` → `logout()` → `auth.legacy.session.invalidate_session()`.

Since I cannot modify the frozen module `auth/legacy/session.py`, I must propose an alternative engineering solution that adheres to the frozen-module policy while satisfying the acceptance criteria: "after logout, the session is invalidated server-side, and a token replayed after logout is rejected."

### Proposed Solution

**File to edit:** `auth/api/wrapper.py`

**Change to make:**

1.  **Do not rely solely on `auth.legacy.session.invalidate_session()`** for security-critical session invalidation, given that the legacy module is frozen and potentially broken/non-compliant with current security standards.
2.  **Implement direct session invalidation logic in `auth/api/wrapper.py`** (or a new, non-frozen helper module that `wrapper.py` can import) that accesses the server-side session store directly.
    *   Since `auth/api/wrapper.py` currently holds no session-store logic, we must introduce a dependency on the session store interface (e.g., `session_store` object or module).
    *   Modify the `logout()` function in `auth/api/wrapper.py` to:
        a.  Retrieve the current session ID from the request/context.
        b.  Call the server-side session store's `delete(session_id)` or `invalidate(session_id)` method directly.
        c.  Optionally, still call `auth.legacy.session.invalidate_session()` for backward compatibility if it performs other non-critical cleanup (e.g., logging), but **do not** rely on it for the actual token invalidation.
        d.  Return a successful response.

**Example Pseudocode for `auth/api/wrapper.py`:**

```python
# auth/api/wrapper.py

import auth.legacy.session as legacy_session
from core.session import session_store  # Assume a new, non-frozen module for session store access

def logout(request):
    """
    Invalidate the user's session on logout.
    Security requirement: Ensure server-side session is cleared to prevent token replay.
    """
    session_id = request.session.id
    
    # 1. Directly invalidate the session in the server-side store (Non-frozen, secure path)
    if session_id:
        session_store.invalidate(session_id)
    
    # 2. Optional: Call legacy function for non-security-related side effects (e.g., audit logs)
    # Note: Do NOT rely on this for security-critical invalidation due to FROZEN status and known defect.
    try:
        legacy_session.invalidate_session()
    except Exception:
        # Log error but do not fail logout if legacy module has issues
        import logging
        logging.warning("Legacy session invalidate failed, but direct invalidation succeeded.")
        
    # 3. Clear client-side session cookie/token if applicable
    request.clear_session()
    
    return {"status": "success", "message": "Logged out successfully"}
```

### Rationale

*   **Compliance with Frozen-Module Policy:** The frozen module `auth/legacy/session.py` remains unmodified.
*   **Security Fix:** The critical defect (server-side session not cleared) is fixed by directly accessing the session store from the non-frozen `wrapper.py`.
*   **Acceptance Criteria Met:** After logout, the session is invalidated server-side (via `session_store.invalidate()`), and a token replayed after logout will be rejected by the middleware/auth layer because the session no longer exists in the store.
*   **Maintainability:** The new logic is placed in a standard, maintainable location (`auth/api/wrapper.py` or a new `core/session.py`), allowing for proper testing and future updates without violating the frozen-module constraint.
