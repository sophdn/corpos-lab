The issue is that the `config-validator` exits with status 0 (success) even when the `auth_service_url` is malformed, instead of exiting with status 1 (failure). The root cause is in the `validate_url_field()` function within `config/validator.py`, which only checks if the field is present and non-empty, but does not validate the URL structure.

#### Steps to resolve the issue:
1. **Add URL validation**: Modify the `validate_url_field()` function to validate the structure of the URL. This can be done using regular expressions or a URL validation library.
2. **Test cases**: Ensure that the function exits with status 1 for malformed URLs and continues to pass for valid URLs.

Here is a proposed implementation for `validate_url_field()`:

```python
import re

def validate_url_field(url):
    # Regular expression to validate URL structure
    url_pattern = re.compile(
        r'^(http|https)://'  # scheme
        r'([A-Z0-9][A-Z0-9-]{1,61}[A-Z0-9]\.)+[A-Z]{2,6}'  # domain
        r'(:\d+)?'  # optional port
        r'(/?|/.+)$',  # path
        re.IGNORECASE
    )

    if not url:
        return False

    if not url_pattern.match(url):
        return False

    return True
```

- **Valid URL**: `auth_service_url = "https://example.com"` should return `True`.
