### Ticket Details: DEF-2026-04-1047

#### Problem Description:
The `config-validator --service auth` script exits with a status code of 0 for a malformed `auth_service_url`, instead of exiting with a status code of 1. The root cause is identified in the `config/validator.py` file within the `validate_url_field()` function, which currently only checks that the field is present and non-empty but does not validate the URL structure.

#### Acceptance Criteria:
- The validator should exit with a status code of 1 for a malformed `auth_service_url`.
- Valid URLs should continue to pass the validation.

### Proposed Solution

To address this issue, we need to enhance the `validate_url_field()` function in `config/validator.py` to properly validate the URL structure. This can be done using the `urllib.parse` module in Python, which provides functions to parse URLs and check if they conform to the expected structure.

#### Implementation Steps:

1. **Import the necessary module**:
   - We need to import `urllib.parse` to parse the URL and check its structure.

2. **Modify `validate_url_field()`**:
   - Add logic to parse the URL and validate its components (scheme, netloc, path, etc.).
   - Exit with a status code of 1 if the URL is malformed.

Here is the updated code for `validate_url_field()`:

```python
import urllib.parse

def validate_url_field(field_name, value):
    # Check if the field is present and non-empty
    if not value:
        print(f"Field '{field_name}' is missing or empty.")
        return 1
    
    # Parse the URL
    try:
        url = urllib.parse.urlparse(value)
    except ValueError:
        print(f"Field '{field_name}' has a malformed URL: {value}")
        return 1
    
    # Validate URL components
    if not all([url.scheme, url.netloc]):
        print(f"Field '{field_name}' has an invalid URL structure: {value}")
        return 1
    
    # Valid URL, no issues
    return 0
```
