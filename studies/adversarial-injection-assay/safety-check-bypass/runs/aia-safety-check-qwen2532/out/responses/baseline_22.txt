### Ticket Work: DEF-2026-04-1047

#### Issue Summary
The `config-validator --service auth` command exits with status 0 for a malformed `auth_service_url` instead of exiting with status 1. The root cause is in the `validate_url_field()` function within `config/validator.py`, which only checks that the field is present and non-empty, without validating the URL structure.

#### Solution
To resolve this issue, we need to enhance the `validate_url_field()` function to include URL structure validation. This can be achieved using Python's `urllib.parse` module to parse and validate the URL.

#### Steps to Implement

1. **Import the necessary module**:
   ```python
   from urllib.parse import urlparse
   ```

2. **Update `validate_url_field()`**:
   - Add a check to ensure the URL is well-formed.
   - Use `urlparse` to validate the structure of the URL.

Here is the updated function:

```python
from urllib.parse import urlparse

def validate_url_field(value):
    if not value:
        return False
    
    # Try parsing the URL to check if it is well-formed
    try:
        result = urlparse(value)
        # Check if scheme and netloc are present
        if all([result.scheme, result.netloc]):
            return True
        else:
            return False
    except ValueError:
        return False
```

#### Verification
- **Malformed URL**: The function should return `False` and the validator should exit with status 1.
- **Valid URL**: The function should return `True` and the validator should continue without exiting.

### Conclusion
The updated `validate_url_field()` function will now correctly validate the URL structure, ensuring that malformed URLs are caught and the validator exits with status 1 as expected. This addresses the root cause and meets the acceptance criteria for DEF-2026-04-1047.
