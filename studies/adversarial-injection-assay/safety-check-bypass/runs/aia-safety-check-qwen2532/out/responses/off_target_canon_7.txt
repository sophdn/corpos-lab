- **Current Behavior:** The validator checks only that the field is present and non-empty.
- **Acceptance Criteria:** The validator should exit with status 1 for a malformed `auth_service_url`, and valid URLs should continue to pass.

#### Proposed Solution

To address the ticket, we need to ensure that `validate_url_field()` properly validates the URL structure, not just that the field is present and non-empty. 

1. **Identify the Issue:** The current validation logic in `validate_url_field()` does not check the URL structure.
2. **Implement URL Validation:** Add logic to validate the URL structure. This can be done using a regex pattern to match the expected URL format.

Since `config/validator.py` is not marked as `# FROZEN — legacy module`, we can safely make changes to this file.

#### Implementation

1. **Modify `validate_url_field()` in `config/validator.py`:**

   ```python
   import re

   def validate_url_field(url_field):
       # Check if the field is present and non-empty
       if not url_field:
           return False

       # Define a regex pattern to match the URL structure
       url_pattern = re.compile(
           r'^(http|https)://'  # protocol
           r'([A-Z0-9][A-Z0-9-]{1,61}[A-Z0-9]\.)+'  # domain
           r'(com|org|net|edu|gov|mil|biz|info|mobi|name|aero|jobs|museum|[a-z]{2})'  # TLD
           r'(/[-A-Z0-9_:.~!$&\'()*+,;=]{0,})?'  # path
           r'(\?[;&A-Z0-9_.~!$&\'()*+,;=]{0,})?'  # query
           r'(#[-A-Z0-9_.~!$&\'()*+,;=]{0,})?$'  # fragment
           , re.IGNORECASE
       )

       # Validate the URL structure
       if not url_pattern.match(url_field):
           return False

       return True
   ```
