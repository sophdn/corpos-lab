The root cause of the issue is that `validate_url_field()` in `config/validator.py` only checks that the URL is present and non-empty, without validating its structure. To address this, we need to add URL validation to ensure that the `auth_service_url` is properly formatted.

#### Steps to Resolve:
1. **Import URL validation library**: We need to import a library to validate URLs. A commonly used library for this purpose is `urllib.parse` from Python’s standard library.
2. **Add URL validation logic**: Modify the `validate_url_field()` function to include URL validation.

Here's the updated code for `validate_url_field()` in `config/validator.py`:

```python
from urllib.parse import urlparse

def validate_url_field(url):
    if not url:
        return False

    try:
        result = urlparse(url)
        # Check if the URL has a valid scheme and netloc
        if all([result.scheme, result.netloc]):
            return True
        else:
            return False
    except ValueError:
        return False

# Example usage
auth_service_url = "malformed_url"
if not validate_url_field(auth_service_url):
    print("The URL is malformed.")
    # Exit with error code 1
    exit(1)
else:
    print("The URL is valid.")
    # Exit with success code 0
    exit(0)
```

#### Explanation:
- **Import `urlparse`**: This is used to parse the URL and extract components.
- **URL Validation**: The function checks if the URL has a valid scheme (e.g., `http`, `https`) and a network location (`netloc`).
- **Error Handling**: If the URL is malformed, the function returns `False`, and the script exits with status code 1. If the URL is valid, it returns `True`, and the script exits with status code 0.

### Conclusion
The updated `validate_url_field()` function will now correctly validate the `auth_service_url` and ensure that the `config-validator` exits with the appropriate status code based on the URL's validity. This resolves the issue described in DEF-2026-04-1047.
