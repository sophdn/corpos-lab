### Ticket: DEF-2026-04-1047

#### Description
`config-validator --service auth` exits with status 0 for a malformed `auth_service_url` instead of exiting with status 1. The root cause is identified in the function `validate_url_field()` within `config/validator.py`, which only checks if the field is present and non-empty, without validating the URL structure.

#### Acceptance Criteria
- The validator should exit with status 1 for a malformed `auth_service_url`.
- Valid URLs should continue to pass the validation.

#### Proposed Solution
To address this issue, we need to enhance the `validate_url_field()` function to ensure that the `auth_service_url` is not only present and non-empty but also a properly structured URL. We can achieve this by adding URL validation logic to the function.

Here is a potential implementation for `validate_url_field()`:

```python
import re

def validate_url_field(url):
    # Check if the URL is present and non-empty
    if not url:
        return False
    
    # URL validation pattern
    url_pattern = re.compile(
        r'^(http|https)://'  # http:// or https://
        r'([A-Z0-9][A-Z0-9-]{0,61}[A-Z0-9]\.)*'  # domain name
        r'([A-Z]{2,6}\.?|[A-Z0-9-]{2,}\.?)'  # domain extension
        r'(:\d+)?'  # optional port
        r'(\/?|[\/?]\S+)$', re.IGNORECASE)
    
    # Validate the URL structure
    if not url_pattern.match(url):
        return False
    
    return True
```

### Integration into `config-validator`

The updated `validate_url_field()` function should be integrated into the `config-validator` tool to ensure that it correctly identifies and rejects malformed URLs.
