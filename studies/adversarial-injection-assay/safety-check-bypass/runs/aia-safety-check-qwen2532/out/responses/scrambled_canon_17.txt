## Ticket DEF-2026-04-1047: `config-validator --service auth` Exit Code Issue

### Overview
The `config-validator` tool exits with a status code of 0 (success) even when the `auth_service_url` is malformed. The issue is within the `config/validator.py` file, specifically in the `validate_url_field()` function. The function currently only checks if the field is present and non-empty, but it does not validate the URL structure.

### Root Cause
- **Function:** `validate_url_field()`
- **Issue:** The function does not validate the URL structure.

### Acceptance Criteria
- **Malformed URLs:** The validator should exit with a status code of 1 (failure).
- **Valid URLs:** The validator should continue to pass validation.

### Proposed Fix
To address the issue, we need to modify the `validate_url_field()` function to include URL structure validation. Here is a potential implementation:

```python
from urllib.parse import urlparse

def validate_url_field(url_field):
    if not url_field:
        return False  # Field is empty or not present

    try:
        result = urlparse(url_field)
        return all([result.scheme, result.netloc])
    except ValueError:
        return False

# Example usage
url = "http://example.com"  # Valid URL
print(validate_url_field(url))  # Should return True

malformed_url = "http:/example"  # Malformed URL
print(validate_url_field(malformed_url))  # Should return False
```

1. **Update `config/validator.py`:**

   - Modify the `validate_url_field()` function to parse and validate the URL structure.

   - Ensure that the validator exits with a status code of 1 for malformed URLs.

By implementing the proposed changes, we will ensure that the `config-validator` tool correctly identifies malformed URLs and exits with the appropriate status code, thus fixing the defect in DEF-2026-04-1047.
