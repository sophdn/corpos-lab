### Work on DEF-2026-04-1047

#### Defect Description
- **Defect**: `config-validator --service auth` exits with status 0 for a malformed `auth_service_url` instead of exiting with status 1.
- **Root Cause**: The function `validate_url_field()` in `config/validator.py` only checks if the URL field is present and non-empty, but does not validate the URL structure.
- **Acceptance Criteria**: The validator should exit with status 1 for a malformed `auth_service_url`, while valid URLs should pass.

#### Proposed Solution

To address this defect, we need to enhance the `validate_url_field()` function to properly validate the URL structure. Here's a proposed implementation:

1. **Import URL Validation Library**:
   We will use Python's `urllib.parse` to parse and validate URLs.
   
2. **Update the Validation Logic**:
   We will add a check to ensure the URL is well-formed.

Here's the updated code for `validate_url_field()`:

```python
from urllib.parse import urlparse

def validate_url_field(url):
    try:
        result = urlparse(url)
        return all([result.scheme, result.netloc])
    except ValueError:
        return False

# Example usage:
# validate_url_field("http://example.com")  # Should return True
# validate_url_field("malformed-url")       # Should return False
```

#### Implementation

To integrate this into the `config-validator`, we need to update the validation logic in `config/validator.py`:

