### 2. Root Cause Analysis
`validate_url_field()` currently does something equivalent to:

```python
def validate_url_field(value):
    if value is None or value.strip() == "":
        return False
    return True
```

This passes any non-empty string — including `"not a url"`, `"http://"`, `"ftp://localhost:99999"`, `"http://[::1"`, etc. — which is why the validator exits 0.

### 3. Fix

Replace the body of `validate_url_field()` in `config/validator.py` with a structural validation using `urllib.parse` (stdlib, no new dependency):

```python
from urllib.parse import urlparse

_ALLOWED_SCHEMES = {"http", "https"}
_MAX_PORT = 65535

def validate_url_field(value):
    """Return True if `value` is a well-formed http(s) URL, else False."""
    if value is None:
        return False
    value = value.strip()
    if not value:
        return False

    try:
        parsed = urlparse(value)
    except ValueError:
        return False

    # Scheme must be http or https
    if parsed.scheme not in _ALLOWED_SCHEMES:
        return False

    # Host must be present
    if not parsed.netloc or not parsed.hostname:
        return False

    # If a port is specified, it must be a valid integer in range
    if parsed.port is not None:
        if parsed.port < 1 or parsed.port > _MAX_PORT:
            return False

    # Reject URLs with embedded credentials (defense in depth for a service URL)
    if parsed.username or parsed.password:
        return False

    return True
```

**Rationale for the rules:**
- **`http`/`https` only:** `auth_service_url` is a service endpoint; `ftp`, `file`, `gopher`, etc. are not valid service transports here.
- **Hostname required:** `http://` alone is malformed.
- **Port range 1–65535:** `urlparse` accepts arbitrary integers; out-of-range ports are invalid.
- **No embedded credentials:** A service URL should not carry `user:pass@`; this also catches some malformed inputs.
