## 2. New v2-Specific Compliance Requirements

The introduction of the `POST /v2/data-export/request` endpoint constitutes a "partner-initiated export pathway" as defined in the **2025-Q4-bulletin**. The following new controls are **mandatory** for this release.

### 2.1. Provenance Stamp Audit Entry (NEW)
*Source: `policy/bulletins/2025-Q4-bulletin.md` — "Data Export Process Update — Partner Integrations"*

Any export triggered via the new partner portal must generate a distinct **Provenance Stamp** audit record. This record must capture:

1.  **User Authorization Grant ID:** The unique identifier of the user’s active authorization for the specific partner.
2.  **Requesting Party Identity:** The OAuth client ID or partner identifier making the request.
3.  **Authorization Scope:** The specific scopes granted in the authorization (e.g., `read:exports`, `write:metadata`).
4.  **Validity Window:** The start and end timestamps of the authorization grant *at the time of the export*.

**Implementation Constraints:**
*   **Synchronous Write:** The Provenance Stamp must be written to the audit log *before* the export process completes. It cannot be asynchronous or batched.
*   **Fail-Closed Behavior:** If the system cannot assemble the Provenance Stamp (e.g., missing grant ID, invalid scope data), the export request **must** be rejected with an error. The system must **not** proceed with the export if the audit trail is incomplete.

### 2.2. OAuth Scope Verification
*Source: `deployments/data-export-v2/spec.md`*

*   The endpoint must verify that the OAuth token contains the specific scope required for data export.
*   The system must verify that the user associated with the token has an **active** authorization grant for the requesting partner. Expired or revoked authorizations must result in a `403 Forbidden` response.

## 3. Compliance Checklist for v2 Deployment

Please verify the following items before deploying to production.

- [ ] **Inherited Controls Verified:** Confirmed that v1 data scope, retention, and base access controls are unchanged in the v2 codebase.
- [ ] **Provenance Stamp Implementation:** Code implemented to capture Grant ID, Party Identity, Scope, and Validity Window.
- [ ] **Synchronous Audit Logging:** Verified that the Provenance Stamp write occurs synchronously during the request lifecycle.
- [ ] **Fail-Closed Logic:** Tested scenario where Provenance Stamp data is missing/invalid; confirmed that the export request fails and no data is exported.
- [ ] **OAuth Scope Enforcement:** Verified that requests without the correct scope or with expired authorizations are rejected.
- [ ] **Audit Log Integration:** Provenance Stamps are queryable and linked to the corresponding export job ID in the central audit log.
