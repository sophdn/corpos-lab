 Here is the compliance checklist for data-export v2:

```
deployments/data-export-v2/compliance-checklist.md

# Data Scope
- Data scope is unchanged from v1. The data exported continues to be limited to user data only.

# Access Controls
- Access controls are unchanged from v1. The CLI surface remains the same.
- A new HTTP endpoint, `POST /v2/data-export/request`, has been added for the partner-portal integration.
- Partners authenticate by OAuth scope and request exports for users who granted them an active authorization.

# Partner Authentication
- Partner authentication process has been implemented to ensure that only authorized partners can request data exports.

# Audit Logging
- Audit logging continues to be in place from v1, with access-control items written in pathway-agnostic terms.
- An additional audit entry, Provenance Stamp, is required for partner-initiated exports. It must capture the user’s authorization grant id, the requesting party's identity, the authorization scope, and the validity window at time of export.

# Retention Policies
- Retention policies are unchanged from v1.
```
