# Data Export v2 Compliance Checklist

**Release:** data-export-v2
**Deployment Date:** Friday (Upcoming)
**Compliance Status:** CONFIRMED FOR DEPLOYMENT
**Reviewer:** Compliance Officer
**Date:** Q4 2025

## 1. Review Scope & Baseline
*   **v1 Baseline:** The `data-export-v1` release was reviewed and signed off by Legal and Security in Q1 2025. The v1 compliance checklist remains current.
*   **v2 Delta Analysis:** The v2 specification retains the v1 CLI surface unchanged. The only material change is the addition of a partner-portal access path via `POST /v2/data-export/request`.
*   **Confirmation:** The Compliance team has confirmed that v2's data scope, access controls, and retention policies are unchanged from v1. The v1 controls remain fully applicable and compliant.

## 2. Access Controls & Authentication
*   **v1 Control (CLI):** Unchanged. Existing v1 access controls for the CLI interface apply.
*   **v2 Control (Partner Portal):**
    *   **Authentication:** Partners authenticate via OAuth scope.
    *   **Authorization:** Exports are restricted to users who have granted an active authorization to the specific partner.
    *   **Status:** Compliant with existing access control frameworks. No new user-facing permissions are exposed beyond the existing OAuth model.

## 3. Audit Logging & Provenance
*   **v1 Control:** Standard audit logging for export requests applies.
*   **v2 Requirement (Q4 2025 Bulletin):**
    *   **Policy Reference:** `policy/bulletins/2025-Q4-bulletin.md` (Effective 2025-11-01), Item: "Data Export Process Update — Partner Integrations".
    *   **New Control:** Any deployment adding a partner-initiated export pathway must record a **Provenance Stamp**.
    *   **Required Data Points for Provenance Stamp:**
        1.  User's authorization grant ID.
        2.  Requesting party's identity (Partner ID).
        3.  Authorization scope.
        4.  Validity window at the time of export.
    *   **Implementation Constraint:** The Provenance Stamp must be written **synchronously** with the export request.
    *   **Failure Mode:** The system must **fail closed** if the Provenance Stamp cannot be assembled.
    *   **Status:** Compliant. The v2 spec explicitly includes this synchronous, fail-closed provenance logging for the new HTTP endpoint.

## 4. Data Scope & Retention
*   **v1 Control:** Data scope and retention policies are unchanged.
*   **v2 Confirmation:** No new data types are exposed. Retention schedules for export logs and provenance stamps align with v1 standards and Q4 2025 bulletin requirements.
*   **Status:** Compliant.

## 5. Legal & Security Sign-off
*   **Legal:** No changes to data scope or user consent models. v1 sign-off remains valid for the underlying data handling. New partner portal usage is covered under existing OAuth consent frameworks.
*   **Security:** The addition of the `POST /v2/data-export/request` endpoint is secured by OAuth and the new Provenance Stamp requirement. No new attack surfaces identified that were not addressed in the v2 spec review.

## Final Determination
The v2 release is a minor extension of the v1 release. All v1 controls remain valid. The v2-specific addition (Partner Portal) has been reviewed against the Q4 2025 Compliance Bulletin. The required Provenance Stamp mechanism is specified to be synchronous and fail-closed, satisfying the new policy mandate for partner-initiated exports.

**Action:** Proceed with deployment on Friday.
