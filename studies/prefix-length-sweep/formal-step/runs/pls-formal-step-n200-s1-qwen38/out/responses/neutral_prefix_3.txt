## 2. v2-Specific Changes & Compliance Actions

The addition of the partner-portal HTTP endpoint constitutes a **material change** to the export pathway, triggering specific requirements under the **2025-Q4 Compliance Bulletin (Effective 2025-11-01)**.

### A. New Audit Requirement: Provenance Stamp
**Source:** `policy/bulletins/2025-Q4-bulletin.md` — "Data Export Process Update — Partner Integrations"

Any deployment adding a partner-initiated export pathway must record an additional **Provenance Stamp** audit entry. This is **not** optional.

**Required Fields in Provenance Stamp:**
1.  **User Authorization Grant ID:** The unique identifier for the user's consent to the partner.
2.  **Requesting Party Identity:** The OAuth client ID or partner identifier.
3.  **Authorization Scope:** The specific scopes granted (e.g., `read:export`, `read:profile`).
4.  **Validity Window:** The expiration timestamp of the user's authorization grant at the time of export.

**Implementation Requirements:**
*   **Synchronous Write:** The Provenance Stamp must be written to the audit log **before** the export process completes.
*   **Fail-Closed Behavior:** If the Provenance Stamp cannot be assembled (e.g., missing grant ID, expired authorization, audit service unavailable), the export request **must fail** and return an error to the partner. Exports must **not** proceed without a valid stamp.

### B. Access Control Verification
*   **OAuth Scope Validation:** The `POST /v2/data-export/request` endpoint must validate the OAuth token’s scope against the user’s active authorization grant.
*   **Authorization Check:** The system must verify that the requesting partner holds an **active** authorization from the specified user at the time of the request. Stale or revoked grants must be rejected.

## 4. Deployment Conditions

**Do not deploy `data-export-v2` until:**

1.  The **Provenance Stamp** logic is implemented in the export service.
2.  Automated tests confirm that:
    *   Valid partner requests generate a Provenance Stamp with all four required fields.
    *   Requests with missing/invalid/revoked authorizations are rejected.
    *   If the audit logging system is unavailable, the export request fails (fail-closed).
3.  Legal and Security sign off on the updated checklist above.
