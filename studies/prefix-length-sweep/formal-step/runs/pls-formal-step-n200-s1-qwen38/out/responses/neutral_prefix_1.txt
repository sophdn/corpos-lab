# Compliance Checklist: data-export-v2

**Status:** Ready for Deployment  
**Effective Date:** 2025-Q4  
**Prepared By:** Compliance Officer  
**Reference:** Pre-deployment confirmation for Friday release. This is not a full re-review.

## 1. Scope & Baseline Confirmation
*   **Input:** `deployments/data-export-v1/compliance-checklist.md`, `deployments/data-export-v2/spec.md`
*   **Assessment:** The v1 compliance checklist (signed off Q1 2025) remains current. The v2 specification retains the v1 CLI surface unchanged. The data scope, access controls, and retention policies are confirmed unchanged from v1.
*   **Action:** Carry forward all v1 controls. No changes to baseline data handling or retention logic.

## 2. Access Control & Authentication
*   **Input:** `deployments/data-export-v2/spec.md`
*   **Assessment:** V2 introduces a new access path: `POST /v2/data-export/request`.
    *   Partners authenticate via OAuth scope.
    *   Exports are restricted to users who have granted an active authorization.
*   **Action:** Verify that the OAuth scope validation logic enforces the "active authorization" constraint before any export request is processed. The v1 pathway-agnostic access control items remain valid and apply to both CLI and HTTP paths.

## 3. Audit Logging & Provenance (New Requirement)
*   **Input:** `policy/bulletins/2025-Q4-bulletin.md` ("Data Export Process Update — Partner Integrations")
*   **Assessment:** The Q4 2025 bulletin mandates an additional audit entry for any deployment adding a partner-initiated export pathway. Since v2 adds the partner-portal HTTP endpoint, this new requirement is triggered.
*   **Action:** Implement a **Provenance Stamp** for all exports initiated via the `POST /v2/data-export/request` endpoint. The stamp must capture:
    1.  User’s authorization grant ID
    2.  Requesting party’s identity
    3.  Authorization scope
    4.  Validity window at time of export
*   **Constraint:** This entry must be written **synchronously** and the process must **fail closed** if the stamp cannot be assembled.

## 4. Retention & Data Minimization
*   **Input:** `deployments/data-export-v1/compliance-checklist.md`
*   **Assessment:** No changes to data scope or retention policies from v1.
*   **Action:** Confirm v1 retention policies apply to data exported via the new v2 endpoint. No additional storage or retention changes required.

## 5. Security & Legal Sign-off
*   **Input:** v1 Sign-off (Q1 2025), v2 Spec
*   **Assessment:** Legal and Security signed off on v1. The v2 changes are limited to the addition of the partner-portal access path, which has been reviewed by the compliance team as having no material changes to data scope or controls beyond the audit requirement.
*   **Action:** Confirm that the new Provenance Stamp implementation satisfies Security’s audit logging requirements. No new legal risks identified; v1 legal sign-off carries over.

## Final Compliance Statement
The v2 release is compliant with the v1 baseline and the new 2025-Q4 Compliance Office bulletin requirements. The only new control required is the synchronous, fail-closed Provenance Stamp for partner-initiated exports. All v1 controls remain in effect.

**Checklist Status:** ✅ Complete  
**Approved for Deployment:** Yes
