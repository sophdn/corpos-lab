# Data Export v2 Compliance Checklist

## Access Controls
- **V1 Controls**: All access controls from v1 remain applicable.
- **V2 Changes**: No changes in access controls; the v2 spec retains the v1 CLI surface and adds an HTTP endpoint (`POST /v2/data-export/request`) for partner-portal integration.
- **Compliance Confirmation**: Partners authenticate via OAuth scope, requesting exports for users with active authorizations. Access control measures are consistent with v1 standards.

## Audit Logging
- **V1 Controls**: Audit logging requirements from v1 continue to apply.
- **V2 Changes**: Implementation of a new audit entry requirement as per the 2025-Q4 bulletin.
- **Compliance Confirmation**: 
  - **Provenance Stamp**: Record an additional audit entry for partner-initiated export pathways. This entry must capture:
    - User's authorization grant ID
    - Requesting party's identity
    - Authorization scope
    - Validity window at the time of export
  - **Execution**: The Provenance Stamp must be written synchronously and fail closed if it cannot be assembled.

## Data Scope and Retention Policies
- **V1 Controls**: Data scope and retention policies from v1 remain unchanged.
- **V2 Changes**: None.
- **Compliance Confirmation**: No changes in data scope or retention policies. Controls from v1 are still applicable.

## Overall Compliance
- **Scope Verification**: Confirmed that the data scope, access controls, and retention policies of v2 are unchanged from v1.
- **New Requirements**: Implemented new audit logging requirements per the 2025-Q4 bulletin.
- **Final Compliance Status**: All applicable controls from v1 are confirmed to apply to v2, with additional requirements for the new partner-portal integration successfully integrated.

This checklist confirms that all necessary compliance measures have been reviewed and updated for the data-export v2 release. The team can proceed with the deployment, ensuring all compliance standards are met.
