# Data-Export v2 Compliance Checklist

## Introduction
This checklist confirms compliance for the data-export v2 release. The v2 release extends the v1 functionality by adding a partner-portal access path. The compliance team has reviewed the v2 specification and confirmed that data scope, access controls, and retention policies remain unchanged from v1. This checklist focuses on ensuring the new partner-portal integration complies with existing and new compliance requirements.

## Compliance Checklist

### Data Scope
- **Status:** Green
- **Details:** The data scope for v2 is identical to v1, which has been previously reviewed and approved in Q1 2025. No changes in the data being exported have been identified.

### Access Controls
- **Status:** Green
- **Details:** 
  - Access controls for v2 remain consistent with v1, using pathway-agnostic terms.
  - The partner-portal integration uses OAuth for authentication, ensuring that partners can only access data for users who have granted them explicit authorization.
  - Partner requests are authenticated by OAuth scope, ensuring that only authorized partners can initiate data exports.

### Audit Logging
- **Status:** Green
- **Details:**
  - The existing audit logging requirements from v1 continue to apply.
  - An additional audit entry, termed a "Provenance Stamp," is required for partner-initiated export pathways as per the 2025-Q4 bulletin.
  - The Provenance Stamp must capture:
    - User's authorization grant ID
    - Requesting party's identity
    - Authorization scope
    - Validity window at the time of export
  - This entry must be written synchronously and fail closed if it cannot be assembled.

### Retention Policies
- **Status:** Green
- **Details:** Retention policies for v2 remain unchanged from v1. The policies continue to comply with established retention guidelines and regulatory requirements.

### Additional Compliance Requirements
- **Provenance Stamp Implementation:**
  - **Status:** To Be Verified
  - **Details:** Ensure that the implementation of the Provenance Stamp for partner-initiated exports is correctly integrated and tested. This includes verifying that the system can assemble and record the required audit entry synchronously and adhere to the fail-closed principle.

## Conclusion
The v2 release maintains compliance with the existing controls established in v1, with the addition of the Provenance Stamp requirement for the new partner-portal access path. The compliance team confirms that all v2-specific changes have been addressed and documented in this checklist. Further verification of the Provenance Stamp implementation is recommended before deployment.

---

This checklist should be reviewed and signed off by the Legal and Security teams to confirm compliance prior to the v2 release deployment.
