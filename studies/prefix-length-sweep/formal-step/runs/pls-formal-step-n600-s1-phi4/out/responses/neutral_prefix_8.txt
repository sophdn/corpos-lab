# Data-Export v2 Compliance Checklist

## Access Controls

- **Scope**: The data export scope for v2 remains unchanged from v1.
- **Control Measures**: Access controls from v1 still apply. Partners authenticate via OAuth scope, ensuring only authorized users are requested for data exports.
- **Compliance Confirmation**: v2 has successfully integrated the partner-portal access path without altering existing access controls. All access control measures are compliant with the v1 standards.

## Audit Logging

- **Scope**: The audit logging mechanisms remain consistent with v1.
- **Control Measures**: v1's pathway-agnostic audit logging controls are applicable to v2.
- **Compliance Confirmation**: v2 introduces a new requirement for a Provenance Stamp, capturing:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
- **Implementation**: Ensure the Provenance Stamp is written synchronously and follows a fail-closed policy if it cannot be assembled.

## Retention Policies

- **Scope**: Retention policies are consistent with v1.
- **Control Measures**: No changes to data retention policies from v1 to v2.
- **Compliance Confirmation**: Retention policies remain compliant and unchanged.

## Partner-Portal Integration

- **Scope**: Introduction of a new HTTP endpoint `POST /v2/data-export/request`.
- **Control Measures**: Partners authenticate via OAuth scope and request exports for users who granted them active authorization.
- **Compliance Confirmation**: The integration adheres to the compliance requirements outlined in the Q4 2025 bulletin.

## Summary

The data-export v2 release maintains the same data scope, access controls, and retention policies as v1. The addition of the partner-portal access path is compliant with the latest policy bulletin, incorporating necessary audit logging enhancements. All controls from v1 remain applicable and have been confirmed to meet compliance standards.

---

This checklist confirms that the data-export v2 release is compliant with existing policies and introduces necessary changes as per the latest compliance bulletin. The release is ready for deployment.
