## Data-Export v2 Compliance Checklist

**Prepared by:** Compliance Officer  
**Date:** [Current Date]  
**Release Version:** v2  
**Review Status:** Pre-deployment compliance confirmation

### 1. Data Scope
- [ ] Data scope remains unchanged from v1.
- [ ] No additional data types are included in v2.

### 2. Access Controls
- [ ] Access controls for the v1 CLI surface are unchanged.
- [ ] OAuth scope used by partners in the new HTTP endpoint `/v2/data-export/request` is validated.
- [ ] Partners authenticate through OAuth scope and only access data for users who have granted them an active authorization.

### 3. Retention Policies
- [ ] Data retention policies from v1 remain unchanged in v2.
- [ ] No new data types are subject to different retention periods.

### 4. Audit Logging
- [ ] Existing audit-logging requirements from v1 are still in place.
- [ ] New audit entry requirement: Provenance Stamp must be recorded for partner-initiated export pathways.
  - Includes user's authorization grant ID.
  - Includes requesting party's identity.
  - Includes authorization scope.
  - Includes validity window at time of export.
- [ ] Provenance Stamp must be written synchronously.
- [ ] System must fail closed if it cannot assemble a Provenance Stamp.

### 5. Partner-Portal Access Path
- [ ] Partner-portal access path added via HTTP endpoint `/v2/data-export/request`.
- [ ] OAuth authentication for partners is implemented correctly.

### 6. Security Measures
- [ ] Security measures for the v1 release are applicable to v2.
- [ ] No new vulnerabilities introduced by the addition of the partner-portal access path.

### 7. Legal Compliance
- [ ] Legal requirements reviewed and met for the new partner integration.
- [ ] Compliance with any relevant data protection regulations is confirmed.

### 8. General
- [ ] All previous compliance checklist items from v1 still apply and are confirmed.
- [ ] No other material changes identified that affect compliance.
