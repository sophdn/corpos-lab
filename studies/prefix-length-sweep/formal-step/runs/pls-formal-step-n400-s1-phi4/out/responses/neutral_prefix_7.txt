# Data-Export v2 Compliance Checklist

## Data Scope

- [x] The data scope for v2 remains unchanged from v1. All exported data continues to comply with the organization's data governance policies.

## Access Controls

- [x] Access controls for v2 remain consistent with v1, ensuring that only authorized entities can request data exports.
- [x] Partners authenticate via OAuth scope, as specified in the v2 spec, ensuring secure partner integration.

## Retention Policies

- [x] Retention policies for exported data remain unchanged from v1, ensuring compliance with data retention requirements.

## Audit Logging

- [x] Audit logging requirements from v1 apply to v2, ensuring all data export activities are logged.
- [x] New requirement: Implement a Provenance Stamp for partner-initiated export pathways. This stamp must capture:

  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
- [x] The Provenance Stamp must be written synchronously and fail closed if it cannot be assembled, as per the 2025-Q4 bulletin.

- [x] The addition of an HTTP endpoint (`POST /v2/data-export/request`) for partner-portal integration has been reviewed.
- [x] Ensure that the partner-portal access path adheres to all relevant security and compliance guidelines.

## General Compliance

- [x] All other compliance controls from the v1 checklist remain applicable to v2, as no other material changes have been made.
