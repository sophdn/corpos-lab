# Data-Export v2 Compliance Checklist

## Data Scope

- **Control**: Ensure the data scope is unchanged from v1.
- **Status**: Confirmed
- **Comments**: The data-export v2 retains the same data scope as v1. No changes are necessary here.

## Access Controls

- **Control**: Verify that access controls remain consistent with v1.
- **Status**: Confirmed
- **Comments**: Access controls are unchanged from v1. The new HTTP endpoint for partner-portal integration uses OAuth scope for authentication, ensuring consistent access control policies.

## Retention Policies

- **Control**: Confirm retention policies have not changed from v1.
- **Status**: Confirmed
- **Comments**: Retention policies remain consistent with v1.

## Audit Logging

- **Control**: Ensure audit logging requirements from v1 are still applicable.
- **Status**: Confirmed with additions
- **Comments**: Existing audit logging practices from v1 apply. Additionally, due to the Q4 2025 bulletin, a new audit entry (Provenance Stamp) must be recorded for partner-initiated export requests. This entry should capture:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
  - The entry must be written synchronously and fail closed if it cannot be assembled.

## Partner-Portal Access Path

- **Control**: Implement and verify the new access path as per v2 specifications.
- **Status**: To be implemented
- **Comments**: A new HTTP endpoint `POST /v2/data-export/request` has been added for partner-portal integration. Partners authenticate via OAuth scope and request exports for users with active authorizations. Ensure the endpoint is implemented correctly and securely.

---

This checklist confirms that the v2 release maintains all the necessary compliance controls from v1 while incorporating the new requirements introduced by the partner-portal access path. The compliance team should ensure that the implementation of the new audit logging requirements and the partner-portal access path is verified during deployment.
