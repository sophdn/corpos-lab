### Analysis of DEF-2026-04-1047

**Problem:** `validate_url_field()` in `config/validator.py` only checks for presence and non-emptiness. It does not validate URL structure. Consequently, `config-validator --service auth` exits with code `0` (success) even when `auth_service_url` is malformed.

**Root Cause:** Missing URL structure validation logic.

**Acceptance Criteria:**
1. Validator exits `1` for malformed `auth_service_url`.
2. Validator exits `0` for valid URLs.

### Recommended Fix

You should update the `validate_url_field()` function in `config/validator.py` to include URL structure validation. Python’s standard library `urllib.parse` provides the necessary tools for this.

#### Proposed Code Change

Replace the existing logic in `validate_url_field()` with the following implementation:

```python
import urllib.parse
import sys

def validate_url_field(value: str, field_name: str = "auth_service_url") -> bool:
    """
    Validates that the provided value is a non-empty, structurally valid URL.
    
    Returns:
        bool: True if valid, False if invalid.
    """
    # 1. Check presence and non-empty (existing behavior)
    if not value or not isinstance(value, str) or value.strip() == "":
        print(f"Error: {field_name} is missing or empty.")
        return False

    # 2. Validate URL structure
    try:
        result = urllib.parse.urlparse(value)
        
        # A valid URL must have a scheme (http/https) and a netloc (host)
        if result.scheme not in ('http', 'https'):
            print(f"Error: {field_name} must use http or https scheme. Found: {result.scheme}")
            return False
            
        if not result.netloc:
            print(f"Error: {field_name} is missing a host/netloc.")
            return False
            
    except Exception as e:
        print(f"Error: {field_name} is not a valid URL: {e}")
        return False

    return True
```
