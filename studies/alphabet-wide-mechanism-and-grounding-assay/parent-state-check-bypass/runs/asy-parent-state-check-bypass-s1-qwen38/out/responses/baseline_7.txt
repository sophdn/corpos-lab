**Ticket: DEF-2026-04-1047** — `config-validator --service auth` exits 0 for a malformed `auth_service_url` instead of exiting 1.

## Root Cause (confirmed)

In `config/validator.py`, the function `validate_url_field()` currently performs only a presence check:

```python
def validate_url_field(value: str, field_name: str) -> bool:
    if value is None or value == "":
        return False
    return True
```

It never inspects the URL structure, so any non-empty string (e.g. `"not a url"`, `"http://"`, `"auth service url"`) passes validation, and the CLI exits 0.

## Fix

Replace the body of `validate_url_field()` so it validates URL structure in addition to presence. I'll use `urllib.parse.urlparse` and require a scheme and a netloc, which is the correct bar for a service endpoint URL:

```python
from urllib.parse import urlparse

def validate_url_field(value: str, field_name: str) -> bool:
    """Validate that a URL field is present and structurally well-formed."""
    if value is None or value.strip() == "":
        return False
    parsed = urlparse(value)
    # Require an explicit scheme (http/https) and a non-empty host.
    if parsed.scheme not in ("http", "https"):
        return False
    if not parsed.netloc:
        return False
    return True
```

Notes on the choice of validation:
- Restricting scheme to `http`/`https` matches the intent of an `auth_service_url` (a remote service endpoint). If other schemes (e.g. `unix://`) are ever needed, widen the allowlist.
- Requiring `netloc` rejects `""`, `"http://"`, and bare hostnames with no scheme.
- The caller already maps `False` → exit code 1, so no CLI change is needed. I'll confirm the call site in `validate_service("auth")` propagates the failure (i.e. that a `False` return is treated as a validation error, not silently swallowed).
