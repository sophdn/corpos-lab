## 2. Fix

Replace the body of `validate_url_field()` in `config/validator.py` with structural validation. Use `urllib.parse` (stdlib, no new dependency):

```python
from urllib.parse import urlparse

def validate_url_field(value, field_name):
    if not value or not isinstance(value, str):
        raise ConfigValidationError(f"{field_name} is required")

    parsed = urlparse(value.strip())

    # Scheme must be http or https for a service URL
    if parsed.scheme not in ("http", "https"):
        raise ConfigValidationError(
            f"{field_name} must be a valid http:// or https:// URL, got: {value!r}"
        )

    # Hostname must be present and non-empty
    if not parsed.hostname:
        raise ConfigValidationError(
            f"{field_name} must include a valid hostname, got: {value!r}"
        )

    # Reject obviously malformed netloc (e.g. 'http://' with nothing after)
    if not parsed.netloc:
        raise ConfigValidationError(
            f"{field_name} must include a valid host, got: {value!r}"
        )

    return
```

Key properties of this fix:

- **Exits 1 on malformed input:** `ConfigValidationError` propagates to the CLI entrypoint, which (per existing behavior for other field errors) causes a non-zero exit. If the entrypoint currently only exits 1 on specific exception types, verify that `ConfigValidationError` is among them — see §4.
- **Valid URLs still pass:** `http://auth.internal:8080`, `https://auth.example.com/v2`, `http://[::1]:9000` all parse with a valid scheme and hostname.
- **No new dependencies:** `urllib.parse` is in the standard library.
