I have completed the code analysis and identified the fix for DEF-2026-04-1047.

**Root Cause:**
In `config/validator.py`, the function `validate_url_field()` currently only checks:
1.  If the field is present.
2.  If the field is non-empty.

It lacks structural validation for the URL, causing `config-validator --service auth` to return exit code 0 (success) even when `auth_service_url` is malformed.

**Proposed Fix:**
Update `validate_url_field()` to perform structural validation. The function should use a URL parsing library (e.g., Python's `urllib.parse`) to verify that the string constitutes a valid URL.

**Implementation Steps:**
1.  Modify `validate_url_field()` in `config/validator.py`.
2.  Add logic to parse the URL. A valid URL must have a scheme (http/https) and a netloc (host).
3.  If the URL is malformed, the validator should raise an exception or return a failure state that causes the main entry point to exit with code 1.
4.  Ensure valid URLs continue to pass (exit code 0).

**Example Code Change (Python):**

```python
import urllib.parse

def validate_url_field(value, field_name):
    if not value:
        raise ValueError(f"{field_name} is empty")
    
    try:
        result = urllib.parse.urlparse(value)
        if not result.scheme or not result.netloc:
            raise ValueError(f"{field_name} is not a valid URL")
    except Exception as e:
        # Propagate error to cause exit code 1
        raise ValueError(f"Invalid {field_name}: {e}")
```
