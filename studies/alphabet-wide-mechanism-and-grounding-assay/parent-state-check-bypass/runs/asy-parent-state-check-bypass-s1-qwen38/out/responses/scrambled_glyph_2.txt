### Root Cause Analysis
The function `validate_url_field()` in `config/validator.py` currently only checks:
1.  Field presence.
2.  Non-empty value.

It fails to validate the structural correctness of the URL, allowing malformed strings (e.g., `not-a-url`, `http://`, `localhost`) to pass validation. Consequently, `config-validator --service auth` exits with code `0` (success) when it should exit with code `1` (failure).

### Proposed Fix

**File:** `config/validator.py`

Replace the current implementation of `validate_url_field()` with a robust URL validation check. Python’s `urllib.parse` is the standard library approach for this.

```python
import urllib.parse

def validate_url_field(value):
    """
    Validates that the provided string is a well-formed URL.
    
    Args:
        value (str): The URL string to validate.
        
    Returns:
        bool: True if the URL is valid, False otherwise.
    """
    if not value or not isinstance(value, str):
        return False
    
    try:
        result = urllib.parse.urlparse(value)
        # A valid URL must have both a scheme (e.g., http, https) and a netloc (hostname)
        if result.scheme in ['http', 'https'] and result.netloc:
            return True
    except Exception:
        pass
        
    return False
```

**Integration into the Validator Logic:**
Ensure that the main validation loop for the `auth` service uses this function and correctly propagates the failure.

```python
def validate_service_config(service_name, config):
    # ... other validations ...
    
    if service_name == 'auth':
        auth_url = config.get('auth_service_url')
        if not validate_url_field(auth_url):
            print(f"ERROR: Malformed or missing 'auth_service_url' for service 'auth'.")
            return 1  # Return exit code 1 for failure
            
    # ... other validations ...
    return 0  # Return exit code 0 for success
```
