### Artifact Update Management

1. **Y-fire and Y-not-fire Scenarios:**
   - **Y-fire:** Occurs when an agent completes an operation on a primary artifact but does not include an update to a companion artifact, which is necessary to reflect the primary artifact's state. This omission results in an unmet obligation.
   - **Y-not-fire:** Occurs when both the primary artifact and the companion artifact updates are included within the operation's scope, meeting the obligation.

2. **Marker Axis:**
   - **Invariant:** If the companion artifact's state does not reflect the primary artifact's state post-operation, the obligation to update it was not met.
   - **Firing Condition:** The operation concludes without the companion artifact update being part of the execution scope.
   - **Violation Signal:** Observable in the execution trace when the primary artifact is updated, but the companion artifact is not.

3. **Aim Axis:**
   - **Invariant:** The operation is correctly executed if both the primary and companion artifact updates are present in the execution scope before the operation closes.

4. **Rest Axis:**
   - **Absent Preconditions:** No companion artifact update obligation exists, so no action is required.
   - **Present Preconditions Delegated Elsewhere:** The companion update is assigned to another role, and the current agent must delegate rather than execute the update.
