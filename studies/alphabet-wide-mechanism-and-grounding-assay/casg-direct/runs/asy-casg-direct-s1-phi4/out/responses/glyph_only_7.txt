### Framework Overview

#### Y-fire and Y-not-fire

- **Y-fire**: 
  - **Scenario**: An agent completes an operation on a primary artifact and holds direct execution authority over a companion artifact.
  - **Decision Point**: Whether to treat the primary artifact update as the terminal step or include the companion artifact update as a required component.
  - **Execution Obligation**: The companion artifact update must reflect the current state of the primary artifact set.

- **Y-not-fire**:
  - **Scenario**: The companion artifact update is already within the operation's execution scope alongside the primary artifact action.
  - **Condition**: Both updates are co-present within scope before the operation closes.

#### Marker Axis

- **Invariant**: The companion artifact's state must reflect the primary artifact set. If not, the obligation is unmet.
- **Firing Condition**: The operation closes with the primary artifact updated but without the companion artifact update in the same scope.
- **Violation Signal**: Observable in the execution trace when a primary artifact is updated without a corresponding companion artifact update.

#### Aim Axis

- **Invariant**: Both the primary artifact action and companion artifact update must be present in the execution trace before the operation closes.
- **Recognition Signal**: The agent holds a completed companion artifact update co-present with the primary artifact action.

#### Rest Axis

- **Characterization**:
  - **Absent Preconditions**: No companion artifact update obligation arises.
  - **Present Preconditions, Delegated Elsewhere**: The update is assigned to another role, and the current agent must file a delegation hand-off.

- **Distinguishing Conditions**:
  - **Absent Preconditions**: No obligation for a companion update.
  - **Present Preconditions, Delegated Elsewhere**: Obligation exists but is assigned to another role.
