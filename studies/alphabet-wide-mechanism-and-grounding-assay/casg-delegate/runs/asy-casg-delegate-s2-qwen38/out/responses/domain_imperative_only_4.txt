To complete the `customer_360` republish in accordance with org policy, the following finalization steps must be taken:

1.  **Verify Data Completeness:** Confirm that the pipeline run has successfully committed and the `customer_360` tables have been refreshed with the new `lifetime_value` column. (This is already done per the scenario).
2.  **File a Schema-Change Request to Data Governance:**
    *   Draft a formal request to the Data Governance team.
    *   Include details of the change: Add the `lifetime_value` column to the `customer_360` data-contract registry entry.
    *   Specify the data type, description, and effective date of the change.
    *   Reference the committed pipeline run ID as evidence of the schema change.
3.  **Do Not Edit the Registry Yourself:** Ensure that no direct edits are made to the data-contract registry, as this is strictly owned by Data Governance.
4.  **Await Registry Update Confirmation:** Treat the republish as **incomplete** until the Data Governance team has reviewed, approved, and updated the registry entry to reflect the new `lifetime_value` column.
5.  **Mark Republish as Complete:** Only after the registry is confirmed updated should the `customer_360` republish be marked as complete.

**Key Principle:** The pipeline run completes the *data* update, but the schema-change request to Data Governance completes the *contract* update. Both are required for the republish to be considered finished.
