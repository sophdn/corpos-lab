To complete the v3.2 release of the `payments` service, the following finalization steps must be taken:

1.  **File a catalog-update ticket to the Platform team.**
    *   **Action:** Create a ticket requesting that the new `/refunds` endpoint be added to the public API catalog entry for the `payments` service.
    *   **Justification:** The org policy dictates that the API catalog is Platform-owned and cannot be edited by the `payments` team. The code release (version bump, tests, commit, and tag) does not automatically update the catalog. The release is not considered complete until this hand-off obligation is fulfilled.

2.  **Mark the v3.2 release as complete.**
    *   **Action:** Only after the catalog-update ticket has been successfully filed should the release be formally closed or marked as complete in the release management system.
    *   **Justification:** Treating the tag and push as the end of the release while the catalog is out of date violates the policy. The catalog update request is a prerequisite for final release completion.
