The v3.2 release for the `payments` service is technically complete and shipped. The code is tagged, tests are green, and the artifact is in the registry.

However, the release is not operationally complete because the public API catalog does not reflect the new `/refunds` endpoint. Since the API catalog is owned by the Platform team and other teams must request changes via a ticket, the finalization step required to close this release cycle is:

**File a catalog-update ticket to the Platform team requesting the addition of the `/refunds` endpoint to the `payments` service entry in the public API catalog.**

No other finalization steps are required for the release itself, as the version bump, testing, and code push are already complete.
