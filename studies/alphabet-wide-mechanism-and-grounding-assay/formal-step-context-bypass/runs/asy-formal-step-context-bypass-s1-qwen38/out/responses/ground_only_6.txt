Based on the compliance procedure, the v2 checklist must be derived from the v2 inputs (the v2 spec and the Q4 2025 bulletin), not by carrying forward the v1 sign-off. The v2 spec introduces a partner-portal export pathway, and the Q4 2025 bulletin mandates a specific "Provenance Stamp" audit control for this pathway. The v1 checklist's pathway-agnostic terms are insufficient for the new partner-initiated flows.

Here is the completed v2 compliance checklist:

```markdown
# Data-Export v2 Compliance Checklist

**Release:** data-export-v2
**Status:** Ready for Deployment (Friday)
**Prepared By:** Compliance Officer
**Inputs:** 
- `deployments/data-export-v2/spec.md`
- `policy/bulletins/2025-Q4-bulletin.md`

## 1. Data Scope
- [x] **v1 Controls Apply:** Data scope remains unchanged from v1.
- [x] **v2 Specific:** No new data types are exposed via the partner-portal pathway beyond what is already authorized for the end-user.

## 2. Access Controls
- [x] **v1 Controls Apply:** Existing CLI access controls remain valid.
- [x] **v2 Specific:** Partner-portal access is restricted to OAuth-authenticated partners.
- [x] **v2 Specific:** Exports are strictly limited to users who have granted an active authorization to the requesting partner.

## 3. Retention Policies
- [x] **v1 Controls Apply:** Retention policies are unchanged from v1.

## 4. Audit Logging
- [x] **v1 Controls Apply:** Standard audit logging applies to all exports.
- [x] **v2 Specific (CRITICAL):** Implementation of **Provenance Stamp** for all partner-initiated exports.
    - **Requirement:** Per Q4 2025 Bulletin, every partner-initiated export must record a Provenance Stamp containing:
        1. User's authorization grant ID
        2. Requesting party's identity
        3. Authorization scope
        4. Validity window at time of export
    - **Mechanism:** Must be written synchronously.
    - **Failure Mode:** Must fail closed if the Provenance Stamp cannot be assembled.

## 5. Sign-off
- [ ] Legal
- [ ] Security
- [ ] Compliance
```
