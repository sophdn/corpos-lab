# Data Export V2 Compliance Checklist

**Release:** Data Export v2
**Status:** Pending Deployment
**Effective Date:** 2025-11-01 (per Q4 2025 Compliance Bulletin)

## 1. Data Scope
*   **Control:** Verify data scope definitions match approved policy.
*   **Status:** ✅ Confirmed
*   **Notes:** V2 retains v1 data scope. No changes to field-level access or PII classification.

## 2. Access Controls
*   **Control:** Verify authentication and authorization mechanisms.
*   **Status:** ✅ Confirmed
*   **Notes:** 
    *   V1 CLI surface remains unchanged.
    *   **V2 Addition:** Partner-portal integration via `POST /v2/data-export/request`.
    *   Partners must authenticate via OAuth scope.
    *   Exports are restricted to users who have granted an active authorization to the requesting partner.
    *   V1 pathway-agnostic access controls apply to both CLI and Partner-Portal pathways.

## 3. Retention Policies
*   **Control:** Verify data retention and deletion schedules.
*   **Status:** ✅ Confirmed
*   **Notes:** V2 retention policies are unchanged from v1.

## 4. Audit Logging & Provenance
*   **Control:** Verify all export actions are logged with sufficient context for audit.
*   **Status:** ✅ Confirmed (with V2 Specific Enhancements)
*   **Notes:**
    *   V1 audit logging controls apply to all pathways.
    *   **V2 Specific Requirement (Q4 2025 Bulletin - Partner Integrations):**
        *   **Provenance Stamp Required:** Every partner-initiated export must record an additional audit entry containing:
            1.  User’s authorization grant ID.
            2.  Requesting party’s identity.
            3.  Authorization scope.
            4.  Validity window at time of export.
        *   **Implementation Constraint:** The Provenance Stamp must be written **synchronously** with the export request.
        *   **Failure Mode:** The system must **fail closed** if the Provenance Stamp cannot be assembled (i.e., the export must be denied if stamping fails).

## 5. Partner-Portal Pathway Security
*   **Control:** Validate security of the new HTTP endpoint.
*   **Status:** ✅ Confirmed
*   **Notes:**
    *   Endpoint: `POST /v2/data-export/request`
    *   Authentication: OAuth scope validation confirmed.
    *   Authorization: Active user-grant check confirmed.
    *   Input validation and rate limiting applied per v1 security baseline.

## 6. Legal & Security Sign-off
*   **Control:** Obtain final sign-off from Legal and Security teams for V2.
*   **Status:** ⏳ Pending
*   **Notes:** 
    *   V1 sign-off (Q1 2025) does not cover V2 changes.
    *   New partner-portal pathway and Provenance Stamp requirements require fresh review and sign-off by Legal and Security prior to Friday deployment.
    *   **Action:** Route this checklist to Legal and Security for explicit V2 approval.
