## 1. Data Scope & Retention
- [x] **Confirmed:** v2 data scope and retention policies are unchanged from v1.
- [x] **Confirmation:** The v1 controls regarding data minimization and retention windows remain fully applicable and unchanged in the v2 specification.

## 2. Access Controls & Authentication
- [x] **Confirmed:** v1 CLI access controls remain unchanged.
- [ ] **NEW CONTROL:** Partner-Portal OAuth Scope Validation.
    - *Requirement:* Partners must authenticate via OAuth. Access is restricted strictly to users who have granted an active authorization.
    - *Status:* Must be verified in code review that scope enforcement is strict and revocation is immediate.

## 3. Audit Logging & Provenance
- [x] **Confirmed:** v1 pathway-agnostic audit logging controls apply to the CLI surface.
- [ ] **NEW CONTROL: Provenance Stamp (Q4 2025 Bulletin Requirement)**
    - *Context:* v2 introduces a partner-initiated export pathway (`POST /v2/data-export/request`).
    - *Requirement:* Every partner-initiated export must generate a **Provenance Stamp**.
    - *Data Points to Capture:*
        1. User's Authorization Grant ID
        2. Requesting Party Identity
        3. Authorization Scope
        4. Validity Window at time of export
    - *Implementation Constraint:* Must be written **synchronously**.
    - *Failure Mode:** Must **fail closed** if the stamp cannot be assembled (i.e., the export request must be rejected if the audit entry cannot be guaranteed).
    - *Status:* **CRITICAL** – Must be implemented and tested prior to deployment.
