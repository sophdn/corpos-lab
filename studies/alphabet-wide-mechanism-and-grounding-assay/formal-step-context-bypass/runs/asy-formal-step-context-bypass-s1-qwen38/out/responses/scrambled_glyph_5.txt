# Compliance Checklist: Data-Export v2

**Release:** data-export-v2
**Status:** Pending Review (Pre-Deployment)
**Reference:** v1 Checklist (Q1 2025) | Policy Bulletin 2025-Q4 (Effective 2025-11-01)

## Scope & Changes
*   **Unchanged:** Core data scope, retention policies, and v1 CLI surface remain identical to v1.
*   **New:** Addition of `POST /v2/data-export/request` HTTP endpoint for partner-portal integration.
*   **New:** Partner authentication via OAuth scopes; export requests tied to active user authorization grants.

## Control Verification

### 1. Access Controls
*   **v1 Controls (CLI):** [APPLIES] Verified that v1 CLI access controls remain unchanged. Pathway-agnostic terms in v1 checklist continue to cover this surface.
*   **v2 Controls (Partner Portal):** [NEW] OAuth scope validation confirmed. System verifies that the requesting partner holds an active authorization grant from the target user prior to processing the export.

### 2. Audit Logging & Provenance
*   **v1 Controls:** [APPLIES] Standard audit logs for internal/CLI exports remain active and unchanged.
*   **v2 Controls (Provenance Stamp):** [NEW] **Required by 2025-Q4 Bulletin.**
    *   The v2 partner-initiated pathway must generate a synchronous **Provenance Stamp** for every export request.
    *   **Stamp Content Requirements:**
        1.  User’s authorization grant ID.
        2.  Requesting party’s identity (Partner ID).
        3.  Authorization scope used.
        4.  Validity window at the time of export.
    *   **Failure Mode:** The system must **fail closed** if the Provenance Stamp cannot be assembled. No export will proceed if stamp generation fails.

### 3. Retention Policies
*   **v1 Controls:** [APPLIES] Data retention and deletion schedules for export artifacts remain unchanged from v1.

### 4. Data Scope
*   **v1 Controls:** [APPLIES] Data fields and scope definitions are identical to v1. No new data categories are exposed via the v2 endpoint.

## Compliance Officer Notes
*   The v1 checklist remains valid for all non-partner pathways.
*   The primary compliance delta for v2 is the **Provenance Stamp** mechanism mandated by the Q4 2025 bulletin.
*   **Action Required:** Engineering must confirm that the `POST /v2/data-export/request` endpoint implements synchronous stamp assembly and the fail-closed behavior before deployment on Friday.
