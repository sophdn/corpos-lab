# Data Export v2 Compliance Checklist

This compliance checklist is specific to the data-export v2 release. It confirms the compliance of the new release with the v2 specifications and the Q4 2025 compliance bulletin requirements. The checklist includes changes introduced in v2 and confirms that existing controls from v1 are still applicable.

## Data Scope

- **Compliance Confirmation:** The data scope for v2 remains unchanged from v1, ensuring that data being exported is within the authorized scope.
- **Action Required:** None

## Access Controls

- **Compliance Confirmation:** Access controls from v1 continue to apply, ensuring secure access to the data export functionalities.
- **v2 Specific Changes:**
  - Introduction of an HTTP endpoint `POST /v2/data-export/request` for partner-portal integration.
  - Partners authenticate by OAuth scope and request exports for users with active authorizations.
- **Action Required:** Ensure OAuth authentication is properly implemented for partner requests.

## Retention Policies

- **Compliance Confirmation:** Retention policies from v1 remain unchanged and are applicable to v2.
- **Action Required:** None

## Audit Logging

- **Compliance Confirmation:** The existing audit logging mechanisms from v1 apply to v2.
- **v2 Specific Changes:**
  - Requirement to add a Provenance Stamp for partner-initiated exports as per the Q4 2025 bulletin.
  - The Provenance Stamp must capture:
    - User's authorization grant id
    - Requesting party's identity
    - Authorization scope
    - Validity window at the time of export
  - Must be written synchronously and fail closed if it cannot be assembled.
- **Action Required:** Implement logging for the Provenance Stamp for partner-initiated exports.

## Provenance Stamp

- **Compliance Confirmation:** Newly introduced requirement per Q4 2025 bulletin.
- **Details:**
  - Capture the user's authorization grant id.
  - Record the requesting party's identity.
  - Note the authorization scope.
  - Include the validity window at the time of export.
  - Ensure the Provenance Stamp is written synchronously and fails closed if not assembled.
- **Action Required:** Implement and verify the Provenance Stamp logging for all partner-initiated exports.

## General

- **Compliance Confirmation:** All existing controls from v1 are confirmed to be applicable to v2, with additional requirements for the new partner-portal integration.
- **Action Required:** Ensure all new requirements are implemented and tested before deployment.

---

This checklist confirms that the v2 release complies with both the v2 specifications and the Q4 2025 compliance bulletin. All necessary changes have been captured, and existing controls have been verified to remain applicable. The team should ensure all actions are completed before the deployment on Friday.
