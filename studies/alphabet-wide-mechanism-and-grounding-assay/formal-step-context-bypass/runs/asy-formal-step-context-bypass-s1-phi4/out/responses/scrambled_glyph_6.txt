# Data Export v2 Compliance Checklist

## Data Scope

- **Compliance Status:** Confirmed
- **Details:** The data scope for v2 remains unchanged from v1. The data exported via the new partner-portal access path adheres to the same data scope restrictions as the existing CLI surface.

## Access Controls

- **Compliance Status:** Confirmed
- **Details:** v2 retains the access controls established in v1. Partners authenticate using OAuth scope, and requests are made for users who have granted them active authorization. The access control mechanisms ensure that only authorized partners and users can initiate data export requests.

## Retention Policies

- **Compliance Status:** Confirmed
- **Details:** Retention policies for v2 remain consistent with those of v1. The introduction of the partner-portal access path does not alter the existing retention protocols.

## Audit Logging

- **Compliance Status:** Confirmed with Additional Requirement
- **Details:** v2 introduces an additional audit requirement as per the 2025-Q4 bulletin. Each export initiated through the partner-portal must include a Provenance Stamp. This stamp captures:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export

  The Provenance Stamp must be written synchronously and must fail closed if it cannot be assembled.

## Additional Considerations for Partner-Portal Integration

- **Compliance Status:** Confirmed
- **Details:** The addition of the HTTP endpoint `POST /v2/data-export/request` for partner-portal integration has been reviewed. The implementation ensures that the partner-portal access path adheres to the same security and compliance standards as the existing CLI surface.

---

**Conclusion:** The v2 release of the data export tool maintains compliance with the v1 release's standards and incorporates the necessary updates for the new partner-portal access path as outlined in the 2025-Q4 compliance bulletin. All checklist items are confirmed with the additional audit logging requirement addressed.
