# Data-Export v2 Compliance Checklist

This compliance checklist is for the data-export v2 deployment. It confirms that v2 complies with the necessary regulations and policies, with specific attention to changes introduced by the v2 release.

## Access Controls

- **User Authentication**: Confirm that the existing CLI and HTTP endpoint access controls from v1 are retained. 
  - [ ] v1 access controls are unchanged and continue to apply.
  - [ ] Partners authenticate via OAuth scope for the new HTTP endpoint `POST /v2/data-export/request`.
  - [ ] Partners must have an active authorization to request exports.
  
## Audit Logging

- **Audit-logging Requirements**: Ensure existing audit-logging mechanisms are in place and meet current standards.
  - [ ] Audit logs from v1 are maintained.
  - [ ] Implement a Provenance Stamp for partner-initiated exports:
    - [ ] Record the user’s authorization grant ID.
    - [ ] Record the requesting party’s identity.
    - [ ] Record the authorization scope.
    - [ ] Record the validity window at the time of export.
  - [ ] Ensure Provenance Stamp is written synchronously.
  - [ ] Implement a "failing closed" mechanism if Provenance Stamp cannot be assembled.

## Data Scope

- **Data Scope Confirmation**: Validate that the data scope remains unchanged from v1.
  - [ ] Confirm data scope is unchanged from v1.
  - [ ] Verify that the data exported via the new partner-portal access path adheres to existing data scope regulations.

## Retention Policies

- **Retention Compliance**: Verify that data retention policies from v1 are still applicable.
  - [ ] Confirm retention policies are unchanged from v1.

## Additional Considerations

- **Partnership Integration**: Address any additional compliance considerations due to the new partner-portal integration.
  - [ ] Ensure all new data flows via the partner portal are compliant with the established data-export policies.
  - [ ] Validate that partners understand and comply with the data handling and retention requirements.

## Legal and Security Sign-off

- **Approval**: Await legal and security team sign-off to confirm that v2 meets compliance standards.
  - [ ] Request sign-off from Legal and Security teams upon completion of the checklist review.

## Notes

- This checklist confirms that the v2 release adheres to compliance requirements as defined in the 2025-Q4 Compliance Office bulletin and maintains the controls from the v1 release.
- Any deviations or additional requirements identified should be documented and addressed prior to deployment.

---

This checklist should be reviewed and signed off by the compliance team, legal, and security teams before deployment.
