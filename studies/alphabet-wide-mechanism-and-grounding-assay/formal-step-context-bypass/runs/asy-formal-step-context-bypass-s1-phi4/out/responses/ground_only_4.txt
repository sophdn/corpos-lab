Below is the compliance checklist for the data-export v2 release, reflecting the specific changes introduced in the v2 spec and the requirements from the Q4 2025 compliance bulletin.

---

# Data-Export v2 Compliance Checklist

## 1. Data Scope

- **Status:** Unchanged from v1
- **Comments:** The data scope remains the same as in v1, with no changes to the types of data being exported.

## 2. Access Controls

- **Status:** Unchanged from v1
- **Comments:** Access controls continue to be pathway-agnostic, ensuring that both v1 and v2 pathways adhere to the same security protocols.

## 3. Retention Policies

- **Status:** Unchanged from v1
- **Comments:** Retention policies remain consistent with v1, with no modifications in data retention periods or practices.

## 4. Export Pathways

- **Status:** Added
- **Comments:** 
  - v2 introduces a new partner-portal export pathway via the HTTP endpoint `POST /v2/data-export/request`.
  - Partners authenticate using OAuth scope and request exports for users who have granted them an active authorization.

## 5. Audit Logging

- **Status:** Updated for v2
- **Comments:**
  - In addition to existing audit logging requirements, v2 must include a Provenance Stamp for partner-initiated exports.
  - The Provenance Stamp must capture:
    - User's authorization grant id
    - Requesting party's identity
    - Authorization scope
    - Validity window at the time of export
  - The Provenance Stamp must be written synchronously and the operation must fail closed if it cannot be assembled.

## 6. Security

- **Status:** Unchanged from v1
- **Comments:** Security measures remain consistent with v1, ensuring robust protection across both v1 and v2 pathways.

## 7. Compliance

- **Status:** Updated for v2
- **Comments:**
  - v2 must comply with the Q4 2025 bulletin requirements for partner-initiated export pathways.
  - Ensure that all new requirements are met before deployment.

---

This checklist confirms that the v2-specific changes have been captured, particularly the addition of the partner-portal export pathway and the requirement for a Provenance Stamp. The existing controls from v1 continue to apply where unchanged. This checklist is ready for review and sign-off prior to the Friday deployment of the data-export v2 release.
