# Data Export v2 Compliance Checklist

## Data Scope
- **Control**: Ensure that the data export scope is consistent with v1.
- **Status**: Unchanged, controls from v1 apply.
- **Details**: The v2 release retains the same data scope as v1, ensuring no additional data fields are exposed through the new partner-portal access.

## Access Controls
- **Control**: Verify that access controls remain consistent with v1.
- **Status**: Unchanged, controls from v1 apply.
- **Details**: The v2 release maintains the original CLI access controls and introduces OAuth for partner-portal authentication, ensuring robust access management.

## Retention Policies
- **Control**: Confirm retention policies are unchanged from v1.
- **Status**: Unchanged, controls from v1 apply.
- **Details**: Retention policies continue to apply as defined in v1, with no modifications introduced in v2.

## Audit Logging
- **Control**: Ensure audit logging requirements from v1 are met.
- **Status**: Unchanged, controls from v1 apply with additional requirements.
- **Details**: The audit logging requirements for v1 are applicable. Additionally, v2 introduces a Provenance Stamp requirement for partner-initiated exports, capturing:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at time of export
  - The Provenance Stamp must be written synchronously and fail closed if it cannot be assembled.

## Provenance Stamp
- **Control**: Implement a Provenance Stamp for partner-initiated exports.
- **Status**: New requirement for v2.
- **Details**: This audit entry captures critical information for partner-initiated data exports, as per the Q4 2025 compliance bulletin.

---

This checklist confirms that the v2 release maintains the compliance standards established in v1 while incorporating the necessary changes for the new partner-portal access path. The additional requirement for the Provenance Stamp has been documented to ensure full compliance with the updated policy.
