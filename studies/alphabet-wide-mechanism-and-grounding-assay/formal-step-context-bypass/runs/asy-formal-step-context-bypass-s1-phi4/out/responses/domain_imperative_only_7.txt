# Data Export v2 Compliance Checklist

## Introduction
This compliance checklist is for the pre-deployment confirmation of the data-export v2 release, scheduled for deployment on Friday. The checklist ensures that the new v2 release adheres to the compliance requirements as per the v2 specification and the Q4 2025 compliance bulletin.

## Data Scope
- **Compliance Status:** Green
- **Details:** The data scope for v2 remains unchanged from v1. The checklist confirms that the data scope is compliant with existing policies.

## Access Controls
- **Compliance Status:** Green
- **Details:** Access controls for v2 continue to align with those of v1. The addition of a partner-portal access path does not alter existing access controls, which remain pathway-agnostic.

## Retention Policies
- **Compliance Status:** Green
- **Details:** Retention policies for v2 are consistent with v1. No changes have been made to data retention policies.

## Partner-Portal Export Pathway
- **Compliance Status:** Green
- **Details:** The v2 spec introduces a new HTTP endpoint `POST /v2/data-export/request` for partner-portal integration. Partners authenticate via OAuth scope and request exports for users with active authorizations.
- **Provenance Stamp Requirement:** As per the Q4 2025 compliance bulletin, a Provenance Stamp must be recorded for every partner-initiated export. This stamp should capture:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
- **Implementation:** The Provenance Stamp must be written synchronously and should fail closed if it cannot be assembled.

## Audit Logging
- **Compliance Status:** Green
- **Details:** Audit logging requirements from v1 are maintained. The addition of the Provenance Stamp for partner-initiated exports is included as per the Q4 bulletin.
- **Provenance Stamp Logging:** Ensure that the Provenance Stamp is logged as part of the audit trail for partner-initiated exports.

## Summary
- The data-export v2 release maintains compliance with existing data scope, access controls, and retention policies from v1.
- The addition of a partner-portal access path requires the implementation of the Provenance Stamp as per the Q4 2025 compliance bulletin.
- All changes and requirements specific to v2 have been captured and confirmed for compliance.

This checklist should be reviewed and signed off by the compliance team before the deployment of the data-export v2 release.
