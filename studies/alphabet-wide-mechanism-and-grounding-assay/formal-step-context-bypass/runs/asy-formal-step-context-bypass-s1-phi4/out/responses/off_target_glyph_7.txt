To create the compliance checklist for the data-export v2 release, we need to consider both the unchanged elements from v1 and any new requirements introduced by the v2 deployment. Since the core data scope, access controls, and retention policies remain unchanged, we can carry over the compliance checks from v1. However, we must also address the new requirement from the 2025-Q4 bulletin regarding partner-initiated export pathways.

Here's how the v2 compliance checklist should be structured:

---

### Deployments/Data Export v2 Compliance Checklist

#### Data Scope
- [ ] Ensure data export scope is limited to authorized data sets as per v1 specifications.
- [ ] Confirm no additional data types are included in v2.

#### Access Controls
- [ ] Verify that access controls for the CLI surface remain unchanged from v1.
- [ ] Ensure that OAuth authentication for partners is implemented correctly.
- [ ] Confirm that partners can only request exports for users who have granted them active authorization.

#### Retention Policies
- [ ] Check that data retention policies are consistent with v1 guidelines.
- [ ] Ensure no changes have been made to data retention durations or procedures.

#### Audit Logging
- [ ] Validate that audit logs capture all necessary details for both CLI and HTTP endpoint usage.
- [ ] Confirm logs include user actions, access attempts, and any changes to data exports.

#### Provenance Stamp (New Requirement)
- [ ] Implement a Provenance Stamp for partner-initiated export pathways.
  - Capture the user's authorization grant ID.
  - Record the requesting party's identity.
  - Log the authorization scope.
  - Document the validity window at the time of export.
- [ ] Ensure the Provenance Stamp is written synchronously.
- [ ] Implement a fail-closed mechanism if the Provenance Stamp cannot be assembled.

#### General Compliance
- [ ] Review all compliance checks for completeness.
- [ ] Ensure all compliance documentation is up-to-date and accessible.
- [ ] Obtain final sign-off from Legal and Security for the v2 release.

---

This checklist ensures that all necessary compliance elements are addressed for the v2 release, including the new requirements for partner-initiated export pathways. Once completed, this checklist can be reviewed and signed off by the relevant teams.
