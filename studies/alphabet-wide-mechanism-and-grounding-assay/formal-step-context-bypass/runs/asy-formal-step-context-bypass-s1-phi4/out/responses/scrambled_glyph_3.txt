## Introduction

## Overview
The data-export v2 release retains the data scope, access controls, and retention policies from v1, with the addition of a partner-portal access path. The compliance team has reviewed the v2 specification and confirmed that the fundamental controls remain unchanged. The checklist below addresses v2-specific changes and verifies the continued applicability of v1 controls.

- **Verification:** Confirm that the data scope of v2 remains unchanged from v1.
- **Compliance Status:** Compliant.  
  _Rationale:_ The v2 spec indicates no changes to the data scope.

### Access Controls
- **Verification:** Ensure access controls are consistent with v1 specifications.
- **Compliance Status:** Compliant.  
  _Rationale:_ The v2 spec retains v1 CLI access controls and adds OAuth scope authentication for partners.

### Retention Policies
- **Verification:** Confirm retention policies are unchanged from v1.
- **Compliance Status:** Compliant.  
  _Rationale:_ The v2 spec does not alter retention policies.

### Audit Logging
- **Verification:** Confirm that audit logging requirements from v1 are met.
- **Compliance Status:** Compliant.  
  _Rationale:_ Existing audit logging practices remain applicable.

### New Requirements for Partner-Portal Access
- **Verification:** Confirm that the new partner-portal access path complies with the latest policy updates.
- **Compliance Status:** Compliant.  
  _Rationale:_ The v2 spec includes an HTTP endpoint for partner-portal integration, with OAuth scope authentication.

### Provenance Stamp Requirement
- **Verification:** Ensure that a Provenance Stamp is recorded for each partner-initiated export.
- **Compliance Status:** Compliant.  
  _Rationale:_ The v2 spec includes a requirement for a Provenance Stamp capturing the user's authorization grant ID, the requesting party's identity, the authorization scope, and the validity window at the time of export.
