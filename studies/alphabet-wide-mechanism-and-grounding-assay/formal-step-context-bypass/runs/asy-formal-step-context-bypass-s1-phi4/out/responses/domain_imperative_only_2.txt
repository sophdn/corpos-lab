# Deployments/Data-Export-v2/Compliance-Checklist.md

## Introduction
This checklist serves as a pre-deployment compliance confirmation for the data-export v2 release, scheduled for deployment on Friday. While the v1 release was reviewed and signed off by Legal and Security in Q1 2025, this checklist focuses on ensuring that the new v2 features comply with the latest policies, particularly those introduced in the Q4 2025 compliance bulletin.

## Data Scope
- **Confirmation**: The data scope for v2 remains unchanged from v1. No new data categories are introduced.
- **Compliance**: Confirmed that the unchanged data scope continues to comply with existing policies.

## Access Controls
- **Confirmation**: Access controls for v1 remain applicable. The new partner-portal access path uses OAuth scope for authentication.
- **Compliance**: Partners must authenticate via OAuth scope and request exports for users who have granted them an active authorization.
- **Verification**: Ensure that access controls are enforced for both the CLI and the new HTTP endpoint.

## Retention Policies
- **Confirmation**: Retention policies remain unchanged from v1.
- **Compliance**: Ensure that data retention policies continue to meet regulatory requirements.

## Audit Logging
- **Confirmation**: Existing audit logging controls from v1 are applicable.
- **Compliance**: Ensure audit logs capture all necessary events for both the CLI and the new HTTP endpoint.
- **New Requirement**: Implement a Provenance Stamp for partner-initiated exports, capturing:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
- **Verification**: Ensure Provenance Stamp is written synchronously and fails closed if it cannot be assembled.

## Provenance Stamp
- **New Requirement**: As per the Q4 2025 compliance bulletin, any deployment adding a partner-initiated export pathway must record a Provenance Stamp.
- **Implementation**: Capture the following details at the time of export:
  - Authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window
- **Synchronous Writing**: Ensure the Provenance Stamp is written synchronously.
- **Fail Closed**: Ensure the process fails closed if the Provenance Stamp cannot be assembled.

## Partner-Portal Export Pathway
- **New Feature**: v2 introduces an HTTP endpoint `POST /v2/data-export/request` for partner-portal integration.
- **Compliance**: Ensure the new pathway complies with all relevant policies, particularly regarding authentication and authorization.

## Conclusion
This checklist confirms that the data-export v2 release complies with all relevant policies, including the new requirements introduced in the Q4 2025 compliance bulletin. All v1 controls continue to apply, and new features have been assessed for compliance. This checklist should be reviewed and signed off by Legal and Security before deployment.

---

**Note**: This checklist is a pre-deployment compliance confirmation and not a full re-review. It focuses on ensuring that the new v2 features comply with the latest policies.
