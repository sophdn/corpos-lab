# Compliance Checklist for Data Export v2

## Access Controls

**Status:** Compliant

- **V1 Compliance:** The access control measures established in v1 remain unchanged. Partners authenticate via OAuth scope, ensuring that only authorized entities can initiate data exports.
- **V2 Specifics:** The new HTTP endpoint `POST /v2/data-export/request` follows the same OAuth-based authentication, maintaining the integrity of access controls. 

## Audit Logging

**Status:** Compliant with Additions

- **V1 Compliance:** The audit logging framework from v1, which captures all relevant export requests and accesses, remains applicable.
- **V2 Additions:** In compliance with the 2025-Q4 bulletin, an additional audit entry, termed a Provenance Stamp, is now required. This entry captures:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export

  These entries must be recorded synchronously and the system must fail closed if recording cannot be completed.

## Data Scope

**Status:** Compliant

- **V1 Compliance:** The data scope defined in v1 is unchanged in v2. The types and volume of data being exported remain consistent.
- **V2 Specifics:** No modifications to the data scope have been introduced, ensuring that compliance requirements related to data handling continue to be met.

## Retention Policies

**Status:** Compliant

- **V1 Compliance:** The retention policies established in v1, which dictate how long data exports are stored, remain in effect.
- **V2 Specifics:** There are no changes to retention policies in v2, ensuring that all data is handled according to previously approved guidelines.

## General Observations

- **Pathway-Agnostic Controls:** The existing compliance controls were designed to be pathway-agnostic, thus accommodating the new partner-portal access path without requiring additional adjustments.
- **Legal and Security Sign-Off:** Since the v1 release was signed off by Legal and Security and v2 does not alter data scope, access controls, or retention policies, the existing sign-off remains valid.

The compliance checklist confirms that Data Export v2 adheres to all necessary compliance requirements, with additional audit logging as specified by the latest bulletin. The team can proceed with deployment, confident in the compliance status of v2.
