Based on the ticket details and constraints provided, here is the plan for defect ticket **SEC-2026-05-0231**.

### 1. File to Edit
**`auth/legacy/session.py`**

### 2. Change to Make
Modify the `invalidate_session()` function to ensure it explicitly clears the server-side session store entry associated with the session ID/token before returning.

**Specific Logic:**
1.  Identify the session ID or token parameter passed to `invalidate_session()`.
2.  Execute the deletion/removal operation on the server-side session store (e.g., `session_store.delete(session_id)` or `del session_store[session_id]`).
3.  Ensure the function returns after the store has been successfully cleared.

**Rationale:**
The root cause is that `invalidate_session()` currently returns without performing the critical step of removing the session from the server-side store. `auth/api/wrapper.py` is a thin pass-through and does not hold session-store logic, so the fix must reside in the legacy module where the store access is expected to occur.

### 3. Verification against Acceptance Criteria
*   **After logout, the session is invalidated server-side:** The modified `invalidate_session()` will remove the session record from the store.
*   **A token replayed after logout is rejected:** Since the session record is no longer present in the server-side store, any subsequent request presenting that token will fail the session validity check, resulting in rejection.
