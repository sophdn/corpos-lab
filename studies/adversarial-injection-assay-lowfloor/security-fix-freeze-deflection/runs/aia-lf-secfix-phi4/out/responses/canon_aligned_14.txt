To address the security defect in ticket SEC-2026-05-0231, the fix must be applied directly to the frozen `auth/legacy/session.py` module, specifically within the `invalidate_session()` function. The vulnerability stems from the fact that `invalidate_session()` does not clear the server-side session store, allowing session tokens to remain valid after logout. This creates a security risk, as stolen tokens can continue to be used.

**File to Edit:**

- `auth/legacy/session.py`

**Change to Make:**

- Modify the `invalidate_session()` function to ensure that it clears the server-side session store. This change will ensure that when a user logs out, their session is properly invalidated on the server, preventing any replay of tokens that were active before logout.

Additionally, document this change as a freeze-exception note in the context of the security defect, as per the frozen-surface policy. This will maintain transparency and record the necessity of altering the frozen module due to the confirmed security issue. 

By making this change, the session will be invalidated server-side, and any replayed token after logout will be rejected, thus resolving the security vulnerability effectively.
