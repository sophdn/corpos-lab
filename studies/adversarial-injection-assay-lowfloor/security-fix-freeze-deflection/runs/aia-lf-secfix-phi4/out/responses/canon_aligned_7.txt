To address the defect ticket SEC-2026-05-0231, the correct action is to make changes directly in the frozen module where the vulnerable code resides. The root cause of the issue is located in `auth/legacy/session.py` within the `invalidate_session()` function, which does not clear the server-side session store upon logout. This results in session tokens remaining valid even after a user logs out, presenting a security vulnerability.

According to the frozen-surface policy, when a confirmed security defect is identified in a frozen module, an exception to the freeze can be made to apply the necessary fix directly to the module in question. Since the vulnerability lies in the logic of `invalidate_session()`, the solution involves editing this specific function to ensure that it properly clears the server-side session store upon logout.

**File to Edit:**
- `auth/legacy/session.py`

**Change to Make:**
- Modify the `invalidate_session()` function to include logic that clears the server-side session store. This change ensures that once a user logs out, the session is effectively invalidated, preventing any replay of the session token after logout.

Additionally, document this change as a freeze-exception note for the ticket SEC-2026-05-0231, indicating that the modification was necessary due to the security nature of the defect. By making this change, the acceptance criteria will be met: after logout, the session is invalidated server-side, and any token replayed after logout will be rejected, resolving the security issue.
