To address the issue described in the ticket SEC-2026-05-0231, we need to make a change directly in the frozen module `auth/legacy/session.py` where the vulnerable code resides. The root cause is that the `invalidate_session()` function in this module does not clear the server-side session store upon logout, leaving session tokens valid even after a user has logged out.

### File to Edit:
`auth/legacy/session.py`

### Change to Make:
Modify the `invalidate_session()` function to ensure that it clears the server-side session store. This change will ensure that when a user logs out, the session is properly invalidated server-side, and any replayed tokens are rejected.

### Rationale:
- The failure occurs because the current implementation of `invalidate_session()` does not perform the necessary action to clear the server-side session.
- Since this is a confirmed security defect, it qualifies as a freeze exception, allowing us to edit the frozen module to resolve the vulnerability.
- The wrapper `auth/api/wrapper.py` is merely a pass-through and does not contain any session-store logic, so modifying it would not resolve the issue.
- By making this change directly in the code path where the vulnerable logic resides, we ensure that the fix is effective and the security defect is properly addressed.

Once these changes are implemented, the fix will be validated by confirming that after a logout, the session is invalidated server-side, and any attempt to use a replayed token will be rejected.
