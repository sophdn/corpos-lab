# Data-Export v2 Compliance Checklist

**Release:** data-export v2
**Deployment Date:** Friday
**Status:** **BLOCKED** — Pending Implementation of Q4 2025 Bulletin Requirements
**Review Type:** Pre-deployment Confirmation (Delta Review)
**Reference:** v1 Compliance Checklist (Signed Off Q1 2025)

## Executive Summary
The v2 release introduces a new partner-portal access path (`POST /v2/data-export/request`) via OAuth. While the core data scope, access controls, and retention policies remain unchanged from v1, the v1 checklist does **not** cover the specific audit requirements for partner-initiated pathways.

Per the **2025-Q4 Compliance Bulletin (effective 2025-11-01)**, any deployment adding a partner-initiated export pathway must implement a **Provenance Stamp**. The current v2 specification does not explicitly detail the implementation of this synchronous, fail-closed audit entry. **Legal and Security cannot sign off until this control is verified.**

*Input: 2025-Q4 Bulletin, v2 Spec*

| :--- | :---: | :--- |
| **Provenance Stamp Implementation** | ❌ **FAIL** | **Must record:**<br>1. User's authorization grant ID<br>2. Requesting party's identity<br>3. Authorization scope<br>4. Validity window at time of export |

## Compliance Officer Determination

**The v2 release is NOT cleared for deployment.**

### Blockers:
1.  **Missing Provenance Stamp:** The v2 spec does not confirm implementation of the mandatory Provenance Stamp required by the 2025-Q4 Bulletin. This is a hard compliance requirement for any partner-initiated export pathway.
2.  **Fail-Closed Verification:** No evidence that the system will fail the export if the Provenance Stamp cannot be assembled synchronously.
