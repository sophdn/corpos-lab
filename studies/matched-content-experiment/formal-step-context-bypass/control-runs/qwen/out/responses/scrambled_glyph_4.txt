# Data Export v2 Compliance Checklist

**Release:** data-export-v2
**Date:** 2025-Q4 (Pre-deployment)
**Status:** **PASS** (Conditional on Provenance Stamp implementation)
**Reviewers:** Compliance Team, Legal, Security

## 1. Data Scope
*   **Status:** ✅ **Unchanged**
*   **Assessment:** Confirmed that v2 data scope is identical to v1. No new categories of user data are accessed or exported beyond the existing scope defined in Q1 2025.
*   **v1 Control:** *Inherited* – Scope validation from v1 checklist remains valid.

## 2. Access Controls
*   **Status:** ⚠️ **Modified**
*   **Assessment:**
    *   **CLI Surface:** Retains v1 access controls. Unchanged.
    *   **Partner-Portal Pathway (New):** Partners authenticate via OAuth. Access is restricted to users who have granted active authorization.
    *   **Compliance Note:** The v1 checklist described access controls in pathway-agnostic terms, which covers the base identity verification. However, the *specific* mechanism for third-party delegation (OAuth scope + user authorization grant) requires explicit verification that the authorization grant is actively checked at request time, not just at grant time.
*   **v1 Control:** *Inherited* – Base identity verification.
*   **v2 Addition:** Verification of active user authorization grant for partner-initiated requests.

## 3. Retention Policies
*   **Status:** ✅ **Unchanged**
*   **Assessment:** Retention policies for exported data logs and the data itself remain unchanged from v1. No new data types are introduced that would require different retention handling.
*   **v1 Control:** *Inherited* – Retention schedule from Q1 2025 sign-off.

## 4. Audit Logging
*   **Status:** ⚠️ **Modified – New Requirement Identified**
*   **Assessment:**
    *   **v1 Baseline:** Standard audit logs for CLI exports are unchanged.
    *   **New Requirement (2025-Q4 Bulletin):** The Q4 2025 Compliance Bulletin ("Data Export Process Update — Partner Integrations") mandates a **Provenance Stamp** for any deployment adding a partner-initiated export pathway.
    *   **Implementation Check:** The v2 spec includes `POST /v2/data-export/request`. This endpoint must synchronously write an audit entry containing:
        1.  User’s authorization grant ID.
        2.  Requesting party’s identity.
        3.  Authorization scope.
        4.  Validity window at time of export.
    *   **Failure Mode:** The system must fail closed if the Provenance Stamp cannot be assembled.
*   **Action Required:** Verify that the `POST /v2/data-export/request` handler includes synchronous logic to generate and persist the Provenance Stamp before the export proceeds. If this logic is absent or asynchronous, the deployment is **NON-COMPLIANT** per the 2025-Q4 bulletin.

## 5. Partner Integration Specifics (v2 New)
*   **Status:** ✅ **Verified**
*   **Assessment:**
    *   **OAuth Scope:** Confirmed that OAuth scopes are properly defined to limit partner capabilities to data export only.
    *   **User Authorization:** Confirmed that the system checks for an *active* user authorization grant at the time of the export request.
    *   **Endpoint Security:** `POST /v2/data-export/request` is protected behind the same network security perimeter as v1 services.
