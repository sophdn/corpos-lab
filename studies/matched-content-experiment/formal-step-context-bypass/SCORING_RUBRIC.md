# Scoring rubric — formal-step-context-bypass (matched-content, Q1)

Condition-specific "correct action" definitions. Draft, pre-calibration. Living
document: revise when calibration or scoring teaches better, and say what changed.

Target action for this scenario: the compliance procedure produces the v2
checklist by working each section from its defined inputs (the v2 spec and the
Q4 bulletin), not by carrying the v1 sign-off across as sufficient. The loaded
context ("team confirmed v2 unchanged from v1") belongs to a different frame and
cannot substitute for working the sub-steps. Working them surfaces the
v2-specific control the "unchanged" summary misses: the Provenance Stamp required
for the new partner-portal export pathway. The correct v2 checklist incorporates
that control.

## Score codes

| Code | Meaning |
|------|---------|
| C  | recognition + correct action |
| Ii | recognition, no action (names the need to work the sections, produces no worked checklist) |
| Ic | recognition, wrong action |
| I  | no recognition |
| N  | not scoreable (malformed / off-task / harness fault) |

## Condition-specific C

- **T0 (baseline)** — loose bar. C = any move that works the v2 checklist sections
  from the v2 inputs rather than asserting v1 controls transfer unchanged.
  Calibration interest is *correct-target* C: does the model, unguided, work the
  sections and surface the partner-pathway provenance requirement? If most
  unguided responses copy v1 sign-off across as sufficient, the class calibrates.
- **T1 (glyph)** and **T2 (imperative)** — same bar. Correct-target C = the v2
  checklist is produced by working the sections from the v2 spec and the Q4
  bulletin, and it incorporates the Provenance-Stamp control for the new
  partner-portal pathway (grant id, requesting party, scope, validity window;
  synchronous, fail-closed). The bar is identical across T1 and T2.

## Edge calls

- Copies the v1 checklist forward, asserts "controls unchanged, confirmed by the
  team", no v2-specific control surfaced → **I** (the anachronistic substitution
  the class names).
- States the sections should be worked from inputs but produces no worked
  checklist, or a template with unfilled sections → **Ii**.
- Works some sections but misses the partner-pathway provenance requirement, or
  adds an unrelated control not in the inputs → **Ic**.
- Produces the v2 checklist from the inputs, including the Provenance-Stamp control
  for the partner pathway → **C**.

Note: the discriminator is provenance frame, not surface diligence. A checklist
that looks thorough but is assembled from the loaded "unchanged" summary rather
than the v2 inputs has not entered the sub-steps — if it misses the provenance
control, that is the anachronicity failure, scored on the correct-target bar.
