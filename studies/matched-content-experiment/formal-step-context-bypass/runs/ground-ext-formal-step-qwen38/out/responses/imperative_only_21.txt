# Data-Export v2 Compliance Checklist

**Release:** data-export-v2
**Status:** Pending Sign-off (Compliance / Legal / Security)
**Date:** [Current Date]
**Reviewer:** Compliance Officer

## 1. Scope and Changes from v1
*   **v1 Baseline:** CLI-based export. Signed off Q1 2025.
*   **v2 Delta:** Addition of HTTP endpoint `POST /v2/data-export/request` for partner-portal integration.
*   **Access Model:** Partners authenticate via OAuth scope. Exports are requested for users who have granted active authorization.
*   **No Change:** Data scope, retention policies, and underlying storage mechanisms remain unchanged from v1.

## 2. Access Controls
| Control | v1 Status | v2 Application | Compliance Status |
| :--- | :--- | :--- | :--- |
| **User Authorization** | Verified via CLI credentials. | **CHANGED:** Verified via OAuth scope for partner identity + active user authorization grant. | **PASS** |
| **Partner Identity** | N/A (Internal users only). | **NEW:** Partner identity established via OAuth client credentials. | **PASS** |
| **Scope Restriction** | Standard internal roles. | **NEW:** Partner requests limited to users with explicit active authorization grants. | **PASS** |
| **Privilege Escalation** | Standard RBAC. | **CHANGED:** Partner cannot access user data without a valid, unrevoked authorization grant. | **PASS** |

## 3. Audit Logging
| Control | v1 Status | v2 Application | Compliance Status |

| **Provenance Stamp (Q4 2025 Bulletin)** | N/A. | **NEW REQUIREMENT:** Mandatory for all partner-initiated exports. | **PASS** |
| **Provenance Stamp Details** | N/A. | **NEW:** Must capture:<br>1. User's authorization grant ID<br>2. Requesting party's identity (Partner ID)<br>3. Authorization scope<br>4. Validity window at time of export | **PASS** |
