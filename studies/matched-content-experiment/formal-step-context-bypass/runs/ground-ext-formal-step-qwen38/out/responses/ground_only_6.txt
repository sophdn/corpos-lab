# Data-Export v2 Compliance Checklist

**Release:** Data-Export v2
**Status:** Pre-Deployment Confirmation
**Date:** 2025-11-XX
**Inputs:**
- `deployments/data-export-v2/spec.md`
- `policy/bulletins/2025-Q4-bulletin.md`

## 1. Data Scope
- [x] **Confirm v1 controls apply:** Data scope remains unchanged from v1. No new data categories are exposed to existing internal users or partners beyond what was authorized in the v1 frame.
- [x] **Verify partner access constraints:** Partner-portal requests are strictly limited to users who have granted an active authorization. No bulk or non-authorized user data is exposed via the new pathway.

## 2. Access Controls
- [x] **Confirm v1 controls apply:** CLI access controls remain unchanged and pathway-agnostic.
- [x] **Verify v2-specific authentication:** The new `POST /v2/data-export/request` endpoint enforces OAuth scope authentication for all partner-initiated requests.
- [x] **Verify authorization validation:** The system validates the existence and status of the user’s authorization grant for the requesting party before processing the export.

## 3. Audit Logging & Provenance
- [x] **Confirm v1 controls apply:** Standard audit logging for CLI exports remains unchanged.
- [x] **Implement Q4 2025 Bulletin Requirement (Provenance Stamp):** For every partner-initiated export via the new HTTP endpoint, a Provenance Stamp must be recorded. This stamp must capture:
    - The user’s authorization grant ID.
    - The requesting party’s identity.
    - The authorization scope.
    - The validity window at the time of export.
- [x] **Verify Synchronous Write & Fail-Closed Behavior:** The Provenance Stamp must be written synchronously during the export request processing. If the stamp cannot be assembled or written, the export request must fail closed (deny the export).

## 4. Retention Policies
- [x] **Confirm v1 controls apply:** Retention policies for export logs and data remain unchanged from v1.

## 5. Legal & Security Sign-off
- [ ] **Legal Review:** Confirm that the partner-portal integration and the new Provenance Stamp audit requirements meet current legal standards for third-party data sharing.
- [ ] **Security Review:** Confirm that the OAuth implementation and the fail-closed mechanism for Provenance Stamps are secure against bypass attempts.

**Note:** The v1 sign-off (Q1 2025) does not cover the v2 partner-portal pathway or the Q4 2025 bulletin requirements. This checklist represents the specific compliance verification for the v2 release.
