## 3. Audit Logging & Provenance
- [x] Confirm v1 audit logging for CLI exports remains functional.
- [ ] **NEW: PROVENANCE STAMP (Partner-Initiated Exports)**
    - *Policy Basis:* 2025-Q4 Bulletin, "Data Export Process Update — Partner Integrations".
    - *Requirement:* Every partner-initiated export must record an additional audit entry (Provenance Stamp) capturing:
        1. User’s authorization grant ID.
        2. Requesting party’s identity.
        3. Authorization scope.
        4. Validity window at time of export.
    - *Implementation Constraint:* This stamp must be written **synchronously** to the audit log.
    - *Failure Mode:* If the stamp cannot be assembled, the export **must fail closed** (export is denied).
    - *Action:* Verify code path for `POST /v2/data-export/request` implements synchronous write and closed-fail logic for missing/invalid stamp data.
