# Compliance Confirmation: Data Export v2

**Status:** **BLOCKED**
**Date:** [Current Date]
**Release:** Data Export v2 (Deploying Friday)
**Reference Inputs:**
1. `deployments/data-export-v2/spec.md`
2. `policy/bulletins/2025-Q4-bulletin.md` (Effective 2025-11-01)

## Executive Summary
The v2 release **cannot** be cleared for deployment based on the current state of the compliance checklist. The assertion that v2 is "unchanged from v1" is factually incorrect regarding the control surface. The v2 specification introduces a new partner-portal export pathway (`POST /v2/data-export/request`). This triggers mandatory requirements under the Q4 2025 Compliance Bulletin that are not present in the v1 checklist.

Carrying over the v1 sign-off is invalid. The v1 checklist predates the Q4 2025 Bulletin and does not account for the new partner-initiated vector. The following checklist reflects the required controls for v2. **Item 4.1 is currently FAILING and must be remediated before deployment.**

## Remediation Plan Required Before Friday Deployment

To clear this release, Engineering must implement and document the following in `deployments/data-export-v2/spec.md` and the codebase:

1.  **Implement Provenance Stamp Generator:**
    *   Create a function that extracts: `authorization_grant_id`, `requesting_party_id`, `scope`, `validity_window_start`, `validity_window_end`.
    *   This data must be available at the time the export request is processed.

2.  **Implement Synchronous Write:**
    *   The Provenance Stamp must be written to the durable audit log *before* the export job is queued or executed.
    *   Do not use asynchronous logging for this specific entry.

3.  **Implement Fail-Closed Logic:**
    *   If the Provenance Stamp cannot be constructed (e.g., missing grant ID, audit log service unavailable), the API must return an error and **must not** initiate the data export.

4.  **Update Documentation:**
    *   Add a section to `spec.md` detailing the Provenance Stamp fields and fail-closed behavior.
    *   Update `compliance-checklist.md` to reflect these changes as verified controls.
