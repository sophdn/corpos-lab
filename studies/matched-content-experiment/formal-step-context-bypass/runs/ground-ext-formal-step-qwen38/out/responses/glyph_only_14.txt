# Data-Export v2 Compliance Checklist

**Release:** data-export v2
**Status:** Draft for Review
**Date:** 2025-Q4
**Prepared By:** Compliance Officer

## 1. Scope and Changes from v1
- **CLI Surface:** Unchanged from v1.
- **New Feature:** Partner-Portal Access Path (`POST /v2/data-export/request`).
- **Authentication:** Partners authenticate via OAuth scope.
- **Authorization:** Exports permitted only for users with active partner authorizations.

## 2. Inherited Controls (From v1)
*Verification that v1 controls remain applicable and unaltered in v2.*

- [x] **Access Control (CLI):** v1 CLI access controls remain in effect. No new users or roles added to CLI surface.
- [x] **Retention Policy:** Data retention policies are unchanged from v1.
- [x] **Audit Logging (Base):** Standard audit logs for CLI exports continue to function as defined in v1.

## 3. New Controls: Partner-Portal Pathway
*Specific controls for the new `POST /v2/data-export/request` endpoint.*

- [ ] **OAuth Scope Validation:**
  - [ ] Verify that the OAuth token presented by the partner contains the specific `data-export` scope.
  - [ ] Verify that the token is issued by the trusted identity provider.
  - [ ] Reject requests with insufficient or missing scopes.

- [ ] **User Authorization Check:**
  - [ ] Verify that the requesting partner has an active authorization grant for the specific user whose data is being exported.
  - [ ] Verify that the authorization grant has not been revoked or expired.
  - [ ] Reject requests if no active authorization exists for the target user.

## 4. Mandatory Provenance Stamp (Per 2025-Q4 Bulletin)
*Requirement: Any deployment adding a partner-initiated export pathway must record a Provenance Stamp.*

- [ ] **Provenance Stamp Implementation:**
  - [ ] The system must generate a Provenance Stamp synchronously during the export request processing.
  - [ ] **Data Fields Captured:**
    - [ ] User's Authorization Grant ID
    - [ ] Requesting Party's Identity (Partner ID/Subject)
    - [ ] Authorization Scope (from OAuth token)
    - [ ] Validity Window (Time of export vs. grant expiration)
  - [ ] **Fail-Closed Behavior:**
    - [ ] If the Provenance Stamp cannot be assembled (e.g., missing grant ID, internal error), the export request MUST fail.
    - [ ] No data is exported if the stamp is not successfully written to the audit log.

- [ ] **Audit Integration:**
  - [ ] Provenance Stamp entries are written to the same immutable audit log as other compliance events.
  - [ ] Log entries are tamper-evident.

## 5. Confirmation

- [ ] Verification that v1 signed-off controls are not inadvertently bypassed by the new path.
