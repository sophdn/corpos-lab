# Data-Export v2 Compliance Checklist

**Release:** data-export-v2
**Status:** Pending Sign-off
**Reviewer:** Compliance Officer
**Date:** [Current Date]

## 1. Context & Scope
- [x] **v1 Sign-off Status:** The Q1 2025 v1 sign-off is recorded as historical context only. It is **not** treated as sufficient evidence for v2 compliance.
- [x] **Change Analysis:** v2 introduces a new partner-portal export pathway (`POST /v2/data-export/request`). While the compliance team noted that data scope, access controls, and retention policies are unchanged from v1, the addition of a new external integration surface constitutes a material change requiring independent verification against current policy.
- [x] **Applicable Policy:** Compliance Office Q4 2025 Bulletin (Effective 2025-11-01).

## 2. Access Control & Authentication
- [x] **v1 Controls:** Retained. CLI access controls remain unchanged from v1.
- [x] **v2 Partner Authentication:** Verified that partner-portal requests authenticate via OAuth scope.
- [x] **Authorization Validation:** Verified that the system only permits exports for users who have granted an active authorization to the requesting party.

## 3. Audit Logging & Provenance
- [x] **v1 Audit Logs:** Existing v1 audit logging controls apply to the retained CLI surface.
- [ ] **NEW: Partner-Initiated Provenance Stamp:** 
    - **Requirement:** Per Q4 2025 Bulletin ("Data Export Process Update — Partner Integrations"), any deployment adding a partner-initiated export pathway must record an additional audit entry (Provenance Stamp).
    - **Data Elements:** The stamp must capture:
        1. User’s authorization grant ID
        2. Requesting party’s identity
        3. Authorization scope
        4. Validity window at time of export
    - **Technical Implementation:**
        - [ ] Written **synchronously** during the export request processing.
        - [ ] **Fails closed**: If the Provenance Stamp cannot be assembled, the export request must be rejected.
    - **Verification:** Code review and test evidence must confirm that the `POST /v2/data-export/request` handler enforces this synchronous, fail-closed behavior before any data is transferred.

## 4. Data Handling & Retention
- [x] **Data Scope:** Confirmed unchanged from v1.
- [x] **Retention Policies:** Confirmed unchanged from v1.
- [x] **Partner Data Lifecycle:** Verified that partner-initiated exports adhere to the same retention and deletion policies as v1 internal exports.

## 5. Compliance Confirmation
- [ ] **Provenance Stamp Implementation Verified:** Engineering has provided evidence that the Provenance Stamp logic is implemented synchronously and fails closed for all partner-initiated exports.
- [ ] **No Material Uncontrolled Changes:** Confirmed that the "unchanged from v1" assessment does not overlook the new compliance requirements introduced in the Q4 2025 Bulletin.
