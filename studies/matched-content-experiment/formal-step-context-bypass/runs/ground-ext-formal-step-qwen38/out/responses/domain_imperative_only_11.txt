# Compliance Checklist: Data Export v2

**Release:** Data Export v2
**Deployment Date:** Friday (Pre-deployment confirmation)
**Status:** **ACTION REQUIRED / PENDING REVIEW**
**Compliance Officer Note:** This checklist is generated based on the v2 specification and the 2025-Q4 Compliance Bulletin. The v1 sign-off is **not** carried over as sufficient. The v1 "unchanged from v1" summary is disregarded because the v2 spec introduces a new partner-portal pathway that triggers mandatory Q4 2025 controls which were not present in v1.

## Action Items for Deployment Block

1.  **Implement Provenance Stamp:** Engineering must add logic to the `POST /v2/data-export/request` endpoint to synchronously generate and write the Provenance Stamp containing:
    *   User Authorization Grant ID
    *   Requesting Party Identity (Partner)
    *   Authorization Scope
    *   Validity Window
2.  **Implement Fail-Closed Logic:** Ensure that if the Provenance Stamp cannot be written (e.g., database error, timeout), the export request is immediately rejected with a 500/403 error. It must **not** proceed with the export.
3.  **Update Spec:** The `spec.md` must be updated to explicitly document the Provenance Stamp mechanism to satisfy the Q4 Bulletin.
4.  **Re-Review:** Compliance will re-review the checklist once the above items are evidenced in the codebase and test results.

**Conclusion:** The v2 release is **NOT** compliant with the 2025-Q4 Bulletin. The v1 sign-off is invalid for the new partner pathway. Deployment should be blocked until the Provenance Stamp controls are implemented and verified.
