# Data Export v2 — Compliance Checklist

**Release:** data-export-v2
**Deployment Date:** Friday (Pre-deployment)
**Status:** **PENDING** — New control required for Partner Portal pathway.

## 1. Scope & Access Controls
- [x] **Verify Data Scope Unchanged:** Confirmed via v2 spec that data scope, access controls, and retention policies are unchanged from v1.
- [x] **Verify CLI Surface:** Confirmed v1 CLI surface remains unchanged.
- [ ] **Verify Partner-Portal Authentication:** Verify that the new `POST /v2/data-export/request` endpoint enforces OAuth scope validation for partners.
- [ ] **Verify Authorization Check:** Verify that the system validates the existence of an *active* user authorization grant for the specific user ID requested before processing the export.

## 2. Audit Logging
- [x] **Verify v1 Audit Logging:** Confirmed that v1 audit logging controls (pathway-agnostic) remain applicable to the CLI pathway.
- [ ] **PROVENANCE STAMP (NEW CONTROL REQUIRED):** Per `policy/bulletins/2025-Q4-bulletin.md` (effective 2025-11-01), the partner-initiated export pathway must record a **Provenance Stamp**. This entry must capture:
    1.  The user's authorization grant ID.
    2.  The requesting party's identity (partner ID).
    3.  The authorization scope.
    4.  The validity window at the time of export.
- [ ] **Synchronous Write Verification:** Confirm that the Provenance Stamp is written **synchronously** to the audit log.
- [ ] **Fail-Closed Verification:** Confirm that if the Provenance Stamp cannot be assembled (missing data, logging failure), the export request **fails closed** (is rejected) rather than proceeding without the audit record.

## 3. Data Retention
- [x] **Verify Retention Policy:** Confirmed that v2 retention policies are unchanged from v1.

---

**Note to Team:**
The v1 sign-off does not carry over to v2. While data scope and retention are unchanged, the introduction of the partner-portal pathway triggers the Q4 2025 Compliance Bulletin requirement for a **Provenance Stamp**. This control was not present in v1 and is not covered by the v1 checklist. The v2 deployment is **not compliant** until the synchronous, fail-closed Provenance Stamp logging is implemented and verified for the `POST /v2/data-export/request` endpoint.
