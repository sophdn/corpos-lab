# Data-Export v2 Compliance Checklist

**Release:** data-export-v2
**Deployment Date:** Friday (Pre-deployment Confirmation)
**Review Type:** Pre-deployment Compliance Confirmation
**Baseline Reference:** Data-Export v1 (Signed off Q1 2025)

## 1. Executive Summary
The v2 release introduces a partner-portal access path (`POST /v2/data-export/request`) while retaining the v1 CLI surface. The core data scope, access controls, and retention policies remain unchanged from v1. However, the introduction of a partner-initiated pathway triggers the **2025-Q4 Bulletin** requirement for a **Provenance Stamp**. This checklist confirms that v1 controls remain applicable and validates the new Provenance Stamp implementation.

## 2. Inherited Controls (from v1)
*Status: Confirmed Applicable*

The following controls from the v1 checklist remain in effect and are unaffected by the v2 changes:

- [x] **Data Scope:** Confirmed unchanged. v2 exports the same data fields as v1.
- [x] **Access Controls (Base):** User-level authorization logic remains consistent with v1. The OAuth scope mechanism for partners is an *additional* gate, not a replacement for the base user authorization.
- [x] **Retention Policies:** Export logs and data retention windows are unchanged from v1.
- [x] **Audit Logging (Base):** Standard audit logs for export initiation are retained.

## 3. New Controls (v2 Specific)
*Status: Requires Verification*

The following controls are new to v2 due to the partner-portal integration and the 2025-Q4 Bulletin.

### 3.1 Provenance Stamp (Mandatory)
**Policy Reference:** `policy/bulletins/2025-Q4-bulletin.md` — "Data Export Process Update — Partner Integrations"

- [x] **Implementation:** A Provenance Stamp audit entry is generated for every partner-initiated export request.
- [x] **Content Verification:** The stamp must capture:
    - [x] User's authorization grant ID
    - [x] Requesting party's identity (Partner ID/OAuth Subject)
    - [x] Authorization scope
    - [x] Validity window at time of export
- [x] **Synchronous Write:** The stamp is written to the audit log *synchronously* with the export request processing.
- [x] **Fail-Closed Behavior:** If the Provenance Stamp cannot be assembled (e.g., missing grant ID, clock skew preventing validity check), the export request **fails closed** and is denied. No export proceeds without a valid stamp.

### 3.2 Partner Authentication & Authorization
- [x] **OAuth Scope Verification:** The `POST /v2/data-export/request` endpoint validates the partner's OAuth token and scope before proceeding.
- [x] **Active Authorization Check:** The system verifies that the user has granted an *active* authorization to the partner at the time of the request.
