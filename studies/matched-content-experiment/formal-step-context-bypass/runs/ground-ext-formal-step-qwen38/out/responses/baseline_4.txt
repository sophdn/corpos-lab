# Data Export v2 Compliance Checklist

**Status:** Ready for Sign-off
**Review Type:** Pre-deployment Confirmation (v1 baseline + v2 delta)
**Date:** Q4 2025
**Reviewer:** Compliance Officer

## 1. Context & Scope
*   **Base Release:** Data Export v1 (Signed off Q1 2025).
*   **Current Release:** Data Export v2.
*   **Change Summary:** v2 adds an HTTP endpoint (`POST /v2/data-export/request`) for partner-portal integration. The v1 CLI surface remains unchanged. Data scope, access controls, and retention policies are confirmed unchanged from v1.
*   **New Regulatory Trigger:** Compliance Office Q4 2025 Bulletin (Effective 2025-11-01) requires a **Provenance Stamp** for all partner-initiated export pathways.

## 2. Data Scope & Retention
*   **Status:** ✅ Confirmed Unchanged
*   **Verification:** Spec review confirms v2 utilizes the exact same data fields and retention schedules as v1. No new PII types are introduced by the partner portal path.
*   **Action:** N/A. v1 controls remain fully applicable.

## 3. Access Controls & Authentication
*   **v1 Controls (CLI):** ✅ Confirmed Unchanged
    *   Existing internal service account and user token validation logic remains intact for the CLI pathway.
*   **v2 Controls (Partner Portal):** ✅ New Control Implemented
    *   **Authentication:** Partners authenticate via OAuth scopes.
    *   **Authorization:** Exports are restricted to users who have granted an active authorization to the specific partner.
    *   **Verification:** Spec confirms that the endpoint rejects requests if the OAuth scope does not include `export:read` or if the user authorization grant is not active/valid at the time of the request.

## 4. Audit Logging & Provenance
*   **v1 Standard Logging:** ✅ Confirmed Unchanged
    *   Standard audit logs for data access and export completion continue to function as per v1 specification.
*   **v2 Provenance Stamp (New Requirement):** ✅ Implemented
    *   **Requirement Source:** `policy/bulletins/2025-Q4-bulletin.md` ("Data Export Process Update — Partner Integrations").
    *   **Implementation Details:**
        *   A synchronous audit entry is generated for every partner-initiated export.
        *   **Captured Fields:**
            1.  User's authorization grant ID.
            2.  Requesting party's identity (Partner ID).
            3.  Authorization scope.
            4.  Validity window of the authorization at the time of export.
    *   **Failure Mode:** Verified to be **Fail-Closed**. If the Provenance Stamp cannot be assembled (e.g., missing grant ID or invalid scope data), the export request is rejected immediately. No data is released.
    *   **Verification:** Code review confirms the stamp generation occurs synchronously within the request lifecycle, prior to data serialization.

## 5. Security & Infrastructure
*   **Status:** ✅ Confirmed Unchanged
*   **Verification:** The new HTTP endpoint utilizes the same TLS termination and network segmentation as other v2 API services. No new infrastructure components (e.g., separate databases or queues) are introduced; the endpoint leverages existing v1 backend services.
