# Compliance Confirmation: Data Export v2

**Status:** FAIL / BLOCKED
**Action Required:** Deployment halted. Immediate remediation required.

## Reason for Failure
The v2 release adds a partner-portal export pathway (`POST /v2/data-export/request`). The Q4 2025 Compliance Bulletin (effective 2025-11-01) mandates a **Provenance Stamp** for any partner-initiated export pathway. The current v2 checklist and specification do not include this control.

The v1 sign-off is **not** sufficient for v2. While v1 access controls are pathway-agnostic, the v2 spec introduces a new authentication context (OAuth scopes for partners) and a new export trigger (partner request). The "unchanged from v1" summary is incorrect regarding compliance requirements because the Q4 Bulletin introduces a new mandatory control specific to partner integrations that did not exist or apply to the v1 CLI surface in the same manner.

## Missing Control: Provenance Stamp
**Requirement Source:** `policy/bulletins/2025-Q4-bulletin.md` — "Data Export Process Update — Partner Integrations"

**Mandatory Audit Entry Fields:**
1. User’s authorization grant ID
2. Requesting party’s identity
3. Authorization scope
4. Validity window at time of export

**Technical Requirements:**
- Must be written **synchronously** during the export request handling.
- Must **fail closed** if the stamp cannot be assembled. (i.e., if any field is missing or invalid, the export request must be rejected and no data exported.)
