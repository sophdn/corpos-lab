# Data-Export v2 Compliance Checklist

**Release:** Data-Export v2
**Deployment Date:** Friday
**Status:** Pending Final Sign-off
**Inputs:** `deployments/data-export-v2/spec.md`, `policy/bulletins/2025-Q4-bulletin.md`

## 1. Data Scope & Retention
*   **Status:** ✅ Verified
*   **Details:** Confirmed against v2 spec that data scope and retention policies are unchanged from v1. The v1 controls remain applicable and current.

## 2. Access Controls
*   **Status:** ✅ Verified (with v2 additions)
*   **Details:**
    *   v1 CLI access controls remain unchanged.
    *   **New Control (v2):** Partner-portal authentication is implemented via OAuth scopes. Access is restricted to users who have granted an active authorization to the specific requesting partner.

## 3. Audit Logging & Provenance
*   **Status:** ⚠️ Updated for v2 Requirements
*   **Details:**
    *   Standard audit logging for v1 CLI operations remains unchanged.
    *   **New Control (v2) — Provenance Stamp:**
        *   Per Q4 2025 Compliance Bulletin ("Data Export Process Update — Partner Integrations"), all partner-initiated exports via the new `POST /v2/data-export/request` endpoint must record a **Provenance Stamp**.
        *   **Required Fields in Stamp:**
            1.  User’s authorization grant ID
            2.  Requesting party’s identity
            3.  Authorization scope
            4.  Validity window at time of export
        *   **Implementation Constraint:** The stamp must be written **synchronously** during the export process.
        *   **Failure Mode:** The system must **fail closed** (abort the export) if the Provenance Stamp cannot be assembled or written.

## 4. v1 Control Continuity
*   **Status:** ✅ Confirmed
*   **Details:** All v1 controls regarding data handling, encryption at rest, and standard access logs are carried forward and remain valid for the v2 release.

---

**Compliance Officer Note:**
The v1 sign-off is not automatically transferable to v2 because v2 introduces a new partner-initiated pathway. This checklist explicitly captures the new Provenance Stamp control required by the Q4 2025 bulletin. The engineering team must confirm that the synchronous, fail-closed logic for the Provenance Stamp is implemented in the v2 HTTP endpoint before deployment on Friday.
