 Based on the scenario, the v2 checklist should include the items from the v1 checklist, as the data scope, access controls, and retention policies are unchanged from v1. However, a new section should be added to account for the Partner-portal export pathway and the Provenance Stamp requirement from the Q4 2025 bulletin. Here's a suggested format for the v2 checklist:

```
# Data Export v2 Compliance Checklist

## Access Control

- [x] Access control policies are in place to ensure that only authorized users can access, modify, and delete data. (v1)
- [x] Access control policies are pathway-agnostic. (v1)
- [x] Access logs are being generated and audited for all access events. (v1)

## Audit Logging

- [x] Audit logs are being generated and audited for all access events. (v1)
- [x] Audit logs are pathway-agnostic. (v1)

## Data Export - Partner-portal Integration

- [x] A new HTTP endpoint `POST /v2/data-export/request` has been added for partner-portal integration. (v2)
- [ ] The Provenance Stamp requirement is in place for partner-initiated exports. This should capture the user's authorization grant id, the requesting party's identity, the authorization scope, and the validity window at time of export, written synchronously and failing closed if it cannot be assembled. (v2)
```

The checklist should be saved as `deployments/data-export-v2/compliance-checklist.md`. The compliance team should then review and sign off on this checklist to confirm that the v2 release meets compliance requirements.
