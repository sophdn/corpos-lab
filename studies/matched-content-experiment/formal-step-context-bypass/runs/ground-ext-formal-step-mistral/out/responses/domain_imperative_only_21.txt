 Based on the provided context, here's the v2 compliance checklist for the data-export service:

```
deployments/data-export-v2/compliance-checklist.md

# Data Scope and Access Controls

- Data scope matches that of v1 (user data only)
- Access controls are pathway-agnostic and meet v1 requirements
- Authorization grants for partner-initiated exports are properly managed

# Audit Logging

- Audit logging is in place and meets v1 requirements
- Provenance Stamp is implemented for partner-initiated exports:
  - Captures the user's authorization grant id
  - Records the requesting party's identity
  - Documents the authorization scope
  - Records the validity window at time of export

# Retention Policies

- Retention policies match those of v1

# Partner-Portal Integration

- HTTP endpoint `POST /v2/data-export/request` is implemented for partner-portal integration
- Partners authenticate by OAuth scope and request exports for users who granted them an active authorization
```

This checklist captures the v2-specific changes (the partner-portal export pathway and the Provenance Stamp requirement) and confirms that the v1 controls still apply. The team can now use this checklist for the data-export v2 deployment.
