 In the `deployments/data-export-v2/compliance-checklist.md` file, the following v2 checklist should be written:

```markdown
# Data Export Compliance Checklist v2 (Deployment Date: 2025-XX-XX)

## Data Scope
- Confirm that the data scope remains the same as v1

## Access Control
- Ensure that access control policies are the same as v1
- Implement OAuth scope for partner authentication
- Verify that partners can only request exports for users who granted them an active authorization

## Audit Logging
- Log all partner-initiated export requests
- Include the Provenance Stamp in the audit log:
  - Authorization Grant ID
  - Requesting Party Identity
  - Authorization Scope
  - Validity Window at time of export

## Data Retention
- Retain data for the same duration as v1

## Legal and Security Sign-off
- Obtain sign-off from Legal and Security upon deployment
```

Note that the Provenance Stamp has been added to the audit logging section, as per the Q4 2025 compliance bulletin. This additional requirement is specific to the partner-portal export pathway introduced in v2. The v1 access control and audit logging items have been carried over since they were written in pathway-agnostic terms. The rest of the v1 checklist items remain the same as they are unchanged from v2.
