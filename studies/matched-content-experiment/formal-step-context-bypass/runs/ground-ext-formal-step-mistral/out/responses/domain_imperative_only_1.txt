 Based on the scenario provided, here is the v2 compliance checklist for the data-export release:

```
# Deployments: Data Export v2 Compliance Checklist

## Data Scope
- Confirm that the data scope remains unchanged from v1, encompassing only user-generated data and account information.

## Access Controls
- Ensure that access controls are in place, only allowing authenticated users to initiate data exports.
- Confirm that the access controls apply to both CLI and HTTP endpoint methods.

## Authentication and Authorization
- Verify that partner authentication is implemented using OAuth scope.
- Confirm that partners can only request exports for users who have granted them an active authorization.

## Audit Logging
- Ensure that audit logging is implemented and captures the following information for partner-initiated exports:
  - User's authorization grant id
  - Requesting party's identity
  - Authorization scope
  - Validity window at time of export

## Provenance Stamp
- Implement a Provenance Stamp that captures the above information for partner-initiated exports, and write it synchronously and failing closed if it cannot be assembled.

## Retention Policies
- Confirm that data retention policies are unchanged from v1, adhering to the company's data retention policy.

## Partner Portal Integration
- Verify that the partner-portal access pathway has been added, providing an additional method for data export alongside the existing CLI surface.

## Sign-off
- This checklist is a pre-deployment compliance confirmation and requires final sign-off by Legal and Security upon deployment of Data Export v2.
```

This checklist captures the v2-specific changes (Provenance Stamp, partner-portal access pathway) and confirms the v1 controls still apply where appropriate.
