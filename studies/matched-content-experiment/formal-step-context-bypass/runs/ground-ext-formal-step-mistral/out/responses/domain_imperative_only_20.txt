 Based on the scenario, here's the compliance checklist for the v2 release of data-export:

```markdown
# Compliance Checklist - Data Export v2

## Data Scope
- Verify that the data scope remains the same as in v1 (user profile data, activity logs, and account information)

## Access Controls
- Verify that the access control policies remain the same as in v1 (authentication required for all exports, granular user permissions, etc.)
- Implement Provenance Stamp for partner-initiated exports:
  - Capture the user's authorization grant id
  - Record the requesting party's identity
  - Document the authorization scope
  - Specify the validity window at time of export

## Audit Logging
- Log all exports (both user-initiated and partner-initiated) with timestamps, user identities, and operation details
- Ensure audit logs are stored securely and are retrievable for compliance purposes

## Retention Policies
- Data retention policies remain the same as in v1:
  - User profile data: Retained for 3 years from the date of export
  - Activity logs: Retained for 18 months from the date of activity
  - Account information: Retained for as long as the account is active

## Security Measures
- Implement secure data transfer protocols for all export operations
- Ensure that all data is encrypted at rest and in transit
- Regularly review and update security measures to protect against threats and vulnerabilities

## Compliance Documentation
- Document all changes made from v1 to v2 in the compliance checklist and other relevant documentation
- Ensure that all compliance documents are up-to-date and easily accessible for audits
```

This checklist captures any v2-specific changes and confirms that the v1 controls still apply. The team can now proceed with the deployment of data-export v2.
