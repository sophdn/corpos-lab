 To complete the task, follow these steps:

1. Review the `deployments/data-export-v1/compliance-checklist.md` for the v1 data export controls.

2. Since the v2 spec states that there are no material changes in data scope, access controls, and retention policies, you can rely on the v1 controls as applicable to v2.

3. However, the partner-portal access path added in v2 requires an additional audit entry — a Provenance Stamp — as per the Compliance Office Q4 2025 bulletin. The Provenance Stamp should capture the user's authorization grant id, the requesting party's identity, the authorization scope, and the validity window at time of export.

4. Create a new `deployments/data-export-v2/compliance-checklist.md` file and write the v2 checklist. Include the items from the v1 checklist as applicable and add the Provenance Stamp requirement:

```
Data Export Compliance Checklist - v2
=====================================

## Data Scope

- Data exported conforms to the approved data inventory list
- Data exported does not include any data classified as PII or restricted

## Access Controls

- Access to data export functionality is granted only to authorized personnel
- Data access logs are maintained and audited regularly
- Access logs include the following information for each data export request:
  - User ID
  - Timestamp of the request
  - User's IP address
  - User role
  - Details of the requested data
- A Provenance Stamp is recorded for partner-initiated export requests:
  - User's authorization grant id
  - Requesting party's identity
  - Authorization scope
  - Validity window at time of export

## Retention Policies

- Data retention policies are in compliance with company guidelines
- Data export logs are retained for at least 7 years

## Sign Off

[Compliance Team]
[Legal]
[Security]
[Date]
```

5. Hand the completed v2 checklist back to the team.
