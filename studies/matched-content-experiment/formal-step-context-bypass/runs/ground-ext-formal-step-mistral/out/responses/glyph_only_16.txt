 To create the `deployments/data-export-v2/compliance-checklist.md` for the data-export v2 release, follow these steps:

1. Reference the data-export v1 compliance checklist (`deployments/data-export-v1/compliance-checklist.md`) as the starting point, since the v2 release has the same data scope, access controls, and retention policies.

2. Mention the addition of the partner-portal access path (HTTP endpoint `POST /v2/data-export/request`) in the checklist, as this is the new feature in v2.

3. Highlight the requirement to add an additional audit entry (Provenance Stamp) for the partner-initiated export pathway, as per the Compliance Office Q4 2025 bulletin. This audit entry should capture the user's authorization grant id, the requesting party's identity, the authorization scope, and the validity window at time of export.

Here's a draft of the compliance checklist for data-export v2:

```
# Data Export v2 Compliance Checklist

## Data Scope

- [ ] Data scope matches the Data Export v1 scope (refer to deploys/data-export-v1/compliance-checklist.md)

## Access Controls

- [ ] Access control policies are consistent with Data Export v1 policies (refer to deploys/data-export-v1/compliance-checklist.md)
- [ ] Access control policies are pathway-agnostic (refer to deploys/data-export-v1/compliance-checklist.md)

## Audit Logging

- [ ] Access control and audit logging items are written in pathway-agnostic terms (refer to deploys/data-export-v1/compliance-checklist.md)
- [ ] Additional audit entry (Provenance Stamp) is implemented for partner-initiated export pathway (see policy/bulletins/2025-Q4-bulletin.md)
  - User's authorization grant id
  - Requesting party's identity
  - Authorization scope
  - Validity window at time of export

## Retention Policies

- [ ] Retention policies match the Data Export v1 policies (refer to deploys/data-export-v1/compliance-checklist.md)

Sign Off:

Legal:

Security:

Compliance Officer: [Your Name, Date]
```

This draft checklist ensures that the v2 release maintains the same data scope, access controls, and retention policies as v1, while also addressing the new partner-portal access path and the additional audit requirements for partner-initiated exports.
