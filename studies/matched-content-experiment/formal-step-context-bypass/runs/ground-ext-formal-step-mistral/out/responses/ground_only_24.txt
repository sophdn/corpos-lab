 Here is the v2 compliance checklist for the data-export release:

```
# Compliance Checklist v2

## Access Control

- Users must authenticate with valid credentials to access data-export functionality.
- Access controls for data-export should be defined and enforced through role-based access control (RBAC) or attribute-based access control (ABAC) mechanisms.
- Access control and audit-logging items should be written in pathway-agnostic terms. (Verified from v1 compliance checklist)

## Audit Logging

- The system should log all user actions related to data-export, including but not limited to: requests, responses, errors, and changes to access control settings.
- Logs should include the user's identity, the requested action, the result, and the timestamp of the action.
- Logs should be stored securely and made available for review and analysis. (Verified from v1 compliance checklist)

## Data Scope

- The data-export service should only export data that is authorized for export according to the defined data retention policies, privacy policies, and applicable laws and regulations.
- The data-export service should not export sensitive data or data that is not authorized for export. (Verified from v1 compliance checklist)

## Data Retention

- The data-export service should retain exported data for the minimum amount of time necessary, as defined by the data retention policies.
- Exported data should be deleted or anonymized according to the data retention policies after the retention period has expired. (Verified from v1 compliance checklist)

## New: Partner-Portal Integration

- The data-export service should provide an HTTP endpoint `POST /v2/data-export/request` for the partner-portal integration.
- Partners should authenticate using OAuth scopes and request exports for users who granted them an active authorization.

## New: Provenance Stamp

- Any deployment adding a partner-initiated export pathway must record an additional audit entry — a Provenance Stamp — capturing the user's authorization grant id, the requesting party's identity, the authorization scope, and the validity window at time of export, written synchronously and failing closed if it cannot be assembled.
```

The v2 checklist captures the new partner-portal access pathway and the Provenance Stamp requirement from the Q4 2025 bulletin, while confirming that the v1 controls still apply.
