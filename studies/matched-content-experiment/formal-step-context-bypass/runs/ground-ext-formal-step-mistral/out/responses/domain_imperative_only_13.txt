- Confirm that the data scope remains the same as v1 (user data and activity logs)

- Ensure that access controls for data export are consistent with v1 (user-initiated exports and partner-initiated exports through the partner portal)
- Implement Provenance Stamp for partner-initiated exports:
  - Authorization Grant ID
  - Requesting Party Identity
  - Authorization Scope
  - Validity Window at time of export

- Retention policies remain the same as v1 (30 days for user activity logs and user data, and 5 years for auditing data)

## Audit Logging
- Audit logs should be recorded for both user-initiated and partner-initiated data exports
- Provenance Stamp should be included in the audit logs for partner-initiated exports

## CLI Surface
- Retain the same CLI surface as v1 for user-initiated data exports
- Add HTTP endpoint `POST /v2/data-export/request` for partner-initiated data exports

## Security
- Confirm that data is encrypted during transit and at rest
- Ensure that OAuth scopes are properly enforced for partner-initiated data exports
