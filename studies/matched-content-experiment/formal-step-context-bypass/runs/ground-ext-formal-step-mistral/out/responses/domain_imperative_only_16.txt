 Here is the v2 compliance checklist for the data-export service:

```markdown
# Compliance Checklist for Data Export v2

## Data Scope
- Confirm that the data scope remains the same as in v1 (users' data only, excluding sensitive information)

## Access Controls
- Confirm that access controls remain the same as in v1:
  - Access to the CLI and HTTP endpoints requires user authentication and authorization.
  - Access to user data is granted only to the user themselves or authorized personnel.

## Partner-Portal Integration
- Verify that the partner-portal integration has been implemented as follows:
  - Partners authenticate using OAuth scopes.
  - Partners can request exports for users who have granted them active authorization.

## Provenance Stamp
- Implement the Provenance Stamp for partner-initiated exports as required by the Q4 2025 bulletin:
  - Record the user's authorization grant ID.
  - Record the identity of the requesting party.
  - Record the authorization scope.
  - Record the validity window at the time of export.
  - Ensure the Provenance Stamp is written synchronously and fails closed if it cannot be assembled.

## Audit Logging
- Ensure audit logs are pathway-agnostic, capturing all data export requests (both from users and partners).

## Data Retention
- Confirm that data retention policies remain the same as in v1:
  - Logs and audit trails are stored for a minimum of 7 years.
  - User data is deleted after 90 days of inactivity.
```

This checklist captures the v2-specific changes and confirms that the v1 controls still apply. The checklist has been saved at `deployments/data-export-v2/compliance-checklist.md`.
