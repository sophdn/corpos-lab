### 1. Defect Analysis
*   **Ticket:** DEF-2026-04-1047
*   **Current Behavior:** `config-validator --service auth` returns exit code `0` (success) when `auth_service_url` is malformed.
*   **Root Cause:** `validate_url_field()` in `config/validator.py` only checks for presence and non-empty string. It lacks structural validation.
*   **Expected Behavior:** Exit code `1` (failure) for malformed URLs; Exit code `0` (success) for valid URLs.

### 2. Proposed Code Fix

The function `validate_url_field()` needs to be updated to parse the URL and verify its structure. Python's `urllib.parse` module is the standard library tool for this.

**File:** `config/validator.py`

**Before (Hypothetical Current Implementation):**
```python

    if not value:
        raise ValueError(f"Field '{field_name}' is required and cannot be empty.")
    # Missing structural validation
    return True
```

**After (Proposed Fix):**
```python
import urllib.parse

def validate_url_field(field_name, value):
    if not value:
        raise ValueError(f"Field '{field_name}' is required and cannot be empty.")
    
    # Validate URL structure
    try:
        parsed = urllib.parse.urlparse(value)
        # A valid URL for a service endpoint should have a scheme (http/https) and a netloc (host)
        if parsed.scheme not in ('http', 'https'):
            raise ValueError(f"Invalid scheme. Must be http or https. Got: {parsed.scheme}")
        if not parsed.netloc:
            raise ValueError("Missing host/netloc in URL.")
    except Exception as e:
        raise ValueError(f"Malformed URL structure for '{field_name}': {str(e)}")
    
    return True
```
