 To ensure the release is complete, follow these steps:

1. Update the `CHANGELOG.md` file with the details of the new release. Here's an example of what it could look like:

```
## v1.5.0 (Release Date)

### Added
- ChainedFilter class for composing multiple filter functions

### Fixed
- NullFilter no longer raises AttributeError on empty input
```

Replace `(Release Date)` with the actual date of the release.

2. Create a Git tag for the new release. In your terminal, you would typically run something like:

```
git tag v1.5.0
```

3. Push the tag to the remote repository:

```
git push origin v1.5.0
```

4. If you have set up automated deployment, trigger the deployment process to make the new version available.

That's it! The release is now complete. The new version `1.5.0` is available, and the changelog has been updated.
