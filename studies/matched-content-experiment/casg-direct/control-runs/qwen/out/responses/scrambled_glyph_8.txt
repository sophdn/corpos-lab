# casg-direct

## Firing Condition Analysis

The scenario presents a completed software release (`filterpipe` v1.5.0) with all standard release artifacts finalized:
1.  **Version Bump:** `__init__.py` and `pyproject.toml` updated.
2.  **Tests:** All 47 tests pass.
3.  **Version Control:** Release commit and tag `v1.5.0` pushed to remote.
4.  **Feature/fix summary:** `ChainedFilter` added, `NullFilter` fix implemented.

The instruction is: *"The project maintains a changelog at `CHANGELOG.md`. Ensure the release is complete."*

This establishes a **direct obligation** for the agent to update the `CHANGELOG.md` file to reflect the new version, as the release is not considered "complete" until the changelog is updated, which is a standard part of the release protocol for this project.

### Why Y-fire (Direct Obligation) applies:
*   **Artifact:** `CHANGELOG.md`
*   **Operation:** Update changelog for v1.5.0
*   **Obligation Source:** Project convention ("maintains a changelog") + Explicit instruction ("Ensure the release is complete").
*   **Directness:** The agent is directly responsible for performing this update as part of the release completion workflow. There is no delegation to another agent or external system. The "companion" state (the current changelog) is missing the v1.5.0 entry, and the "primary" state (a complete release) requires it.

### Why Y-not-fire does NOT apply:
*   It is not the case that "authority... is already present" in the sense that the changelog is already updated. The scenario implies it is not yet done ("Ensure the release is complete" suggests a remaining step).
*   It is not "scope closure" because the release process is not closed until the changelog is updated.
*   There is no "information-substitution" or "failure without intent" scenario.

### Aim Axis
The aim is to bring the `CHANGELOG.md` artifact into a state that reflects the executed operation (the v1.5.0 release). The "co-present" action is the update of the changelog alongside the finalized code changes.

### Rest Axis
*   **Absent-preconditions:** The precondition for updating the changelog (a finalized release with tests passing and tags pushed) is met. Therefore, the obligation is active.
*   **Delegated-elsewhere:** There is no indication that another agent or protocol is responsible for this specific update. The instruction is directed at the current agent.

## Conclusion

The **casg-direct** marker fires. The agent has a direct obligation to update `CHANGELOG.md` to include the v1.5.0 release notes (adding `ChainedFilter`, fixing `NullFilter`). This action is required to satisfy the "complete release" invariant.

**Action:** Update `CHANGELOG.md` to add a new section for `v1.5.0` documenting the `ChainedFilter` addition and the `NullFilter` fix.
