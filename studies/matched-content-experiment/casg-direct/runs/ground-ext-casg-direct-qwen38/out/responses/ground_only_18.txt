## Changelog Entry for v1.5.0

To make the release complete as a record, `CHANGELOG.md` needs a new entry for v1.5.0 placed above the previous version entries. Based on the Keep a Changelog format and the described changes:

```markdown
## [1.5.0] - 2024-XX-XX

### Added
- `ChainedFilter` class for composing multiple filter functions

### Fixed
- `NullFilter` raising `AttributeError` on empty input
```

### Explanation

The release is complete as **code** (version bumped, tests pass, commit pushed, tag pushed), but it is **incomplete as a record** because `CHANGELOG.md` does not yet reflect the v1.5.0 changes. Per the project's convention, a release is only fully complete when the changelog entry exists.

The entry above:
- Uses the correct version heading format `[1.5.0]`
- Places `ChainedFilter` under **Added** (new feature)
- Places the `NullFilter` fix under **Fixed** (bug fix)
- Should be inserted **above** all existing version entries in `CHANGELOG.md`
- The date (`2024-XX-XX`) should be replaced with the actual release date

Once this entry is added to `CHANGELOG.md`, the release will be complete both as code and as a record.
