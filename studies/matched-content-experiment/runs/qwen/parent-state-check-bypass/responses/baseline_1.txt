### Root Cause Analysis
The function `validate_url_field()` in `config/validator.py` currently only checks:
1.  Field presence.
2.  Non-empty value.

It fails to validate URL structure, causing malformed URLs (e.g., `not-a-url`, `http://`, `://bad`) to pass validation, resulting in exit code `0`.

### Proposed Fix
We need to add URL structure validation to `validate_url_field()`. Python's `urllib.parse` is the standard library approach for this. We will ensure the URL has a valid scheme (like `http` or `https`) and a valid netloc (host).

Here is the code change to apply to `config/validator.py`:

```python
import urllib.parse

def validate_url_field(field_name, value):
    """
    Validates that a URL field is present, non-empty, and structurally valid.
    """
    if not value:
        return False, f"Field '{field_name}' must be non-empty."
    
    try:
        result = urllib.parse.urlparse(value)
        
        # Check for valid scheme (http, https, etc.)
        if result.scheme not in ('http', 'https'):
            return False, f"Field '{field_name}' must use a valid scheme (http or https). Got: {result.scheme}"
        
        # Check for valid netloc (host)
        if not result.netloc:
            return False, f"Field '{field_name}' must include a valid host."
            
    except ValueError as e:
        return False, f"Field '{field_name}' is malformed: {e}"
        
    return True, "OK"
```
