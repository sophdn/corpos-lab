# Compliance Checklist: data-export v2

**Status:** Approved for Deployment
**Date:** Q4 2025 (Pre-deployment Confirmation)
**Reviewer:** Compliance Officer
**Reference:** `policy/bulletins/2025-Q4-bulletin.md` (Effective 2025-11-01)

## 1. Executive Summary

This document confirms the compliance status of the **data-export v2** release. As per the pre-deployment confirmation scope, this review validates that v2 introduces no material changes to the data scope, access controls, or retention policies established in v1 (signed off Q1 2025).

The primary change in v2 is the addition of an HTTP endpoint (`POST /v2/data-export/request`) for partner-portal integration. This introduces a **partner-initiated export pathway**. Consequently, this release is subject to the **Q4 2025 Compliance Bulletin** requirement for **Provenance Stamps** on partner-initiated exports.

All v1 controls remain applicable and verified. The new Provenance Stamp requirement has been integrated into the checklist below.

## 2. Compliance Checklist

### 2.1. Data Scope & Retention
| Item | Status | Notes |
|------|--------|-------|
| **DS-01**: Data scope unchanged from v1 | ✅ **Confirmed** | v2 spec confirms identical data fields and scope as v1. No new sensitive data types added. |
| **DS-02**: Retention policy unchanged from v1 | ✅ **Confirmed** | v2 spec confirms identical retention windows and deletion mechanisms as v1. |

### 2.2. Access Control & Authentication
| Item | Status | Notes |
|------|--------|-------|
| **AC-01**: User authentication (v1 CLI surface) | ✅ **Confirmed** | v1 CLI authentication mechanisms remain unchanged and in effect. |
| **AC-02**: Partner authentication (v2 New) | ✅ **Confirmed** | Partners authenticate via OAuth scope. Implementation aligns with standard OAuth 2.0 security baselines. |
| **AC-03**: User authorization check (v2 New) | ✅ **Confirmed** | Export requests are only processed if the target user has granted an **active authorization** to the requesting partner. Authorization status is verified at request time. |
| **AC-04**: Pathway-agnostic access controls | ✅ **Confirmed** | v1 checklist items regarding access controls are written in pathway-agnostic terms and apply fully to the new HTTP endpoint. |

### 2.3. Audit Logging & Provenance
| Item | Status | Notes |
|------|--------|-------|
| **AL-01**: Standard audit logging (v1) | ✅ **Confirmed** | All v1 audit log items (user ID, timestamp, data scope, export destination) are unchanged and apply to all export paths, including the new partner-portal path. |
| **AL-02**: Provenance Stamp (v2 New – Q4 2025 Bulletin) | ✅ **Implemented** | **Required for partner-initiated exports.** The system must record a Provenance Stamp capturing: <br>1. User’s authorization grant ID <br>2. Requesting party’s identity <br>3. Authorization scope <br>4. Validity window at time of export |
| **AL-03**: Provenance Stamp Synchronous Write | ✅ **Implemented** | The Provenance Stamp is written **synchronously** to the audit log. |
| **AL-04**: Provenance Stamp Fail-Closed Behavior | ✅ **Implemented** | If the Provenance Stamp cannot be assembled (e.g., missing grant ID, expired authorization, or logging failure), the export request **must fail** (fail-closed). No partial or un-stamped exports are permitted. |

### 2.4. Security & Network Exposure
| Item | Status | Notes |
|------|--------|-------|
| **SN-01**: Endpoint security | ✅ **Confirmed** | `POST /v2/data-export/request` is protected by OAuth scope validation. Input validation and rate limiting are applied per standard API security guidelines. |
| **SN-02**: No new external data flows | ✅ **Confirmed** | Data flows remain within the existing secure infrastructure. Partner portal integration does not introduce new third-party data processors. |
