 In the given context, here is the compliance checklist for data-export v2:

1. Data Scope: Confirm that the data scope remains the same as in v1, covering only user data for which explicit consent has been obtained. (Reference: v1 compliance checklist)

2. Access Control: Confirm that access control policies remain unchanged from v1, ensuring that only authorized users and partners can initiate data exports. (Reference: v1 compliance checklist and pathway-agnostic terms in v1 checklist)

3. Partner-Portal Integration:
   - Implement the new HTTP endpoint `POST /v2/data-export/request` for partner-portal integration.
   - Ensure that partners authenticate using OAuth scope and can only request exports for users who granted them an active authorization.
   - Implement the Provenance Stamp feature, capturing the user's authorization grant id, the requesting party's identity, the authorization scope, and the validity window at the time of export.

4. Audit Logging:
   - Ensure that audit logs capture all data export activities, including those initiated through the partner-portal.
   - Verify that the Provenance Stamp is included in the audit logs for partner-initiated exports.

5. Retention Policies: Confirm that retention policies remain the same as in v1. (Reference: v1 compliance checklist)

6. Compliance Documentation: Ensure that all changes related to the partner-portal integration are properly documented.

After confirming these points, the compliance team can sign off on the v2 compliance checklist. The team should then proceed with the data-export v2 release.
