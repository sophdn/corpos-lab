# Data Export v2 Compliance Checklist

## Access Control
- **Status: Green**
- **Details:** The access control mechanisms from v1 remain unchanged in v2. The CLI surface is retained, and the new HTTP endpoint requires partners to authenticate via OAuth scope. The access control policies are pathway-agnostic and continue to ensure secure access to data exports.

## Audit Logging
- **Status: Green with Update**
- **Details:** The audit logging requirements from v1 are maintained. However, due to the addition of a partner-initiated export pathway, v2 requires an additional audit entry, known as a Provenance Stamp. This entry must capture:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
- **Implementation Note:** The Provenance Stamp must be recorded synchronously and must fail closed if it cannot be assembled, as per the Compliance Office Q4 2025 bulletin.

## Data Scope
- **Status: Green**
- **Details:** The data scope for v2 remains consistent with v1. No changes have been made to the types or categories of data being exported.

## Retention Policies
- **Status: Green**
- **Details:** Retention policies from v1 are unchanged in v2. The data export process continues to adhere to the established retention guidelines.

## Partner-Portal Access Path
- **Status: Green**
- **Details:** The new HTTP endpoint for partner-portal integration (`POST /v2/data-export/request`) has been added. Partners must authenticate using OAuth scopes and request exports only for users who have granted them active authorization. This integration does not introduce any changes to the core data export functionality or policies.

---

**Overall Compliance Status:** The v2 release of Data Export is compliant with the existing v1 compliance checklist, with the addition of the Provenance Stamp requirement for the new partner-initiated export pathway. All other controls and policies remain effective and unchanged.
