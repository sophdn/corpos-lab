# Compliance Checklist: data-export-v2

**Release Date:** Friday (Upcoming)

## Context
This is a pre-deployment compliance confirmation for `data-export-v2`. 
- **Baseline:** `data-export-v1` was reviewed, signed off by Legal and Security in Q1 2025, and its checklist remains current.
- **Delta:** v2 adds a partner-portal access path (`POST /v2/data-export/request`) on top of v1.
- **Scope:** Data scope, access controls, and retention policies are unchanged from v1.
- **Policy Reference:** Compliance Office Q4 2025 Bulletin (Effective 2025-11-01), specifically the "Data Export Process Update — Partner Integrations" item.

---

## 1. Data Scope & Minimization
**Status:** ✅ Confirmed (Inherited from v1)

- [x] **Data Fields:** The set of data fields exported in v2 is identical to v1. No new sensitive data categories are exposed.
- [x] **Minimization Principle:** The partner-portal path adheres to the same data minimization principles as the CLI path. Users only receive data they have authorized.
- [x] **Retention Policies:** Retention policies for export logs and data artifacts are unchanged from v1.

*Note: Compliance team has confirmed v2's data scope is unchanged from v1.*

## 2. Access Control & Authentication
**Status:** ✅ Confirmed (Inherited from v1) + ⚠️ New Pathway Verification

- [x] **v1 CLI Controls:** The existing CLI access controls remain active and unchanged.
- [x] **OAuth Scope Enforcement:** The new `POST /v2/data-export/request` endpoint requires valid OAuth authentication. Access is strictly limited to partners holding a valid OAuth scope.
- [x] **User Authorization Check:** The system verifies that the requesting partner has an active authorization grant from the specific user for whom the export is requested.
- [x] **Pathway-Agnostic Controls:** The v1 checklist’s access-control items are written in pathway-agnostic terms and remain applicable to both CLI and HTTP pathways.
