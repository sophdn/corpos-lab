# Compliance Checklist: Data-Export v2

**Status:** Ready for Sign-off
**Prepared By:** Compliance Officer
**Date:** [Current Date]
**Reference:** `deployments/data-export-v2/compliance-checklist.md`

## 1. Scope & Context
*   **v1 Baseline:** The v1 compliance checklist (signed off Q1 2025) remains current and valid. Access control and audit logging items are written in pathway-agnostic terms, confirming that the core data scope, access controls, and retention policies are unchanged in v2.
*   **v2 Changes:** v2 introduces a new partner-portal access path via `POST /v2/data-export/request`. Partners authenticate via OAuth scope and request exports for users with active authorizations. No other material changes exist.

## 2. Access Controls
*   **Status:** ✅ **Confirmed (Carry-over from v1)**
*   **Details:** The v1 access control mechanisms remain intact. The new partner-portal pathway utilizes OAuth scopes, which aligns with the existing pathway-agnostic access control definitions in the v1 checklist. No new access control logic is introduced beyond the standard OAuth integration for partners.

## 3. Audit Logging
*   **Status:** ⚠️ **Updated (v2-Specific Requirement)**
*   **v1 Carry-over:** Standard audit logging for the CLI surface remains unchanged and compliant.
*   **New Requirement (per 2025-Q4-bulletin):** A new **Provenance Stamp** audit entry is required for the partner-initiated export pathway.
*   **Implementation Details:**
    *   **Trigger:** Synchronous execution during `POST /v2/data-export/request`.
    *   **Data Captured:**
        1.  User's authorization grant ID.
        2.  Requesting party's identity.
        3.  Authorization scope.
        4.  Validity window at the time of export.
    *   **Failure Mode:** **Fail closed**. If the Provenance Stamp cannot be assembled, the export request must be rejected.

## 4. Data Retention
*   **Status:** ✅ **Confirmed (Carry-over from v1)**
*   **Details:** Retention policies are unchanged. The Provenance Stamp data is subject to the same retention policies as standard audit logs.
