# Compliance Confirmation: Data-Export v2

**To:** Data-Export Team
**From:** Compliance Office
**Date:** Q4 2025
**Subject:** Pre-deployment Compliance Confirmation for Data-Export v2

## Executive Summary

This is a **pre-deployment compliance confirmation**, not a full re-review.

The Data-Export v1 release was fully reviewed and signed off by Legal and Security in Q1 2025. The v1 compliance checklist remains current. The v2 specification introduces a new partner-portal access path (`POST /v2/data-export/request`) via OAuth scope authentication.

**Critical Action Required:**
Per the **Q4 2025 Compliance Bulletin** (effective 2025-11-01), any deployment adding a partner-initiated export pathway must implement a **Provenance Stamp**. This is a new, material control that was not present in v1. This control must be verified as implemented and tested before deployment.

All other v1 controls are confirmed to remain applicable and unchanged.

---

## Compliance Checklist: Data-Export v2

### 1. Data Scope & Retention
*   **Status:** ✅ **CONFIRMED (Unchanged from v1)**
*   **Detail:** v2 retains the v1 data scope and retention policies. No new data types are exposed. The v1 checklist items regarding data minimization and retention schedules remain valid.

### 2. Access Control & Authentication
*   **Status:** ✅ **CONFIRMED (Unchanged)** / ⚠️ **NEW CONTROL REQUIRED**
*   **Detail:**
    *   **v1 Controls:** Existing access controls for internal/CLI usage remain unchanged and apply to all export paths.
    *   **v2 New Path:** Partners authenticate via OAuth. Access is restricted to users who have granted an active authorization.
    *   **Compliance Note:** The OAuth scope mechanism must be verified to strictly enforce that partners can only request exports for users with *active* authorizations. Expired or revoked authorizations must result in immediate denial.
