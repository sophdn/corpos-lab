To address defect ticket **DEF-2026-04-1047**, the `validate_url_field()` function in `config/validator.py` must be updated to enforce URL structure validation, not just presence and non-emptiness.

### 1. Analysis of Current Behavior
*   **Current Logic:** The function checks `if field_value:` (or similar).
*   **Defect:** A string like `"not-a-url"` or `"http://"` passes this check, causing the validator to exit with code `0` (success) when it should exit with code `1` (failure).

### 2. Proposed Fix
We need to introduce a robust URL validation check. In Python, the standard library's `urllib.parse` module is sufficient for basic structure validation. For stricter validation (e.g., ensuring it's an absolute URL with a valid scheme and netloc), we can use `urllib.parse.urlparse` and check the result.

**Recommended Implementation Logic:**
1.  Check if the field is present and non-empty (existing logic).
2.  Parse the URL using `urllib.parse.urlparse(url)`.
3.  Validate that the `scheme` (e.g., `http`, `https`) and `netloc` (host) are present.
4.  If validation fails, return `False` (or raise an exception handled by the caller to trigger exit code 1).

### 3. Code Change for `config/validator.py`

```python
import urllib.parse

def validate_url_field(field_value: str) -> bool:
    """
    Validates that the field is present, non-empty, and is a structurally valid URL.
    
    Returns:
        bool: True if valid, False otherwise.
    """
    # 1. Check presence and non-emptiness (existing requirement)
    if not field_value or not isinstance(field_value, str) or not field_value.strip():
        return False
    
    url = field_value.strip()
    
    # 2. Validate URL structure
    try:
        result = urllib.parse.urlparse(url)
        
        # A valid URL for a service endpoint must have a scheme (http/https) and a netloc (host)
        if not result.scheme or not result.netloc:
            return False
