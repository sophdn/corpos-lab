 Based on the given descriptions, it appears that the Y-fire and Y-not-fire scenarios are related to a system where an agent is completing an operation on a primary artifact and also has the direct execution authority over a companion artifact. The companion artifact's validity depends on reflecting the current state of the primary artifact set.

1. Y-fire: This scenario occurs when the companion artifact update is not within the operation's executed scope. The agent holds the direct update authority, the obligation is unmet, and no transfer was filed. The firing condition is the execution trace showing the operation closed (primary artifact updated and task marked complete) without a companion artifact update in the same execution scope.

2. Y-not-fire: This scenario occurs when the companion artifact update is already present in the operation's execution scope alongside the primary artifact action. In this case, the discriminating condition is present: both the primary artifact action and the companion artifact update are co-present within scope before the operation closes. The glyph does not fire.
