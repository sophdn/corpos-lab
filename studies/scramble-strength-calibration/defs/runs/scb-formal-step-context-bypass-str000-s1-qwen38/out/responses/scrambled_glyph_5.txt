**Status:** **BLOCKED — Pending Engineering Implementation**
**Date:** 2025-11-XX
**Reviewer:** Compliance Office

## Executive Summary
The v2 release introduces a new partner-portal access path (`POST /v2/data-export/request`). While the base data scope, access controls, and retention policies remain unchanged from v1 (which is fully compliant), the **2025-Q4 Bulletin** mandates a new control for partner-initiated pathways: the **Provenance Stamp**.

**Current State:** The v2 specification currently relies on OAuth scope and active user authorization. It **does not** currently specify the synchronous, fail-closed audit logging required for the Provenance Stamp. Therefore, this checklist cannot be marked as "Green" until the engineering team confirms the implementation of this specific audit entry.

## Detailed Checklist

### 1. Data Scope & Retention
*   **Status:** ✅ **Confirmed**
*   **Basis:** v1 Checklist (Item 1.1, 1.2)
*   **Verification:** Spec confirms v2 retains v1 CLI surface and data scope. No new data types are exported; only the access vector changes. Retention policies remain identical to v1.

### 2. Access Controls (Internal & Admin)
*   **Status:** ✅ **Confirmed**
*   **Basis:** v1 Checklist (Item 2.1)
*   **Verification:** Internal admin access controls remain pathway-agnostic and unchanged from v1.

### 3. Access Controls (Partner Portal)
*   **Status:** ⚠️ **Partial / Needs Verification**
*   **Basis:** v2 Spec (`POST /v2/data-export/request`)
*   **Verification:**
    *   Partners authenticate via OAuth.
    *   Exports are restricted to users with active authorization.
    *   **Gap:** The spec does not yet detail how the system verifies the *validity window* of the authorization at the moment of export request beyond standard OAuth token expiry. This is a prerequisite for the next item.
