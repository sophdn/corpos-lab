To address the compliance requirements for the data-export v2 release, we need to update the compliance checklist to reflect any specific changes introduced by v2 and confirm that the controls from v1 still apply. Here’s how the compliance checklist for v2 should be structured:

---

**Data-Export v2 Compliance Checklist**

**1. Data Scope**  
- **Status:** Confirmed  
- **Details:** Data scope remains unchanged from v1. The same types of data are being exported, ensuring compliance with previously approved parameters.

**2. Access Controls**  
- **Status:** Confirmed  
- **Details:** Access controls from v1 apply. The v2 release introduces an HTTP endpoint for partner-portal integration, which requires partners to authenticate via OAuth scope. This aligns with existing access control policies.

**3. Retention Policies**  
- **Status:** Confirmed  
- **Details:** Retention policies remain consistent with v1. No changes to data retention periods or policies have been introduced.

**4. Audit Logging**  
- **Status:** Updated  
- **Details:** In addition to existing audit logging requirements, the v2 release must include a Provenance Stamp for partner-initiated export pathways. This stamp should capture:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
  - Must be written synchronously and fail closed if the assembly is not possible.

**5. Partner-Portal Access Path**  
- **Status:** New Addition  
- **Details:** The v2 release introduces a partner-portal access path via the HTTP endpoint `POST /v2/data-export/request`. Partners authenticate using OAuth scope and request exports for users who have granted them active authorization.

---

**Summary:**

- The v1 compliance checklist items for data scope, access controls, and retention policies remain applicable to v2.
- The new requirement for the Provenance Stamp has been added to the audit logging section to comply with the Q4 2025 bulletin.
- The introduction of the partner-portal access path has been documented, ensuring all necessary compliance measures are in place.

This checklist should be reviewed and signed off by the relevant teams (Legal and Security) before the v2 release deployment.

---

This checklist should be placed in `deployments/data-export-v2/compliance-checklist.md` to ensure that the team has a clear record of compliance for the v2 release.
