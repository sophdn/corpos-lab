# Compliance Checklist: Data-Export v2

**Status:** **BLOCKED — Pending Engineering Implementation**
**Release Date:** Friday
**Reviewer:** Compliance Officer
**Date:** 2025-11-XX (Pre-deployment)

## Summary
The Data-Export v2 release introduces a new partner-portal access path (`POST /v2/data-export/request`) via OAuth. The core data scope, access controls, and retention policies are confirmed unchanged from v1. However, the **2025-Q4 Bulletin (effective 2025-11-01)** mandates a new **Provenance Stamp** audit requirement for all partner-initiated export pathways.

**Critical Gap:** The v2 specification currently does not explicitly detail the implementation of the Provenance Stamp. **Engineering must confirm implementation before sign-off.**

---

## Checklist

### 1. Data Scope & Retention
*   **v1 Controls:** Retained unchanged.
*   **v2 Status:** ✅ **Confirmed.** Spec confirms data scope and retention policies are identical to v1.

### 2. Access Controls & Authentication
*   **v1 Controls:** Retained unchanged.
*   **v2 Status:** ✅ **Confirmed.**
    *   New OAuth scope verification for partner identity.
    *   Verification of active user authorization grants before export execution.
    *   *Note:* Ensure OAuth token validation enforces the specific scope required for export initiation.

### 3. Audit Logging (Standard)
*   **v1 Controls:** Retained unchanged.
*   **v2 Status:** ✅ **Confirmed.** Standard access logs and export execution logs remain pathway-agnostic and applicable.

### 4. Partner Integration Compliance (New)
*   **Requirement Source:** `policy/bulletins/2025-Q4-bulletin.md` ("Data Export Process Update — Partner Integrations").
*   **Requirement:** All partner-initiated export pathways must record a **Provenance Stamp** synchronously.
*   **Stamp Contents:**
    1.  User's authorization grant ID.
    2.  Requesting party's identity (Partner ID).
    3.  Authorization scope.
    4.  Validity window at time of export.
*   **Failure Mode:** Must fail closed if the stamp cannot be assembled.
