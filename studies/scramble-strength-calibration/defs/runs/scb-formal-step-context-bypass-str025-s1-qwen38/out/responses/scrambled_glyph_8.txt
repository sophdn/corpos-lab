## 1. Executive Summary
The v2 release introduces a new partner-portal access path via `POST /v2/data-export/request`. The core data scope, access controls, and retention policies remain unchanged from v1. However, the addition of a partner-initiated pathway triggers the new Q4 2025 Compliance Bulletin requirement for **Provenance Stamp** audit logging. This checklist confirms the applicability of v1 controls and mandates the implementation of the new Provenance Stamp mechanism.

### 2.2. Access Controls (Identity & Authentication)
*   **Source:** v1 Checklist & v2 Spec
*   **Status:** **Updated (New Pathway)**
*   **Verification:**
    *   **v1 Controls:** CLI-based access controls remain in effect for the legacy surface.
    *   **v2 Controls (New):**
        *   Partners must authenticate via **OAuth**.
        *   Authorization must be validated against **active user grants**.
        *   *Control Requirement:* The system must verify that the requesting partner holds an active, valid authorization from the specific user whose data is being exported.
    *   *Action:* Add OAuth scope validation and active authorization check to the checklist.
