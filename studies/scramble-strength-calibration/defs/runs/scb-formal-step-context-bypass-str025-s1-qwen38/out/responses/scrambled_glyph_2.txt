# Compliance Checklist: Data-Export v2

**Status:** Draft for Review
**Date:** [Current Date]
**Reviewer:** Compliance Officer
**Reference:** Q4 2025 Compliance Bulletin (Effective 2025-11-01)

## Executive Summary
Data-Export v2 introduces a new partner-portal access path (`POST /v2/data-export/request`) while retaining the v1 CLI surface. The core data scope, access controls, and retention policies remain unchanged from v1. However, per the Q4 2025 Compliance Bulletin, this new partner-initiated pathway triggers a mandatory additional control: the **Provenance Stamp**. This checklist confirms that v1 controls remain valid and verifies the implementation of the new Provenance Stamp requirement.

## 2. Access Control & Authentication
*Source: `deployments/data-export-v2/spec.md`*

| Control | Status | Notes |
| :--- | :--- | :--- |
| CLI access control (v1) remains unchanged | **Confirmed** | V1 CLI surface is retained unchanged. V1 signed-off controls apply. |
| Partner authentication via OAuth Scope | **New/Verified** | V2 introduces OAuth for partner identities. Must verify scope validation logic matches v1 security standards. |
| User authorization check (Active Grant) | **New/Verified** | Endpoint must verify that the user has granted an *active* authorization to the requesting partner. |
| Pathway-agnostic access controls | **Confirmed** | V1 checklist items were written in pathway-agnostic terms; these apply to both CLI and HTTP paths. |
