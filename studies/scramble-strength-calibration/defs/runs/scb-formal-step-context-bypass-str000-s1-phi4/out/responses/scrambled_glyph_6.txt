# Data Export v2 Compliance Checklist

## Access Control

- **Status:** Compliant
- **Details:** The v2 release retains the same CLI surface as v1. The partner-portal access path adds an HTTP endpoint (`POST /v2/data-export/request`) for partner-portal integration. Partners authenticate using OAuth scope, ensuring that access controls remain robust and unchanged from v1.

## Audit Logging

- **Status:** Compliant with Modifications
- **Details:** The v1 compliance checklist had access-control and audit-logging items written in pathway-agnostic terms. For v2, the addition of a partner-portal access path requires a new audit entry — a Provenance Stamp. This entry must capture:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
- **Action Required:** Ensure the system writes the Provenance Stamp synchronously and fails closed if it cannot be assembled.

## Data Scope

- **Status:** Compliant
- **Details:** The data scope remains unchanged from v1, as confirmed by the compliance team review.

## Retention Policies

- **Status:** Compliant
- **Details:** Retention policies continue to be in effect as per v1, with no changes introduced in v2.

## Partner-Portal Integration

- **Status:** Compliant with New Requirement
- **Details:** The new partner-portal access path requires the implementation of a Provenance Stamp as per the Q4 2025 bulletin. This ensures compliance with the updated audit logging requirements for partner-initiated export pathways.

## Overall Compliance

- **Status:** Compliant
- **Details:** All v1 controls continue to apply to v2, with the addition of specific requirements for the new partner-portal integration. The compliance team has confirmed that the data scope, access controls, and retention policies remain unchanged from v1.
