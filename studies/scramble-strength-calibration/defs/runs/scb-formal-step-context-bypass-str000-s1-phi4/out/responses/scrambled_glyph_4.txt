# Data-Export v2 Compliance Checklist

## Introduction

This checklist ensures the data-export v2 release complies with all applicable policies and standards, building upon the previously approved v1 release. This version introduces a new HTTP endpoint for partner portal integration while retaining the existing CLI functionality.

## Scope

- **Data Scope:** Unchanged from v1. The same data sets are accessible, ensuring no unauthorized expansion of data exposure.
- **Access Controls:** Consistent with v1. No changes to the access controls for existing endpoints.

## Access Control

- [ ] Ensure that access controls for the new partner portal endpoint (`POST /v2/data-export/request`) enforce the same principles as the existing v1 controls.
- [ ] Verify that partner authentication is robust, using OAuth scopes for requesting exports.
- [ ] Confirm that partners can only request exports for users who have granted them active authorization.

## Audit Logging

- [ ] Ensure that the audit logging mechanism is pathway-agnostic, as per the v1 checklist, and applies equally to the new partner portal integration.
- [ ] Introduce an additional audit entry requirement, the "Provenance Stamp," for any partner-initiated export pathway as per the 2025-Q4 bulletin. This should capture:
  - User's authorization grant ID.
  - Requesting party's identity.
  - Authorization scope.
  - Validity window at the time of export.
- [ ] Ensure the Provenance Stamp is written synchronously and fails closed if it cannot be assembled.

## Retention Policies

- [ ] Verify that data retention policies remain unchanged from v1, ensuring no additional retention beyond what is specified.

## Partner Portal Integration

- [ ] Confirm that the integration with the partner portal does not introduce new security vulnerabilities.
- [ ] Validate that all API requests from partners are authenticated and authorized correctly.

## Compliance with Policy Bulletins

- [ ] Ensure compliance with the 2025-Q4 bulletin requirements for data export processes involving partner integrations.
- [ ] Document any additional steps taken to meet these requirements, focusing on the Provenance Stamp requirement.

## Conclusion

- [ ] Review all checklist items to ensure compliance.
- [ ] Obtain sign-off from Legal and Security teams prior to deployment.
