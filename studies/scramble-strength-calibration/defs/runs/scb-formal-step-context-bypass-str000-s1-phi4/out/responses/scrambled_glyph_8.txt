# Data-Export v2 Compliance Checklist

This checklist confirms compliance for the Data-Export v2 deployment, ensuring that all v1 controls remain valid and any v2-specific changes are captured and addressed.

## Access Control

- **Checklist Item:** Verify that the access controls for data export remain consistent with v1.
- **Status:** Compliant
- **Details:** The data-export v2 continues to use the same CLI surface as v1, maintaining existing access control policies. The introduction of a partner portal via an HTTP endpoint does not alter the core access control mechanisms.
- **Notes:** Partners authenticate using OAuth scope, which aligns with existing access control policies.

## Audit Logging

- **Checklist Item:** Ensure audit logging requirements from v1 are satisfied in v2.
- **Status:** Compliant
- **Details:** The audit logging mechanism remains unchanged from v1, with access-control and audit-logging items written in pathway-agnostic terms.
- **Notes:** An additional audit entry, a Provenance Stamp, is required for partner-initiated export pathways. This stamp must capture:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
  - The Provenance Stamp must be written synchronously and fail closed if it cannot be assembled.

## Data Scope

- **Checklist Item:** Confirm that the data scope for exports remains unchanged from v1.
- **Status:** Compliant
- **Details:** Data-export v2 retains the same data scope as v1, with no modifications to the types or categories of data exported.

## Retention Policies

- **Checklist Item:** Ensure retention policies are consistent with those defined in v1.
- **Status:** Compliant
- **Details:** Retention policies remain unchanged from v1, with no new data types introduced that would affect retention schedules.

## Partner-Portal Integration

- **Checklist Item:** Validate the integration of the partner portal and its compliance with security policies.
- **Status:** Compliant
- **Details:** The partner portal introduces a new HTTP endpoint `POST /v2/data-export/request` for initiating exports. Partners authenticate via OAuth scope, and exports are requested for users who have granted active authorization.
- **Notes:** The integration complies with the policy bulletin requirement for recording a Provenance Stamp for partner-initiated exports.
