Below is the compliance checklist for the data-export v2 release, addressing both specific changes introduced in v2 and confirming the applicability of v1 controls:

---

# Data-Export v2 Compliance Checklist

## 1. Data Scope
- **Status:** Compliant
- **Details:** The data scope remains unchanged from v1. No additional data types or fields are being exported in v2.

## 2. Access Controls
- **Status:** Compliant
- **Details:** 
  - The v1 access controls still apply, as the CLI surface remains unchanged.
  - The new HTTP endpoint (`POST /v2/data-export/request`) for partner-portal integration uses OAuth scope for authentication, ensuring only authorized partners can request data exports.

## 3. Retention Policies
- **Status:** Compliant
- **Details:** Retention policies from v1 are unchanged. Data retention periods and conditions remain consistent with prior compliance standards.

## 4. Audit Logging
- **Status:** Compliant with Additional Requirement
- **Details:**
  - Audit logs from v1 are maintained as per the existing compliance requirements.
  - In accordance with the 2025-Q4 bulletin, v2 introduces a new requirement to record a Provenance Stamp for partner-initiated exports. This includes:
    - User's authorization grant ID
    - Requesting party's identity
    - Authorization scope
    - Validity window at the time of export
  - The Provenance Stamp must be written synchronously and fail closed if it cannot be assembled.

## 5. Partner Portal Access Path
- **Status:** Compliant
- **Details:** The addition of the partner portal access path (`POST /v2/data-export/request`) is compliant with the policy bulletin requirements, ensuring secure and auditable partner-initiated data exports.

---

This checklist confirms that the data-export v2 release maintains compliance with existing policies while incorporating necessary updates for the new partner portal access path. The additional audit entry requirement for partner-initiated exports has been addressed, ensuring full compliance with the 2025-Q4 bulletin.
