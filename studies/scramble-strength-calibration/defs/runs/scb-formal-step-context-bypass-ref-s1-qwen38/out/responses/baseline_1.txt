# Compliance Checklist: data-export-v2

**Status:** Draft for Confirmation  
**Prepared By:** Compliance Officer  
**Date:** 2025-Q4  
**Reference:** Pre-deployment confirmation for v2 release (Deploy Friday)

## 1. Scope & Changes from v1
- [x] **Confirmed:** v1 CLI surface remains unchanged.
- [x] **New Pathway:** `POST /v2/data-export/request` added for partner-portal integration.
- [x] **Authentication:** Partners authenticate via OAuth scope.
- [x] **Authorization:** Exports limited to users who granted active authorization to the partner.

## 2. Data Scope
- [x] **Unchanged:** Data scope is identical to v1.
- [x] **Action:** No new data fields added; no changes to data classification.

## 3. Access Controls
- [x] **v1 Controls:** Access-control items from v1 checklist apply as-is (pathway-agnostic terms).
- [x] **New Control - Partner Identity:** Partner identity verified via OAuth scope.
- [x] **New Control - User Authorization:** System must validate active user authorization grant before processing export.
- [x] **New Control - Scope Enforcement:** Requested export must fall within the scope of the user’s active authorization.

## 4. Retention Policies
- [x] **Unchanged:** Retention policies are identical to v1.
- [x] **Action:** No changes to data lifecycle or deletion schedules.

## 5. Audit Logging
- [x] **v1 Controls:** Standard audit logging from v1 checklist applies.
- [x] **NEW REQUIREMENT (Per 2025-Q4 Bulletin):** **Provenance Stamp** must be recorded for every partner-initiated export.
    - [x] **Content:** The Provenance Stamp must capture:
        1. User’s authorization grant ID.
        2. Requesting party’s identity (partner OAuth identity).
        3. Authorization scope.
        4. Validity window at the time of export.
    - [x] **Timing:** Written synchronously during the export request processing.
    - [x] **Failure Mode:** Fail closed (reject request) if the Provenance Stamp cannot be assembled.
    - [x] **Implementation Verified:** Engineering
