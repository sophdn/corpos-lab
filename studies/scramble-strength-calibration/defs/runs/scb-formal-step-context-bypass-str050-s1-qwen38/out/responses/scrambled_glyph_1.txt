# Compliance Checklist: data-export-v2

**Status:** Complete
**Release:** data-export-v2
**Pre-deployment Confirmation:** Yes
**Baseline:** data-export-v1 (Signed off Q1 2025)

## Executive Summary
This document confirms compliance for the `data-export-v2` release. The v2 release introduces a partner-portal access path via `POST /v2/data-export/request`. All v1 controls (data scope, access controls, retention) remain unchanged. This review incorporates the requirements from the **2025-Q4 Bulletin** regarding partner-initiated export pathways.

## 1. Data Scope & Access Controls
*Status: Confirmed (Unchanged from v1)*

- [x] **Data Scope:** Verified that v2 retains the v1 CLI surface and does not alter the defined data scope.
- [x] **Access Control (CLI):** v1 CLI access controls remain active and unchanged.
- [x] **Access Control (Partner Portal):**
    - Partners authenticate via OAuth scope.
    - Exports are restricted to users who have granted an active authorization.
    - *Note:* Access control logic is pathway-agnostic as per v1 checklist, but the new pathway enforces the specific OAuth/authorization checks defined in the v2 spec.

## 2. Audit Logging & Provenance
*Status: Updated (New Requirement Applied)*

- [x] **Standard Audit Logs:** v1 audit logging requirements remain active for all export events.
- [x] **Provenance Stamp (New - 2025-Q4 Bulletin):**
    - **Requirement:** Any deployment adding a partner-initiated export pathway must record a Provenance Stamp.
    - **Implementation Check:** The v2 spec confirms that the `POST /v2/data-export/request` endpoint captures the following synchronously:
        - [x] User's authorization grant ID
        - [x] Requesting party's identity
        - [x] Authorization scope
        - [x] Validity window at time of export
    - **Failure Mode:** Verified that the system fails closed if the Provenance Stamp cannot be assembled.
