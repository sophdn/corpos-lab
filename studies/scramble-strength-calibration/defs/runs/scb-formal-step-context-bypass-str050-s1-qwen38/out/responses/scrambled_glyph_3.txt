# Compliance Confirmation: Data-Export v2

**To:** Data-Export Team
**From:** Compliance Office
**Date:** Q4 2025
**Subject:** Pre-deployment Compliance Confirmation for Data-Export v2

## Executive Summary

This is a **pre-deployment compliance confirmation** for the Data-Export v2 release, scheduled for deployment this Friday. This is not a full re-review.

Based on the Q4 2025 Compliance Bulletin (effective 2025-11-01) and the v2 specification, the v1 compliance controls remain valid and applicable. However, v2 introduces a **partner-initiated export pathway** (`POST /v2/data-export/request`), which triggers a specific new requirement: the **Provenance Stamp** audit entry.

All v1 controls are confirmed to carry over. One new control (Provenance Stamp) is added. No other material changes to data scope, access controls, or retention policies were identified.

---

## Compliance Checklist: Data-Export v2

### 1. Data Scope & Retention
*Status: Unchanged from v1 — Confirmed*

- [x] **Data Scope:** v2 retains the exact same data scope as v1. No new data fields, datasets, or PII categories are exposed.
- [x] **Retention Policies:** Data retention periods and deletion schedules are identical to v1. No changes to lifecycle management.

### 2. Access Controls
*Status: Unchanged from v1 — Confirmed (with note on new pathway)*

- [x] **CLI Access:** The v1 CLI surface is unchanged. Existing authentication and authorization mechanisms for internal CLI users remain intact.
- [x] **Pathway-Agnostic Controls:** The v1 checklist’s access-control items are written in pathway-agnostic terms and remain fully applicable to v2.
- [x] **Partner Authentication:** The new partner-portal path uses OAuth scopes. This is a standard, compliant authentication mechanism. Partners can only request exports for users who have granted them an active authorization. This aligns with the principle of least privilege.

### 3. Audit Logging
*Status: Enhanced — New Requirement Identified*

- [x] **v1 Audit Logs:** All existing audit logging requirements from v1 remain in effect.
