# Data Export v2 Compliance Checklist

**Status:** Ready for Review
**Date:** Pre-deployment (Friday)
**Reviewer:** Compliance Office
**Reference:** v1 Checklist (Signed Off Q1 2025), 2025-Q4 Bulletin (Effective 2025-11-01)

## Executive Summary
Data Export v2 introduces a new partner-portal access path via `POST /v2/data-export/request`. The v1 CLI surface remains unchanged. Per the 2025-Q4 Bulletin, the addition of a partner-initiated export pathway triggers a new mandatory control: the **Provenance Stamp**. All other v1 controls (access control, retention, audit logging) remain applicable and are confirmed valid for v2, provided the Provenance Stamp logic is implemented as specified.

## 1. Data Scope & Retention
*   **Status:** ✅ Confirmed (No Change)
*   **Details:**
    *   Data scope is identical to v1.
    *   Retention policies are unchanged from v1.
    *   *Action:* Carry over v1 checklist items for data classification and retention periods. No new data types are introduced in v2.

## 2. Access Controls
*   **Status:** ✅ Confirmed (v1) / ⚠️ New Control Required (v2)
*   **v1 Controls (CLI):**
    *   Pathway-agnostic access control checks remain valid.
    *   *Action:* Confirm v1 CLI authentication/authorization logic is unchanged in the v2 codebase.
*   **v2 Controls (Partner Portal):**
    *   **Authentication:** Partners must authenticate via OAuth.
    *   **Authorization:** Requests must validate an active user authorization grant.
    *   **Scope Enforcement:** The OAuth scope must match the requested export scope.
    *   *Action:* Verify that the `POST /v2/data-export/request` endpoint rejects requests lacking a valid OAuth token and an active user authorization.

## 3. Audit Logging & Provenance
*   **Status:** ⚠️ **NEW REQUIREMENT — MUST IMPLEMENT**
*   **v1 Controls:**
    *   Standard audit logging for CLI exports remains required.
*   **v2 Specific Requirement (Per 2025-Q4 Bulletin):**
    *   **Provenance Stamp:** For **all**
