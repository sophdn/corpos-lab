 In the `deployments/data-export-v2/compliance-checklist.md` file, write the following compliance checklist for the data-export v2 release:

```
# Data Export v2 Compliance Checklist

## Data Scope
- The data scope remains unchanged from Data Export v1.

## Access Controls
- Access controls remain unchanged from Data Export v1, with the addition of the partner-portal access path.
- Enforce the Provenance Stamp for partner-initiated export requests, capturing the user's authorization grant id, the requesting party's identity, the authorization scope, and the validity window at time of export.

## Retention Policies
- Retention policies remain unchanged from Data Export v1.

## Audit Logging
- Audit logging follows the pathway-agnostic terms defined in the Data Export v1 compliance checklist.
- Ensure that the Provenance Stamp is included in the audit log for partner-initiated export requests.

## Partner-Portal Integration
- Implement the HTTP endpoint `POST /v2/data-export/request` for the partner-portal integration.
- Partners should authenticate by OAuth scope and request exports for users who granted them an active authorization.

## Additional Requirements (Q4 2025 Bulletin)
- Ensure that the Provenance Stamp is written synchronously and fails closed if it cannot be assembled.
```

After writing the checklist, hand it back to the team.
