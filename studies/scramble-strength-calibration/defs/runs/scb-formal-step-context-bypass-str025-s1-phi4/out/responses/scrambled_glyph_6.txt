# Data Export v2 Compliance Checklist

## Access Control

- **Control:** Access to the data export functionality is restricted to authorized users only.
- **Compliance:** 
  - v2 retains v1's access control measures.
  - Partners authenticate via OAuth scope, ensuring only authorized partners can request exports.
- **Status:** Compliant

## Audit Logging

- **Control:** All access to data exports is logged for audit purposes.
- **Compliance:** 
  - v2 extends v1's audit logging requirements to include partner-initiated requests.
  - A new "Provenance Stamp" is required for partner requests, capturing:
    - User's authorization grant ID
    - Requesting party's identity
    - Authorization scope
    - Validity window at time of export
- **Status:** Compliant

## Data Scope

- **Control:** The data exported must be limited to what is necessary and appropriate.
- **Compliance:** 
  - v2 maintains the same data scope as v1, with no changes to the type or amount of data exported.
- **Status:** Compliant

## Retention Policies

- **Control:** Data retention must adhere to defined policies and regulations.
- **Compliance:** 
  - v2 continues to follow the same retention policies as v1.
- **Status:** Compliant

## Partner-Portal Integration

- **Control:** Any new access pathways must be secure and compliant with existing policies.
- **Compliance:** 
  - v2 introduces a partner-portal access path via `POST /v2/data-export/request`.
  - Partners authenticate using OAuth, ensuring secure access.
- **Status:** Compliant

## General Observations

- All controls from v1 are applicable to v2.
- The addition of the partner-portal access path is the only material change, which has been addressed with new audit logging requirements.

This checklist confirms that the v2 release complies with existing policies and incorporates necessary changes for the new partner-portal integration.
