To produce the v2 compliance checklist for the data-export v2 release, we need to ensure that all v1 compliance controls remain applicable while addressing any new requirements introduced by v2. Here’s how the compliance checklist for v2 should be structured:

---

### `deployments/data-export-v2/compliance-checklist.md`

#### Data Scope
- **Compliance Status:** Green
- **Notes:** The data scope for v2 remains unchanged from v1, ensuring continued compliance with existing data handling policies.

#### Access Controls
- **Compliance Status:** Green
- **Notes:** Access controls are unchanged from v1. The new HTTP endpoint for the partner-portal is secured via OAuth, requiring partners to authenticate and request exports based on active user authorizations. This aligns with the existing access control framework.

#### Retention Policies
- **Compliance Status:** Green
- **Notes:** Retention policies remain consistent with v1, ensuring no deviation in how data is retained and managed over time.

#### Audit Logging
- **Compliance Status:** Green
- **Notes:** The audit logging requirements from v1 apply. However, v2 introduces a new requirement to capture a Provenance Stamp for partner-initiated exports. This includes recording the user's authorization grant ID, the requesting party's identity, the authorization scope, and the validity window at the time of export. This must be written synchronously and adhere to the "failing closed" principle if it cannot be assembled.

#### Additional Requirements for v2
- **Provenance Stamp for Partner-Initiated Exports:**
  - **Requirement:** For any partner-initiated export, record a Provenance Stamp capturing:
    - User's authorization grant ID
    - Requesting party's identity
    - Authorization scope
    - Validity window at time of export
  - **Implementation:** Ensure this is written synchronously and fails closed if the information cannot be assembled.

---

This checklist confirms that all v1 compliance controls are still applicable to v2, with the addition of the Provenance Stamp requirement as per the 2025 Q4 bulletin. The compliance team should review this checklist to ensure all aspects are addressed before deployment.
