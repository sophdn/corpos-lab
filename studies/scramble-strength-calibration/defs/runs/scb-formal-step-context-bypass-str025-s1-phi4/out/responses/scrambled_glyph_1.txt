# Data-Export v2 Compliance Checklist

## Introduction
- The data-export v2 release maintains the data scope, access controls, and retention policies of v1.
- v2 adds a partner-portal access path without other material changes.

## Data Scope
- [ ] Data scope remains unchanged from v1. Ensure no additional data types are included without prior review.

## Access Controls
- [ ] Access controls remain unchanged from v1, with pathway-agnostic terms applicable.
- [ ] Partners authenticate via OAuth scope for the new HTTP endpoint `POST /v2/data-export/request`.
- [ ] Ensure active authorizations are required for partners to request exports on behalf of users.

## Retention Policies
- [ ] Retention policies remain unchanged from v1.

## Audit Logging
- [ ] Audit logging requirements from v1 apply to v2.
- [ ] Implement a Provenance Stamp for partner-initiated export pathways:
  - Capture the user's authorization grant ID.
  - Record the requesting party's identity.
  - Log the authorization scope.
  - Note the validity window at the time of export.
  - Ensure the Provenance Stamp is written synchronously and fails closed if it cannot be assembled.

## Security
- [ ] Security measures from v1 continue to apply to v2.
- [ ] Review the security implications of the new HTTP endpoint and ensure it adheres to existing security protocols.

## Compliance with Policy Bulletins
- [ ] Ensure compliance with the "Data Export Process Update — Partner Integrations" from the 2025-Q4 bulletin.
- [ ] Confirm that the Provenance Stamp is implemented as per the bulletin's requirements.

## General
- [ ] Confirm that all v1 checklist items are still applicable and marked as "green."
- [ ] Document any new compliance requirements introduced by v2.

---

This checklist should be reviewed and signed off by the compliance team, Legal, and Security before the deployment of data-export v2.
