# Data-Export v2 Compliance Checklist

## Data Scope
- **Status:** Compliant
- **Details:** The data scope remains unchanged from v1. All data handled by v2 continues to align with the previously approved scope.

## Access Controls
- **Status:** Compliant
- **Details:** Access controls are unchanged from v1, ensuring that only authorized users can access the data. The addition of the partner-portal access path uses OAuth scope for authentication, which adheres to established security protocols.

## Retention Policies
- **Status:** Compliant
- **Details:** Retention policies continue to be consistent with v1, ensuring that data is retained for the appropriate duration as per legal and organizational requirements.

## Audit Logging
- **Status:** Compliant
- **Details:** Audit logs from v1 remain applicable. The addition of the partner-portal access path requires recording an additional audit entry, the Provenance Stamp, which captures the user's authorization grant ID, the requesting party's identity, the authorization scope, and the validity window at the time of export. This entry must be written synchronously and fail closed if it cannot be assembled.

## Partner-Portal Access Path
- **Status:** Compliant
- **Details:** The new HTTP endpoint `POST /v2/data-export/request` for partner-portal integration has been added. Partners authenticate using OAuth scope and request exports for users with active authorizations. This new pathway includes the required Provenance Stamp for audit purposes.

## Overall Compliance
- **Status:** Compliant
- **Details:** All controls from the v1 compliance checklist remain applicable. The v2 release introduces no material changes beyond the addition of the partner-portal access path, which has been addressed with the necessary audit logging requirements.
