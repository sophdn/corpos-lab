# Deployments/Data-Export-V2/Compliance-Checklist.md

## Data Scope
- **Status:** Verified
- **Details:** The data scope remains unchanged from v1, ensuring compliance with existing policies. The addition of the partner portal does not affect data scope.

## Access Controls
- **Status:** Verified
- **Details:** Access controls continue to be pathway-agnostic as specified in the v1 checklist. Partners authenticate via OAuth scope, maintaining the integrity of access control mechanisms.

## Retention Policies
- **Status:** Verified
- **Details:** Retention policies are unchanged from v1, ensuring continued compliance with data retention guidelines.

## Audit Logging
- **Status:** Updated
- **Details:** 
  - **Provenance Stamp Requirement:** As per the Q4 2025 bulletin, an additional audit entry, the Provenance Stamp, must be recorded for partner-initiated export pathways. This entry includes:
    - User's authorization grant ID
    - Requesting party's identity
    - Authorization scope
    - Validity window at time of export
  - **Implementation:** The logging mechanism must write this entry synchronously and fail closed if it cannot be assembled, ensuring compliance with the new requirement.

## Partner Portal Access Path
- **Status:** Verified
- **Details:** The new HTTP endpoint `POST /v2/data-export/request` for partner portal integration has been reviewed and confirmed to adhere to existing compliance standards. Partners must authenticate via OAuth scope and request exports only for users with active authorizations.

---

### Summary
The v2 release maintains all compliance controls from v1, with the addition of the Provenance Stamp requirement for partner-initiated exports. The compliance checklist confirms that all necessary controls are in place and operational for the v2 release.
