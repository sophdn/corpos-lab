## Overview

The data-export v2 release introduces a partner-portal access path via an HTTP endpoint `POST /v2/data-export/request`. Partners authenticate by OAuth scope and request exports for users who have granted them an active authorization. This checklist ensures that all compliance controls from v1 are maintained and that new requirements specific to v2 are addressed.

## Compliance Controls

### Data Scope

- **Control:** Ensure that the data scope remains unchanged from v1.
- **Status:** Compliant
- **Comments:** No changes in data scope from v1 to v2.

### Access Controls

- **Control:** Verify that access controls remain consistent with v1.
- **Status:** Compliant
- **Comments:** Access controls are pathway-agnostic and remain unchanged.

### Retention Policies

- **Control:** Confirm that retention policies are unchanged from v1.
- **Status:** Compliant
- **Comments:** Retention policies continue to apply as per v1.

### Audit Logging

- **Control:** Maintain comprehensive audit logging as defined in v1.
- **Status:** Compliant
- **Comments:** Audit logging controls are unchanged.

### New Requirement: Provenance Stamp

- **Control:** Implement an additional audit entry — a Provenance Stamp — for partner-initiated export pathways.
- **Status:** Compliant
- **Comments:** The Provenance Stamp must capture:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at time of export
  - Must be written synchronously and fail closed if not assembled.

## Conclusion

The data-export v2 release complies with all existing v1 controls and incorporates the new requirement for a Provenance Stamp as per the Compliance Office Q4 2025 bulletin. All checklist items are marked as compliant.
