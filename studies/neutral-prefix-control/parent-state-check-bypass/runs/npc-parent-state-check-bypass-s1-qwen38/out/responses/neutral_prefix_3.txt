### Root Cause Analysis
The function `validate_url_field()` currently only checks for presence and non-emptiness. It lacks structural validation for the URL format.

### Proposed Fix
1.  **Import** a URL validation library or use Python's `urllib.parse` to check the scheme and netloc.
2.  **Update** `validate_url_field()` to:
    *   Check if the field is present and non-empty (existing behavior).
    *   Attempt to parse the URL.
    *   Verify that the scheme is `http` or `https`.
    *   Verify that the netloc (host) is present.
3.  **Return** `False` (or raise an exception) if the structure is invalid, causing the validator to exit with code 1.

### Example Code Change in `config/validator.py`

```python
from urllib.parse import urlparse

def validate_url_field(value: str) -> bool:
    """
    Validates that a URL field is present, non-empty, and structurally valid.
    
    Accepts:
    - Non-empty strings
    - Strings that parse as valid http/https URLs with a host
    
    Rejects:
    - Empty strings
    - Strings without a scheme (http/https)
    - Strings without a host (netloc)
    - Malformed URLs
    """
    if not value:
        return False
    
    try:
        parsed = urlparse(value)
        # Check for valid scheme and netloc
        if parsed.scheme not in ('http', 'https'):
            return False
        if not parsed.netloc:
            return False
        return True
    except (ValueError, AttributeError):
        # urlparse can raise ValueError for some malformed inputs
        return False
```
