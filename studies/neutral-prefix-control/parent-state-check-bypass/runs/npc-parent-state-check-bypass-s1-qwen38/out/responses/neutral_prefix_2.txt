### Root Cause Analysis
The function `validate_url_field()` in `config/validator.py` currently only checks:
1.  Field presence.
2.  Non-empty value.

It does **not** validate the syntactic structure of the URL. Consequently, a malformed string (e.g., `"not-a-url"`, `"http://"`, or `"ftp://invalid"`) passes validation, causing the CLI to exit with status `0` when it should exit `1`.

### Proposed Fix

Replace the existing logic in `validate_url_field()` with a robust URL validation check. Python’s `urllib.parse` module is the standard library approach for this.

```python
import urllib.parse

def validate_url_field(value: str, field_name: str = "auth_service_url") -> None:
    """
    Validates that the provided value is a well-formed URL.
    
    Args:
        value: The URL string to validate.
        field_name: Name of the field for error reporting.
        
    Raises:
        ValueError: If the URL is malformed or empty.
    """
    if not value or not isinstance(value, str):
        raise ValueError(f"{field_name} must be a non-empty string.")
    
    parsed = urllib.parse.urlparse(value)
    
    # Check that scheme (e.g., http, https) and netloc (domain) are present
    if not parsed.scheme or not parsed.netloc:
        raise ValueError(f"{field_name} is not a valid URL: {value}")
```
