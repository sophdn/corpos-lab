## The change

I can't verify the exact current implementation of `validate_url_field()`, so I'll write the replacement to be self-contained and robust. It uses the standard library `urllib.parse` (no new dependency), enforces a valid scheme and a non-empty host, and rejects empty/whitespace values.

```python
# config/validator.py
from urllib.parse import urlparse

def validate_url_field(value, field_name="auth_service_url"):
    """
    Validate that `value` is a structurally well-formed URL.

    Returns (ok: bool, message: str).
    - ok is True only for a non-empty string with a valid scheme and host.
    - ok is False for missing/empty/whitespace values or malformed structure.
    """
    if value is None:
        return False, f"{field_name} is missing"

    if not isinstance(value, str):
        return False, f"{field_name} must be a string"

    stripped = value.strip()
    if not stripped:
        return False, f"{field_name} must not be empty"

    parsed = urlparse(stripped)

    # Require a recognized scheme (http/https expected for a service URL).
    # Using a whitelist is stricter than urlparse, which accepts any alpha scheme.
    allowed_schemes = {"http", "https"}
    if parsed.scheme not in allowed_schemes:
        return False, (
            f"{field_name} must use an http or https scheme; got "
            f"{parsed.scheme!r}"
        )

    # Require a non-empty netloc (host). urlparse leaves netloc empty for
    # strings like "foo/bar" or "not-a-url".
    if not parsed.netloc:
        return False, f"{field_name} is missing a host"

    # netloc can include userinfo@host:port; ensure a host component exists.
    host = parsed.hostname
    if not host:
        return False, f"{field_name} has an invalid host"

    return True, f"{field_name} is valid"
```

How this satisfies the acceptance criteria:

- **Malformed input → exit 1.** A value like `not-a-url`, `htp:/broken`, `http://`, or empty/whitespace fails one of the checks above, so `validate_url_field()` returns `ok=False`. Assuming the existing validator maps a failed field check to exit 1 (per the stated root cause, the exit path already exists), the CLI will now exit 1.
- **Valid URLs still pass.** `https://auth.internal:8443/v1` and `http://auth.example.com` parse to a scheme in the whitelist and a non-empty host, returning `ok=True` → exit 0.
