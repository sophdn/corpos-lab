## Introduction

The learning-portal v2 release builds upon the foundations established by the v1 release, which was audited and signed off by the Accessibility Board in Q1 2025. The v2 release retains the page structure, color palette, and keyboard navigation of v1, with the addition of a voice-command input path. This report confirms the conformance of v2 to WCAG 2.1 AA standards, addressing both the unchanged criteria from v1 and the new requirements introduced by the addition of voice-command functionality.

## Conformance to v1 Criteria

The v2 release continues to meet all success criteria established in the v1 conformance report, which confirmed compliance with WCAG 2.1 AA standards. These criteria include, but are not limited to, page structure, color contrast, keyboard navigation, and error handling, all of which remain unchanged in v2.

## New Voice-Command Input Path

### Introduction of Voice-Command Functionality

The v2 release introduces a voice-command input path, allowing learners to navigate and submit answers using spoken commands. This functionality is implemented via the browser's speech API, which transcribes spoken input into text.

### Modality Alternative Mapping

In accordance with the "Input Modality Update — Speech Interfaces" bulletin from Q4 2025, the v2 release includes a Modality Alternative Mapping. This mapping ensures that for every voice command, there is an equivalent non-voice control option, a transcription-failure fallback, and a timeout mechanism that returns the learner to a usable non-voice pathway.

#### Voice Command to Non-Voice Control Mapping

- **Voice Command:** "Navigate to next question"
  - **Equivalent Non-Voice Control:** Press the "Next" button
  - **Transcription-Failure Fallback:** Provide audio feedback indicating the command was not recognized and prompt for a retry
  - **Timeout Mechanism:** Return to keyboard navigation after 5 seconds of inactivity

- **Voice Command:** "Submit answer"
  - **Equivalent Non-Voice Control:** Click the "Submit" button
  - **Transcription-Failure Fallback:** Display a message prompting the user to use the keyboard or mouse for submission
  - **Timeout Mechanism:** Revert to keyboard input method after 5 seconds

#### Documentation and Fallbacks

The voice-command path is thoroughly documented, ensuring that all learners have access to alternative input methods if voice recognition fails. The system is designed to fail safely, meaning that any issues with voice input do not prevent access to content or functionality.

## Conclusion

The learning-portal v2 release maintains full compliance with WCAG 2.1 AA standards, incorporating the new voice-command input path while ensuring all existing accessibility criteria from v1 are met. The addition of the Modality Alternative Mapping addresses the requirements set forth in the Q4 2025 accessibility bulletin, providing a robust and inclusive user experience.
