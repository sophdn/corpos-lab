# Learning Portal v2 Conformance Report

## Introduction

The Learning Portal v2 release builds upon the successful conformance of the Learning Portal v1 to the WCAG 2.1 AA standards, as confirmed in Q1 2025. The primary change in v2 is the introduction of a voice-command input path, which allows learners to navigate and interact with the portal using spoken commands. This report confirms that the v2 release remains compliant with WCAG 2.1 AA standards and addresses the additional requirements specified in the 2025-Q4 Accessibility Bulletin.

## WCAG 2.1 AA Conformance

### Structure, Color Palette, and Keyboard Navigation

- **Status:** Unchanged from v1
- **Details:** The page structure, color palette, and keyboard navigation remain consistent with the v1 release, which was previously audited and confirmed to meet all success criteria for WCAG 2.1 AA.

### Voice-Command Input Path

- **Status:** New addition
- **Details:** The v2 release introduces a voice-command input path, allowing learners to issue spoken commands that are transcribed by the browser's speech API. This new feature requires additional conformance documentation as per the 2025-Q4 Accessibility Bulletin.

## Modality Alternative Mapping

As per the "Input Modality Update — Speech Interfaces" item in the 2025-Q4 Accessibility Bulletin, the Learning Portal v2 includes a Modality Alternative Mapping for the voice-command input path. This mapping ensures that all voice commands have equivalent non-voice controls, a transcription-failure fallback, and a timeout mechanism that returns the learner to a usable non-voice pathway.

### Mapping Details

1. **Voice Commands and Equivalent Non-Voice Controls:**
   - For each voice command, an equivalent keyboard or pointer command is documented.
   - Example: 
     - Voice Command: "Next"
     - Equivalent Non-Voice Control: Press the "Right Arrow" key or click the "Next" button.

2. **Transcription-Failure Fallback:**
   - If a voice command is not recognized, the system provides feedback to the user and allows them to retry or use a keyboard/pointer alternative.
   - Example: "Command not recognized. Please try again or use the arrow keys."

3. **Timeout Mechanism:**
   - A timeout is implemented to return the user to a usable non-voice pathway if no command is issued within a specified period.
   - Example: After 10 seconds of inactivity, the system returns control to the user via keyboard/pointer interface.

## Conclusion

The Learning Portal v2 release maintains full conformance with WCAG 2.1 AA standards as established in the v1 release. The addition of the voice-command input path has been documented with a comprehensive Modality Alternative Mapping, ensuring accessibility and usability for all learners. This report is submitted for the Accessibility Board's review and approval.
