# Learning Portal v2 Conformance Report

## Introduction

The Learning Portal v2 release introduces a voice-command input path while retaining the existing pointer and keyboard navigation methods. This report confirms conformance to WCAG 2.1 AA standards, building on the v1 release, which was fully audited and signed off by the Accessibility Board in Q1 2025. This report addresses additional requirements for the newly introduced voice-command modality.

## Continuation of v1 Criteria

The Learning Portal v2 retains the page structure, color palette, and keyboard navigation from v1, which were previously confirmed to meet all WCAG 2.1 AA success criteria. The following v1 criteria are confirmed to still apply:

- **Page Structure**: The semantic structure of the pages remains unchanged, ensuring compatibility with screen readers and other assistive technologies.
- **Color Palette**: The color contrast and usage continue to meet accessibility standards, providing sufficient contrast ratios for text and UI elements.
- **Keyboard Navigation**: The keyboard surface remains unchanged, supporting efficient navigation for users who rely on keyboard-only interactions.

## New Criteria for Voice-Command Input Path

In accordance with the "Input Modality Update — Speech Interfaces" from the Accessibility Office Q4 2025 bulletin, the Learning Portal v2 includes a Modality Alternative Mapping for the voice-command input path. This mapping ensures that voice commands have equivalent non-voice controls, and provides a transcription-failure fallback and a timeout mechanism.

### Modality Alternative Mapping

1. **Voice Command to Non-Voice Control Equivalence**:
   - Each voice command has an equivalent keyboard or pointer-based action. For example, a spoken "next page" command corresponds to pressing the "Enter" key or clicking the "Next" button.

2. **Transcription-Failure Fallback**:
   - In cases where a voice command is not accurately transcribed, the system provides a clear notification to the user. The user is then redirected to a non-voice interface, ensuring continued usability.

3. **Timeout and Usable Pathway**:
   - A timeout is implemented to return the user to a usable non-voice pathway if voice interaction is not completed within a reasonable time frame. This ensures that users are not left in an inaccessible state.

### Documentation

The Modality Alternative Mapping is thoroughly documented within the system, detailing each voice command, its non-voice equivalent, the fallback mechanisms, and the timeout procedures. This documentation is available for review and testing to ensure compliance and reliability.

## Conclusion

The Learning Portal v2 continues to meet all WCAG 2.1 AA criteria as previously established in the v1 release. The addition of the voice-command input path has been carefully integrated with a comprehensive Modality Alternative Mapping, ensuring full accessibility for all users. This conformance report is submitted for the board's review and approval.
