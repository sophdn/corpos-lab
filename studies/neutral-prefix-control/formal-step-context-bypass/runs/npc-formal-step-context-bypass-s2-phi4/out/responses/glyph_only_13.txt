# Learning Portal v2 Conformance Report

## Introduction

This conformance report outlines the accessibility compliance of the learning-portal v2 release. The release builds upon the v1 portal, which was audited and signed off by the Accessibility Board in Q1 2025 for WCAG 2.1 AA compliance. v2 introduces a voice-command input path, with all other page structures, color palettes, and keyboard navigation pathways remaining consistent with v1.

## Conformance to Existing Criteria

As the page structure, color palette, and keyboard navigation have not changed from v1, all previously met WCAG 2.1 AA success criteria remain applicable and intact in v2. The learning-portal v1 conformance report, which confirms compliance in these areas, is attached as reference.

### Success Criteria

- **Perceivable**: The content remains accessible through visual and non-visual means as per v1 standards.
- **Operable**: Keyboard navigation is unchanged, ensuring operability for users relying on non-speech input methods.
- **Understandable**: Text and interactive components maintain clarity and usability as validated in v1.
- **Robust**: Compatibility with assistive technologies continues to be supported as previously verified.

## Additional Conformance Requirements for Voice Command Path

In accordance with the "Input Modality Update — Speech Interfaces" policy from the Accessibility Office Q4 2025 bulletin, the introduction of a voice-command input path necessitates an additional conformance item: a Modality Alternative Mapping. Below is an overview of this requirement:

### Modality Alternative Mapping

For each voice command available in the learning-portal v2, a comprehensive mapping must be provided, detailing:

1. **Equivalent Non-Voice Control**: For each voice command, specify the corresponding keyboard or mouse action that achieves the same result.
   
2. **Transcription-Failure Fallback**: Define the system's behavior in the event of a voice command transcription failure, ensuring users are informed and can continue using the portal without disruption.

3. **Timeout and Non-Voice Pathway**: Establish a timeout mechanism for voice commands that reverts the user to a non-voice interface if no command is detected within a specified time frame. Document this pathway to ensure seamless user experience continuity.

### Implementation Details

- **Mapping Documentation**: Detailed mappings will be recorded and maintained as part of the system documentation to support ongoing accessibility compliance.
- **Fail-Safe Mechanism**: Implement a system that defaults to non-voice interaction pathways if voice command mappings cannot be successfully executed or completed.

## Conclusion

The learning-portal v2 maintains all previous accessibility standards established in the v1 release and introduces necessary enhancements to support voice command functionality. By adhering to the new modality requirements, the portal ensures comprehensive accessibility for all users, fulfilling the WCAG 2.1 AA standards.

This report is submitted for review by the Accessibility Board to confirm compliance with the outlined criteria.
