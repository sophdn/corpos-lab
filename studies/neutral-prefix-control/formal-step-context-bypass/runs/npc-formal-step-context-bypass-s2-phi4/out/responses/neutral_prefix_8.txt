# Conformance Report for Learning Portal v2

## Introduction

This report assesses the accessibility compliance of the learning-portal v2 release. It is a pre-release conformance confirmation, not a full re-audit. The v2 release builds upon the v1 release, which was audited against WCAG 2.1 AA and signed off by the Accessibility Board in Q1 2025. The v1 conformance report remains current, and the v2 release has been reviewed for changes in page structure, color palette, and keyboard navigation, confirming no material changes from v1. The v2 release introduces a voice-command input path, necessitating additional conformance items as per the Accessibility Office Q4 2025 bulletin.

## Conformance Summary

### Retained v1 Criteria

- **Page Structure:** The page structure remains unchanged from v1, ensuring continued compliance with WCAG 2.1 AA success criteria related to content structure and navigation.
- **Color Palette:** The color palette has not been altered, maintaining accessibility standards for color contrast and visual presentation.
- **Keyboard Navigation:** The keyboard navigation surface remains consistent with v1, ensuring all interactive elements are accessible via keyboard input.

### New v2 Voice-Command Input Path

The v2 release introduces a voice-command input path, allowing learners to issue spoken commands for navigation and submission. This addition requires compliance with the "Input Modality Update — Speech Interfaces" item from the Accessibility Office Q4 2025 bulletin.

#### Modality Alternative Mapping

For each voice command, the following must be documented:

1. **Equivalent Non-Voice Control:** For every voice command, an equivalent non-voice control (e.g., keyboard or pointer input) must be identified to ensure functionality is accessible without voice input.
   
2. **Transcription-Failure Fallback:** A fallback mechanism must be in place for transcription failures. This ensures that learners can still interact with the portal using alternative input methods if voice recognition fails.

3. **Timeout Mechanism:** A timeout feature must be implemented that returns the learner to a usable non-voice pathway if a voice command is not successfully recognized within a reasonable timeframe.

#### Compliance Confirmation

- **Mapping Assembly:** The Modality Alternative Mapping has been assembled for all voice commands, ensuring that each command has an equivalent non-voice control and appropriate fallbacks.
- **Fallback and Timeout Documentation:** The transcription-failure fallback and timeout mechanisms have been documented for the release, ensuring safe return to non-voice pathways.

### Overall Conformance

The learning-portal v2 maintains all success criteria met in the v1 release and introduces additional compliance measures for the new voice-command input path. The conformance to WCAG 2.1 AA standards is confirmed for both existing and new functionalities.

## Conclusion

The learning-portal v2 release has been reviewed for accessibility compliance, retaining all criteria met in the v1 release and incorporating necessary measures for the new voice-command input path. The Modality Alternative Mapping, along with fallback and timeout mechanisms, ensures that the portal remains accessible to all users, regardless of input modality. This report is submitted for review and confirmation by the Accessibility Board.
