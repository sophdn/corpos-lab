# Learning Portal v2 Conformance Report

## Executive Summary
This conformance report addresses the compliance of Learning Portal v2 with WCAG 2.1 AA standards, focusing on the new voice-command input path introduced in this version. The v1 conformance report remains current for all aspects except those related to the new modality. The Accessibility Board has reviewed and approved the addition of the voice-command feature, ensuring that it adheres to the new policy requirements set out in the 2025 Q4 accessibility bulletin.

## Conformance to WCAG 2.1 AA
The Learning Portal v2 maintains all success criteria met in the v1 release. The core structure, color palette, and keyboard navigation have not been altered and continue to comply with WCAG 2.1 AA standards as documented in the v1 conformance report.

## Voice-Command Input Path
### Introduction
Version 2.0 introduces a voice-command input path, allowing learners to issue spoken commands for navigation and form submission. This functionality is supported by the browser's speech API, transcribing spoken words into actionable commands within the portal.

### Modality Alternative Mapping
In accordance with the "Input Modality Update — Speech Interfaces" directive from the 2025 Q4 accessibility bulletin, a Modality Alternative Mapping has been created for the voice-command path. This mapping includes:

1. **Equivalent Non-Voice Control**: For every voice command, an equivalent keyboard or pointer control has been identified and documented. This ensures that users who cannot or choose not to use voice commands have a viable alternative.

2. **Transcription-Failure Fallback**: In cases where the speech API fails to accurately transcribe spoken commands, the system will:
   - Notify the user of the transcription failure.
   - Provide an option to retry the voice command.
   - Allow the user to switch to an alternative input method immediately.

3. **Timeout and Usable Non-Voice Pathway**: The voice-command system includes a timeout mechanism. If a user does not issue a command within a specified period, the system will:
   - Return the user to a state where they can continue using pointer or keyboard inputs.
   - Ensure that the timeout duration is reasonable and documented for user accessibility.

### Safety and Usability
The voice-command path is designed to fail safe, meaning that if the voice-command system cannot assemble a mapping for a particular command, the user will be seamlessly redirected to a non-voice pathway without losing data or context.

## Conclusion
The Learning Portal v2 complies with WCAG 2.1 AA standards, maintaining all the criteria met in the v1 release. The addition of the voice-command input path has been thoroughly mapped to ensure equivalent non-voice interactions, robust error handling, and safe fallback mechanisms. The Accessibility Board is requested to review and approve this conformance report.
