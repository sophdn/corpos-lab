# Learning-Portal v2 Conformance Report

## Introduction

This report documents the accessibility conformance of the learning-portal v2 release against WCAG 2.1 AA standards. It incorporates the findings from the v1 release and addresses new elements introduced in v2, specifically the voice-command input path.

## Conformance to v1 Criteria

The learning-portal v1 was audited and confirmed to meet all WCAG 2.1 AA success criteria. Since the v2 release retains the same page structure, color palette, and keyboard navigation, all the criteria from the v1 conformance report apply without modification. The v1 conformance report, signed off in Q1 2025, remains current for these aspects.

## New Input Modality: Voice Commands

In accordance with the Accessibility Office Q4 2025 bulletin, the introduction of a voice-command input path necessitates a new conformance item: Modality Alternative Mapping. This mapping ensures that all voice commands have equivalent non-voice controls, along with a transcription-failure fallback and a timeout mechanism to return the learner to a usable non-voice pathway.

### Modality Alternative Mapping

For each voice command implemented in the learning-portal v2, the following details are documented:

1. **Equivalent Non-Voice Control**: Describe the keyboard or other non-voice control equivalent for each voice command. This ensures that all functionalities are accessible via traditional input methods.

2. **Transcription-Failure Fallback**: Specify the fallback mechanism in the event of a transcription failure. This should provide clear feedback to the user and offer alternative methods to achieve the intended action.

3. **Timeout Mechanism**: Detail the timeout procedure that returns the learner to a usable non-voice pathway if the voice command is not recognized within a specified period. This ensures that the user is not left in an unusable state.

### Implementation Details

- **Voice Command Recognition**: The browser's speech API is used to transcribe spoken commands. This process must be tested to ensure it works reliably across different devices and browsers.

- **Feedback and Error Handling**: Users should receive immediate feedback on whether their command was recognized and executed. In case of errors, clear instructions should guide the user on how to proceed.

- **Testing and Validation**: Conduct thorough testing with users who rely on voice input to ensure that the voice-command path is intuitive and accessible. This includes testing for various accents, speech impediments, and background noise conditions.

## Conclusion

The learning-portal v2 has been evaluated for accessibility conformance, maintaining compliance with WCAG 2.1 AA standards as established in the v1 release. The addition of the voice-command input path has been addressed with a comprehensive Modality Alternative Mapping, ensuring that all users have equitable access to the portal's functionalities.

This report is submitted for review and approval by the Accessibility Board.
