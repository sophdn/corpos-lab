# Conformance Report for Learning Portal v2

## Introduction

This report serves as a pre-release conformance confirmation for the learning-portal v2 release. The report ensures compliance with WCAG 2.1 AA standards, building upon the successful audit of the v1 release. The v1 conformance report remains current, with the board's confirmation that the core structure, color palette, and keyboard navigation have not changed in v2. The primary addition in v2 is the introduction of a voice-command input path.

## Conformance to WCAG 2.1 AA

The v1 release met all success criteria under WCAG 2.1 AA standards. As the structural and interactive elements of v2 remain unchanged from v1, the existing conformance criteria continue to apply. The following sections detail any v2-specific changes and confirm ongoing compliance.

### 1. Perceivable

- **Non-Verbal Content:** Text alternatives for non-text content remain unchanged and continue to meet WCAG 2.1 AA requirements.
- **Adaptable Content:** Content structure is consistent with v1, ensuring adaptability for various user needs.

### 2. Operable

- **Keyboard Accessible:** The pointer and keyboard navigation paths remain unchanged, ensuring operability for users who rely on these methods.
- **Voice Command Path:** A new voice-command input path has been added. This path requires additional documentation to ensure compliance with the new policy requirements.

### 3. Understandable

- **Readable Content:** Text readability and language comprehension remain consistent with v1 standards.
- **Input Modality Update:** The introduction of voice commands necessitates additional documentation as per the Accessibility Office Q4 2025 bulletin.

### 4. Robust

- **Compatibility:** The platform continues to be compatible with current and future user agents, including the new voice-command functionality.

## Voice Command Path Compliance

In accordance with the Accessibility Office Q4 2025 bulletin, the addition of a voice-command input path requires a Modality Alternative Mapping. This mapping includes:

- **Equivalent Non-Voice Controls:** For each voice command, an equivalent non-voice control must be documented.
- **Transcription-Failure Fallback:** A clear fallback mechanism must be in place for transcription failures.
- **Timeout Mechanism:** A timeout that returns the learner to a usable non-voice pathway must be documented and fail-safe.

### Modality Alternative Mapping

For each voice command, the following must be documented:

1. **Voice Command:** Description of the spoken command.
2. **Equivalent Non-Voice Control:** Corresponding keyboard or pointer action.
3. **Transcription-Failure Fallback:** Procedure for handling transcription errors.
4. **Timeout Return Pathway:** Steps to return to a non-voice pathway after a timeout.

## Conclusion

The learning-portal v2 release maintains compliance with WCAG 2.1 AA standards as established in the v1 audit. The addition of a voice-command input path has been documented in accordance with the new policy requirements. The board is requested to review and sign off on this conformance report to confirm that the v2 release meets all accessibility standards.
