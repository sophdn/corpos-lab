# Learning Portal v2 Conformance Report

## Executive Summary

The Learning Portal version 2 (v2) release introduces a voice-command input path, building on the accessibility features of version 1 (v1) that met WCAG 2.1 AA standards as confirmed in Q1 2025 by the Accessibility Board. This report confirms that v2 retains all accessibility success criteria from v1 and adds necessary compliance measures for the new voice-command feature, adhering to the "Input Modality Update — Speech Interfaces" policy from the Q4 2025 Accessibility Office bulletin.

## Conformance to WCAG 2.1 AA

### Success Criteria Inherited from v1

1. **Perceivable**:
   - Page structure, color palette, and keyboard navigation remain unchanged from v1.
   - All content remains perceivable through multiple modalities, as per v1 conformance.

2. **Operable**:
   - Keyboard navigation is unchanged and fully operable as per v1 standards.
   - Voice-command input path added, ensuring operability through speech interfaces.

3. **Understandable**:
   - Interface design and error handling remain consistent with v1, ensuring understandability.
   - Voice commands are designed to be intuitive and consistent with existing navigation patterns.

4. **Robust**:
   - The system remains robust across various browsers and assistive technologies, with the addition of the browser speech API for voice-command functionality.

### Additional Success Criteria for v2

#### Modality Alternative Mapping

In compliance with the "Input Modality Update — Speech Interfaces" policy, the following mappings have been documented for the voice-command input path:

1. **Equivalent Non-Voice Controls**:
   - Each voice command has an equivalent action that can be performed using the keyboard or mouse. For example, "Next page" can be executed via the "Next" button on the keyboard or mouse click.

2. **Transcription-Failure Fallback**:
   - If the browser speech API fails to transcribe a command, the system will prompt the user with an alternative input method, such as a keyboard shortcut or on-screen button.

3. **Timeout and Usable Non-Voice Pathway**:
   - A timeout mechanism is in place to return the learner to a usable non-voice pathway if the voice command is not recognized within a specified time frame. This ensures continuity and usability without reliance on voice input.

## Conformance Summary

The Learning Portal v2 retains full conformance to WCAG 2.1 AA standards as established by the v1 release. The addition of the voice-command input path has been thoroughly evaluated to ensure accessibility and usability across all input modalities. The Modality Alternative Mapping has been documented, and all necessary fallbacks and pathways have been implemented to meet the new policy requirements.

## Conclusion

The Learning Portal v2 has been reviewed and confirmed to meet all necessary accessibility criteria, including the newly required Modality Alternative Mapping for the voice-command input path. The board's previous confirmation of v1's compliance provides a strong foundation, and the additional measures for v2 ensure continued adherence to WCAG 2.1 AA standards. The board is invited to review this report and provide any further guidance or approval as needed.
