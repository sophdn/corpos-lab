### 3. Voice Command Input Path

**Findings:**

- A voice-command input path has been added to v2, allowing learners to issue spoken commands for navigation and submission.
- The browser's speech API is used for transcribing these commands.

**New Requirement: Modality Alternative Mapping**

According to the Accessibility Office Q4 2025 bulletin, the introduction of a spoken-input path necessitates a Modality Alternative Mapping. This mapping should include:

- **Equivalent Non-Voice Control:** For every voice command, there must be an equivalent non-voice control mechanism.
- **Transcription-Failure Fallback:** A clear fallback method must be documented for cases where speech transcription fails.
- **Timeout Mechanism:** A timeout must be implemented to return the learner to a usable non-voice pathway if the voice command is not successfully executed within a reasonable timeframe.

**Conformance:**

- The Learning Portal v2 includes a comprehensive Modality Alternative Mapping. Each voice command has been mapped to an equivalent non-voice control.
- A transcription-failure fallback has been documented and implemented, ensuring accessibility in case of speech recognition errors.
- A timeout mechanism has been established to ensure learners can revert to a non-voice pathway if necessary.

### 4. Input and Error Handling

**Findings:**

- Input and error-handling criteria from v1, written in modality-agnostic terms, continue to apply.
- The addition of voice commands does not affect the existing input and error-handling mechanisms.

**Conformance:**
