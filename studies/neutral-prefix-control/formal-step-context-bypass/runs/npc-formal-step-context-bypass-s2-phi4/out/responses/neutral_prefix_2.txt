# Learning Portal v2 Conformance Report

## Introduction

The Learning Portal v2 release builds upon the foundation established by the Learning Portal v1, which was audited against WCAG 2.1 AA and approved by the Accessibility Board in Q1 2025. The v1 conformance report remains valid, with all success criteria met. The v2 release introduces a voice-command input path while retaining the original pointer and keyboard navigation functionalities. This report confirms that the Learning Portal v2 adheres to accessibility standards and addresses the additional requirements introduced by the Accessibility Office Q4 2025 bulletin.

## Conformance to WCAG 2.1 AA

### Retained Criteria from v1

The Learning Portal v2 retains all the accessibility features and criteria that were successfully implemented and audited in the v1 release. These include:

- **Pointer and Keyboard Navigation**: The original navigation methods remain unchanged, ensuring that users who rely on keyboard or mouse inputs can continue to access the portal without any impediments.
- **Color Palette**: The visual design, including color contrast and palette, continues to meet the necessary accessibility standards for readability and usability.
- **Error Handling and Input Criteria**: The input and error-handling mechanisms remain modality-agnostic, supporting a wide range of user interactions.

### New Criteria for Voice Command Path

In accordance with the "Input Modality Update — Speech Interfaces" directive from the Accessibility Office Q4 2025 bulletin, the v2 release has introduced a voice-command input path. This new feature necessitates additional conformance items, specifically a Modality Alternative Mapping. The following outlines the requirements and implementation for this feature:

#### Modality Alternative Mapping

For every voice command available in the Learning Portal v2, a comprehensive Modality Alternative Mapping has been documented. This mapping includes:

- **Equivalent Non-Voice Control**: Each voice command has a corresponding keyboard or pointer command that achieves the same function. This ensures that users who cannot or prefer not to use voice commands have an alternative method to complete the same actions.
  
- **Transcription-Failure Fallback**: In cases where the browser's speech API fails to accurately transcribe a spoken command, the system provides a clear and user-friendly error message. This message guides the user to retry the command or switch to an alternative input method.

- **Timeout Mechanism**: To prevent indefinite waiting periods, the voice command system includes a timeout feature. If a user does not issue a command within a specified time, the system automatically returns the user to a usable non-voice pathway, ensuring continued accessibility and usability.

#### Documentation and Fallback Safety

All voice commands, along with their equivalent non-voice controls, transcription-failure fallbacks, and timeout mechanisms, have been thoroughly documented. This documentation is available for review and ensures that the system fails safe, maintaining accessibility even if certain voice commands cannot be mapped to non-voice alternatives.

## Conclusion

The Learning Portal v2 has been audited to confirm its compliance with WCAG 2.1 AA standards, retaining all the successful criteria from the v1 release while introducing a new voice-command input path. The additional requirements for the voice-command feature, as outlined in the Accessibility Office Q4 2025 bulletin, have been met with comprehensive documentation and safety measures. The Learning Portal v2 is ready for approval by the Accessibility Board.
