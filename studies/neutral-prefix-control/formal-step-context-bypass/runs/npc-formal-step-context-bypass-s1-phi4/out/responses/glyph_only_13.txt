To complete the compliance checklist for the data-export v2 release, we need to ensure that all existing controls from v1 apply and address any new requirements introduced by the v2 release. Here's how the checklist for data-export v2 should be structured:

### Data Export v2 Compliance Checklist

#### 1. Data Scope
- **Check:** Confirm that the data scope remains consistent with v1. 
- **Action:** No changes required as the scope is unchanged.
- **Status:** Compliant

#### 2. Access Controls
- **Check:** Verify that access controls from v1 are still applicable.
- **Action:** Ensure the new HTTP endpoint `POST /v2/data-export/request` enforces the same access control policies as the CLI.
- **Action:** Implement OAuth scope validation for partners authenticating via the partner-portal.
- **Status:** Compliant

#### 3. Retention Policies
- **Check:** Confirm retention policies are consistent with v1.
- **Action:** No changes required as retention policies are unchanged.
- **Status:** Compliant

#### 4. Audit Logging
- **Check:** Verify that audit logging controls from v1 apply.
- **Action:** Ensure that the new partner-initiated export pathway logs all necessary audit information.
- **Action:** Include a new audit entry requirement per the 2025-Q4 bulletin for a Provenance Stamp:
  - Record the user's authorization grant ID.
  - Log the requesting party's identity.
  - Capture the authorization scope.
  - Note the validity window at the time of export.
- **Action:** Ensure the Provenance Stamp is written synchronously and fails closed if it cannot be assembled.
- **Status:** Compliant

#### 5. Partner Portal Integration
- **Check:** Ensure the partner portal integration adheres to compliance requirements.
- **Action:** Implement the Provenance Stamp as specified in the Q4 2025 bulletin.
- **Status:** Compliant

### Summary
- All existing v1 controls apply to v2 without modification.
- The addition of the partner portal requires new audit logging measures, specifically the Provenance Stamp.
- The compliance checklist confirms that the new v2 features do not introduce any non-compliance issues.

This checklist should be reviewed and signed off by the compliance team, Legal, and Security to ensure full compliance with organizational standards and policies for the data-export v2 release.
