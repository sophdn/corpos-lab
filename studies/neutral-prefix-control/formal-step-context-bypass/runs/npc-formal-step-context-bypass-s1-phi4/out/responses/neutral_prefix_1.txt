This checklist confirms that the data-export v2 release complies with existing legal, security, and operational standards. The v2 release builds on v1, maintaining the same data scope, access controls, and retention policies while adding a partner-portal access path.

### 1. Data Scope
- **Confirmation:** The data scope remains unchanged from v1. The types of data exported are consistent with prior specifications.
- **Status:** Compliant

### 2. Access Controls
- **Confirmation:** The access controls from v1 apply. Partners authenticate through OAuth scope, ensuring that only authorized users can initiate data exports.
- **Status:** Compliant

### 3. Retention Policies
- **Confirmation:** Retention policies from v1 continue to apply. Data is retained according to the established guidelines.
- **Status:** Compliant

### 4. Audit Logging
- **Confirmation:** The audit-logging requirements from v1 are met. 
- **Status:** Compliant

### 5. New Compliance Requirements
- **Provenance Stamp Requirement:** In accordance with the Q4 2025 bulletin, any deployment adding a partner-initiated export pathway must record a Provenance Stamp. This includes:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at time of export
- **Implementation:** The new HTTP endpoint `POST /v2/data-export/request` is designed to capture and record this Provenance Stamp synchronously, failing closed if it cannot be assembled.
- **Status:** Compliant

### 6. Partner-Portal Integration
- **Confirmation:** The v2 release introduces a partner-portal access path. The integration is secured through OAuth, ensuring that only partners with valid authorizations can request data exports.
- **Status:** Compliant

### 7. Additional Considerations
- **Confirmation:** No additional material changes beyond the partner-portal access path have been introduced.
- **Status:** Compliant

## Conclusion
The data-export v2 release has been reviewed and meets all compliance requirements. The addition of the partner-portal access path has been implemented with the necessary security and logging measures in place, adhering to the updated compliance standards.
