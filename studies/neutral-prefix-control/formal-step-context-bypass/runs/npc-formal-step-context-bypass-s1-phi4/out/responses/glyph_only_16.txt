To create the v2 compliance checklist for the data-export v2 release, we'll focus on confirming that the existing controls from v1 still apply and address any new requirements introduced by the addition of a partner-portal access path. Given the information provided, the checklist should ensure compliance with the new audit entry requirement specified in the 2025-Q4 bulletin.

Here's a structured approach to drafting the v2 compliance checklist:

### Data Export v2 Compliance Checklist

#### Overview
- **Release Version:** v2
- **Scope:** Adds partner-portal access path with OAuth authentication.
- **Compliance Review Date:** [Insert Date]
- **Prepared By:** [Your Name/Compliance Team]

#### Compliance Areas

1. **Data Scope**
   - Confirm that the data scope remains unchanged from v1.
   - Verify that data access through the new partner-portal endpoint adheres to existing data scope policies.
   - **Status:** Compliant

2. **Access Controls**
   - Ensure that OAuth scope-based authentication for partners is implemented correctly.
   - Validate that only partners with active authorizations can initiate exports.
   - **Status:** Compliant

3. **Retention Policies**
   - Confirm that data retention policies are consistent with v1.
   - Ensure that data exported via the partner-portal is subject to the same retention policies.
   - **Status:** Compliant

4. **Audit Logging**
   - Verify that existing audit logging mechanisms are in place and operational.
   - **New Requirement:** Implement the Provenance Stamp for partner-initiated exports.
     - Capture the user's authorization grant ID.
     - Record the requesting party's identity.
     - Log the authorization scope.
     - Document the validity window at the time of export.
     - Ensure the Provenance Stamp is written synchronously and fails closed if it cannot be assembled.
   - **Status:** Compliant (New Requirement Implemented)

5. **Security Controls**
   - Confirm that security measures from v1 are still applicable.
   - Ensure that the new HTTP endpoint is secured and follows best practices for OAuth implementations.
   - **Status:** Compliant

#### Summary
- All v1 compliance controls remain applicable and have been confirmed.
- The new requirement for a Provenance Stamp has been implemented in accordance with the 2025-Q4 bulletin.
- No material changes to data scope, access controls, or retention policies have been made beyond the partner-portal integration.

#### Sign-off
- **Compliance Officer:** [Your Name]
- **Legal and Security Approval:** [Names/Signatures]

This checklist ensures that the v2 release complies with existing policies and incorporates new requirements introduced by the partner-portal access path. It provides a clear record for the compliance team and facilitates a smooth deployment.
