# Data Export v2 Compliance Checklist

## Data Scope

- [x] Data scope remains unchanged from v1.  
  - **Confirmation**: The v2 specification confirms that the data scope is identical to v1, with no new data types being exported.

## Access Controls

- [x] Access controls remain unchanged from v1.
  - **Confirmation**: The v2 specification retains the v1 CLI surface and adds an HTTP endpoint for partner-portal integration. Partners authenticate via OAuth scope, ensuring that only authorized entities can request data exports.

## Retention Policies

- [x] Retention policies remain unchanged from v1.
  - **Confirmation**: The v2 specification does not introduce any changes to data retention policies, maintaining the existing guidelines.

## Audit Logging

- [x] Audit logging requirements from v1 apply.
  - **Confirmation**: The audit-logging requirements are pathway-agnostic and continue to be applicable.

- [ ] Additional audit entry required for v2.
  - **Requirement**: As per the Compliance Office Q4 2025 bulletin, any deployment adding a partner-initiated export pathway must record an additional audit entry, known as a Provenance Stamp.
  - **Details**:
    - Capture the user's authorization grant ID.
    - Record the requesting party's identity.
    - Document the authorization scope.
    - Note the validity window at the time of export.
    - Ensure the entry is written synchronously and fails closed if it cannot be assembled.

## Partner-Portal Integration

- [x] Partner-portal access path added.
  - **Confirmation**: The v2 spec introduces an HTTP endpoint `POST /v2/data-export/request` for partner-portal integration, with partners authenticating via OAuth scope.
