# Deployments / Data-Export v2 / Compliance Checklist

---

## Introduction

This checklist is for the v2 release of the data-export service, set to deploy on Friday. This checklist confirms that compliance requirements are met for the v2 release, focusing on changes introduced with the partner-portal access path. The v2 release maintains unchanged data scope, access controls, and retention policies from v1, with the compliance team having confirmed this alignment.

---

## Data Scope

- **v1 Compliance**: The data scope remains unchanged from v1.
- **v2 Confirmation**: Confirm that the data scope in v2 remains consistent with v1.
- **Status**: Compliant.

---

## Access Controls

- **v1 Compliance**: Access controls from v1 were compliant and pathway-agnostic.
- **v2 Changes**: 
  - v2 introduces an HTTP endpoint (`POST /v2/data-export/request`) for partner-portal integration.
  - Partners authenticate via OAuth scope and request exports for users with active authorization.
- **Additional Requirements**: 
  - Ensure OAuth scope is correctly implemented and verified.
  - Confirm that only users with active authorization can initiate exports.
- **Status**: Compliant.

---

## Audit Logging

- **v1 Compliance**: The v1 checklist indicated compliance with audit logging requirements.
- **v2 Changes**: 
  - New requirement to record a Provenance Stamp for partner-initiated export pathways.
  - Provenance Stamp must capture:
    - User's authorization grant ID
    - Requesting party's identity
    - Authorization scope
    - Validity window at time of export
  - Must be written synchronously and fail closed if unable to assemble.
- **Implementation**: Ensure Provenance Stamp is implemented and tested for failure scenarios.
- **Status**: Compliant.
