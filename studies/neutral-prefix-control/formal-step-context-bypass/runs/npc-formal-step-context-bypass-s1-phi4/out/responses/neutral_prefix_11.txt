# Compliance Checklist for Data Export v2

**Review Date:** Q4 2025  
**Review Status:** Completed  
**Approval:** Pending

---

## 1. Data Scope

- **Compliance Verification:** 
  - The data scope for v2 remains unchanged from v1.
  - No new data types or fields are exposed through the partner-portal access path.

- **Status:** Confirmed  
  - All data types remain within the approved scope.

## 2. Access Controls

- **Compliance Verification:** 
  - v2 introduces a new HTTP endpoint `POST /v2/data-export/request` for partner portal access.
  - Partners authenticate using OAuth scope.
  - Export requests are made for users with active authorizations.

- **Status:** Confirmed  
  - OAuth scope-based authentication aligns with the existing access control policies.
  - Active authorizations ensure compliance with access control requirements.

## 3. Retention Policies

- **Compliance Verification:** 
  - Retention policies for v2 are identical to v1.
  - No changes in data retention periods or procedures.

- **Status:** Confirmed  
  - Retention policies remain compliant with organizational standards.

## 4. Audit Logging

- **Compliance Verification:** 
  - v2 introduces a requirement for a Provenance Stamp for partner-initiated export pathways.
  - The Provenance Stamp must capture:
    - User's authorization grant ID
    - Requesting party's identity
    - Authorization scope
    - Validity window at time of export
  - Must be written synchronously and fail closed if not possible.

- **Status:** Action Required  
  - Ensure logging mechanism for Provenance Stamp is implemented and tested.
  - Validate that the system fails closed if the Provenance Stamp cannot be recorded.

## 5. General Compliance

- **Compliance Verification:** 
  - Confirm that all previous v1 compliance controls still apply.
  - Verify that the addition of the partner-portal access path does not introduce new compliance risks.

- **Status:** Confirmed  
  - All v1 compliance controls are applicable to v2.
  - No new compliance risks identified with the addition of the partner-portal access path.
