To ensure compliance for the data-export v2 release, we will create a checklist that confirms adherence to existing protocols and identifies any new requirements introduced by the addition of the partner-portal access path. Given that the core data scope, access controls, and retention policies from v1 remain unchanged, our focus will be on verifying the new audit entry requirement specified in the Q4 2025 bulletin.

### Deployments: Data-Export v2 Compliance Checklist

#### 1. Data Scope
- [ ] Confirm that the data scope for v2 remains identical to v1. No changes in the types of data being exported.

#### 2. Access Controls
- [ ] Verify that access controls for the CLI interface are unchanged from v1.
- [ ] Ensure that the new HTTP endpoint `POST /v2/data-export/request` implements access controls via OAuth scopes, as specified in the v2 spec.

#### 3. Retention Policies
- [ ] Confirm that retention policies remain consistent with v1, with no modifications required for v2.

#### 4. Audit Logging
- [ ] Ensure that existing audit-logging mechanisms for the CLI interface continue to function as per v1 standards.
- [ ] Implement a new audit entry, termed a "Provenance Stamp," for the partner-portal access path. This entry must capture:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
- [ ] Ensure that the Provenance Stamp is written synchronously and configured to fail closed if it cannot be assembled.

#### 5. Partner-Portal Access Path
- [ ] Confirm that the integration with the partner portal through `POST /v2/data-export/request` adheres to the specified authentication and authorization mechanisms.
- [ ] Verify that the Provenance Stamp is correctly implemented to capture necessary data for compliance with the Q4 2025 bulletin.

#### 6. General Compliance
- [ ] Review the v2 specification for any other potential compliance implications not covered by the above sections.
- [ ] Ensure that all compliance documentation is up-to-date and reflects the current state of the v2 release.

### Conclusion
Upon completion of the checklist, confirm that all items are addressed and documented. This checklist should be reviewed and signed off by the appropriate compliance, legal, and security teams before the deployment of data-export v2.
