# Data-Export v2 Compliance Checklist

## Access Controls

- **Scope**: The data scope remains consistent with v1, ensuring no new data types are exposed.
- **Access Path**: The addition of a partner-portal access path via `POST /v2/data-export/request` is implemented. Partners authenticate using OAuth scope, ensuring secure access.
- **Authorization**: Partners must have an active authorization from users to request data exports. This maintains user consent and control over data sharing.

## Audit Logging

- **Audit Entries**: The v1 audit logging mechanism remains unchanged for CLI access. For the new partner-portal pathway, an additional audit entry, termed a Provenance Stamp, is required.
- **Provenance Stamp**: This entry must capture:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
- **Synchronous Logging**: The Provenance Stamp must be written synchronously. The process should fail closed if any component of the stamp cannot be assembled, ensuring integrity and traceability.

## Retention Policies

- **Data Retention**: No changes to data retention policies from v1. Data is retained according to the established guidelines, ensuring compliance with data protection regulations.

## Security

- **Authentication**: OAuth scope is used for partner authentication, aligning with industry standards for secure access.
- **Data Integrity**: The synchronous writing of the Provenance Stamp ensures data integrity and accountability.

## Compliance with Policy Bulletin

- **Policy Bulletin Compliance**: The deployment adheres to the Q4 2025 bulletin requirement for recording a Provenance Stamp for partner-initiated export pathways.

## Conclusion

The v2 deployment maintains all v1 compliance controls and introduces necessary enhancements for the partner-portal integration. The Provenance Stamp requirement is implemented to ensure auditability and compliance with the latest policy bulletin.

---

This checklist confirms that the data-export v2 release complies with existing policies and introduces the necessary controls for the new partner-initiated export pathway. The v1 checklist items remain applicable, with specific updates for v2 addressed above.
