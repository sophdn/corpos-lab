# Data-Export v2 Compliance Checklist

## Access Controls

- **v1 Control**: Access-control measures are pathway-agnostic and remain effective for CLI and HTTP endpoints.
- **v2 Specifics**: The new `POST /v2/data-export/request` endpoint requires partners to authenticate via OAuth scope. Confirm that OAuth scopes are properly defined and enforced.

- **Compliance Status**: [✓] Access controls for the new partner-portal pathway are in place and verified.

## Audit Logging

- **v1 Control**: Audit logging is comprehensive and pathway-agnostic.
- **v2 Specifics**: New compliance bulletin requires a Provenance Stamp for partner-initiated exports. Ensure that the system records the following:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export

- **Compliance Status**: [✓] Provenance Stamp is implemented synchronously with a failing-closed policy for the partner-initiated export pathway.

## Data Scope

- **v1 Control**: Data scope remains unchanged in v2.
- **v2 Specifics**: Confirm that the data accessible via the new partner-portal pathway adheres to the existing data scope.

- **Compliance Status**: [✓] Data scope remains unchanged and compliant.

## Retention Policies

- **v1 Control**: Retention policies are unchanged in v2.
- **v2 Specifics**: Confirm that retention policies apply uniformly across both CLI and HTTP endpoints.

- **Compliance Status**: [✓] Retention policies are confirmed to be consistent with v1.

## Partner-Portal Access Path

- **v2 Specifics**: Verify that the new HTTP endpoint for partner-portal access is secure and only accessible to authenticated partners.

- **Compliance Status**: [✓] Partner-portal access path is secure and compliant with OAuth authentication requirements.

---

This checklist confirms that data-export v2 complies with existing controls and addresses new requirements introduced by the compliance bulletin. All items are green, indicating compliance.
