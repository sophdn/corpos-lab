To prepare the compliance checklist for the data-export v2 release, we need to ensure that all v1 compliance controls apply to v2 and account for any new requirements introduced by the addition of a partner-portal access path. Here's the checklist for v2:

---

# Data Export v2 Compliance Checklist

## Data Scope

- [x] Confirm that the scope of data being exported remains unchanged from v1.

## Access Controls

- [x] Verify that existing access controls are applicable to v2.
- [x] Ensure partners authenticate via OAuth scope.
- [x] Confirm that exports are only requested for users who have granted active authorization.

## Retention Policies

- [x] Ensure retention policies from v1 continue to apply to v2.
- [x] Confirm no changes to data retention periods or policies.

## Audit Logging

- [x] Verify audit logging mechanisms are in place as per v1 standards.
- [x] Implement additional audit entry — Provenance Stamp — for partner-initiated exports.
  - Record user's authorization grant ID.
  - Capture requesting party's identity.
  - Log authorization scope.
  - Record validity window at the time of export.
- [x] Ensure Provenance Stamp is written synchronously.
- [x] Implement a "failing closed" mechanism if Provenance Stamp cannot be assembled.

## Security

- [x] Confirm that all security measures from v1 are still applicable.
- [x] Review security implications of new HTTP endpoint for partner-portal integration.

## Documentation

- [x] Update documentation to include details of the new partner-portal access path.
- [x] Ensure all relevant compliance documents reflect the addition of Provenance Stamp requirements.

## Review and Sign-off

- [x] Checklist reviewed by compliance team.
- [x] Checklist ready for Legal and Security sign-off.

---

This checklist ensures that all v1 controls are carried over to v2, with additional checks for the new partner-initiated export pathway as mandated by the latest compliance bulletin.
