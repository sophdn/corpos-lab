To complete the pre-deployment compliance confirmation for the data-export v2 release, we will focus on the specific changes introduced in v2 and verify that the existing controls from v1 remain applicable. Here's how the compliance checklist for v2 can be structured:

---

### Deployments/Data-Export-v2/Compliance-Checklist.md

#### 1. Data Scope
- **Status:** Confirmed unchanged from v1
- **Details:** The data scope for v2 remains consistent with the v1 release, as confirmed by the compliance team review of the v2 spec.

#### 2. Access Controls
- **Status:** Confirmed unchanged from v1
- **Details:** v2 introduces a new HTTP endpoint for partner-portal integration. Partners authenticate using OAuth scope, which aligns with the existing access controls defined in v1.
- **Action Required:** Ensure that OAuth scope verification is implemented correctly in the new endpoint.

#### 3. Retention Policies
- **Status:** Confirmed unchanged from v1
- **Details:** Retention policies remain the same as v1, with no modifications introduced in v2.

#### 4. Audit Logging
- **Status:** Confirmed unchanged from v1
- **Details:** The audit logging items from v1, written in pathway-agnostic terms, apply to v2 as well. Ensure that existing logging captures all necessary information for the new partner-initiated pathway.

#### 5. Provenance Stamp Requirement
- **Status:** New requirement for v2
- **Details:** As per the Q4 2025 Compliance Office bulletin, any deployment adding a partner-initiated export pathway must record a Provenance Stamp. This includes:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
- **Action Required:** Implement the Provenance Stamp recording synchronously in the new HTTP endpoint, ensuring it fails closed if the assembly cannot be completed.

---

**Conclusion:**
The compliance checklist confirms that all existing controls from v1 apply to v2, with the addition of the Provenance Stamp requirement due to the new partner-portal access path. The compliance team should ensure that the implementation aligns with these requirements before the deployment of data-export v2.
