# Accessibility Conformance Report: Learning Portal v2

**Release:** learning-portal-v2
**Standard:** WCAG 2.1 AA
**Date:** [Current Date]
**Status:** **NON-CONFORMANT (Fail-Safe Applied)**

## 1. Executive Summary
This report confirms the accessibility conformance of Learning Portal v2. While the structural, color, and keyboard navigation components remain unchanged from the v1 release (which was fully compliant), v2 introduces a new voice-command input path.

Per the Accessibility Office Q4 2025 Bulletin ("Input Modality Update — Speech Interfaces"), releases adding spoken-input paths must include a **Modality Alternative Mapping**.

**Conclusion:** The required Modality Alternative Mapping could not be fully assembled from the provided release documentation. Specifically, the **timeout mechanism** required to return learners to a usable non-voice pathway upon transcription failure is not documented in the v2 change summary. Consequently, the release triggers the **fail-safe** provision of the bulletin. Conformance is not confirmed.

## 2. v1 Baseline Confirmation
*   **Page Structure:** Unchanged from v1. (Confirmed via Change Summary)
*   **Color Palette:** Unchanged from v1. (Confirmed via Change Summary)
*   **Keyboard Navigation:** Unchanged from v1. (Confirmed via Change Summary)
*   **v1 Conformance Status:** All success criteria met per `releases/learning-portal-v1/conformance-report.md` (Q1 2025 Sign-off). These criteria continue to apply and are assumed to remain met for the unchanged components.

## 3. v2 New Feature: Voice-Command Input Path
**Description:** Learners may issue spoken commands to navigate and submit answers. Transcription is handled by the browser speech API.

### 3.1 Prerequisite Sub-Step Record: Modality Alternative Mapping
*Required by: `policy/bulletins/2025-Q4-accessibility-bulletin.md`*

| Component | Status | Details |
| :--- | :--- | :--- |
| **Voice Command Inventory** | **Partial** | Commands identified: "Navigate [Location]", "Submit Answer". |
| **Equivalent Non-Voice Control** | **Met** | Navigation: Standard keyboard navigation (Tab/Arrow keys) remains available. Submission: Standard form submit button (Enter key or mouse click) remains available. |
| **Transcription-Failure Fallback** | **Met** | If transcription fails, the system should allow manual input via existing keyboard/form controls. |
| **Timeout Mechanism** | **MISSING** | **FAIL-SAFE TRIGGERED.** The v2 Change Summary does not specify a timeout duration or mechanism that automatically returns the learner to a usable non-voice pathway if the speech API fails or hangs. |

**Fail-Safe Determination:**
Because the timeout mechanism is not documented, the Modality Alternative Mapping cannot be considered complete. Per the Q4 2025 Bulletin, this release is treated as **non-conformant** for the new input modality.

## 4. Recommendations for Release

2.  **Re-Audit:** Once the timeout mechanism is defined and documented, the Modality Alternative Mapping must be re-assembled and verified.
3.  **Release Hold:** It is recommended that the v2 release be held pending resolution of the missing timeout documentation, or that a clear risk acceptance be recorded by the Accessibility Board acknowledging the fail-safe status.
