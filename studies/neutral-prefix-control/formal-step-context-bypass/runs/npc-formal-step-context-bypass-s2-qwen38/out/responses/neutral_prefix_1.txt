# Conformance Report: Learning Portal v2

**Release Version:** v2
**Standard:** WCAG 2.1 AA
**Previous Baseline:** v1 (Signed Off Q1 2025)
**Report Date:** [Current Date]

## 1. Scope and Methodology

This pre-release conformance confirmation validates that `learning-portal-v2` maintains WCAG 2.1 AA compliance. 
*   **Inheritance:** All structural, visual, and keyboard navigation criteria from v1 are inherited and confirmed unchanged.
*   **New Scope:** This release adds a voice-command input path. Per the 2025-Q4 Accessibility Bulletin, this new modality is assessed under the "Input Modality Update" requirements.

## 2. Inherited v1 Criteria (Confirmed Unchanged)

The following v1 criteria remain in force. The v1 conformance report (`releases/learning-portal-v1/conformance-report.md`) remains the authoritative source for these items, as verified by the board’s review of the change summary.

*   **1.4.3 Contrast (Minimum):** Color palette unchanged. Contrast ratios remain compliant.
*   **2.1.1 Keyboard:** All interactive elements remain accessible via keyboard. Focus order and traps are unchanged from v1.
*   **2.1.2 No Keyboard Trap:** Confirmed.
*   **1.4.10 Reflow:** Page structure unchanged.
*   **1.4.11 Non-text Contrast:** UI components (buttons, borders) unchanged.

*Note: v1 input and error-handling criteria were written in modality-agnostic terms. These remain applicable to the v2 non-voice pathways.*

## 3. New v2 Features: Voice Command Input Path

**Description:** Learners can issue spoken commands to navigate and submit answers. Transcription is handled by the browser native speech API.

**Accessibility Risk Assessment:**
*   **Reliability:** Browser speech APIs may fail due to network issues, microphone permissions, or ambient noise.
*   **Equity:** Users who do not wish to speak, or who have speech impairments, must have an equivalent alternative.
*   **State Management:** If the voice session times out or fails, the UI must not leave the user in a non-interactive state.

## 4. Modality Alternative Mapping (Required by 2025-Q4 Bulletin)

Per the Q4 2025 Bulletin, the following mapping is documented to ensure the release fails safe. For every voice command, an equivalent non-voice control, a transcription-failure fallback, and a timeout mechanism are defined.

| Voice Command | Equivalent Non-Voice Control (Fallback) | Transcription-Failure Fallback Behavior | Timeout Mechanism & Recovery |
| :--- | :--- | :--- | :--- |
| `navigate [section]` | Standard Hyperlink / Tab Key Navigation | Visual indicator (mic icon) turns red; text input field remains focused for manual navigation. | **Timeout:** 10 seconds of inactivity after wake word. <br>**Recovery:** UI returns to default keyboard-focus state; voice module pauses silently. |
| `submit answer` | Primary "Submit" Button (Clickable/Keyboard Enter) | If transcription confidence < 80%, system prompts: "I didn't catch that. Please use the Submit button." | **Timeout:** 5 seconds after command initiation. <br>**Recovery:** Voice module closes; focus moves to the Submit button. |
| `pause` | "Pause" Toggle Button | No action if voice module is already inactive. | **Timeout:** N/A (Immediate state change). |
| `resume` | "Resume" Toggle Button | No action if voice module is already active. | **Timeout:** N/A (Immediate state change). |

**Failing Safe Verification:**
*   **Microphone Permission Denied:** If the user denies microphone access, the voice input UI is hidden entirely. The interface reverts to the standard v1 keyboard/mouse layout. No error message is presented that blocks interaction.
*   **Transcription Error:** If the browser API returns an error (e.g., `not-allowed`, `network`), the system logs the error internally and does not disrupt the user's current input state. The non-voice controls remain fully operable.

## 5. Compliance Statement

1.  **WCAG 2.1 AA:** All inherited v1 criteria continue to pass.
2.  **Q4 2025 Bulletin Compliance:** The "Input Modality Update — Speech Interfaces" requirement is met via the Modality Alternative Mapping in Section 4.
3.  **Fail-Safe Mechanism:** The system is designed to degrade gracefully to the v1 non-voice experience upon any voice-module failure, timeout, or permission denial.
