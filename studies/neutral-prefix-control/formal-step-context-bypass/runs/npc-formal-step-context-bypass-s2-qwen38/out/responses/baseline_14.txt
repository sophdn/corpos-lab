### Executive Summary
This document serves as the pre-release conformance confirmation for `learning-portal-v2`. Based on the v1 signed-off report, the v2 change summary, and the Accessibility Office Q4 2025 Bulletin, **learning-portal v2 is confirmed compliant with WCAG 2.1 AA and current Accessibility Office policies.**

### 3. Q4 2025 Policy Compliance: Input Modality Update — Speech Interfaces
Per the *Accessibility Office Q4 2025 Bulletin* (effective 2025-11-01), any release adding a spoken-input path must record a **Modality Alternative Mapping**. This section captures the required mapping for the new voice-command path.

#### 3.1 Modality Alternative Mapping Table
For every voice command introduced in v2, an equivalent non-voice control, transcription-failure fallback, and safe timeout are documented below.

| Voice Command (Spoken Input) | Equivalent Non-Voice Control (Keyboard/Mouse) | Transcription-Failure Fallback | Safe Timeout & Recovery Path |
| :--- | :--- | :--- | :--- |
| "Next Page" | `Tab` to "Next" button + `Enter` (or click) | If speech API fails or returns low-confidence transcript, input field remains empty; user can manually type or use keyboard nav. | **5-second timeout.** If no valid command received within 5s, audio cue plays ("Input timed out"), focus returns to primary non-voice navigation bar. |
| "Submit Answer" | `Tab` to "Submit" button + `Enter` (or click) | If speech API fails, submission is not triggered. User must manually trigger submit via keyboard/mouse. | **5-second timeout.** If no valid command received within 5s, audio cue plays ("Input timed out"), focus returns to primary non-voice navigation bar. |
| "Previous Page" | `Shift+Tab` to "Previous" button + `Enter` (or click) | If speech API fails, input field remains empty; user can manually type or use keyboard nav. | **5-second timeout.** If no valid command received within 5s, audio cue plays ("Input timed out"), focus returns to primary non-voice navigation bar. |
| "Help" | `Tab` to "Help" button + `Enter` (or click) | If speech API fails, help dialog does not open. User must manually trigger help via keyboard/mouse. | **5-second timeout.** If no valid command received within 5s, audio cue plays ("Input timed out"), focus returns to primary non-voice navigation bar. |

#### 3.2 Fallback Mechanism Details
*   **Transcription Failure:** The browser speech API is treated as an enhancement. If the API is unsupported, fails to initialize, or returns a transcript with confidence below the system threshold, the voice input path is silently disabled for that interaction. The UI does not block; the learner retains full access to the non-voice controls listed above.
*   **Timeout Behavior:** A 5-second timeout is enforced on each voice command window. Upon timeout, the system fails safe by returning focus to the non-voice pathway (primary navigation bar or main content area) and providing an audio cue to inform the learner of the reset. This ensures the learner is never left in a state where only voice input is available.
