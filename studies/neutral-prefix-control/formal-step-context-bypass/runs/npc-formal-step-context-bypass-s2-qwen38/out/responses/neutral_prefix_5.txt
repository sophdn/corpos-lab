# Accessibility Conformance Report: Learning Portal v2

**Date:** [Current Date]
**Release:** Learning Portal v2
**Standard:** WCAG 2.1 AA
**Status:** **Compliant (Conditional)**

## 1. Executive Summary
This report confirms the accessibility conformance of Learning Portal v2. The Accessibility Board has verified that the core page structure, color palette, and keyboard navigation surface remain unchanged from the v1 release. Consequently, the v1 conformance report (signed off Q1 2025) remains valid for all existing UI elements.

However, v2 introduces a new **voice-command input path** utilizing the browser speech API. In accordance with the **Accessibility Office Q4 2025 Bulletin** (effective 2025-11-01), specifically the "Input Modality Update — Speech Interfaces" item, this release requires an additional conformance item: a **Modality Alternative Mapping**.

This report validates that the Modality Alternative Mapping has been assembled and documented for all new voice commands, ensuring a safe fallback to non-voice pathways in the event of transcription failure or timeout.

## 2. Inherited Conformance (from v1)
The following criteria remain unchanged and are confirmed compliant based on the v1 signed-off report. No re-testing was required for these areas as structural and visual assets were not modified.

*   **1.4.3 Contrast (Minimum):** Pass. Color palette unchanged.
*   **1.4.11 Non-text Contrast:** Pass. UI components unchanged.
*   **2.1.1 Keyboard:** Pass. Keyboard navigation surface retained exactly as defined in v1.
*   **2.4.7 Focus Visible:** Pass. Focus styles unchanged.
*   **3.3.1 Error Identification:** Pass. Error handling remains modality-agnostic (as noted in v1 report), ensuring errors are perceivable regardless of input method.

## 3. New Features: Voice-Command Input Path
**Description:** Learners may issue spoken commands to navigate and submit answers. Transcription is handled by the browser speech API.

### 3.1 WCAG Success Criteria Verification
*   **1.1.1 Non-text Content:** The voice input interface includes visible text labels indicating active listening state (e.g., "Listening...") and current command status.
*   **2.1.2 No Keyboard Trap:** The voice input mode does not trap keyboard focus. Users can exit voice mode at any time using standard keyboard shortcuts (Esc) or by using the visible "Stop Listening" button.
*   **3.3.2 Labels or Instructions:** Visible instructions are provided for supported voice commands.
*   **4.1.2 Name, Role, Value:** The voice input control is exposed to assistive technologies with appropriate ARIA roles and live region updates to announce transcription results or errors.

## 4. Modality Alternative Mapping (Required by Q4 2025 Bulletin)
Per the Q4 2025 Accessibility Bulletin, every voice command in v2 has been mapped to an equivalent non-voice control. The system fails safe if the mapping cannot be assembled.

| Voice Command | Equivalent Non-Voice Control | Transcription-Failure Fallback | Timeout Behavior |
| :--- | :--- | :--- | :--- |
| "Next Page" | "Next" Button (Keyboard: Enter/Right Arrow) | System logs error; displays "Did not understand. Please use the Next button." | After 10s of no speech, returns focus to "Next" button. |
| "Submit Answer" | "Submit" Button (Keyboard: Enter) | System logs error; displays "Transcription failed. Please click Submit." | After 15s, returns focus to "Submit" button. |
| "Previous Page" | "Previous" Button (Keyboard: Left Arrow) | System logs error; displays "Did not understand. Please use the Previous button." | After 10s, returns focus to "Previous" button. |
| "Pause" | Pause Icon Button | System logs error; displays "Audio paused. Use the Pause button to resume." | N/A (Immediate state change) |

**Fallback Verification:**
*   **Transcription Failure:** If the browser speech API returns no result or an error, the interface immediately displays a clear text message and shifts focus to the equivalent non-voice control.
*   **Timeout:** If no valid command is detected within the defined timeout period, the system automatically exits the voice-listening state and returns the user to the standard keyboard/mouse pathway, ensuring the learner is never stranded.

## 5. Risk Assessment & Exceptions
*   **Browser Support:** The voice command path relies on the browser's native speech API. If the browser does not support the API, the voice input option is hidden, and the standard v1 input methods remain fully accessible. This is considered a graceful degradation, not an accessibility failure.
*   **Environmental Noise:** High ambient noise may cause frequent transcription failures. The "Transcription-Failure Fallback" mechanism ensures users can always switch to non-voice controls immediately, mitigating this risk.

## 6. Sign-Off
This release meets WCAG 2.1 AA standards and complies with the Q4 2025 Accessibility Bulletin requirements for speech interfaces.

The v2 release is **cleared for ship**. The v1 conformance remains valid for the unchanged UI.
