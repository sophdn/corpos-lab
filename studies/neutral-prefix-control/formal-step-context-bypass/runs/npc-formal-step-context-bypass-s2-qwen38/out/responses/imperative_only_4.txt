## 3. New Features: Voice-Command Input Path
v2 introduces a voice-command input path utilizing the browser speech API. This addition introduces new accessibility obligations under the Q4 2025 Accessibility Bulletin ("Input Modality Update — Speech Interfaces").

### 3.1 Assessment of Speech Input
The voice path allows learners to navigate and submit answers via spoken commands. This functionality must meet WCAG 2.1 AA standards for alternative input methods and must comply with the specific **Modality Alternative Mapping (MAM)** requirement.

## 4. Modality Alternative Mapping (MAM)
*Required by `policy/bulletins/2025-Q4-accessibility-bulletin.md` (Effective 2025-11-01).*

For every voice command introduced in v2, the following mappings are recorded to ensure fail-safe accessibility:

| Voice Command | Equivalent Non-Voice Control | Transcription-Failure Fallback | Timeout Behavior |
| :--- | :--- | :--- | :--- |
| "Go to [Page Name]" | Keyboard Tab/Enter to focus [Page Name] link; Mouse Click | Visual prompt: "Speech input not recognized. Please use keyboard or mouse." | 5 seconds. If no valid command received, focus returns to the main navigation menu bar. |
| "Submit Answer" | Keyboard: Focus on "Submit" button and press Enter; Mouse: Click "Submit" button | Visual prompt: "Speech input not recognized. Please use keyboard or mouse." | 5 seconds. If no valid command received, focus returns to the answer input field. |
| "Next Question" | Keyboard: Focus on "Next" button and press Enter; Mouse: Click "Next" button | Visual prompt: "Speech input not recognized. Please use keyboard or mouse." | 5 seconds. If no valid command received, focus returns to the current question container. |
| "Previous Question" | Keyboard: Focus on "Previous" button and press Enter; Mouse: Click "Previous" button | Visual prompt: "Speech input not recognized. Please use keyboard or mouse." | 5 seconds. If no valid command received, focus returns to the current question container. |

**MAM Status:** **Complete.**
All voice commands have defined non-voice equivalents, failure fallbacks, and safe timeout behaviors. The system fails safe to a usable non-voice pathway.
