## 1. Executive Summary

This report confirms the accessibility conformance of learning-portal v2 against WCAG 2.1 AA. As determined by the Accessibility Board’s review of the v2 change summary, v2 retains the page structure, color palette, and keyboard navigation of v1. Consequently, all Success Criteria met by v1 (signed off Q1 2025) remain valid for v2.

However, v2 introduces a **voice-command input path** using the browser speech API. Per the *2025-Q4 Accessibility Bulletin (Effective 2025-11-01)*, this addition triggers a mandatory compliance requirement: the **Modality Alternative Mapping**.

**Conformance Status:**
*   **WCAG 2.1 AA Success Criteria:** **PASS** (Inherited from v1; no regressions identified).
*   **Q4 2025 Bulletin Compliance:** **FAIL / INCOMPLETE** (Modality Alternative Mapping not yet documented in the v2 release artifacts).

**Recommendation:** Do not ship v2 until the Modality Alternative Mapping is assembled and documented as specified in Section 4 below.

## 4. Q4 2025 Bulletin Compliance: Speech Interface

**Policy Reference:** `policy/bulletins/2025-Q4-accessibility-bulletin.md`, Item: "Input Modality Update — Speech Interfaces".

**Requirement:** Any release adding a spoken-input path must record an additional conformance item — a **Modality Alternative Mapping** — capturing:
1.  For every voice command, an equivalent non-voice control.
2.  The transcription-failure fallback.
3.  A timeout that returns the learner to a usable non-voice pathway.
4.  Documentation of the above, failing safe if the mapping cannot be assembled.

### 4.1 Current Status: **NOT MET**

The v2 change summary confirms the addition of a voice-command path for navigation and answer submission. However, the current v2 conformance report template is blank regarding this mapping. No evidence has been provided that the Modality Alternative Mapping has been documented for this release.

### 4.2 Required Modality Alternative Mapping (To Be Completed)

To achieve conformance, the following mapping must be documented and verified before release:

| Voice Command | Equivalent Non-Voice Control | Transcription-Failure Fallback | Timeout Behavior (Return to Non-Voice) | Status |
| :--- | :--- | :--- | :--- | :--- |
| *Example: "Navigate to Lesson 5"* | Keyboard: Tab to nav menu, Enter to select Lesson 5. Mouse/Touch: Click "Lesson 5" link. | If transcription fails, display visual alert "Speech input unclear." Highlight the currently focused non-voice control for immediate manual action. | After 10 seconds of inactivity or repeated failure, auto-focus the primary non-voice input field (e.g., search bar or main nav) and display tooltip: "Use keyboard or mouse to continue." | **PENDING** |
| *Example: "Submit Answer"* | Keyboard: Focus "Submit" button, Press Enter. Mouse/Touch: Click "Submit" button. | If transcription fails, do **not** submit. Display error: "Command not recognized." Ensure "Submit" button remains focusable and visible. | After 5 seconds, if no valid command is received, revert focus to the answer input field and allow manual submission. | **PENDING** |
| *Example: "Cancel Action"* | Keyboard: Press Escape key. Mouse/Touch: Click "Cancel" or "Back" button. | If transcription fails, perform **no** action. Ensure Escape key remains functional. | N/A (Immediate fallback to keyboard Escape). | **PENDING** |
| *(All other commands must be listed)* | | | | |

**Failing Safe Requirement:** If the mapping cannot be fully assembled for any command, the voice input feature must be **disabled by default** for that specific action, ensuring the non-voice pathway remains fully accessible and unimpeded.

---

## 5. Risk Assessment

*   **Risk:** Shipping v2 without the documented Modality Alternative Mapping violates the Q4 2025 Accessibility Bulletin.
*   **Impact:** Learners with motor disabilities who may rely on voice input due to lack of manual control may encounter no fallback or timeout, leading to task abandonment or frustration. This constitutes a violation of organizational accessibility policy, even if WCAG 2.1 AA base criteria are met.
*   **Severity:** **High**

---

## 6. Recommendations and Actions

1.  **Immediate Action:** The development team must complete the **Modality Alternative Mapping** table (Section 4.2) for all voice commands in v2.
2.  **Verification:** The accessibility team must verify that:
    *   Each voice command has a clearly identified non-voice equivalent.
    *   Transcription failures do not block the non-voice pathway.
    *   Timeouts correctly redirect focus to a usable non-voice control.
3.  **Documentation:** The completed mapping must be appended to this conformance report and included in the release notes.
4.  **Re-Audit:** Once the mapping is documented, the Accessibility Compliance Officer will perform a final check to confirm "Failing Safe" behavior.
5.  **Release Decision:** **HOLD** v2 release until the above actions are completed and signed off.
