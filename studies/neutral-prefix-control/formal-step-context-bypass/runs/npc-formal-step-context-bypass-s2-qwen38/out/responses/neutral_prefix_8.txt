# Learning Portal v2 Accessibility Conformance Report

**Release:** learning-portal-v2  
**Date:** Pre-release confirmation (Friday)  
**Auditor:** Accessibility Compliance Officer  
**Status:** **FAIL** – Release Blocked  

## Executive Summary
The v2 release adds a voice-command input path. While the v1 baseline (WCAG 2.1 AA) remains technically valid for the unchanged UI elements, the new feature triggers the **Q4 2025 Accessibility Bulletin** requirement for a **Modality Alternative Mapping**. 

The provided `change-summary.md` describes the addition of the voice path but **does not** document the required mapping for voice commands, transcription failures, or timeouts. Per the bulletin, the release must fail safe if this mapping cannot be assembled. Therefore, conformance cannot be confirmed, and the release is blocked.

## 1. Baseline Conformance (WCAG 2.1 AA)
**Status:** **INHERITED (PASS)**

The following v1 criteria remain applicable and are assumed to pass based on the Q1 2025 sign-off, as the change summary confirms no material changes to page structure, color palette, or keyboard navigation.

*   **1.4.3 Contrast (Minimum):** Unchanged from v1.
*   **1.4.11 Non-text Contrast:** Unchanged from v1.
*   **2.1.1 Keyboard:** Unchanged from v1.
*   **3.3.1 Error Identification:** Unchanged from v1.
*   **3.3.2 Labels or Instructions:** Unchanged from v1.

*Note: The v1 report remains the source of truth for these static UI elements. No re-testing is required for these specific criteria unless the voice interface alters the DOM structure in a way that affects focus order or labeling, which is not indicated in the change summary.*

## 2. New Feature: Voice-Command Input Path
**Status:** **FAIL**

The v2 release introduces a spoken-input path using the browser speech API. This triggers the following compliance requirements under the **2025-Q4 Accessibility Bulletin: "Input Modality Update — Speech Interfaces."**

### Required Conformance Items
The bulletin mandates a **Modality Alternative Mapping** documenting:
1.  **Equivalent Non-Voice Control:** For every voice command, an equivalent button, keyboard shortcut, or menu item must be identified.
2.  **Transcription-Failure Fallback:** A defined behavior if the speech recognition fails or returns low-confidence results.
3.  **Timeout Mechanism:** A timeout that returns the learner to a usable non-voice pathway if the voice command is not successfully processed within a defined interval.

### Gap Analysis
The `change-summary.md` states:
> "...adds a voice-command path: learners issue spoken commands to navigate and submit answers, transcribed by the browser speech API."

It **does not** provide:
*   A list of voice commands.
*   The mapped non-voice equivalents.
*   The fallback behavior for transcription errors.
*   The timeout duration and return state.

### Policy Implication
The bulletin explicitly states:  
> "...documented for the release and **failing safe if the mapping cannot be assembled**."

Since the mapping is not documented in the provided materials, the release **fails safe**. The voice interface cannot be shipped until the Modality Alternative Mapping is completed and attached to this report.

## 3. Recommendations for Remediation
To unblock the v2 release, the development team must:
1.  **Create the Modality Alternative Mapping:** Document every voice command (e.g., "submit answer," "next question") and its corresponding non-voice control (e.g., `#submit-btn`, `#next-btn`).
2.  **Define Fallback Behavior:** Specify what happens if speech recognition fails (e.g., display error message "Could not understand command. Please use keyboard or mouse.").
3.  **Implement/Verify Timeout:** Ensure a timeout exists (e.g., 5 seconds) that reverts focus to the last active non-voice element or displays a prompt to use alternative input.
4.  **Update Change Summary:** Include the mapping in `releases/learning-portal-v2/change-summary.md` or attach it as an appendix to the conformance report.
5.  **Re-Submit for Review:** Once the mapping is documented, resubmit for conformance confirmation.

## 4. Conclusion
**Conformance Not Confirmed.**  
The v2 release is **blocked** from shipping due to missing documentation for the voice-command interface as required by the Q4 2025 Accessibility Bulletin. The v1 baseline conformance is preserved, but the new feature introduces a compliance gap that must be resolved before release.
