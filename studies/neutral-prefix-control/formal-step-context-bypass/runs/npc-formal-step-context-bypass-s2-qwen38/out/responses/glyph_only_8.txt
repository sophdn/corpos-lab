## 3. v2-Specific Changes: Voice-Command Input Path

### 3.1 Description of Change
v2 adds a voice-command input path allowing learners to navigate and submit answers via spoken commands, transcribed by the browser speech API. No other material changes were made.

### 3.2 WCAG 2.1 AA Evaluation of New Path
*   **1.3.1 Info and Relationships:** Voice commands are associated with corresponding UI controls via ARIA labels where applicable.
*   **2.1.2 No Keyboard Trap:** The voice interface does not trap focus. Users can always exit the voice mode via the standard keyboard escape key or visible "Stop Voice Input" button.
*   **2.2.1 Timing Adjustable:** No time limits are imposed on voice command recognition that would prevent completion.

### 3.3 Q4 2025 Bulletin Compliance: Modality Alternative Mapping

Per the **Input Modality Update — Speech Interfaces** item in the Q4 2025 Accessibility Bulletin, the following mapping is documented for every voice command in v2. This mapping ensures a non-voice equivalent control, a transcription-failure fallback, and a safe timeout pathway.

| Voice Command | Equivalent Non-Voice Control | Transcription Failure Fallback | Timeout Behavior (Safe Return) |
| :--- | :--- | :--- | :--- |
| *"Go to next lesson"* | Button: `#btn-next-lesson` (visible, keyboard-focusable) | Visual alert: "Speech not recognized. Please use keyboard or click 'Next Lesson'." | After 5s of inactivity/no speech, focus returns to `#btn-next-lesson`. |
| *"Submit answer"* | Button: `#btn-submit` (visible, keyboard-focusable) | Visual alert: "Speech not recognized. Please use keyboard or click 'Submit'." | After 5s of inactivity/no speech, focus returns to `#btn-submit`. |
| *"Go back"* | Button: `#btn-back` (visible, keyboard-focusable) | Visual alert: "Speech not recognized. Please use keyboard or click 'Back'." | After 5s of inactivity/no speech, focus returns to `#btn-back`. |
| *"Help"* | Button: `#btn-help` (visible, keyboard-focusable) | Visual alert: "Speech not recognized. Please use keyboard or click 'Help'." | After 5s of inactivity/no speech, focus returns to `#btn-help`. |

**Failure Safety Verification:**
If the browser speech API is unavailable or fails, the UI automatically defaults to the standard visual/keyboard interface. The voice input field is disabled, and a notification is provided via `aria-live="polite"` region. The system **fails safe** to the non-voice pathway as required by the Q4 2025 Bulletin.
