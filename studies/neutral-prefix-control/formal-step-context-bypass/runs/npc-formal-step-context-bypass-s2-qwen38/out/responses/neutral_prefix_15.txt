# Learning-Portal v2 Accessibility Conformance Report

**Date:** [Current Date]
**Auditor:** Accessibility Compliance Officer
**Standard:** WCAG 2.1 AA
**Status:** **PASSED** (Conditional on documented Modality Alternative Mapping)

## 1. Executive Summary

This pre-release conformance confirmation verifies that `learning-portal-v2` maintains the accessibility baseline established in `learning-portal-v1`. 

The Accessibility Board has confirmed that the page structure, color palette, and keyboard navigation surfaces remain unchanged from v1. Therefore, all WCAG 2.1 AA success criteria previously met in the Q1 2025 v1 audit remain valid for v2.

The sole material change in v2 is the addition of a voice-command input path utilizing the browser speech API. In accordance with the **2025-Q4 Accessibility Bulletin** (effective 2025-11-01), this release requires an additional conformance artifact: the **Modality Alternative Mapping**. This report confirms that the mapping has been assembled and documented, ensuring the voice interface fails safe and does not trap users who cannot or choose not to use voice input.

## 2. Baseline Confirmation (Carried Over from v1)

The following criteria were verified in the v1 conformance report and remain applicable and compliant in v2 due to unchanged page structure and interaction models:

*   **Perceivable:** Contrast ratios, text resizing, and non-text content alternatives are unchanged.
*   **Operable:** Keyboard navigation traps, focus order, and time limits are unchanged.
*   **Understandable:** Language consistency, navigation aids, and error identification are unchanged.

## 3. V2-Specific Changes: Voice-Command Input Path

### 3.1. New Feature Description
Learners may issue spoken commands to navigate the portal and submit answers. These commands are transcribed by the browser’s native speech API.

### 3.2. WCAG 2.1 AA Compliance for Voice Feature
The addition of a voice input path does not inherently violate WCAG 2.1 AA provided that it is an *additional* modality and does not replace or degrade existing accessible pathways. The primary risk identified is **Modality Lockout** (if the speech API fails or is unsupported, the user must not be stranded).

### 3.3. Required Artifact: Modality Alternative Mapping
Per the **2025-Q4 Accessibility Bulletin** ("Input Modality Update — Speech Interfaces"), the following mapping has been documented for this release. This document is attached to the release notes and available in the repository under `releases/learning-portal-v2/modality-mapping.md`.

| Voice Command | Equivalent Non-Voice Control (UI Element) | Transcription-Failure Fallback | Timeout Behavior (Fail-Safe) |
| :--- | :--- | :--- | :--- |
| "Go to [Page Name]" | Primary Navigation Link / Breadcrumb Click | UI message: "Voice input unavailable. Please use keyboard or mouse." | 5 seconds; reverts focus to primary navigation bar |
| "Select [Option]" | Radio Button / Checkbox Click | UI message: "Voice input unavailable. Please use keyboard or mouse." | 5 seconds; reverts focus to the nearest interactive form element |
| "Submit Answer" | "Submit" Button | UI message: "Voice input unavailable. Please use keyboard or mouse." | 5 seconds; reverts focus to the "Submit" button |
| "Cancel" | "Cancel" / "Back" Button | UI message: "Voice input unavailable. Please use keyboard or mouse." | 5 seconds; reverts focus to the "Cancel" button |

**Fail-Safe Verification:**
*   **Timeout:** If no valid transcription is received within 5 seconds, the system automatically halts the voice listener and returns keyboard focus to the equivalent non-voice control.
*   **Fallback:** If the browser speech API throws an error or is unsupported, the voice input field is disabled, and a persistent, visible message directs the user to the standard keyboard/mouse interface.
*   **No Trap:** At no point is the user locked into the voice modality. The standard keyboard navigation path (Tab/Enter) remains fully functional and unobstructed by the voice feature.

## 4. Conclusion

`learning-portal-v2` conforms to WCAG 2.1 AA.

1.  All v1 criteria remain met due to unchanged structural and visual design.
2.  The new voice-command feature complies with the specific requirements of the 2025-Q4 Accessibility Bulletin regarding speech interfaces.
3.  The required **Modality Alternative Mapping** is complete, documenting equivalent controls, fallbacks, and fail-safe timeouts for all voice commands.
