**Pre-Release Conformance Confirmation: learning-portal v2**

**Status:** Conditional Pass – Documentation Update Required Before Sign-Off

**Executive Summary**
As the Accessibility Compliance Officer, I have reviewed the v2 change summary against the current v1 conformance report and the Q4 2025 Accessibility Bulletin. The board’s preliminary assessment that v2 retains v1’s structural, color, and keyboard conformance is accurate. However, the addition of a voice-command input path triggers a specific regulatory requirement under the "Input Modality Update — Speech Interfaces" item of the 2025-Q4 bulletin (effective 2025-11-01).

The v1 report does not cover speech interfaces. Therefore, the v2 report cannot simply reference the v1 report as fully compliant. It must explicitly document a **Modality Alternative Mapping** as required by the bulletin. Until this mapping is documented, the release fails safe and cannot be signed off.

Below is the drafted `conformance-report.md` for v2. It confirms the inherited v1 criteria and defines the required v2-specific conformance item.

## 3. v2-Specific Conformance: Speech Interface

The v2 release adds a voice-command input path. Per the **2025-Q4 Accessibility Bulletin**, section "Input Modality Update — Speech Interfaces," this release must record a **Modality Alternative Mapping**.

This mapping ensures that the voice input path is an *alternative*, not a *dependency*, and that users are never trapped in a non-functional voice loop.

### 3.1 Modality Alternative Mapping

*Requirement: For every voice command, an equivalent non-voice control, a transcription-failure fallback, and a timeout mechanism must be documented.*

| Voice Command | Equivalent Non-Voice Control | Transcription Failure Fallback | Timeout Behavior |
| :--- | :--- | :--- | :--- |
| *(To be completed by Dev Team)* | *(e.g., "Next Lesson" button)* | *(e.g., Visual prompt "Voice input failed. Please use keyboard or mouse.")* | *(e.g., After 10s of inactivity, focus returns to standard UI)* |
| *(To be completed by Dev Team)* | *(e.g., "Submit Answer" button)* | *(e.g., Visual prompt "Voice input failed. Please use keyboard or mouse.")* | *(e.g., After 10s of inactivity, focus returns to standard UI)* |
| *(To be completed by Dev Team)* | *(e.g., "Navigate to Settings" menu item)* | *(e.g., Visual prompt "Voice input failed. Please use keyboard or mouse.")* | *(e.g., After 10s of inactivity, focus returns to standard UI)* |

> **⚠️ Compliance Note:** The table above is currently **incomplete**. The development team must populate this table with the exact voice commands implemented in v2 before this report can be finalized.

### 3.2 Failure Safe Mechanism

If the Modality Alternative Mapping cannot be assembled (i.e., if any voice command lacks a documented non-voice equivalent or fallback), the voice input feature must be **disabled by default** in this release. The release shall not ship with an unmapped speech interface.

## 4. Determination

**Status:** **PENDING DOCUMENTATION**

The v2 release meets the inherited WCAG 2.1 AA criteria from v1. However, it **does not yet meet** the Q4 2025 Bulletin requirements for speech interfaces because the Modality Alternative Mapping (Section 3.1) is not yet documented.

**Action Required:**
1.  Development team to populate Section 3.1 with all voice commands, their non-voice equivalents, fallbacks, and timeouts.
2.  Accessibility Compliance Officer to review the populated mapping.
3.  Accessibility Board to sign off on the completed report.

**Do not ship v2 until Section 3.1 is complete and verified.**
