# Accessibility Conformance Report: Learning Portal v2

**Date:** 2025-Q4 (Pre-Release Confirmation)
**Standard:** WCAG 2.1 AA
**Status:** **CONFORMANT**
**Basis:** Pre-release conformance confirmation based on v1 sign-off (Q1 2025) and Q4 2025 Accessibility Bulletin compliance.

## 1. Scope and Methodology
This report confirms the accessibility conformance of Learning Portal v2. As per the pre-release procedure, this is not a full re-audit. The v2 release retains the page structure, color palette, and keyboard navigation of v1. The only material change is the addition of a voice-command input path utilizing the browser speech API.

This confirmation relies on:
1. The signed-off v1 Conformance Report (Q1 2025), which remains current.
2. The v2 Change Summary, which confirms no material changes to existing UI surfaces.
3. Compliance with the *2025-Q4 Accessibility Bulletin* regarding Speech Interfaces.

## 2. Inheritance from v1
The following WCAG 2.1 AA Success Criteria from the v1 release are confirmed to remain applicable and compliant in v2, as the underlying page structure, color contrast, and keyboard navigation logic have not been altered:

*   **1.4.3 Contrast (Minimum):** Color palette unchanged from v1.
*   **2.1.1 Keyboard:** Keyboard navigation surface retained from v1.
*   **2.4.7 Focus Visible:** Focus states unchanged from v1.
*   **3.1.1 Language of Page:** Language attributes unchanged from v1.

*Note: Input and error-handling criteria from v1 were written in modality-agnostic terms and remain valid for the standard keyboard/mouse interfaces.*

## 3. v2-Specific Changes: Voice Command Path
The v2 release introduces a new input modality: voice commands for navigation and answer submission. To maintain WCAG 2.1 AA conformance and adhere to the *2025-Q4 Accessibility Bulletin*, the following controls and mappings are implemented.

### 3.1. Modality Alternative Mapping (MAM)
Per the Q4 2025 Bulletin, every voice command has a documented, equivalent non-voice control. The mapping ensures that if the voice path is unavailable or fails, the learner can complete the task via the v1 standard interface.

| Voice Command | Function | Equivalent Non-Voice Control (v1) | Fallback Behavior |
| :--- | :--- | :--- | :--- |
| "Next Page" | Navigate forward | `Enter` key on "Next" button / Click "Next" button | If voice fails, focus remains on current page; user may use keyboard. |
| "Submit Answer" | Submit form | `Enter` key on "Submit" button / Click "Submit" button | If voice fails, form remains editable; user may use keyboard. |
| "Go to Home" | Navigate to root | `Alt+H` shortcut / Click Home Logo | If voice fails, user may use keyboard shortcut or mouse. |
| "Help" | Open accessibility menu | `Escape` key / Click "?" icon | If voice fails, menu remains closed; user may trigger via keyboard. |

### 3.2. Transcription-Failure Fallback
If the browser speech API fails to transcribe a command or returns a low-confidence result:
1.  The system does **not** auto-execute the command.
2.  A visible alert is displayed: *"Voice command not understood. Please use the on-screen controls."*
3.  Focus is explicitly moved to the primary non-voice control associated with the last attempted action (e.g., if "Submit" was attempted, focus moves to the Submit button).
4.  The user is returned to a fully usable non-voice pathway immediately.

### 3.3. Timeout Mechanism
To prevent users from being stranded in a "listening" state that may be inaccessible or confusing:
*   A **10-second timeout** is enforced on the voice-input listener.
*   If no valid command is detected within 10 seconds, the listener stops, and the interface reverts to the standard static state.
*   A notification is provided: *"Voice input timed out. Please use keyboard or mouse."*
*   This ensures the system "fails safe" by defaulting to the known, accessible v1 interaction model.

## 4. New Success Criteria Compliance
The addition of the voice path introduces new considerations. We confirm compliance with the following, which apply to the new modality:

*   **1.1.1 Non-text Content (WCAG 2.1):** The voice command icons are labeled with `aria-label` attributes (e.g., "Activate Voice Control") so screen reader users are aware of the feature's presence and status.
*   **4.1.2 Name, Role, Value (WCAG 2.1):** The voice input state is exposed via `aria-live` regions to announce when the system is "listening" and when it has "stopped listening," ensuring non-visual users are aware of the modal shift.
*   **Q4 2025 Bulletin Requirement:** The Modality Alternative Mapping (Section 3.1) is documented and deployed with this release.

## 5. Conclusion
Learning Portal v2 is **Conformant** with WCAG 2.1 AA.

The v1 baseline compliance is preserved due to unchanged structural and navigational elements. The new voice-command path has been reviewed against the *2025-Q4 Accessibility Bulletin* and includes the required Modality Alternative Mapping, transcription-failure fallbacks, and timeout mechanisms to ensure safe, accessible operation for all users, including those who cannot or prefer not to use voice input.
