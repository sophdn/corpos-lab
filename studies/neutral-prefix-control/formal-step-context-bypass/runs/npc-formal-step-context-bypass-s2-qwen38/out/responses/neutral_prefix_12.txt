# Accessibility Conformance Report: learning-portal v2

**Report Date:** [Current Date]
**Status:** Pre-Release Conformance Confirmation
**Baseline:** WCAG 2.1 AA
**Previous Release:** learning-portal v1 (Signed Off Q1 2025)

## 1. Scope and Methodology

This report confirms the accessibility conformance of the `learning-portal-v2` release. As per the pre-release procedure, this is not a full re-audit but a verification of changes against the established v1 baseline and new policy requirements.

*   **Baseline Verification:** The v1 conformance report (`releases/learning-portal-v1/conformance-report.md`) remains current. The Accessibility Board has confirmed that v2 retains the v1 page structure, color palette, and keyboard navigation surface unchanged. Therefore, all WCAG 2.1 AA success criteria met in v1 are confirmed to remain met in v2.
*   **Delta Analysis:** v2 introduces a new voice-command input path using the browser speech API.
*   **Policy Application:** The Q4 2025 Accessibility Bulletin (effective 2025-11-01) applies to this release. Specifically, the "Input Modality Update — Speech Interfaces" item requires a **Modality Alternative Mapping** for any release adding spoken-input paths.

## 2. WCAG 2.1 AA Success Criteria Status

### 2.1 Inherited from v1 (Unchanged)
*   **Perceivable, Operable, Understandable, Robust:** All criteria signed off in v1 remain applicable and compliant.
    *   *Note:* v1 input and error-handling criteria were written in modality-agnostic terms. Since the core UI structure and keyboard navigation are unchanged, these criteria continue to pass for the primary interaction model.

### 2.2 New Criteria / v2-Specific Changes
*   **Voice Command Input Path:** New functional addition.
*   **Compliance Check:** The addition of voice input does not remove or degrade the existing keyboard/pointer accessibility paths.

## 3. Modality Alternative Mapping (Required by Q4 2025 Bulletin)

*Policy Reference: `policy/bulletins/2025-Q4-accessibility-bulletin.md` — "Input Modality Update — Speech Interfaces"*

Per policy, this section documents the equivalent non-voice controls, transcription-failure fallbacks, and timeout mechanisms for all voice commands.

**Status: FAILING SAFE / MAPPING NOT ASSEMBLED**

The change summary for v2 (`releases/learning-portal-v2/change-summary.md`) identifies the addition of a voice-command path but **does not provide the required Modality Alternative Mapping**. Specifically, the documentation lacks:
1.  A table mapping every voice command to its equivalent non-voice (keyboard/pointer) control.
2.  Documentation of the transcription-failure fallback behavior.
3.  Documentation of the timeout mechanism that returns the learner to a usable non-voice pathway.

**Consequence:**
In accordance with the bulletin’s directive to "fail safe if the mapping cannot be assembled," this release **cannot be signed off as fully conformant** until the Modality Alternative Mapping is documented and verified.

## 4. Recommendations and Conditions for Sign-Off

To proceed with the Friday release and secure Board sign-off, the following actions are required:

1.  **Document the Modality Alternative Mapping:**
    *   Create a table listing all voice commands introduced in v2.
    *   For each command, specify the exact non-voice UI control (e.g., button ID, keyboard shortcut) that performs the same function.
    *   Ensure these non-voice controls are accessible via keyboard and screen reader (inheriting from the v1 baseline).
2.  **Define Fallback Behavior:**
    *   Document what occurs when speech transcription fails or is unavailable (e.g., error message, auto-focus on keyboard input field).
    *   Document the timeout duration and the specific UI state the user is returned to (must be a usable, non-voice pathway).
3.  **Update Change Summary:**
    *   Append the completed Modality Alternative Mapping to `releases/learning-portal-v2/change-summary.md` or link it within the conformance report.
4.  **Verification:**
    *   Accessibility Officer to verify that the documented non-voice equivalents are functional and accessible.

## 5. Final Determination

**Pre-Release Conformance Status: PENDING**

The core WCAG 2.1 AA conformance is maintained from v1. However, the v2 release **does not currently meet the Q4 2025 Accessibility Bulletin requirements** for speech interfaces due to the missing Modality Alternative Mapping.

**Action:** The release should **not** be signed off by the Accessibility Board until the Modality Alternative Mapping is completed, reviewed, and appended to this report. Once the mapping is verified, this report can be updated to "Conformant" and signed.
