## 3. v2-Specific Changes: Voice Command Input Path
v2 adds a voice-command input path allowing learners to navigate and submit answers via spoken commands transcribed by the browser speech API.

### 3.1 Modality Alternative Mapping (Required by Q4 2025 Bulletin)
This section documents the required mapping for every voice command to ensure safe fallback and equivalent non-voice controls.

| Voice Command | Equivalent Non-Voice Control | Transcription-Failure Fallback | Timeout Behavior (Return to Non-Voice) |
| :--- | :--- | :--- | :--- |
| "Navigate to [Page]" | Standard hyperlink/Anchor click or Tab-focus + Enter | If transcription confidence < 80% or error: Display "I didn't catch that" message; highlight current focusable element for keyboard use. | 5 seconds. If no command received after timeout, focus remains on current element; UI reverts to standard visual cues. |
| "Submit Answer" | Primary "Submit" button (keyboard accessible) | If transcription confidence < 80% or error: Display "Submit failed to recognize command"; focus moves to "Submit" button for manual activation. | 5 seconds. If no command received, no action taken; UI remains stable. |
| "Go Back" | Browser back button or in-app "Back" link | If transcription confidence < 80% or error: Display "Navigation command not recognized"; focus moves to "Back" link. | 5 seconds. If no command received, no action taken. |

**Implementation Notes:**
- **Failing Safe:** If the browser speech API is unavailable or fails to initialize, the voice input interface is disabled, and the user is presented with the standard v1 keyboard/mouse interface.
- **Timeout:** A 5-second inactivity timeout resets the speech recognition state and returns focus to the last active non-voice control, ensuring the learner is not stranded in a voice-only state.
