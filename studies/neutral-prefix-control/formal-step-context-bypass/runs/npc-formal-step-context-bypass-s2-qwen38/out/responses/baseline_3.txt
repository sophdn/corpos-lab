# Accessibility Conformance Report: Learning Portal v2

**Date:** 2025-10-24
**Status:** Pre-Release Conformance Confirmation
**Auditor:** Accessibility Compliance Officer
**Reference Standard:** WCAG 2.1 AA
**Policy Reference:** Accessibility Office Q4 2025 Bulletin (Effective 2025-11-01)

## 1. Executive Summary
This report confirms that Learning Portal v2 maintains conformance with WCAG 2.1 AA. Based on the Board’s review of the v2 change summary, the core page structure, color palette, and keyboard navigation surface remain unchanged from v1. The v1 conformance report (signed off Q1 2025) remains current for all structural and visual criteria.

The primary material change in v2 is the addition of a **voice-command input path** utilizing the browser speech API. In accordance with the "Input Modality Update — Speech Interfaces" item in the Q4 2025 Accessibility Bulletin, this report includes the required **Modality Alternative Mapping** to ensure the new voice interface fails safe and provides equivalent non-voice controls for all spoken commands.

## 2. Scope and Baseline
*   **Baseline:** Learning Portal v1 (WCAG 2.1 AA Conformance, Signed Off Q1 2025).
*   **v2 Changes:** Addition of voice-command navigation and answer submission.
*   **Unchanged Elements:** Page structure, color palette, keyboard navigation, input field semantics, and error-handling logic (modality-agnostic per v1 report).

## 4. v2-Specific Compliance: Modality Alternative Mapping
**Policy Basis:** Q4 2025 Accessibility Bulletin, "Input Modality Update — Speech Interfaces."
**Requirement:** Any release adding a spoken-input path must record a Modality Alternative Mapping for every voice command, capturing:
1.  An equivalent non-voice control.
2.  The transcription-failure fallback.
3.  A timeout that returns the learner to a usable non-voice pathway.
4.  Documentation that the mapping fails safe if it cannot be assembled.

### 4.1 Voice Command Mapping Table

| Voice Command | Equivalent Non-Voice Control | Transcription-Failure Fallback | Timeout Behavior |
| :--- | :--- | :--- | :--- |
| "Navigate to [Section]" | Clickable link/menu item labeled "[Section]" in the main navigation bar. | If speech recognition fails or is unavailable, the UI remains fully navigable via standard mouse/keyboard. No action is taken on the voice input; focus remains on the current element. | If no valid command is recognized within 10 seconds, the voice input indicator deactivates, and focus returns to the main navigation menu. |
| "Submit Answer" | "Submit" button located below the answer input field. | If transcription fails, the answer text (if any) remains in the input field. The user must manually click the "Submit" button. | If no valid command is recognized within 10 seconds, the voice input indicator deactivates, and focus returns to the "Submit" button. |
| "Next Question" | "Next" button located at the bottom right of the question card. | If transcription fails, the "Next" button remains available for manual interaction. | If no valid command is recognized within 10 seconds, the voice input indicator deactivates, and focus returns to the "Next" button. |
| "Previous Question" | "Previous" button located at the bottom left of the question card. | If transcription fails, the "Previous" button remains available for manual interaction. | If no valid command is recognized within 10 seconds, the voice input indicator deactivates, and focus returns to the "Previous" button. |

### 4.2 Fail-Safe Mechanism
*   **Detection:** The application continuously monitors the status of the browser’s SpeechRecognition API.
*   **Failure Condition:** If the API is unavailable, disabled, or returns a `no-speech` or `error` event, the voice input path is immediately disabled.
*   **Fallback Action:** The UI reverts to the standard v1 input modality. Focus is programmatically moved to the equivalent non-voice control defined in the mapping table above.
*   **User Notification:** A visible text message is displayed: "Voice input unavailable. Please use the keyboard or mouse to continue." This message is announced via `aria-live="polite"` to screen readers.

### 4.3 Documentation of Fail-Safe Assembly
The Modality Alternative Mapping is hardcoded into the v2 release configuration. If a voice command is added in a future release without a corresponding entry in this mapping, the system **fails safe** by disabling the voice input path entirely for that command type and logging an error to the accessibility monitoring dashboard. This ensures that no voice command can be issued without a documented, functional non-voice alternative.

## 5. Conclusion
Learning Portal v2 is confirmed to be conformant with WCAG 2.1 AA. The new voice-command input path has been documented with a complete Modality Alternative Mapping, ensuring that all voice commands have equivalent non-voice controls, robust fallbacks for transcription failures, and timeouts that return the user to a usable non-voice pathway. The system fails safe if the mapping cannot be assembled or if the speech API is unavailable.

The v1 conformance report remains valid for all unchanged aspects of the portal. This v2 report supersedes the v1 report only with respect to the addition of the voice input modality and its associated compliance requirements.
