# Accessibility Conformance Report: Learning Portal v2

**Release:** learning-portal-v2  
**Standard:** WCAG 2.1 AA  
**Date:** Pre-Release Confirmation (Friday, Q4 2025)  
**Status:** **PENDING SIGN-OFF — BLOCKING ISSUE IDENTIFIED**

## 1. Scope and Basis of Assessment

This report confirms conformance for Learning Portal v2, which releases this Friday. This is a pre-release conformance confirmation, not a full re-audit.

**Basis:**
*   The v1 release was audited against WCAG 2.1 AA and signed off by the Accessibility Board in Q1 2025.
*   The Accessibility Board has reviewed the v2 change summary and confirmed that v2’s page structure, color palette, and keyboard navigation are unchanged from v1.
*   The primary change in v2 is the addition of a voice-command input path using the browser speech API.

## 2. Confirmation of v1 Criteria

Based on the Board’s confirmation that structural, color, and keyboard navigation elements remain unchanged from v1, the following v1 conformance items are confirmed as still applicable and met:
*   **Perceivable:** Color palette and contrast ratios remain compliant with WCAG 2.1 AA (1.4.3 Contrast Minimum).
*   **Operable:** Keyboard navigation surface is unchanged and continues to meet WCAG 2.1 AA (2.1.1 Keyboard, 2.4.3 Focus Order).
*   **Robust:** Page structure remains unchanged, ensuring compatibility with assistive technologies.

*Note: The v1 input and error-handling criteria were written in modality-agnostic terms; therefore, the addition of a new input modality (voice) does not invalidate existing criteria but triggers additional requirements under current policy.*

## 3. V2-Specific Changes: Voice-Command Input Path

The v2 release adds a spoken-input path where learners issue commands to navigate and submit answers. This feature introduces new accessibility considerations regarding input modality, transcription reliability, and failure states.

## 4. Policy Compliance: 2025-Q4 Accessibility Bulletin

**Reference:** `policy/bulletins/2025-Q4-accessibility-bulletin.md` (Effective 2025-11-01)  
**Relevant Item:** "Input Modality Update — Speech Interfaces"

The Bulletin mandates that any release adding a spoken-input path must record an additional conformance item: a **Modality Alternative Mapping**. This mapping must capture:
1.  For every voice command, an equivalent non-voice control.
2.  The transcription-failure fallback.
3.  A timeout that returns the learner to a usable non-voice pathway.

**Requirement:** The mapping must be documented for the release. If the mapping cannot be assembled, the feature must fail safe.

## 5. Conformance Determination

**Finding: NON-CONFORMANT**

The v2 release **cannot** be signed off for release at this time.

**Reasoning:**
The `releases/learning-portal-v2/change-summary.md` confirms the addition of the voice-command path but **does not contain the required Modality Alternative Mapping** as defined in the Q4 2025 Accessibility Bulletin. Specifically, the documentation lacks:
*   The explicit mapping of each spoken command to its non-voice equivalent.
*   Defined transcription-failure fallbacks.
*   Documented timeout behaviors that ensure learners are returned to a usable non-voice pathway.

Because the release is subject to the Q4 2025 policy (effective 2025-11-01) and the required documentation is missing, the conformance procedure cannot be completed. The feature has not been shown to "fail safe" or provide a guaranteed accessible alternative for every voice command.

## 6. Required Actions Before Release

To achieve conformance and allow for sign-off, the following must be completed and appended to this report:

1.  **Create the Modality Alternative Mapping:** Document every voice command introduced in v2.
2.  **Define Fallbacks:** For each command, specify the exact non-voice control (e.g., button ID, keyboard shortcut) that performs the identical function.
3.  **Document Timeout and Failure Behavior:** Specify the timeout duration for voice input and the exact user flow triggered upon transcription failure or timeout (must result in a usable non-voice pathway).
4.  **Update `change-summary.md`:** Include this mapping in the release documentation.
5.  **Re-submit for Review:** The Accessibility Compliance Officer will re-evaluate the report once the mapping is provided.

**Recommendation:** **HOLD RELEASE** until the Modality Alternative Mapping is documented and verified. Releasing without this mapping violates the Q4 2025 Accessibility Bulletin and exposes learners with speech, hearing, or motor impairments to inaccessible pathways.
