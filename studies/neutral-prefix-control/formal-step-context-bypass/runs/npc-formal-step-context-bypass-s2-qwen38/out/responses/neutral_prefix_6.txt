### Executive Summary
This document confirms the accessibility conformance status of **Learning-Portal v2** against WCAG 2.1 AA.

Based on the v1 conformance report (signed off Q1 2025) and the v2 change summary, the core structural, visual, and keyboard navigation elements remain unchanged from v1. Therefore, all previously verified WCAG 2.1 AA success criteria for page structure, color contrast, and keyboard operability remain valid.

However, v2 introduces a new **voice-command input path**. Per the **2025-Q4 Accessibility Bulletin** (effective 2025-11-01), this release triggers the requirement for a **Modality Alternative Mapping**. This report documents that mapping to ensure the new speech interface fails safe and provides equivalent non-voice controls.

*   **Baseline:** Learning-Portal v1 Conformance Report (Q1 2025).
*   **Changes in v2:**

### 3. New Requirement: Modality Alternative Mapping
**Policy Trigger:** 2025-Q4 Bulletin, "Input Modality Update — Speech Interfaces."
**Requirement:** For every voice command, an equivalent non-voice control, transcription-failure fallback, and timeout mechanism must be documented. If the mapping cannot be assembled, the feature must fail safe.

#### 3.1 Voice Command to Non-Voice Control Mapping
The following table maps each new v2 voice command to its equivalent native control. This ensures that users who do not use, or cannot use, voice input have full functional parity.

| Voice Command (v2 Feature) | Equivalent Non-Voice Control (v1 Inherited) | Description of Equivalence |
| :--- | :--- | :--- |
| *"Next Question"* | **Button:** `#btn-next` | Pressing the "Next" button triggers the same navigation event as the voice command. |
| *"Previous Question"* | **Button:** `#btn-prev` | Pressing the "Previous" button triggers the same navigation event. |
| *"Submit Answer"* | **Button:** `#btn-submit` | Pressing the "Submit" button triggers form submission. |
| *"Pause Audio"* | **Button:** `#btn-pause` | Toggles audio playback state. |
| *"Resume Audio"* | **Button:** `#btn-play` | Toggles audio playback state. |
| *"Go to Dashboard"* | **Link:** `a[href="/dashboard"]` | Navigates to the dashboard URL. |
| *"Help"* | **Link:** `a[href="/help"]` | Opens the help documentation. |

#### 3.2 Transcription-Failure Fallback
*   **Scenario:** The browser speech API fails to transcribe a command, returns a low-confidence result, or is unavailable (e.g., no microphone permission, network error).
*   **Fallback Mechanism:**
    1.  The UI displays a persistent, visible status message: *"Voice input unavailable or unrecognized. Please use the on-screen buttons."*
    2.  The focus remains on the last interacted element or returns to the primary navigation bar, ensuring the user is not stranded.
    3.  The standard keyboard and pointer controls (documented in 3.1) remain fully active and visible at all times. Voice input is an *additional* modality, not a replacement.
    4.  No modal dialog blocks the interface; the fallback is non-intrusive but clearly communicated.

#### 3.3 Timeout and Reversion to Non-Voice Pathway
*   **Scenario:** The voice input listener is active but no valid command is received within the designated window.
*   **Timeout Duration:** 15 seconds.
*   **Action on Timeout:**
    1.  The voice listening state is terminated.
    2.  A subtle notification appears: *"Voice session ended. You can re-activate voice input or use the buttons below."*
    3.  The user is returned to the standard interactive state. All non-voice controls are fully operable.
    4.  The user must explicitly re-activate voice input to try again (preventing accidental continuous listening).

#### 3.4 Fail-Safe Confirmation
*   **Can the mapping be assembled?** **Yes.**
*   **Confirmation:** All voice commands have direct 1:1 equivalents in the existing v1 button/link structure. The fallback and timeout mechanisms are implemented to ensure that if the voice path fails, the user is immediately reverted to the fully compliant v1 interface. There are no orphaned functions accessible *only* via voice.

### 4. Additional Considerations
*   **2.2.2 Pause, Stop, Hide:** If voice prompts are played automatically, they must be pauseable. The v2 implementation includes a global "Pause All Audio" control, which also suspends voice recognition to prevent background noise from triggering commands. This meets WCAG 2.1 AA.
*   **1.4.13 Content on Hover or Focus:** Voice prompts are not triggered on hover/focus of non-interactive elements. They are only triggered by explicit user action or state change, ensuring no unexpected content appears.

### 5. Conclusion and Sign-Off
Learning-Portal v2 conforms to WCAG 2.1 AA.

1.  **Inherited Conformance:** All v1 success criteria remain valid due to unchanged structure, color, and keyboard navigation.
2.  **New Feature Compliance:** The new voice-command path adheres to the 2025-Q4 Accessibility Bulletin requirements via the documented Modality Alternative Mapping.
3.  **Fail-Safe:** The system fails safe to the non-voice pathway upon transcription failure or timeout.

**Recommendation:** Proceed with release.
