# Accessibility Conformance Report: Learning Portal v2

**Date:** [Current Date]
**Auditor:** Accessibility Compliance Officer
**Standard:** WCAG 2.1 AA
**Status:** **CONDITIONAL PASS** – Pending Board Ratification of Modality Alternative Mapping

## 1. Executive Summary

This pre-release conformance confirmation for **Learning Portal v2** validates the incremental changes made to the application. Based on the Board’s prior review of the v2 change summary, it has been established that v2 retains the v1 page structure, color palette, and keyboard navigation surface unchanged. The v1 Conformance Report (signed off Q1 2025) remains current for all static and keyboard-accessible aspects of the application.

However, v2 introduces a **voice-command input path** utilizing the browser speech API. Per the **Accessibility Office Q4 2025 Bulletin** (effective 2025-11-01), this addition triggers a mandatory new conformance requirement: the **Modality Alternative Mapping**.

**Critical Finding:** The v2 change summary documents the addition of the voice path but does not currently document the required Modality Alternative Mapping (equivalent non-voice controls, transcription-failure fallback, and timeout recovery). Until this mapping is documented and verified, the release **cannot be fully signed off** under the new Q4 2025 policy.

## 2. Baseline Conformance (Carried Over from v1)

The following success criteria are confirmed as still met in v2, based on the Board’s confirmation that structural, visual, and keyboard elements are unchanged from v1:

*   **WCAG 2.1 AA Success Criteria 1.1.1 to 4.1.2:** All criteria previously met in v1 remain compliant.
*   **Input and Error Handling:** The v1 report documented these in modality-agnostic terms. Since the core form structures and error messaging logic are unchanged, these remain compliant.
*   **Keyboard Navigation:** Confirmed unchanged. All interactive elements remain accessible via keyboard.

## 3. v2-Specific Changes: Voice Command Path

### 3.1 Description of New Feature
Learners can issue spoken commands to navigate the portal and submit answers. Transcription is handled by the native browser speech API.

### 3.2 Policy Compliance Check: Modality Alternative Mapping
Per **`policy/bulletins/2025-Q4-accessibility-bulletin.md`**, any release adding a spoken-input path must record a **Modality Alternative Mapping**. This mapping must capture:

1.  **Equivalent Non-Voice Control:** For every voice command, there must be an equivalent button, link, or keyboard shortcut.
2.  **Transcription-Failure Fallback:** A clear mechanism to inform the user if speech recognition fails and offer an alternative input method.
3.  **Timeout Recovery:** A timeout mechanism that returns the learner to a usable non-voice pathway if the voice interface becomes unresponsive or inaccessible.

**Current Status:** **NOT DOCUMENTED**
The `releases/learning-portal-v2/change-summary.md` confirms the feature exists but does not include the required mapping documentation. The `conformance-report.md` template is currently blank in this section.

## 5. Required Actions Before Release

To achieve full conformance and sign-off, the following actions must be completed:

1.  **Document the Modality Alternative Mapping:**
    *   List every voice command introduced in v2.
    *   For each, specify the equivalent non-voice control (e.g., button, keyboard shortcut).
    *   Document the transcription-failure fallback message and UI behavior.
    *   Document the timeout duration and the recovery path (e.g., “Return to standard form input”).

2.  **Verify Fail-Safe Behavior:**
    *   Confirm that if the mapping cannot be assembled for any command, the system fails safe (i.e., disables the voice option for that action and directs the user to the non-voice control).

3.  **Update the Conformance Report:**
    *   Populate the “Modality Alternative Mapping” section of this report with the verified details.

4.  **Board Ratification:**
    *   Submit the updated report and mapping for final Board review and sign-off.

## 6. Recommendation

**Do not release Learning Portal v2 until the Modality Alternative Mapping is fully documented and verified.**

The v1 baseline conformance is strong, and the v2 changes are minimal. However, the Q4 2025 Accessibility Bulletin is explicit: voice interfaces require documented, fail-safe alternatives. Shipping without this documentation would constitute a policy violation and a potential accessibility risk for users who cannot use voice input (e.g., in noisy environments, with speech impairments, or on devices with disabled microphones).

*   Accessibility Officer to verify the mapping against the live v2 build.
*   Final sign-off to be issued upon successful verification.
