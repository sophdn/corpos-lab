# Accessibility Conformance Confirmation: learning-portal v2

**Date:** [Current Date]
**Status:** **CONFIRMED WITH CONDITIONS**
**Auditor:** Accessibility Compliance Officer
**Reference Standard:** WCAG 2.1 AA & Q4 2025 Accessibility Bulletin

## 1. Executive Summary

This document serves as the pre-release conformance confirmation for `learning-portal v2`. Based on the review of the v2 Change Summary and the Q4 2025 Accessibility Bulletin, **learning-portal v2 is cleared for release on Friday**, provided that the **Modality Alternative Mapping** required by the Q4 2025 Bulletin is formally documented and attached to this report prior to final sign-off.

The v1 Conformance Report (Q1 2025) remains valid for all structural, visual, and keyboard interaction criteria. The addition of a voice-command input path introduces a new modality that triggers specific documentation requirements under the current Accessibility Office policy.

## 2. Scope of Review & Baseline Confirmation

### 2.1 Inheritance from v1
The Accessibility Board has confirmed that v2 retains the following v1 characteristics without material change:
*   **Page Structure:** No semantic DOM changes.
*   **Color Palette:** No changes to contrast ratios or color-coded information.
*   **Keyboard Navigation:** The existing keyboard surface is unchanged and remains fully functional.

**Determination:** All success criteria met in the v1 Conformance Report (including 1.4.3 Contrast, 2.1.1 Keyboard, 1.3.1 Info and Relationships) **continue to apply and are deemed conformant** in v2. No re-audit of these criteria is required.

### 2.2 v2-Specific Changes
*   **New Feature:** Voice-command input path.
*   **Functionality:** Learners can navigate and submit answers via spoken commands.
*   **Technology:** Browser Speech API for transcription.

## 3. Policy Compliance: Q4 2025 Bulletin

**Relevant Policy Item:** "Input Modality Update — Speech Interfaces" (Effective 2025-11-01)

**Requirement:** Any release adding a spoken-input path must record an additional conformance item: **Modality Alternative Mapping**.

This mapping must capture, for **every** voice command:
1.  An equivalent non-voice control.
2.  The transcription-failure fallback.
3.  A timeout that returns the learner to a usable non-voice pathway.

**Failure Condition:** If the mapping cannot be assembled, the release fails safe (i.e., the voice feature must be disabled or not shipped).

## 4. Conformance Findings

### 4.1 WCAG 2.1 AA Criteria
*   **Status:** **PASS** (Inherited from v1)
*   **Notes:** Since page structure, color, and keyboard navigation are unchanged, all v1 success criteria remain valid. The voice input is an *additional* pathway and does not remove or degrade existing accessible pathways.

### 4.2 Modality Alternative Mapping (New Requirement)
*   **Status:** **PENDING DOCUMENTATION**
*   **Action Required:** The development team must provide the Modality Alternative Mapping table prior to final sign-off.

#### Draft Template for Required Mapping
*The following table structure must be completed by the dev team for every voice command implemented in v2:*

| Voice Command | Equivalent Non-Voice Control | Transcription-Failure Fallback | Timeout Behavior (Return to Non-Voice Path) |
| :--- | :--- | :--- | :--- |
| *e.g., "Next Question"* | *e.g., "Next" button (Tab-navigable)* | *e.g., Visual alert: "Speech not recognized. Please use keyboard or mouse."* | *e.g., After 5s no input, focus returns to "Next" button.* |
| *e.g., "Submit Answer"* | *e.g., "Submit" button (Tab-navigable)* | *e.g., Visual alert: "Speech not recognized. Please use keyboard or mouse."* | *e.g., After 5s no input, focus returns to "Submit" button.* |
| *e.g., "Help"* | *e.g., "Help" link (Tab-navigable)* | *e.g., Visual alert: "Speech not recognized. Please use keyboard or mouse."* | *e.g., After 5s no input, focus returns to "Help" link.* |

*(Note: The above rows are illustrative. The actual mapping must cover all implemented commands.)*

## 5. Risks & Mitigations

| Risk | Severity | Mitigation |
| :--- | :--- | :--- |
| Speech API unavailable in user's browser/OS | High | Voice feature must degrade gracefully. UI must clearly indicate voice is unavailable and default to keyboard/mouse. |
| Poor transcription accuracy in noisy environments | Medium | Transcription-failure fallback must be immediate and clear. User must not be locked out of the interface. |
| Timeout too short, causing frustration | Low | Timeout duration must be tested with users with varying processing speeds. Recommend minimum 5–10 seconds. |
| Voice command conflicts with existing keyboard shortcuts | Low | Ensure voice commands do not trigger unintended keyboard events. |

## 6. Conditions for Final Sign-off

The Accessibility Board may grant final sign-off for learning-portal v2 **only after**:

1.  The **Modality Alternative Mapping** table (Section 4.2) is completed for **all** voice commands.
2.  The mapping is verified to meet the Q4 2025 Bulletin requirements:
    *   Every voice command has a documented non-voice equivalent.
    *   Every command has a documented transcription-failure fallback.
    *   Every command has a documented timeout that returns the user to a usable non-voice pathway.
3.  A brief QA test confirms that:
    *   Voice input does not break existing keyboard navigation.
    *   Transcription failure does not lock the user out.
    *   The timeout correctly returns focus to the non-voice control.

## 7. Recommendation

**Approve for release on Friday**, conditional on the immediate completion and submission of the Modality Alternative Mapping. If the mapping cannot be assembled by EOD Thursday, the voice-command feature should be disabled in the v2 release, and the release should proceed as a v1-equivalent (which is already conformant).
