# Learning Portal v2 Accessibility Conformance Report

**Status:** **BLOCKED – Conformance Failure**
**Date:** Q4 2025 (Pre-Release Confirmation)
**Auditor:** Accessibility Compliance Officer
**Reference Policy:** Accessibility Office Q4 2025 Bulletin (Effective 2025-11-01)

## 1. Executive Summary

The Learning Portal v2 release **cannot** be signed off for WCAG 2.1 AA conformance at this time.

While the v1 baseline (signed off Q1 2025) remains current, and the unchanged structural, color, and keyboard navigation elements retain their conformance status, the addition of the voice-command input path triggers a mandatory compliance requirement under the **2025-Q4 Accessibility Bulletin**.

The v2 change summary indicates that a new spoken-input pathway has been added. Per the "Input Modality Update — Speech Interfaces" section of the Q4 2025 Bulletin, any release adding a spoken-input path must record a **Modality Alternative Mapping**. This document must detail:
1.  An equivalent non-voice control for every voice command.
2.  The transcription-failure fallback.
3.  A timeout mechanism returning the learner to a usable non-voice pathway.

**Current Status:** The v2 change summary and available documentation do not contain this Modality Alternative Mapping. As the bulletin specifies that the release must fail safe if the mapping cannot be assembled, **v2 is non-conformant** until this documentation is produced and verified.

## 2. Scope of Review

*   **Inherited from v1:** Page structure, color palette, keyboard navigation, core input forms, and error handling (modality-agnostic).
*   **New in v2:** Voice-command input path (navigation and answer submission via browser speech API).

## 3. Conformance Determination

### 3.1. v1 Criteria Verification (Pass)
The Accessibility Board confirmed that v2’s page structure, color palette, and keyboard navigation are unchanged from v1. Therefore, the v1 conformance report remains valid for these aspects. The modality-agnostic terms used in v1 for input and error-handling criteria continue to apply to the non-voice portions of the interface.

### 3.2. New Feature: Voice-Command Input (Fail)
**Requirement:** 2025-Q4 Accessibility Bulletin, Item: "Input Modality Update — Speech Interfaces."

**Finding:**
The v2 release introduces a speech-based input modality. The bulletin mandates that such releases must include a **Modality Alternative Mapping** in the conformance report. This mapping must explicitly document:
*   **Equivalent Non-Voice Control:** For each spoken command (e.g., "next question," "submit answer"), there must be a documented corresponding keyboard or mouse action.
*   **Transcription Failure Fallback:** A defined user-facing behavior when speech recognition fails or is unavailable (e.g., error message, prompt to use keyboard).
*   **Timeout Mechanism:** A documented timeout period after which the system automatically reverts to or prompts the user toward a usable non-voice pathway.

**Evidence Gap:**
The provided `change-summary.md` states that the voice path is added but does not provide the required Modality Alternative Mapping. No documentation was found detailing the fallbacks, timeouts, or explicit non-voice equivalents for the new voice commands.

**Policy Application:**
The bulletin states: *"…documented for the release and failing safe if the mapping cannot be assembled."*

Since the mapping is not present in the release documentation, the "fail safe" condition is triggered. The release is deemed non-conformant.

## 4. Required Actions for Re-Submission

To proceed to release, the Development Team must:

1.  **Create the Modality Alternative Mapping:**
    *   List all voice commands implemented in v2.
    *   Map each command to its specific non-voice control (keyboard shortcut or UI element).
    *   Document the exact fallback behavior for transcription failure.
    *   Document the timeout duration and the resulting state (must be a usable non-voice pathway).
2.  **Update the Conformance Report:**
    *   Add a new section titled **"Modality Alternative Mapping – Voice Input"** to `releases/learning-portal-v2/conformance-report.md`.
    *   Populate this section with the details from step 1.
3.  **Verification:**
    *   Confirm via testing that the timeout and fallback mechanisms function as documented.
    *   Submit the updated report to the Accessibility Board for final sign-off.

## 5. Recommendation

**Do not ship Learning Portal v2.**

The release must be held until the Modality Alternative Mapping is documented and verified. This is a mandatory requirement under the current Q4 2025 Accessibility Policy. Once the documentation is complete and verified, this officer will re-review and issue a conformance confirmation.
