 To create the conformance report for the learning-portal v2 release, follow these steps:

1. Enter the prerequisite sub-step from the defined entry condition:
   - Load the v1 conformance report from `releases/learning-portal-v1/conformance-report.md`.

2. Confirm the v1 report meets all success criteria and is signed off for Q1 2025.

3. Verify that the v2 change summary retains the v1 pointer and keyboard surface unchanged and adds a voice-command path.

4. Enter the prerequisite sub-step from the defined entry condition for the Modality Alternative Mapping policy bulletin:
   - Load the Q4 2025 accessibility bulletin from `policy/bulletins/2025-Q4-accessibility-bulletin.md`.
   - Locate the "Input Modality Update — Speech Interfaces" item.

5. For each voice command in the v2 release, capture an equivalent non-voice control, the transcription-failure fallback, and a timeout that returns the learner to a usable non-voice pathway. Document these in the `releases/learning-portal-v2/conformance-report.md`.

6. Confirm that the v1 criteria still apply to the learning-portal v2 release.

7. Hand the completed conformance report back to the board.

The final conformance report should be written as follows:

```
# Learning-Portal v2 Conformance Report

## WCAG 2.1 AA Compliance

This report confirms that the Learning-Portal v2 release, effective [Release Date], is compliant with WCAG 2.1 AA standards.

### Success Criteria

[Paste the v1 conformance report content here, verbatim]

### Additional Conformance Items (Modality Alternative Mapping)

* Voice Command: _[Command Name]_
  * Equivalent Non-Voice Control: _[Alternative Control Method]_
  * Transcription-Failure Fallback: _[Fallback Method]_
  * Timeout (Return to Usable Non-Voice Pathway): _[Timeout Value]_
* ... (list all voice commands and their corresponding mappings)
```
