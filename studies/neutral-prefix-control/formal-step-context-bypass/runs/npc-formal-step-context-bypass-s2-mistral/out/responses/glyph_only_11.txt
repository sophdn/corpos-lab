# Learning-Portal v2 Conformance Report

## WCAG 2.1 AA Conformance

This report confirms the conformance of Learning-Portal v2 to the Web Content Accessibility Guidelines (WCAG) 2.1 at Level AA as of November 1, 2025. The report is based on the conformance criteria and success measures from the WCAG 2.1 Level AA standard.

## Perceivable

### 1.1.1 Non-text Content
- **Success Criterion 1.1.1**: Non-text content has a text alternative that serves the equivalent purpose. [Met] (See v1 conformance report)

### 1.2.1 Audio-only and Video-only (Prerecorded)
- **Success Criterion 1.2.1**: All non-text content has a text equivalent that can be presented in the same way as the non-text content. [Met] (See v1 conformance report)

### 1.2.3 Audio Description or Media Alternative
- **Success Criterion 1.2.3**: If any audio-only or video-only content is presented, alternatives that present equivalent information are provided for all non-text content. [Met] (See v1 conformance report)

### 1.3.1 Info and Relationships
- **Success Criterion 1.3.1**: Information and relationships conveyed through presentation can also be programmatically determined or presented. [Met] (See v1 conformance report)

### 1.4.1 Use of Color
- **Success Criterion 1.4.1**: Color is not used as the only visual means of conveying information, indicating an action, prompting a response, or distinguishing a visual element. [Met] (See v1 conformance report)

### 1.4.3 Contrast (Minimum)
- **Success Criterion 1.4.3**: The visual presentation of text and images of text has a contrast ratio of at least 4.5:1, except for the following:
  - Large-scale text (18 pt or 14 pt if bold) has a contrast ratio of at least 3:1.
  - Graphics that are part of an inactive user interface, that are part of a picture that contains other graphics or text, or that are part of a graph or chart have no contrast requirement.
  - Text presented as part of a icon does not have a contrast requirement. [Met] (See v1 conformance report)

### 1.4.4 Resize Text
- **Success Criterion 1.4.4**: Except for captions and images of text, text can be resized without assistive technology up to 200 percent without loss of content or functionality. [Met] (See v1 conformance report)

## Operable

### 2.1.1 Keyboard
- **Success Criterion 2.1.1**: All functionality can be operated from a keyboard. [Met] (See v1 conformance report)

### 2.2.1 Timing Adjustable
- **Success Criterion 2.2.1**: All moving, blinking, scrolling, or auto-updating information can be paused, stopped, or slowed down without losing information or functionality. [Met] (See v1 conformance report)

### 2.4.1 Bypass Blocks
- **Success Criterion 2.4.1**: Bypass blocks can be bypassed in at least one way, for example by activating a skip link. [Met] (See v1 conformance report)

### 2.4.3 Focus Order
- **Success Criterion 2.4.3**: Where content requires user input, the sequence of navigation mechanisms offers no surprises. [Met] (See v1 conformance report)

### 2.4.4 Link Purpose (In Context)
- **Success Criterion 2.4.4**: The purpose of each link can be determined from the link text alone or from the link text together with its programmatically determined link context, except where the purpose of the link would be ambiguous to users in the default mode. [Met] (See v1 conformance report)

## Understandable

### 3.1.1 Language of Page
- **Success Criterion 3.1.1**: The default human language of each web page can be programmatically determined. [Met] (See v1 conformance report)

### 3.1.2 Language of Parts
- **Success Criterion 3.1.2**: The operating system and user agent must be able to determine the human language(s) of each part of the content. [Met] (See v1 conformance report)

### 3.2.1 On Focus
- **Success Criterion 3.2.1**: All interactive content receives focus in a visible, operable, and predictable manner when the user activates the content, the user agent activates the content, or both. [Met] (See v1 conformance report)

### 3.2.2 On Input
- **Success Criterion 3.2.2**: All interactive content has a status that can be programmatically determined through operating system interface components. [Met] (See v1 conformance report)

### 3.3.1 Error Identification
- **Success Criterion 3.3.1**: If an input error is automatically detected, the content indicates the error and suggests a corrective action. [Met] (See v1 conformance report)

## Robust

### 4.1.1 Parsing
- **Success Criterion 4.1.1**: Parsing must be well-formed, valid, and conform to specified grammar. [Met] (See v1 conformance report)

### 4.1.2 Name, Role, Value
- **Success Criterion 4.1.2**: Elements have complete and accurate attribute minimally necessary to identify the purpose and role of any element that is presentable to the user. [Met] (See v1 conformance report)

## Modality Alternative Mapping

### G2001: Modality Alternative Mapping
- **Success Criterion G2001**: For all voice commands, an equivalent non-voice control, the transcription-failure fallback, and a timeout that returns the learner to a usable non-voice pathway are documented.

This criterion is specific to the Learning-Portal v2 release, which includes a voice-command input path. The detailed mapping can be found in the Voice Command Mapping document.
