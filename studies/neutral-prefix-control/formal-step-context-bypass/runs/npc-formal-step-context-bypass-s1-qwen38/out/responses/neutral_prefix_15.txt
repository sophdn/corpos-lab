### Executive Summary

This document serves as the pre-deployment compliance confirmation for **Data-Export v2**, scheduled for deployment on Friday.

### Data-Export v2 Compliance Checklist

**Release:** Data-Export v2
**Deployment Date:** Friday
**Baseline:** Data-Export v1 (Signed Off Q1 2025)
**Regulatory Trigger:** 2025-Q4 Bulletin — "Data Export Process Update — Partner Integrations"

#### 1. Data Scope & Retention
*   **Status:** **Confirmed Unchanged**
*   **Notes:**
    *   Data scope is identical to v1.
    *   Retention policies are identical to v1.
    *   No new data types are exposed to partners beyond what is already authorized under v1 user consents.
    *   *Action:* No changes required. v1 checklist items for data scope and retention remain green.

#### 2. Access Control & Authentication
*   **Status:** **Updated for v2**
*   **Notes:**
    *   **v1 CLI Access:** Unchanged. Continues to operate under v1 controls.
    *   **v2 Partner-Portal Access (New):**
        *   Partners authenticate via OAuth scope.
        *   Exports are restricted to users who have granted active authorization to the specific partner.
        *   **Control Verification:** Ensure the OAuth scope validation logic explicitly checks for the `data-export` permission and validates the active authorization grant ID before processing the request.
        *   **Fail-Closed Requirement:** If OAuth token validation or authorization grant lookup fails, the request must be rejected (HTTP 401/403). No default-allow behavior.

#### 3. Audit Logging & Provenance
*   **Status:** **New Requirement (v2-Specific)**
*   **Notes:**
    *   **v1 Audit Logs:** Continue to apply for CLI-initiated exports.
    *   **v2 Partner-Initiated Exports (New - Per 2025-Q4 Bulletin):**
        *   **Requirement:** Every partner-initiated export request must generate a **Provenance Stamp** audit entry.
        *   **Mandatory Fields in Provenance Stamp:**
            1.  User's Authorization Grant ID
            2.  Requesting Party Identity (Partner ID/OAuth Client ID)
            3.  Authorization Scope (e.g., `read:exports`)
            4.  Validity Window (Start/End timestamps of the active authorization)
        *   **Implementation Constraint:**
            *   The Provenance Stamp must be written **synchronously** with the export request processing.
            *   The system must **fail closed** if the Provenance Stamp cannot be assembled or written. If the audit log service is unavailable or the grant ID cannot be resolved, the export request must be aborted and an error returned to the partner.
        *   *Action:* Verify that the `POST /v2/data-export/request` handler includes logic to construct and persist this stamp before any data transmission occurs.

#### 4. Security & Infrastructure
*   **Status:** **Confirmed Unchanged**
*   **Notes:**
    *   Network security, encryption in transit/at rest, and key management remain as defined in v1.
    *   The new HTTP endpoint must be served over TLS 1.2+.
    *   Rate limiting should be applied to the partner endpoint to prevent abuse, consistent with v1 standards for API traffic.

#### 5. Legal & Data Privacy
*   **Status:** **Confirmed Unchanged**
*   **Notes:**
    *   User consent mechanisms for partner integrations were validated in Q1 2025.
    *   No changes to GDPR/CCPA data subject rights procedures.
    *   Partner agreements must already cover data processing responsibilities (DPA in place).
