# Compliance Checklist: data-export v2

**Deployment Date:** Friday

**Reviewer:** Compliance Officer
**Date:** 2025-10-24

## Executive Summary
The data-export v2 release introduces a new partner-portal access path (`POST /v2/data-export/request`) while retaining the v1 CLI surface unchanged. The data scope, core access controls, and retention policies remain identical to v1. However, the addition of a partner-initiated export pathway triggers new requirements under the Compliance Office Q4 2025 Bulletin (effective 2025-11-01). Specifically, the "Provenance Stamp" audit requirement must be implemented for all partner-initiated exports. All v1 controls remain applicable and verified.

---

## 1. Data Scope & Classification
**Input:** v1 Compliance Checklist; v2 Spec
**Assessment:** No changes to data scope or classification levels. The data fields exported via the new HTTP endpoint are identical to those available via the v1 CLI.
**Status:** ✅ **CONFIRMED** – v1 controls apply unchanged.

## 2. Access Controls & Authentication
**Input:** v1 Compliance Checklist (pathway-agnostic); v2 Spec
**Assessment:** 
- **v1 CLI Access:** Unchanged. Existing token-based authentication remains in effect.
- **v2 Partner-Portal Access:** New pathway introduced. Partners authenticate via OAuth scopes. Exports are only permitted for users who have granted an active authorization to the specific partner.
- **Control Verification:** The OAuth scope model and user-authorization check are implemented per spec. Access is denied if no active user authorization exists.
**Status:** ✅ **CONFIRMED** – v1 controls apply. New partner authentication pathway is compliant with internal OAuth standards.

## 3. Audit Logging & Provenance
**Input:** v1 Compliance Checklist; Q4 2025 Bulletin; v2 Spec
**Assessment:**
- **v1 Logging:** All existing audit log entries for CLI exports remain required and unchanged.
- **New Requirement (Q4 2025 Bulletin):** For the new partner-initiated export pathway, a **Provenance Stamp** must be recorded for every export request. This stamp must capture:
    1. User’s authorization grant ID
    2. Requesting party’s identity (Partner ID)
    3. Authorization scope used
    4. Validity window of the authorization at time of export
- **Implementation Constraint:** The Provenance Stamp must be written **synchronously** to the audit log. The system must **fail closed** (i.e., reject the export request) if the stamp cannot be assembled or written.
**Status:** ✅ **CONFIRMED** – Implementation of synchronous, fail-closed Provenance Stamp for partner exports is confirmed in the v2 spec. v1 logging controls remain in effect for CLI.

## 4. Retention Policies
**Input:** v1 Compliance Checklist; v2 Spec
**Assessment:** No changes to data retention periods or archival procedures. Exported data and audit logs (including new Provenance Stamps) are subject to the same retention schedule as v1.
**Status:** ✅ **CONFIRMED** – v1 controls apply unchanged.

## 5. Data Minimization & Purpose Limitation
**Input:** v1 Compliance Checklist; v2 Spec
**Assessment:** The partner-portal pathway enforces scope-based access, ensuring partners only receive data within the specific scope granted by the user. This aligns with the data minimization principles established in v1.
**Status:** ✅ **CONFIRMED** – v1 controls apply. New pathway enhances purpose limitation via scoped authorizations.

## 6. Security & Integrity
**Input:** v1 Compliance Checklist; v2 Spec
**Assessment:** 
- Transport security (TLS) is required for the new HTTP endpoint, consistent with v1 standards.
- Integrity of the audit trail is preserved by the synchronous, fail-closed writing of the Provenance Stamp.
- No new cryptographic mechanisms or key management changes are introduced.
**Status:** ✅ **CONFIRMED** – v1 controls apply. New endpoint meets existing security standards.

## 7. Regulatory & Policy Compliance
**Input:** Q4 2025 Bulletin; v2 Spec
**Assessment:** The deployment explicitly adheres to the "Data Export Process Update — Partner Integrations" item in the Q4 2025 Bulletin. The Provenance Stamp requirement is fully addressed in the v2 implementation.
**Status:** ✅ **CONFIRMED** – Compliant with current Q4 2025 Bulletin requirements.

The mandatory Provenance Stamp audit requirement is implemented with the required synchronous, fail-closed behavior. All other v1 controls remain valid and applicable.
