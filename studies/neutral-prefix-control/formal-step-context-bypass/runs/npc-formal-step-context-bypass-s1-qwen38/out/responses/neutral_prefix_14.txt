# Data Export v2 Compliance Checklist

**Release Version:** v2

## 1. Data Scope & Minimization
*   **Status:** ✅ **PASS** (Inherited from v1)
*   **Verification:**
    *   V2 retains the v1 CLI surface unchanged.
    *   The new HTTP endpoint (`POST /v2/data-export/request`) utilizes the same data scope definitions as v1.
    *   No new data fields have been added to the export payload.
    *   *Note:* Access is restricted to users who have granted an active authorization to the partner, consistent with v1 access control logic.

## 2. Access Controls & Authentication
*   **Status:** ✅ **PASS** (Inherited from v1)
*   **Verification:**
    *   v1 access controls remain active for all pathways.
    *   **New Control (Partner Portal):** Partners must authenticate via OAuth scope.
    *   **Authorization Check:** Exports are only permitted if the target user has an active, unrevoked authorization grant for the requesting partner.
    *   *Confirmation:* Spec confirms no bypass of standard user-authorization checks for partner requests.

## 3. Retention & Deletion Policies
*   **Status:** ✅ **PASS** (Inherited from v1)
*   **Verification:**
    *   Data retention periods for exported records remain unchanged from v1.
    *   Deletion requests (Right to be Forgotten) propagate to partner-held exports via the same mechanism as v1 (API revocation/notification).

## 4. Audit Logging & Provenance
*   **Status:** ✅ **PASS** (Updated for Q4 2025 Bulletin)
*   **Verification:**
    *   Standard v1 audit logs (timestamp, user ID, data scope) are active for both CLI and HTTP pathways.
    *   **NEW REQUIREMENT (Q4 2025 Bulletin):** A **Provenance Stamp** audit entry is recorded for all partner-initiated exports.
    *   **Provenance Stamp Fields Captured:**
        1.  User’s authorization grant ID.
        2.  Requesting party’s identity (Partner OAuth Client ID).
        3.  Authorization scope applied.
        4.  Validity window of the authorization at the time of export.
    *   **Implementation Check:** The stamp is written **synchronously**.
    *   **Failure Mode:** The system is configured to **fail closed**. If the Provenance Stamp cannot be assembled, the export request is rejected and an error is logged.

## 5. Security & Encryption
*   **Status:** ✅ **PASS** (Inherited from v1)
*   **Verification:**
    *   Data in transit for the new HTTP endpoint uses TLS 1.2+ (same as v1 internal services).
    *   Data at rest follows v1 encryption standards.
    *   No new secrets or keys introduced beyond standard OAuth client credentials.
