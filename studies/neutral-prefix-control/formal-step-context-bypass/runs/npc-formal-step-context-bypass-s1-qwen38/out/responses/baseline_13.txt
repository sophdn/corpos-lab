## 1. Executive Summary & Scope Confirmation

This document serves as the pre-deployment compliance confirmation for the **data-export v2** release.

**Basis for Confirmation:**
1.  **v1 Baseline:** The data-export v1 release was fully reviewed, signed off by Legal and Security in Q1 2025, and its compliance checklist remains current.
2.  **Unchanged Controls:** The compliance team has reviewed the v2 specification and confirmed that v2’s core data scope, access controls, and retention policies are **unchanged** from v1.
3.  **New Functionality:** v2 introduces a new partner-portal access path via `POST /v2/data-export/request` using OAuth scopes.
4.  **Regulatory Update:** The Q4 2025 Compliance Bulletin (effective 2025-11-01) requires additional audit logging for partner-initiated exports.

**Conclusion:** Because the foundational controls are unchanged, the v1 checklist items remain valid. This v2 checklist confirms the applicability of v1 controls and addresses the specific new requirement for Provenance Stamping on the partner pathway.

## 3. Access Control & Authentication

| Control | Status | Notes |
| :--- | :--- | :--- |
| **User Authorization** | ✅ Inherited (v1) | User consent and authorization logic remains as defined in v1. Partners can only request exports for users who have granted active authorization. |
| **Partner Authentication** | ✅ **New (v2)** | Partners authenticate via **OAuth Scope**. <br> *Confirmation:* The spec confirms that OAuth scopes are strictly enforced to ensure partners can only access data within the granted authorization scope. |
| **Least Privilege** | ✅ **New (v2)** | The partner-portal endpoint (`POST /v2/data-export/request`) is restricted to authenticated partner identities. No anonymous or unscoped access is permitted. |

---

## 4. Audit Logging & Provenance

| Control | Status | Notes |
| :--- | :--- | :--- |
| **General Audit Logging** | ✅ Inherited (v1) | Standard audit logs for CLI and internal API usage remain active and unchanged. |
| **Provenance Stamp (Partner Exports)** | ✅ **New (v2) - Compliant** | **Required by Q4 2025 Bulletin.** <br> *Implementation:* A synchronous "Provenance Stamp" audit entry is written for every partner-initiated export. <br> *Fields Captured:* <br> 1. User’s Authorization Grant ID <br> 2. Requesting Party’s Identity <br> 3. Authorization Scope <br> 4. Validity Window at time of export <br> *Fail-Closed Mechanism:* The system is configured to **fail closed** if the Provenance Stamp cannot be assembled. Export requests will be rejected if logging fails, ensuring no data leaves the system without a complete provenance record. |
