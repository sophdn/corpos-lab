 To create the compliance checklist for data-export v2, follow these steps:

1. Enter the prerequisite sub-step from the defined entry conditions:
   - Review the v2 spec (`deployments/data-export-v2/spec.md`)
   - Review the v1 compliance checklist (`deployments/data-export-v1/compliance-checklist.md`)
   - Read the Q4 2025 bulletin (`policy/bulletins/2025-Q4-bulletin.md`)

2. Based on the review of the v2 spec and the v1 compliance checklist, the data scope, access controls, and retention policies are unchanged from v1. However, v2 adds a partner-portal access pathway.

3. Since the Q4 2025 bulletin states that any deployment adding a partner-initiated export pathway must record an additional audit entry — a Provenance Stamp — capturing the user's authorization grant id, the requesting party's identity, the authorization scope, and the validity window at time of export, add this new requirement to the compliance checklist.

4. Fill out the compliance checklist for data-export v2 (`deployments/data-export-v2/compliance-checklist.md`) as follows:

```
# Compliance Checklist for Data-Export v2

## Data Scope and Access Controls

- [x] Data Scope: Data export includes only the defined scope of data, as documented in the Data Export Specification (DES).
- [x] Access Controls: Access to data export is controlled by the defined roles and permissions, as documented in the Access Control Specification (ACS).
- [ ] Provenance Stamp (new): When partner-initiated exports are requested, a Provenance Stamp must be recorded, containing:
    - User's authorization grant id
    - Requesting party's identity
    - Authorization scope
    - Validity window at time of export

## Retention Policies

- [x] Data Retention: Data export adheres to the defined retention policies, as documented in the Retention Policy Specification (RPS).
```

5. Hand the compliance checklist back to the team.
