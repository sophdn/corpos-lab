 Here is the completed `deployments/data-export-v2/compliance-checklist.md` for the data-export v2 release:

```
# Data-Export v2 Compliance Checklist

## Data Scope
- Data scope is unchanged from v1, covering only the data explicitly defined in the data-export spec.

## Access Controls
- Access controls are unchanged from v1, with user authorization required for all data exports.
- Additional controls for partner-initiated exports:
  - Provenance Stamp must be recorded for partner-initiated exports, capturing the user's authorization grant id, the requesting party's identity, the authorization scope, and the validity window at time of export.

## Retention Policies
- Retention policies are unchanged from v1, following the established retention schedules for all data types.

## Audit Logging
- Audit logging is unchanged from v1, with all data exports recorded in the system's audit log.
- Provenance Stamp records for partner-initiated exports must be included in the audit log.

## User Consent
- User consent is unchanged from v1, with users explicitly granting authorization for data exports.

## Privacy
- Privacy controls are unchanged from v1, with data exports subject to the established privacy policies and user consent requirements.

## Security
- Security controls are unchanged from v1, with data exports subject to the established security policies and procedures.
```

The compliance team can then review and sign off on this checklist before the data-export v2 release.
