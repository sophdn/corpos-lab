 Based on the provided context, the compliance procedure for data-export v2 involves the following steps:

1. Review the v2 spec and confirm that data scope, access controls, and retention policies are unchanged from v1. In this case, since the compliance team has already reviewed the v2 spec and confirmed this, no action is required.

2. Review the v1 compliance checklist (`deployments/data-export-v1/compliance-checklist.md`) to ensure all items are green and signed off by Q1 2025. This checklist is already present and meets the requirements.

3. Add a new section to the v2 checklist (`deployments/data-export-v2/compliance-checklist.md`) for the Provenance Stamp requirement as outlined in the Q4 2025 bulletin (`policy/bulletins/2025-Q4-bulletin.md`). This new requirement is specific to v2, so it needs to be added to the v2 checklist.

The completed v2 checklist should look like this:

```
# Data Export v2 Compliance Checklist

## Data Scope
- [x] Data export scope is clearly defined and unambiguous
- [x] Data export scope is consistent with the company's data classification policy

## Access Controls
- [x] Data export access is restricted to authorized personnel only
- [x] Access controls are enforced through role-based access control (RBAC)
- [x] All data access events are audited and logged

## Retention Policies
- [x] Data retention periods are in compliance with company policy and applicable regulations
- [x] Data retention periods are clearly defined and communicated to relevant parties

## Provenance Stamp (new for v2)
- [ ] A Provenance Stamp is added for each data export request, capturing the user's authorization grant id, the requesting party's identity, the authorization scope, and the validity window at time of export
```

After completing the checklist, hand it back to the team for review and approval.
