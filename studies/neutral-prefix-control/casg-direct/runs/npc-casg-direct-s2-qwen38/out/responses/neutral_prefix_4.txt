```markdown
## Class: TTLCache

Added in version 2.3.0.

A cache implementation that expires entries after a configurable time-to-live (TTL) interval.

### Constructor

`TTLCache(maxsize=None, ttl=60.0, clock=time.monotonic)`

- `maxsize` (int, optional): The maximum number of items the cache can hold before evicting the least recently used entry. If `None`, the cache grows without bound (subject to memory limits).
- `ttl` (float, optional): The time-to-live in seconds for each cache entry. Defaults to `60.0`.
- `clock` (callable, optional): A function that returns the current time in seconds. Defaults to `time.monotonic`. This allows for deterministic testing.

### Methods

`get(key, default=None)`
- Returns the value for `key` if present and not expired.
- Returns `default` if the key is absent or if the entry has expired.
- Expired entries are removed from the cache upon access.

`set(key, value)`
- Inserts or updates the entry for `key` with `value`.
- Resets the TTL timer for this specific entry.
- If the cache exceeds `maxsize`, the least recently used entry is evicted.

`pop(key, default=None)`
- Removes and returns the value for `key` if present and not expired.
- Returns `default` if the key is absent or if the entry has expired.
- **Note:** Fixed in v2.3.0 to correctly handle concurrent evictions, preventing the return of stale values.

### Behavior
- Entries are considered expired if `current_time - insertion_time > ttl`.
- Expiry is checked lazily upon `get` or `pop`.
- This class inherits from the base `Cache` interface and implements the standard `__len__` and `__contains__` methods, which also account for TTL expiration.
```
