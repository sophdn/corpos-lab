### Updates for v2.3.0

#### New Class: `TTLCache`

A cache implementation that expires entries after a configurable time-to-live (TTL) interval.

```python
from gridcache import TTLCache

# Create a cache with a 60-second TTL
cache = TTLCache(ttl_seconds=60)

cache.set("key", "value")
assert cache.get("key") == "value"

# After 60 seconds, the entry will be expired
# cache.get("key") returns None after expiration
```

**Parameters:**
*   `ttl_seconds` (int, optional): The number of seconds an entry remains valid. Defaults to `None` (no expiration) if not specified in the constructor, though it can be set per-entry if supported by the implementation details.

#### Fixed: `LRUCache.pop`

**Previous Behavior (v2.2.x and earlier):**
`LRUCache.pop(key)` could return a stale value if the key was concurrently evicted by another thread or process between the time the key was looked up and the time the value was returned.

**New Behavior (v2.3.0):**
`LRUCache.pop(key)` now ensures consistency. If the key has been evicted, it returns `None` (or raises `KeyError`, depending on the `default` argument) rather than returning a stale value. This fix addresses race conditions in concurrent access scenarios.
