## v2.3.0 Changes

### New: `TTLCache`
A cache implementation that expires entries after a configurable time-to-live (TTL) interval.

#### Class Signature
```python
class gridcache.TTLCache(capacity: int, ttl: float)
```

#### Parameters
- `capacity` (int): The maximum number of items the cache can hold.
- `ttl` (float): The time in seconds after which an entry expires.

#### Behavior
- Entries are automatically considered stale and removed (or bypassed) once the `ttl` duration has elapsed since their insertion or last access.
- If the cache reaches its `capacity`, the least recently used (or oldest) entry is evicted, adhering to the same policy as `LRUCache` unless specified otherwise by the implementation details.

### Fixed: `LRUCache.pop`
- **Issue**: Previously, `LRUCache.pop` could return a stale value if a concurrent eviction occurred between the key lookup and the value return.
- **Resolution**: The method now safely retrieves the value after confirming the key has not been evicted during the operation, ensuring that `None` (or the defined default) is returned if the key is no longer present due to concurrent activity.
