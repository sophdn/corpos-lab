 In response to your requests, I will provide information about the Y-fire, Y-not-fire, and filterpipe v1.5.0 release.

**Y-fire:** This condition fires when an operation on a primary artifact is completed, but the companion artifact update is not present in the same execution scope. The companion artifact's state does not reflect the current state of the primary artifact set, and the obligation to update it remains unmet.

**Y-not-fire:** This condition does not fire when the companion artifact update is already present in the operation's execution scope alongside the primary artifact action. Both the primary artifact action and the companion artifact update are co-present within the scope before the operation closes, and the glyph does not fire.

**filterpipe v1.5.0 release:** This release introduces a `ChainedFilter` class for composing multiple filter functions and fixes the `NullFilter` raising `AttributeError` on empty input. The project maintains a changelog at `CHANGELOG.md`, and the release is complete. The version is bumped in `filterpipe/__init__.py` and `pyproject.toml`, and all 47 tests pass.
