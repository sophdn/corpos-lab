 To ensure the release is complete, follow these steps:

1. Update the `CHANGELOG.md` file with the changes introduced in the new release. Here's an example of how it could be written:

```
## v1.5.0 (YYYY-MM-DD)

### Added
- ChainedFilter class for composing multiple filter functions

### Fixed
- NullFilter no longer raises AttributeError on empty input
```

Replace `YYYY-MM-DD` with the date of the release.

2. Push the updated `CHANGELOG.md` to the remote repository.

3. Create a GitHub release for the new version (v1.5.0). Make sure to include the release notes from the `CHANGELOG.md` in the GitHub release description.

4. Ensure that the new tag (v1.5.0) is correctly associated with the correct commit in the repository.

By completing these steps, the release is considered complete and the new version (v1.5.0) is ready for users to install.
