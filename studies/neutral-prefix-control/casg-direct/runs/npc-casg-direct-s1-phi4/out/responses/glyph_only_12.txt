To summarize the provided information, we have three main axes describing different scenarios and conditions regarding operations on primary and companion artifacts:

### Marker Axis
- **Invariant:** The companion artifact's state should reflect the current state of the primary artifact set. If the companion artifact update is not included in the operation's executed scope, the obligation is unmet.
- **Firing Condition:** The operation is marked complete with the primary artifact updated, but without the companion artifact update in the same execution scope.
- **Does Not Fire On:** Operations where no companion artifact exists or where the operation does not trigger a companion update obligation.
- **Violation Signal:** The execution trace shows a primary artifact update without a companion artifact update in the same execution scope.

### Aim Axis
- **Invariant:** Both the primary artifact action and the companion artifact update should be present in the execution trace within the same operation's scope before it closes.
- **Recognition Signal:** The agent has successfully included both the primary and companion artifact updates in the same operation's execution scope.

### Rest Axis
- **Characterization (Absent Preconditions):** No companion artifact update obligation exists because either there is no companion artifact, or the operation does not affect the primary artifact in a way that creates such an obligation.
- **Characterization (Present Preconditions, Delegated Elsewhere):** A companion artifact update obligation exists, but it is assigned to another role, not the current agent.
- **Distinguishing Conditions:**
  - **Absent Preconditions:** No obligation to update the companion artifact.
  - **Present Preconditions, Delegated Elsewhere:** The obligation to update the companion artifact is assigned to another role.
