**Y-fire Scenario Analysis:**

In the Y-fire scenario, an agent is executing an operation on a primary artifact and is responsible for updating a companion artifact to reflect the current state of the primary artifact set. The critical issue here is that the agent completes the operation on the primary artifact and considers it the terminal step, without including the companion artifact update. This omission results in the companion artifact not reflecting the current state of the primary artifact set, thus failing to meet the obligation.

**Firing Condition:**

The firing condition is met when the execution trace of the operation shows the primary artifact being updated and the operation marked as complete, without the companion artifact update being included in the same execution scope. This is a clear violation because the agent held direct execution authority over the companion artifact update, and the obligation was not fulfilled.

**Violation Signal:**

The violation signal is observable in the execution trace, which indicates that the primary artifact was updated and the operation was marked complete, but the companion artifact update was not executed within the same operation. A calibration instance illustrating this violation could be a work item marked complete within a tracked workflow, where the work-item status is updated, but the parent tracking document's status record is not updated to reflect the completed work item in the same operation. The absence of the companion artifact update in the execution scope is the trace-readable violation.

**Y-not-fire Scenario Analysis:**

In the Y-not-fire scenario, the agent is in the same position, but the companion artifact update is already included in the operation's execution scope alongside the primary artifact action. Here, the discriminating condition is present: both updates are co-present within the scope before the operation closes. As a result, the glyph does not fire because the obligation is met.

**Rest Axis Characterizations:**

1. **Absent-Preconditions Territory:** In this scenario, neither the primary nor the companion artifact update is relevant because there is no companion artifact whose validity depends on the primary artifact set state, or the operation does not affect the primary artifact in a way that triggers a companion update obligation.

2. **Present-Preconditions-Delegated-Elsewhere Territory:** Here, a companion artifact exists, and its update obligation is live, but the update responsibility is assigned to another role. The current agent's obligation is to delegate the update, not perform it directly.

**Distinguishing Conditions:**

- **Absent-Preconditions:** The structural basis for the companion update obligation is absent.
- **Present-Preconditions-Delegated-Elsewhere:** All preconditions for the companion update are present, but the update is assigned to another role, placing the obligation in the delegate territory.
