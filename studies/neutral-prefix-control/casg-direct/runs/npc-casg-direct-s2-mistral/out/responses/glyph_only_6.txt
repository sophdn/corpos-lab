 Based on the given information, it seems like you are discussing a concept related to operations on artifacts and their companions. Here's a summary of the different states and conditions:

1. **Y-fire:** The primary artifact is updated, but the companion artifact remains unchanged, creating an obligation for the agent to update the companion artifact. This situation fires the condition.

2. **Y-not-fire:** The primary artifact and the companion artifact are both updated within the same operation, and the companion artifact update is already present in the operation's execution scope. In this case, the condition does not fire.

3. **Invariant:** The companion artifact's state does not reflect the current state of the primary artifact set, indicating that the companion artifact update was not part of the operation's executed scope.

4. **Firing condition:** The execution trace shows the operation closed with no companion artifact update in the same execution scope.

5. **Does not fire on:** Operations on a primary artifact where no companion artifact exists or where the current operation does not affect the primary artifact in a way that triggers a companion update obligation.

6. **Violation signal:** The execution trace shows the primary artifact updated, but the companion artifact remains unchanged in the same execution block.

7. **Aim axis:** The agent is holding a completed companion artifact update co-present with the primary artifact action within this operation's execution scope.

8. **Rest axis:** The choice between including and excluding the companion update does not arise in Y-neutral scenarios, where either the companion artifact's preconditions are absent, or the companion update is protocol-assigned to another role.
