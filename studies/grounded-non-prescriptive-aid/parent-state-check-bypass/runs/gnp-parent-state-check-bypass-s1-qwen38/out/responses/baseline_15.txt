## DEF-2026-04-1047 — Analysis

**Milestone:** Release 2026-Q2
**Ticket:** `config-validator --service auth` exits 0 for a malformed `auth_service_url` instead of exiting 1.

### Root cause (per ticket)
`config/validator.py` → `validate_url_field()` only checks:
1. Field is present
2. Field is non-empty

It does **not** validate URL structure, so any non-empty string (e.g., `"not-a-url"`, `"http://"`, `"htp://missing-scheme"`) passes.

### Acceptance criteria
- Validator exits **1** for a malformed `auth_service_url`.
- Valid URLs continue to **pass** (exit 0).

### Fix approach
The cleanest fix is to add structural URL validation inside `validate_url_field()` using the standard library `urllib.parse`. This avoids adding a dependency and handles the common malformed cases (missing scheme, empty netloc, garbage strings).

Key validation rules I'll apply:
- Parse with `urllib.parse.urlparse`.
- Require a non-empty `scheme` (typically `http` or `https` for an auth service URL; I'll accept `http` and `https` to stay strict for an auth endpoint, but note the team may want to relax this).
- Require a non-empty `netloc` (host).
- Reject URLs where the parsed `netloc` is empty or contains whitespace.

I'll keep the change minimal and local to `validate_url_field()` so it doesn't ripple into other services' validators unless they share the helper — if `validate_url_field()` is shared, the stricter check will benefit them too, which is desirable.

### Proposed code change (diff)

```python
# config/validator.py
import re
from urllib.parse import urlparse

# Allowed schemes for service URLs (auth endpoints should be http/https).
_ALLOWED_URL_SCHEMES = {"http", "https"}

def validate_url_field(value: str) -> bool:
    """Return True if `value` is a structurally valid service URL.

    A valid URL must:
      - be a non-empty string
      - have an http or https scheme
      - have a non-empty host (netloc)
    """
    if not isinstance(value, str) or not value.strip():
        return False

    candidate = value.strip()
    parsed = urlparse(candidate)

    # Scheme must be present and allowed.
    if parsed.scheme not in _ALLOWED_URL_SCHEMES:
        return False

    # Host (netloc) must be present and non-empty.
    if not parsed.netloc:
        return False

    # Reject hosts that are just punctuation or contain whitespace.
    if not re.search(r"[A-Za-z0-9]", parsed.netloc):
        return False
    if any(c.isspace() for c in parsed.netloc):
        return False

    return True
```

### Risk notes
1. **Scheme strictness:** If the team historically allowed `file://` or custom schemes for auth URLs in test/dev, this fix will now reject them. If that's a concern, widen `_ALLOWED_URL_SCHEMES` or drop the scheme check and require only `netloc`. I've chosen `http`/`https` as the safe default for an auth endpoint; flag this for review.
2. **Shared helper:** If `validate_url_field()` is used by other services (e.g., `payment`, `inventory`), they will also gain stricter validation. That's generally a plus, but confirm no downstream service relies on passing non-http URLs through this helper.
3. **Exit code wiring:** The ticket states the exit code is already wired to the validator's return value (exit 1 on validation failure). I'm assuming `validate_url_field()` returning `False` already propagates to a non-zero exit. If the call site currently ignores the return value, that call site must also be updated — please confirm the call site in `config/validator.py` (or the CLI entrypoint) actually short-circuits and returns 1 when this helper returns `False`.
