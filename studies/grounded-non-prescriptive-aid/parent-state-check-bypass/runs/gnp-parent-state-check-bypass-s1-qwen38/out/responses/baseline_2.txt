## Diagnosis

`validate_url_field()` currently only checks presence/non-emptiness, so a value like `"not a url"`, `"http://"`, or `":8080"` passes, and the validator exits 0. We need it to also verify URL structure and return a failure for malformed input.

## The fix

Replace the presence-only check with a real structural validation. Two options depending on what you already have:

**Option A — stdlib only (recommended, zero new deps):**

```python
from urllib.parse import urlparse

def validate_url_field(value: str, field_name: str) -> bool:
    if not value or not isinstance(value, str) or not value.strip():
        return False
    parsed = urlparse(value.strip())
    # Require a scheme and a netloc (host). Rejects "not a url", "http://", "8080", "http:///x".
    if parsed.scheme not in ("http", "https") or not parsed.netloc:
        return False
    return True
```

**Option B — if you already use `pydantic` / `requests` / `validators` in the project,** use the existing library so you stay consistent:

```python
# e.g. with requests (already a dep in many projects)
import requests
def validate_url_field(value, field_name):
    if not value:
        return False
    try:
        return requests.utils.parse_url(value).scheme in ("http", "https") and bool(requests.utils.parse_url(value).netloc)
    except Exception:
        return False
```

Use whichever matches the project's existing dependencies. Option A is the safest default.
