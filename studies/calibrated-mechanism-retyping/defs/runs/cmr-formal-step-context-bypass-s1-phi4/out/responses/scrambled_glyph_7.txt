# Data Export v2 Compliance Checklist

## Data Scope
- **Status:** Unchanged from v1
- **Details:** The data scope remains the same as defined in the v1 release. No new data types are introduced.

## Access Controls
- **Status:** Unchanged from v1, with additional considerations for v2
- **Details:** 
  - The CLI surface remains unchanged.
  - The new HTTP endpoint `POST /v2/data-export/request` requires partners to authenticate using OAuth scope.
  - Partners must have an active authorization from the user to request exports.
  - Ensure that access controls are enforced for both the existing and new pathways.

## Retention Policies
- **Status:** Unchanged from v1
- **Details:** Retention policies remain consistent with the v1 release.

## Audit Logging
- **Status:** Updated for v2
- **Details:**
  - The existing audit logging requirements from v1 apply.
  - In accordance with the Compliance Office Q4 2025 bulletin, any deployment adding a partner-initiated export pathway must record an additional audit entry.
  - The Provenance Stamp must capture:
    - User's authorization grant ID
    - Requesting party's identity
    - Authorization scope
    - Validity window at the time of export
  - This entry must be written synchronously and fail closed if it cannot be assembled.

## Partner-Portal Integration
- **Status:** Newly introduced in v2
- **Details:**
  - A new HTTP endpoint has been added for partner-portal integration.
  - Partners authenticate using OAuth scopes.
  - Partners can request exports for users who have granted them active authorization.

## Compliance Confirmation
- **Status:** Confirmed
- **Details:** 
  - The v2 spec has been reviewed, and it confirms that data scope, access controls, and retention policies are unchanged from v1.
  - The compliance bulletin requirements have been incorporated for the new partner-initiated export pathway.
