# Data-Export v2 Compliance Checklist

## Introduction

This checklist confirms the compliance of the data-export v2 release, which adds a partner-portal access path to the existing v1 functionality. The v2 release retains the v1 data scope, access controls, and retention policies, with the addition of a new HTTP endpoint for partner integrations.

## Access Controls

- **Access Pathway**: The v1 CLI surface remains unchanged, and the new HTTP endpoint `POST /v2/data-export/request` has been added. Partners authenticate via OAuth scope.
- **Authorization**: Ensure that partners can only request exports for users who have granted them active authorization.
- **Compliance**: Access controls from v1 are still applicable. The new endpoint adheres to the same principles, with OAuth providing robust authentication.

## Audit Logging

- **Provenance Stamp**: As per the 2025-Q4 compliance bulletin, the new partner-initiated export pathway must record an additional audit entry, known as a Provenance Stamp.
  - **Components**: Capture the user's authorization grant ID, the requesting party's identity, the authorization scope, and the validity window at the time of export.
  - **Implementation**: Ensure this entry is written synchronously and fails closed if it cannot be assembled.
- **Audit Entries**: Verify that all audit logs, including the new Provenance Stamps, are comprehensive and accurately reflect all data-export activities.

## Data Scope and Retention Policies

- **Data Scope**: Confirm that the data scope remains unchanged from v1, ensuring no unauthorized data is exposed through the new endpoint.
- **Retention Policies**: Retention policies continue to apply as defined in v1, with no changes introduced by the v2 release.

## Security

- **Data Integrity**: Ensure that data integrity is maintained across both v1 and v2 pathways.
- **Encryption**: Verify that data in transit and at rest is encrypted according to the standards set in v1.
- **Vulnerability Management**: Conduct a security review to ensure no new vulnerabilities are introduced by the v2 release.

## Documentation

- **Update Documentation**: Ensure that all relevant documentation reflects the addition of the partner-portal access path and the new Provenance Stamp requirements.
- **User Guides**: Update user guides and partner documentation to include instructions on using the new HTTP endpoint.
