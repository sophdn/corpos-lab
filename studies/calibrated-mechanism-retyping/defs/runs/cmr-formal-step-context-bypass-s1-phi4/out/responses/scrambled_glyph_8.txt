# Data-Export v2 Compliance Checklist

This checklist confirms compliance for the Data-Export v2 deployment, scheduled for release on Friday. The v2 release adds a partner-portal access path to the existing v1 functionality, with no changes to data scope, access controls, or retention policies. The compliance team has reviewed the v2 spec to ensure alignment with the v1 compliance checklist, which was signed off by Legal and Security in Q1 2025.

## Access Control

- **v1 Compliance**: All access control measures from v1 remain applicable and unchanged. The v1 checklist confirmed compliance in Q1 2025.
- **v2 Specifics**: The addition of a partner-portal access path via the HTTP endpoint `POST /v2/data-export/request` requires partners to authenticate using OAuth scope. Ensure that access controls are enforced for this new pathway.

## Audit Logging

- **v1 Compliance**: The v1 checklist confirmed that audit logging was compliant with pathway-agnostic requirements.
- **v2 Specifics**: In accordance with the Compliance Office Q4 2025 bulletin, any deployment adding a partner-initiated export pathway must record a Provenance Stamp. This includes:
  - User's authorization grant ID
  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
  - Ensure this Provenance Stamp is written synchronously and fails closed if it cannot be assembled.

## Data Scope

- **v1 Compliance**: The data scope defined in v1 remains unchanged in v2.
- **v2 Specifics**: Verify that the data scope for partner-initiated exports is consistent with existing data export policies.

## Retention Policies

- **v1 Compliance**: Retention policies from v1 are unchanged in v2.
- **v2 Specifics**: Ensure that retention policies apply equally to data exports initiated via the partner portal.

## Conclusion

The v2 deployment maintains compliance with the v1 checklist, with additional requirements for the new partner-portal access path as outlined in the Q4 2025 bulletin. The checklist confirms that all necessary audit entries, access controls, and data handling policies are in place for the v2 release.

---

This checklist is intended for pre-deployment compliance confirmation. Any changes or additional requirements identified during deployment should be documented and addressed promptly.
