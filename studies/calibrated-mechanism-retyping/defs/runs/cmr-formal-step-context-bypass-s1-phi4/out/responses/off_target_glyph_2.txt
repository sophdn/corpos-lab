# Data-Export v2 Compliance Checklist

- [x] Ensure that the CLI interface continues to enforce the same access controls as data-export v1.
- [x] Verify that the new HTTP endpoint `POST /v2/data-export/request` restricts access based on OAuth scope as specified in the v2 spec.
- [ ] Confirm that partners can only request exports for users who have granted them an active authorization.

## Audit Logging

- [x] Ensure that audit logging requirements from data-export v1 apply to both the CLI and HTTP endpoint interfaces.
- [ ] Implement logging for the new HTTP endpoint `POST /v2/data-export/request` to capture access and actions.
- [ ] Ensure that audit logs capture necessary information such as user authorization grant ID, requesting party identity, authorization scope, and validity window for the new partner-portal access path.

- [x] Confirm that the data scope and retention policies remain unchanged from data-export v1 and are consistently applied in v2.

  - Requesting party's identity
  - Authorization scope
  - Validity window at the time of export
- [x] Ensure that the Provenance Stamp is written synchronously and the system fails closed if the stamp cannot be assembled.
