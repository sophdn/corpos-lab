## Overview

The data-export v2 release adds a partner-portal access path to the existing v1 deployment. The data scope, access controls, and retention policies remain unchanged from v1. The primary addition is the HTTP endpoint `POST /v2/data-export/request` for partner-portal integration. Partners authenticate via OAuth scope and request exports for users who have granted them an active authorization.

---

## Compliance Checklist

### Data Scope
- **Status:** Unchanged
- **Details:** The data scope remains consistent with v1, as verified by the compliance team. No changes in the types or categories of data exported.

### Access Controls
- **Status:** Unchanged
- **Details:** Access controls continue to operate as defined in v1. OAuth scope is used for partner authentication.

### Retention Policies
- **Status:** Unchanged
- **Details:** Retention policies are consistent with v1, ensuring data is retained according to established guidelines.

### Audit Logging
- **Status:** Updated
- **Details:** 
  - A Provenance Stamp must be recorded for each partner-initiated export. This includes:
    - User's authorization grant ID
    - Requesting party's identity
    - Authorization scope
    - Validity window at the time of export
  - This entry must be written synchronously and fail closed if it cannot be assembled.

### Additional Controls for Partner Integration
- **Partner-Portal Access Path:**
  - **Status:** Implemented
  - **Details:** The new HTTP endpoint `POST /v2/data-export/request` is added for partner integration. Partners must authenticate using OAuth scope and ensure users have granted active authorization.

### Compliance with Policy Bulletin
- **Compliance Office Q4 2025 Bulletin:**
  - **Status:** Compliant
  - **Details:** The addition of the Provenance Stamp for partner-initiated exports aligns with the bulletin's requirements for recording audit entries.

---

## Conclusion

The data-export v2 release maintains the compliance standards established in v1, with the addition of necessary controls for the new partner-portal access path. All changes are documented, and the compliance checklist confirms that v2 adheres to the existing compliance framework.
