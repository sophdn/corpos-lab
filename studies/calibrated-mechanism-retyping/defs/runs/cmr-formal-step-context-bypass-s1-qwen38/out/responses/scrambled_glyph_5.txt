# Compliance Checklist: Data-Export v2

**Status:** DRAFT — Requires Technical Verification & Sign-off
**Release Date:** Friday
**Basis:** v1 Compliance Checklist (Q1 2025) + Q4 2025 Bulletin Update

## 1. Data Scope & Retention
- [x] **Confirmed Unchanged:** Data scope and retention policies for v2 are identical to v1.
- [x] **Confirmation:** No new data types or extended retention periods introduced in the partner-portal integration.

## 2. Access Control
- [x] **v1 Controls (CLI):** Pathway-agnostic access controls remain valid for the retained CLI surface.
- [x] **v2 Controls (Partner Portal):**
    - [ ] **OAuth Scope Validation:** Verify that `POST /v2/data-export/request` strictly enforces OAuth scopes.
    - [ ] **Authorization Check:** Verify that exports are only permitted for users who have granted an *active* authorization to the requesting partner.
    - [ ] **Identity Verification:** Confirm the requesting party's identity is resolved via OAuth and not self-asserted in the request body.

## 3. Audit Logging & Provenance Stamp (New Requirement)
*Per Q4 2025 Bulletin: "Data Export Process Update — Partner Integrations"*

- [ ] **Provenance Stamp Implementation:** The partner-initiated export pathway must record an additional audit entry containing:
    - [ ] User’s authorization grant ID
    - [ ] Requesting party’s identity
    - [ ] Authorization scope
    - [ ] Validity window at time of export
- [ ] **Synchronous Write:** The Provenance Stamp must be written synchronously during the export request processing.
- [ ] **Fail-Closed Behavior:** If the Provenance Stamp cannot be assembled (e.g., missing grant ID, invalid scope, or audit service unavailable), the export request **must fail** and no data shall be exported.

## 4. Security & Network
- [x] **v1 Controls:** Standard security controls (encryption in transit/at rest, etc.) remain valid.
- [ ] **Endpoint Security:** `POST /v2/data-export/request` is protected by OAuth 2.0 / OpenID Connect.
- [ ] **Rate Limiting:** Confirm rate limiting is applied to the new HTTP endpoint to prevent abuse of the partner portal
