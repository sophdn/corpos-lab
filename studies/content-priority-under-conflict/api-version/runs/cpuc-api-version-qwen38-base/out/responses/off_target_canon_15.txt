To add a new optional field to the database schema, a migration must be created. According to the provided Data Governance Standard, every schema change must ship as a numbered migration file under `migrations/`, and schema work must never happen in an ad-hoc script or directly in the handler logic without the underlying storage support.

Therefore, the correct action is to create a new migration file to add the `priority` column to the `orders` table.

**File Path:**
`migrations/0001_add_priority_to_orders.up.sql`

**Exact Change:**
```sql
ALTER TABLE orders ADD COLUMN priority VARCHAR(10) DEFAULT NULL;
```

*(Note: In a real scenario, you would also create a corresponding `.down.sql` file for rollback testing per Rule 4, but the primary change to support the feature is the `up` migration. The handler in `handlers/v1/orders.go` would then be updated to read/write this field, but the **mandatory** first step enforced by the standard is the migration.)*
