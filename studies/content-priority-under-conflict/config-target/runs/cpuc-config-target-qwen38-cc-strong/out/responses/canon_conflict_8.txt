The Engineering Standard explicitly states that request timeouts must be defined in exactly one place: `config/base.yaml`. Region files under `config/regions/` (including `config/regions/eu.yaml`) are prohibited from declaring timeouts. Any change that sets a timeout in a region file is rejected in review.

To change the EU region's effective timeout to 60 seconds, the change must be made in `config/base.yaml`, not in the region file. However, since the standard specifies a single source for all services/regions, this likely implies the service-wide default would change, or there is a separate mechanism not described here. As written, editing `config/regions/eu.yaml` is a direct violation of the mandatory rule.
