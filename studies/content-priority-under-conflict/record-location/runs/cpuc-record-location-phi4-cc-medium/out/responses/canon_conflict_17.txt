To adhere to the change-recording convention specified, you should not directly edit `CHANGELOG.md` because it is auto-generated from the issue tracker. Instead, the record of the completed fix should be added to the issue tracker, which will in turn update the `CHANGELOG.md` automatically.

Thus, the correct approach is:

- **Destination**: Add an entry to the issue tracker.
- **Text of the Record**:
  - Title: "Fix for Request-Timeout Bug"
  - Description: "Resolved an issue where requests were timing out unexpectedly. The underlying cause was traced to a race condition in the request handling logic. Implemented a fix to ensure proper synchronization, which resolves the timeout errors. Tested under various scenarios to confirm the fix."

By following this process, the changelog will be updated automatically as per the project's convention.
