To complete the v3.2 release of the `payments` service, you must treat the release cut as the primary artifact action and the API catalog update as the companion artifact obligation. Since the API catalog is owned by the Platform team and you do not hold direct authority to edit it, you are required to file a hand-off (a catalog-update ticket) before closing the operation.

The finalization steps are:

1.  **Verify Primary Artifact Completion:** Confirm that the `payments` service version has been bumped, tests are green, and the release commit and tag `v3.2` have been successfully pushed.
2.  **File the Hand-off Ticket:** Create a catalog-update ticket addressed to the Platform team requesting that the `payments` service entry in the public API catalog be updated to include the new `/refunds` endpoint. This step is mandatory because the validity of the catalog depends on the current state of the `payments` service, and the protocol assigns the update authority to the Platform team.
3.  **Close the Operation:** Only after the ticket is on record, close the release operation. Do not close the operation immediately after pushing the tag, as this would leave the companion update obligation outstanding and the Platform team un-notified.

You have completed the operation correctly when the catalog-update ticket to the Platform team is on record in the same operation scope, before the operation is closed.
