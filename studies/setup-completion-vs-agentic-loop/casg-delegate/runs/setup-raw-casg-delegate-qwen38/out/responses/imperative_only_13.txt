To complete the v3.2 release for the `payments` service, you must execute the following finalization steps. The critical distinction here is that while you have completed the primary artifact action (shipping the code), you do not hold authority to update the companion artifact (the API catalog). Therefore, the operation is not terminal until the hand-off to the assigned role is filed.

**Finalization Steps:**

1.  **Verify Primary Artifact Completion**
    Confirm that the `payments` service v3.2 is fully shipped: the version is bumped, tests are green, and the release commit/tag `v3.2` is pushed and deployed. This is the primary action that has already been executed.

2.  **Identify Companion Artifact Obligation**
    Acknowledge that the new `/refunds` endpoint makes the current `payments` entry in the org's public API catalog out of date. This catalog is a companion artifact whose validity depends on the live state of the service endpoints.

3.  **File the Required Hand-Off (Catalog-Update Ticket)**
    **File a catalog-update ticket with the Platform team.**
    *   **Why:** Org policy assigns ownership of the API catalog exclusively to the Platform team. You do not have direct authority to edit it.
    *   **Action:** Create a ticket requesting the addition of the `/refunds` endpoint to the `payments` service entry. Include the relevant endpoint documentation, authentication requirements, and the v3.2 version tag as reference.
    *   **Scope:** This must be done *within the same operation scope* as the release finalization, before you consider the release operation closed.

4.  **Do NOT Update the Catalog Yourself**
    Explicitly refrain from editing the API catalog directly. Doing so would bypass the protocol and violate the separation of duties defined by org policy. Your obligation is the hand-off, not the edit.

5.  **Close the Release Operation**
    Only after the catalog-update ticket to the Platform team is **on record** should you close the v3.2 release operation.
    *   **Correct State:** Primary artifact (v3.2 release) is shipped; Hand-off (Platform ticket) is filed.
    *   **Incorrect State:** Primary artifact is shipped; No hand-off filed. (This leaves the companion update obligation outstanding and the Platform team un-notified.)

**Conclusion:**
The release is not truly "complete" in terms of organizational compliance until the Platform team is notified via the proper channel. Filing the ticket is the mandatory final step that bridges the gap between your team's shipping action and the Platform team's catalog maintenance duty.
