Subject: Compliance Confirmation: Data-Export v2 Pre-Deployment

To the Deployment Team,

This is a pre-deployment compliance confirmation for the **data-export v2** release. Per our procedure, this is not a full re-review. We have verified that the v2 specification retains the v1 CLI surface and that the core data scope, access controls, and retention policies remain unchanged from the v1 release (signed off Q1 2025).

However, v2 introduces a new partner-portal access path (`POST /v2/data-export/request`) utilizing OAuth scopes. This triggers the **"Data Export Process Update — Partner Integrations"** item in the Compliance Office Q4 2025 bulletin (effective 2025-11-01).

Below is the completed v2 compliance checklist.

### Key Changes & Additions for v2
1.  **New Audit Requirement (Provenance Stamp):** Because v2 adds a partner-initiated export pathway, we must record an additional audit entry known as a **Provenance Stamp** for every export request made via the partner portal.
    *   **Fields Required:** User's authorization grant ID, requesting party's identity, authorization scope, and validity window at time of export.
    *   **Implementation Constraint:** This stamp must be written **synchronously** to the audit log. The system must **fail closed** (reject the export request) if the Provenance Stamp cannot be assembled.
2.  **Access Control Verification:** The v1 access-control items are written in pathway-agnostic terms and remain valid. We confirm that the new OAuth scope-based authentication for partners aligns with the existing v1 access control model without weakening user consent requirements.
