# Data Export v2 Compliance Checklist

**Status:** DRAFT – Awaiting Final Sign-off
**Release:** data-export-v2
**Deploy Target:** Friday
**Reference:** Q1 2025 v1 Sign-off (Legal & Security)
**Policy Reference:** 2025-Q4-bulletin.md (Effective 2025-11-01)

## Executive Summary
The v2 release introduces a new partner-portal access path (`POST /v2/data-export/request`) via OAuth scopes. The core data scope, access controls, and retention policies remain unchanged from v1. However, per the **2025-Q4 Compliance Bulletin**, this new partner-initiated pathway triggers a mandatory new control: the **Provenance Stamp**. This checklist confirms the applicability of existing v1 controls and validates the implementation of the new Q4 requirement.

## 3. Audit Logging & Provenance
**Input:** `policy/bulletins/2025-Q4-bulletin.md` (New Requirement)
**v1 Status:** ✅ Green (Pathway-agnostic terms in v1 checklist)
**v2 Change:** **CRITICAL UPDATE REQUIRED**

| Control | Status | Notes |
| :--- | :---: | :--- |
| Standard Audit Logs (v1) | ✅ | All v1 audit logging requirements remain in force. |
| **Provenance Stamp (New)** | ⚠️ **PENDING VERIFICATION** | **MANDATORY per 2025-Q4 Bulletin.** The new partner pathway must record a Provenance Stamp containing: <br>1. User’s authorization grant ID <br>2. Requesting party’s identity <br>3. Authorization scope <br>4. Validity window at time of export |
| **Synchronous Write** | ⚠️ **PENDING VERIFICATION** | Provenance Stamp must be written **synchronously** to the audit log. |
| **Fail-Closed Behavior** | ⚠️ **PENDING VERIFICATION** | If the Provenance Stamp cannot be assembled or written, the export request **must fail closed** (i.e., the export is aborted). |

> **Compliance Officer Note:** The v1 checklist was written in pathway-agnostic terms, meaning it did not anticipate the specific "partner-initiated" trigger. The Q4 Bulletin explicitly requires the Provenance Stamp for *any* deployment adding a partner-initiated export pathway. **The v2 implementation must be verified to ensure the fail-closed mechanism is active before deployment.**
