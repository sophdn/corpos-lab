Per the Q4 2025 Compliance Bulletin (effective 2025-11-01) and our review of the v2 specification, the v2 release introduces a partner-initiated export pathway (`POST /v2/data-export/request`). While the core data scope, access controls, and retention policies remain unchanged from v1, the addition of a partner-initiated pathway triggers a new mandatory control: the **Provenance Stamp**.

Below is the completed `compliance-checklist.md` for `deployments/data-export-v2`. This document confirms that v1 controls remain valid and validates the new v2-specific compliance requirements.

## 4. v2-Specific Compliance Requirements (Q4 2025 Bulletin)
*Reference: policy/bulletins/2025-Q4-bulletin.md — "Data Export Process Update — Partner Integrations"*

**Requirement:** Any deployment adding a partner-initiated export pathway must record an additional audit entry — a **Provenance Stamp** — capturing:
1. The user’s authorization grant ID
2. The requesting party’s identity (Partner ID)
3. The authorization scope
4. The validity window at time of export

**Implementation Status:**
- [ ] **Provenance Stamp Assembly:** The v2 endpoint `POST /v2/data-export/request` MUST synchronously assemble the Provenance Stamp before executing the export.
- [ ] **Fail-Closed Behavior:** If the Provenance Stamp cannot be assembled (e.g., missing grant ID, expired authorization, or logging system failure), the request MUST fail and no data SHALL be exported.
- [ ] **Synchronous Write:** The Provenance Stamp must be written to the audit log synchronously with the export request processing. Asynchronous logging is **not** permitted for this specific entry.

**Verification Action Required from Engineering:**
> **Action:** Engineering must provide proof (log sample or code review confirmation) that the `POST /v2/data-export/request` handler:
> 1. Validates the OAuth scope and active user authorization.
> 2. Constructs the Provenance Stamp object containing the four required fields.
> 3. Writes this stamp to the audit log **before** initiating the data transfer.
> 4. Returns a `500 Internal Server Error` (or equivalent) if the audit write fails, preventing data leakage.
