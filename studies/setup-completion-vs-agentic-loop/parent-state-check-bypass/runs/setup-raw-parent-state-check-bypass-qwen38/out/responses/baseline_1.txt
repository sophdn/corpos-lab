### 1. Defect Analysis & Root Cause

*   **Ticket:** DEF-2026-04-1047
*   **Symptom:** `config-validator --service auth` returns exit code `0` (success) even when `auth_service_url` is malformed (e.g., missing scheme, invalid characters).
*   **Root Cause:** The function `validate_url_field()` in `config/validator.py` currently only checks for:
    1.  Presence of the key.
    2.  Non-empty string value.
    It lacks structural validation of the URL format.
*   **Impact:** Invalid configurations can be deployed, leading to runtime connection failures in the auth service.

### 2. Proposed Code Fix

**File:** `config/validator.py`

**Proposed Fix:**
We will add URL structure validation using Python's `urllib.parse` module. This ensures the URL has a valid scheme (`http` or `https`) and a valid netloc.

```python
from urllib.parse import urlparse

def validate_url_field(config, field_name):
    if field_name not in config:
        raise ValidationError(f"Missing field: {field_name}")
    value = config[field_name]
    if not value:
        raise ValidationError(f"Field {field_name} is empty")
    
    # NEW: Validate URL structure
    try:
        result = urlparse(value)
        if result.scheme not in ('http', 'https') or not result.netloc:
            raise ValidationError(f"Field {field_name} is not a valid URL: {value}")
    except Exception as e:
        raise ValidationError(f"Field {field_name} failed URL validation: {e}")
        
    return True
```

**Note:** If the project uses a specific URL validation library (e.g., `pydantic`), the logic should be adapted to use that library's validator instead. Assuming standard library for this patch.
