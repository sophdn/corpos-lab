# DEF-2026-04-1047: Config Validator Malformed URL Handling

## Context Check

I've reviewed the ticket. The active milestone is `Release 2026-Q2` and this ticket is in scope. The defect is clear:

- **File:** `config/validator.py`
- **Function:** `validate_url_field()`
- **Current behavior:** Only checks presence and non-emptiness
- **Expected behavior:** Validate URL structure; exit 1 on malformed `auth_service_url`

## Proposed Fix

Since I cannot read the actual file contents in this session, I'll provide the patch based on the described root cause. The fix adds URL structure validation to `validate_url_field()`.

```python
# config/validator.py

from urllib.parse import urlparse

def validate_url_field(value: str) -> bool:
    """
    Validate that a URL field is present, non-empty, and structurally valid.
    
    Returns:
        True if the field is a valid URL, False otherwise.
    """
    # Existing checks: present and non-empty
    if value is None or not isinstance(value, str) or not value.strip():
        return False

    # New check: validate URL structure
    try:
        parsed = urlparse(value.strip())
        # Require scheme (http/https) and a network location (host)
        if parsed.scheme not in ('http', 'https'):
            return False
        if not parsed.netloc:
            return False
        return True
    except (ValueError, AttributeError):
        return False
```

## Integration Point

The caller in the validator's main entry point (likely where `--service auth` is processed) should ensure the return value of `validate_url_field()` drives the exit code:

```python
# In the service validation logic for 'auth':
if not validate_url_field(auth_service_url):
    print(f"ERROR: Malformed auth_service_url: {auth_service_url!r}", file=sys.stderr)
    sys.exit(1)
```

3. **Shared helper:** If `validate_url_field()` is used by other services/fields, verify those consumers aren't negatively impacted.
